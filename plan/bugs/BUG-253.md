# BUG-253: 5330 で蓋を閉じても何も起きない（蓋の事象が kernel にも compositor にも届かない）

- 状態: reproduced（実機 5330、ユーザー 2026-10-07「5330にHDMIを繋ぎ、蓋を閉じましたが、何も起こりません。」） / scheduled（直しは d898b0151、実機の確認待ち: 直しの kernel の起動では 5330 で `KWL EVENT lid closed`・`lid open` が届いた（BUG-255 の観察）が、次の起動（BUG-255 の診断の UAT (a)、2026-10-07）では蓋の事象が 1 つも届かなかった）
- 証拠: [kernel-5330.log](BUG-253/kernel-5330.log)・[session-5330.log](BUG-253/session-5330.log)（main 2fe4a5019 の userland、da51e8609+88833c9da+9a42683c9 の kernel）

## 観察（Q1、SSH）

- HDMI は届いている: kernel `HPD-EVENT HDMI-A-1 ... disconnected -> connected (CHANGED)`、EDID 1920x1280。compositor `KWL OUTPUT display index=1 name=...:hdmi:B internal=0 shown=0`・`displays count=2`。
- 蓋: 起動時に `acpi: power device lid value 1`、`ACPI: Notify(\_SB_.LID0, 0x80) has no handler`（起動の早い時期、handler の登録の前）。蓋を閉じた後に kernel の lid の行も compositor の `KWL LID` の行も無い。AC の抜き差しは compositor に届いている（`KWL POWER source=battery`・`source=ac`）。
- 疑い: 蓋の Notify（EC の query → `Notify(LID0, 0x80)`）が来ていない、来ても acpi-power の lid の device の handler が value を読み直さない・事象を出さない、または compositor の backend が lid の事象を購読していない。

## 次

- kernel の lid の経路（src/drivers/acpi/acpi-power.c の notify と事象、EC の GPE と _Qxx）と compositor（backend-host.c の kwl_lid_follow・sleep.c）を読み、実機で蓋を閉じて SSH で確かめる（ユーザーに蓋の操作を頼む時は Q1 経由）。

## 原因と直し（2026-10-07 P2、q854-i01）

- 原因: 5330 の蓋の事象は **GPE 0x18** の `\_GPE._L18` が運ぶ（`ECG7` の bit 1 → `EV3 (3, _LID)` → `\_SB.BTNV` → `Notify (LID0, 0x80)`）。GPE 0x18 は `LID0._PRW`・`PBTN._PRW`（`PPRW`、Dell の SMI `EEAC (3, 0)` が実行時に返す）が名指す GPE でもある。5330 の稼働中の zedBSD で `/dev/acpi` に `\_SB.LID0._PRW` を評価させて `Package [2] { Integer 0x18, Integer 0x3 }`（PBTN も同じ）を確かめた。`acpi-event.c` は `_PRW` が名指す GPE を wake 専用として実行時は mask したままにする（`wake_visitor`、`events_init` の「A GPE with a method that does not only wake is a runtime event」）ので、0x18 は S0 idle の間（armed の時）しか開かず、稼働中の蓋の開閉は kernel に届かなかった。起動の時の `Notify(\_SB_.LID0, 0x80) has no handler` は EC の `_REG` からの `ECIN` の 1 回で、蓋の事象の経路ではない。AC は EC の query（`_Q66` → `NEVT`）で来るので届いていた。Linux は lid・button の driver が自分の wake の GPE を実行時にも有効にする（`acpi_enable_gpe`）ので、この firmware で動く。
- 直し（kernel）: `drv_acpi_gpe_runtime_enable(gpe)`（`src/drivers/acpi/acpi-event.c`、宣言は `include/drivers/acpi/acpi.h`。HAL の API ではない）: method か handler のある GPE を実行時の event にする（`enabled = 1`、sleep の外なら今 unmask、thread が処理中ならその後に thread が unmask。sleep の間は armed に従い、sleep の終わりで実行時の状態に戻る）。`src/drivers/acpi/acpi-power.c` の attach が、蓋と power・sleep の button について notify の handler を付けた後に `_PRW` の GPE（整数の時だけ、0xff 以下）を有効にし、`acpi: lid events on GPE 0x18` を log に出す。
- 0x18 の `_L18` の他の枝: `ECG7` が 0・bit 0・4 の時は `EV3 (1, 1)` → `Notify (PBTN, 0x02)`（Device Wake）で、acpi-power は button の 0x80 だけを押下とするので無視する（二重の押下にならない）。
- compositor の側（`backend-host.c` の `kwl_backend_lid_changed` → `kwl_lid_follow`、HDMI がある時は `kwl_output_use_external`）と backend の購読（`events-zedbsd.c` の `KERN_SYSTEM_EVENT_LID`）は既にある。直していない。
- 確かめ: kernel（`make -j16 ZEDBSD_CONFIG=config/current-uat.mk BUILD=build/bug250 vmunix`）warning 0、include check・vmunix check PASS、cksum `1706135522 3147752`。host の試験 `plan/ws132/tests/run-host-acpi-power.sh`（蓋と button の `_PRW` の GPE だけが実行時に有効になる check を足した、142 checks PASS）、`plan/ws052/tests/run-host-sleep.sh`（sleep.expected・latitude5330.expected の一致、acpi-event.c を含む）PASS。実機（5330）: 新しい kernel で起動し、`acpi: lid events on GPE 0x18` が kernel の log に出ること、HDMI をつないで蓋を閉じると session.log に `KWL EVENT lid closed` と `KWL LID external: ...` が出て desktop が HDMI に移ること、蓋を開けると `KWL LID internal` で panel に戻ること（後者は eDP の connected の残り、BUG-250 の残りの直しにも依る）。未実施。

## 状態の見直し（2026-10-08、Q1 の依頼で P2）

Board の行は「resolved（d898b0151、5330 で `KWL EVENT lid closed`・`lid open`）」だった。しかし ticket にも [BUG-255](BUG-255.md) にも、resolved と言える実機の確認は無い。
- 直しの kernel の起動では、蓋の事象が届いた（BUG-255 の「観察」: `acpi: lid events on GPE 0x18`、`KWL EVENT lid closed`）。
- 次の起動（BUG-255 の「診断の build の UAT (a)」、2026-10-07）では、閉じても開けても `acpi: lid notify`・`KWL EVENT lid` が 1 つも無かった。
→ 起動によって届かないことがあるので、scheduled（実機の確認待ち）に戻した（Board も同じ）。蓋の自動の切り替えはベータ3（2026-10-07 ユーザー、BUG-255）。
