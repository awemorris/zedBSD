# BUG-284: Settings の Ethernet の頁に wlan0（Wi-Fi）の card が出て「No cable」と表示される

Reproduction: reproduced（実機 5330、2026-10-10）
Disposition: resolved（2026-10-10 ユーザーの 5330 の UAT「Ethernet の頁、ue0だけになりました。Closeします」）
Discovery: 2026-10-10 BUG-277 の確かめ（ユーザー「wlan0でした。ue0はConnectedです。」）
Handling: WS089（Settings の Network）・libkeiland-backend-zedbsd の interface の種類の判定

## 観測

Settings → Network の Ethernet の頁に「wlan0」の card があり No cable。5330 の wlan0 は `flags=UP,BROADCAST,MULTICAST`（RUNNING 無し）`media: unknown`。Wi-Fi の interface が wired の card に入っている見込み（種類の判定）。

## 直し（2026-10-10、P1、agent/p1）

- 原因: Settings の wired の判定（`page-network.c` `network_wired`）は「loopback でなく、network service が今の radio と名乗る interface でない物」。service が radio を名乗るのはつないでいる間だけなので、つないでいない wlan0 が wired の card になった。
- 直し（名前でなく system の判定で radio を区別する）:
  - `struct kl_backend_network_link` に `wireless`。zedBSD の backend（`network-link-zedbsd.c` `link_wireless`）は kernel の Wi-Fi の状態の問い合わせ `SIOCGWLANSTATUS`（誰でも出せる query）に答える interface を radio とする（kernel は `NET_DEVICE_CAP_WLAN` の無い device に EOPNOTSUPP を返す。止まりかけの Wi-Fi の他の error も radio。networkd の radio の判定と同じ考え）。`link_wired` の wired の判定も名前の `wlan` から `wireless` に変えた。Linux と FreeBSD の backend は既にある `kwpa_wireless`（sysfs の phy80211・wireless、net80211 の SSID の問い合わせ）を使う。
  - compositor の link の event の flags に `KL_SYSTEM_LINK_WIRELESS`（0x8、古い client は無視）、libkeiland の `struct kl_network_link` の末尾に `wireless`（**KL_VERSION 76**）。
  - Settings の `network_wired` は `wireless` の interface を除く（BUG-277 の調べの中で入れた名前の規則 `wl…` は消した）。
- 確かめ: compositor と Settings の build（current-uat）rc 0・warning 0、Linux の backend の host の構文の確かめ（`cc -fsyntax-only`）OK、style-check の数は変更前と同じ。FreeBSD の backend は host で build できない（net80211 の header）ので目で確かめた。
- 未実施: QEMU には Wi-Fi が無いので、T1 では Ethernet の頁に ue0 の card だけが出て Connected（回帰）を見る。5330 で Ethernet の頁に wlan0 が出ないこと（ユーザーか Q1）。

## 2026-10-10 QEMU（T1）

T1-521 で Ethernet の頁に ue0 だけ（PASS）。実機は次の UAT。
