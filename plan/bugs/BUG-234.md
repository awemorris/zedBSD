## 観測（ユーザー）

「Filesで/binのファイルを開くと、何も起こらないように見えます。一瞬だけターミナルが起動していて、私に見えないだけなのか、起動していないのか、わかりません。GUIアプリはターミナルつきで開くので、一瞬開いているのかも。」

## 次（未確認の見込み）

実行 file の open の規則を確かめる（Terminal で実行して終わると閉じる見込み）。GUI の app（Wayland の client）は Terminal を付けずに起動、CLI は Terminal に残す（終わっても閉じない）など、何が起きたか見える形に。BUG-233 と同じ関連付けの道。

## q782-i01（P1、2026-10-06）: 原因と直し

Status: test-wait（T1 依頼中）

原因: `/bin` の program は ELF の program と判定され、既定が「Run in Terminal」（`@terminal %f`）。terminal は `--command` の command が終わると
window を閉じるので、`ls` などすぐ終わる command は一瞬で消え、何も起きないように見えた。GUI の app（Settings など）は余分な terminal 付きで開いた。

直し（baec07a1、`userland/desktop/files/apps.c`）:
- 「Run in Terminal」の command を `@terminal %f; status=$?; echo; echo "[The program ended with status $status. Press Return to close this window.]"; read reply`
  に。終わった後も window が残り、終わったこと（終了の status）が見える。
- 自分の window を開く program（ELF の DT_NEEDED に `libwayland-client.so` か `libX11.so`、version の付いた名前も）は、1 番目に「Open」（terminal
  無しで直接起動）、2 番目に「Run in Terminal」。ELF64 の little-endian の header・program header・dynamic section・string table を上限付きで読む
  （`apps_opens_windows`）。読めない file・ELF でない file は従来どおり terminal で。

確認: files-model: PASS（新しい項目: terminal が残る、Wayland の program は Open が先、command line の program は Run in Terminal が先。test は
合成した小さい ELF を使う）。scratch の確認で、本物の binary（host の `/usr/bin/eglgears_wayland` と zedBSD の `/bin/settings` は Open が先、
`/bin/ls` と zedBSD の `networkd` は Run in Terminal が先）。zedBSD の build warning 0、Linux の host build exit 0。QEMU は T1 に依頼。
