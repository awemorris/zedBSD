# BUG-387: Pi 5 で、console の login から Wayland の desktop（Keiland）を起動できない

- 状態: open（2026-11-01 08:42 Q1 が起票）
- 発見: 2026-11-01 08:42 ユーザーの報告。VisionFive 2 と Raspberry Pi 5 の両方で、console（文字の画面）に login した後、Wayland の desktop を起動できなかった。
- 2026-11-01 08:44 ユーザーの補足: VF2 で起動できなかったのは console に login できなかったため（[BUG-388](BUG-388.md)）。Pi 5 は console に login でき、その後の Wayland の起動が失敗した。→ この Bug は Pi 5 の分。VF2 は BUG-388 を直した後に確かめる。
- 未確認: 打った命令、画面に出た誤り、起動した kernel と userland の版（main のどの commit か）、x86（5330・10.0.10.3）と QEMU で同じ事が起きるか。
- 実機: VF2 `ssh kei@10.0.30.2`（SwitchBot 3 `AC276E432AE6`）、Pi 5 `10.0.30.7`（SwitchBot 2 `14C19FA80F86`）。
- 次: 担当が実機で再現する（console の login と同じ形で起動し、compositor・sessiond の log と終わり方を取る）。Pi 5 の graphical login（login=graphical）では desktop が出ている（2026-11-01 の P4 の計測）ので、console から起動する時の違い（tty・環境の変数・seat・権限）を疑う。

## 調べ（2026-11-01 P1、q1828-i01）

- Pi 5（10.0.30.7、`uname`: zedBSD 1.0.0-beta2+gce2d6f4 (ce2d6f4 2026-11-01) aarch64）。`/boot/boot0/cmdline.txt` は `login=console v3d.perf=1`。ユーザーの
  `~/.sh_history` の最後の方に `wayland`（console から打った命令）。
- 原因 1（GPU が held）: この起動の kernel は V3D を起動時に止めておく（dmesg `v3d: held; root starts it with: sysctl hw.gpu.start=1`、`src/drivers/gpu/bcm2711/attach71.c`）。
  `rpi5gpu.start=boot` が cmdline に無いので `/dev/gpu0`・`gpu1` が無く、`wayland` は `KWL VULKAN_ERROR operation=device result=-3`・`KWL COMPOSE unavailable errno=5` で
  終わる（SSH から user でも root でも同じ、frames=0）。graphical login の試験（`plan/ws291/tests/rpi5-desk.sh`）は cmdline に `rpi5gpu.start=boot` を足している。
- 原因 2（node の owner）: root が `sysctl hw.gpu.start=1` で V3D を起こす（`v3d: ready: V3D 7.1.10, 12 QPUs, 1150000000 Hz`、/dev/gpu0・gpu1 が出る）と、root の `wayland` は
  30 s 動いて `KWL OUTPUT open width=1920 height=1080`・frames=15・timeout で正常に終わった。user（uid 1000）の `wayland` は同じ result=-3 で終わり、dmesg に
  `gpu: open refused: uid 1000 is neither root nor the device's owner`（`src/drivers/gpu/gpu.c` の gpu_open: root か device node の owner だけが開ける。owner は
  graphical login の sessiond が seat の user に fchown する。console の login は誰にも渡さない。2026-10-03 からの規則）。→ 今の作りでは、console の利用者は root で
  ないと desktop を起動できない。
- hold の由来（直しの (a) の判断の材料）: [WS279](../ws279/ws.md) の p002・p003（2026-10-22）で、起動時は V0（power domain の後ろを読まない発見）だけ、V1〜V9 は
  `sysctl hw.gpu.start=1` で、とした開発中の安全策（engine が bus を固めても、電源の入れ直しで次の起動が無傷）。p007 から graphical login は `rpi5gpu.start=boot` で
  動いていて、2026-11-01 の sysctl の start も self-test は全部 ok（ident・mmu・irq・noop・clear・tfu・csd・reset）。既定を変えるかは Q1 が決める。
- 固まり（未再現）: 2026-11-01 09:2x、user の失敗の直後に root の `wayland` を SSH から 20 s の timeout で走らせた所で Pi 5 が SSH・ping に答えなくなり、Q1 が電源を
  入れ直した。前の起動の `/var/log/messages` は root の `wayland` の sudo の行で終わり、kernel.log にも続きは無い。同じ手順（sysctl の start の後に root の wayland 30 s）を
  もう一度流した時は固まらず正常に終わった（1 回のうち 0 回）。別の Bug かは未確定。

## 直し（2026-11-01 P1、562ebeec0、Q1 の方針の (b)）

- compositor が GPU を使えない時に、理由を 1 行で出す。`userland/desktop/libkeiland-backend/keiland-backend-gpu.h` に `kl_backend_gpu_unavailable_reason()` を足し、
  zedBSD の側（`userland/desktop/libkeiland-backend-zedbsd/gpu-buffer-zedbsd.c`）は /dev/gpu0 が無く `hw.gpu.start` が held の数を返せば「the GPU is held until root starts it:
  run 'sysctl hw.gpu.start=1' as root, then start the desktop again」、/dev/gpu0 の open が EACCES なら「/dev/gpu0 belongs to the graphical login's user; outside the graphical
  login only root may open it」。Linux・FreeBSD の側（`dmabuf/gpu-dmabuf.c`）は ENOENT だけ。`userland/desktop/wayland/main.c` は compose の失敗の後にこれを呼び、
  `KWL COMPOSE reason="…"` と、stderr に `wayland: the desktop cannot start: …` を出す。
- 確かめ: `make -j16 ZEDBSD_CONFIG=config/ci/config-rpi5.mk BUILD=build/q1828-rpi5 build/q1828-rpi5/bin/wayland` rc 0・warning 0。Linux の側は host の clang の
  `-fsyntax-only` だけ（Linux・FreeBSD の build は未実施）。Pi 5 の実機（板の /bin/wayland は変えず、`~/wayland-q1828` として user で起動）:
  - GPU を start した後（node の owner でない）: 上の 2 つ目の文が stderr と KWL の行に出て exit 1。
  - 電源の入れ直しの後（`v3d: held`、/dev/gpu0 無し）: 上の 1 つ目の文が出て exit 1。
- 残り（判断が要る）: console の利用者に desktop を使わせるか（login が console の user に /dev/gpu* を渡す、または console の session の seat）と、Pi 5 の image の既定を
  `rpi5gpu.start=boot` にするか。どちらも Q1・ユーザーの判断。VF2 でも同じ owner の規則に当たる事を SSH で確かめた（2026-11-01 09:4x、板の kernel 3758577736・板の /bin/wayland、kei で `wayland` → result=-3、dmesg
  `gpu: open refused: uid 1000 is neither root nor the device's owner`。VF2 の GPU は held ではない）。VF2 の画面の console からの起動そのもの（有線の keyboard で）は未実施。<!-- awesome-plan project=zedbsd record=BUG-387 -->

## Q1 の判断（2026-11-01 20:34）

- P4 の問い 1（後から作る account を video に入れるか）: 入れる。account-admin と Settings で作る人の account は video の member にする。video group は GPU を使う利用者のための物で、入れなければ後から作った人が同じ Bug に当たる。useradd は低い層の道具なので変えない。
- P4 の問い 2（input の node を video に広げるか）: この Bug ではしない。/dev/input/event* を video に読ませると鍵盤の入力を読める人が増え、security の範囲が変わる。既定の利用者は wheel にいるので当たらない。
- 見つかった `plan/tools/gpu-boundary/v1-check.sh` の失敗（gpu-buffer-zedbsd.c:30 の GPU_FIRST_NODE）は q1842 で P4 が直す。
