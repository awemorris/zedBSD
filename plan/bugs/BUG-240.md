# BUG-240: Browser の URL の欄に `/usr/...` と打つと今の https の頁の相対の URL として開く

Reproduction: reproduced（QEMU、T1-219、2026-10-06）
Disposition: tracking
Discovery: T1-219（BUG-206・207 の確認の時の別の事実）
Handling: WS074（browser の shell）

https の頁で URL の欄に `/usr/share/browser/start.html` と打って Enter すると `https://example.com/usr/…` へ移る。欄の入力が `/` で始まる時は local の file（`file://`）として扱うのが自然（BUG-206 で file の頁は `file:///usr/…` と出す）。UAT 以外の Bug なのでベータ2 の実装の後。

## 2026-10-08 P2 の確認（q869）

- **未実装**: Browser の URL の欄の Enter は、入力をそのまま `shell_follow`（browser/shell/shell.c）へ渡し、今の頁を基に解決する。`/` で始まる入力を `file://` にする処理は無い（titlebar.c の file:// は欄の表示だけ）。
- 証拠: T1-219（2026-10-06）の QEMU で `https://example.com/usr/share/browser/start.html` へ移った。
- Queue・commit 無し。残り: 実装と確認（小さな直し）。

## 修正（2026-10-08 P2、q870）

- `userland/desktop/browser/shell/shell.c`: URL の欄の Enter は新しい `shell_follow_typed` を通る。入力が `/` で始まる時は `file://` を付けて開く（log `ZBROWSER location typed=path url=file:///…`）。それ以外は今どおり、今の頁を基に解決する。
  - file の頁では `/usr/…` は今までも `file:///usr/…` に解決されていたので、変わるのは http(s) の頁の上だけ。
- build: `make ZEDBSD_CONFIG=config/ci/config-amd64.mk BUILD=build/amd64 build/amd64/bin/browser` は rc 0・warning 0。style-check 0。keiland-linux は browser を build しない（rc 0・warning 0）。
- host の試験: browser の shell の host 試験は無いので足していない（変えたのは 10 行の分岐だけ）。
- QEMU（T1 へ依頼）: T1-219 と同じ network のある guest で、https://example.com/ を開く → Ctrl+L で欄に `/usr/share/browser/start.html` → Enter。合格: `ZBROWSER location typed=path url=file:///usr/share/browser/start.html` が出て、start の頁が表示される（PNG）。続けて http の頁で `about` のような相対の入力が今どおり頁を基に解決されること（回帰）。
- Status: test-wait（T1）。
