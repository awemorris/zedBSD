# BUG-418: build system の作り直し（branch refactor）の後、rpi5 の kernel が起動しない・他の機種は未試験

- 状態: open（2026-11-08 19:10 Q1 が起票、ユーザーの報告から）
- 発見: 2026-11-08 ユーザー。branch `refactor`（top の Makefile と `mk/platform-<機種>/` に build system を作り直した）の後、rpi5 で kernel が起動しない。ユーザーは graphics の driver を疑っている。rpi4・vf2・i386・pc9821 は作り直しの後に未試験。
- 扱い: 2026-11-08 ユーザーから、BUG の ticket にして今日いちばん先に取り組む、graphics の driver 以外は取り急ぎ QEMU で確かめて直す、という趣旨の指示を受けた。Q1 が直に行う（branch refactor）。
- 範囲:
  - rpi4: QEMU raspi4b で起動と login。
  - i386: QEMU（PC/AT）で起動と login。
  - pc9821: PC-98 fork の QEMU（`~/qemu-pc98/build/qemu-system-i386`）と `plan/tools/pc98-boot.py`。
  - vf2: QEMU に JH7110 の machine が無いので build（vmunix と image）の確かめまで。実機は別に。
  - rpi5: QEMU に machine が無い。graphics の driver の問題はこの ticket の外（実機で）。build の確かめまで。
- 受け入れ: 上の各機種で `make` の vmunix と disk image が warning 0 で通り、QEMU のある機種は login prompt まで起動する。

## 経過

- 2026-11-08 21:14 Q1（commit d900df0f83・ef1893301f・02af6d85f2）。見つけて直した物:
  - kernel の link: `pci-power.c` が x86 だけにあった（xHCI の D0 の呼び出しで arm64 が未定義）→ `mk/kernel.mk` の PCI の共通へ。RTL815X の `usb-rtl815x-frame.c` の欠け、`driver-startup.c` の未宣言の変数。
  - config が kernel に届かない: USB Bluetooth・RTL815X（macro 名の誤り）・RPi5 の fan（`RPI5_TEMP` の誤り）・GPU の時間の macro 名・`CONFIG_DRIVER_GRAPHICS_DEVICE`（/dev/graphics が全機種で未登録）・serial の console（`ARM64_SERIAL_CONSOLE`）・試験の macro・buffer cache・Dell SMM。VF2 の source が古い名前（`CONFIG_DRIVER_POWERVR`・`CONFIG_DRIVER_VF2_VPU`）のままで GPU・VPU が無効だった → `CONFIG_DRIVER_VF2_GPU_VPU` に。
  - kernel の object が flag の変更で作り直されない → `$(BUILD)/.kernel-flags` の stamp。rpi4・rpi5・vf2 の cmdline.txt・config.txt・zedbsd.cfg が config の変更で作り直されない → 毎回作り、中身が変わった時だけ置き換え。
  - pc9821: B98S の header（`boot-header.S`）が `platform/` の削除で消えていた → `src/hal/i386/bsp-pc98/`。FAT の論理 sector が 512（PBR は 1024 だけを受ける）→ 1024。kernel の `-march=i686` で 486 に無い cmov → `-march=i386`（i386 も同じ）。swap の partition が cylinder で切り上がり header の大きさと食い違う → 既定の swap を 1020 MiB（17 MiB の倍数）、道具で検査。
  - i386: MBR に PARTLABEL が無いのに `swap0=PARTLABEL=…` → `/dev/sda3`。
  - userland: 静的 link に `--gc-sections` が無く、arm64・riscv64 の kernel が扱わない静的な TLS が init に残った。2026-11-08 ユーザーの決定で、init を含め全 program を動的 link（`ld.so`・`libc.so`）に。arm64・riscv64 の `libc.so` に binary128 の補助関数（`softfloat128.c`・`compiler-runtime128.c`）を足した。
- 確かめた事: 7 機種の kernel の build（warning 0）。QEMU raspi4b で rpi4（serial の console・文字の login の config）が login、`uname -a`・`host localhost` が動く（全 program 動的）。QEMU で i386 が login prompt（静的 link の時）。pc9821 は kernel が init の起動まで（静的 link の時、init の exec が ENOEXEC、動的 link で再試験）。
- 2026-11-08 21:44 Q1: 全 program の動的 link の後、rpi5・vf2・i386・pc9821・x86_64 を build（rc 0）し、全機種で rootfs の ELF が要る symbol をどの /lib の共有 library も定義しない物が 0。i386・PC-98 の program の `-march=i686`（`userland/base/package.mk`）で PC-98（486）の init が SIGILL → `-march=i386`。QEMU: x86_64（UEFI・NVMe）`init: system running`、i386（BIOS・IDE）login prompt、PC-98 の fork で root の login と `uname -a`（i386）、rpi4 で login・`host localhost`。
- 残り（この ticket の外か、ユーザーの判断）: `bin/noct`（207 個）と `lib/libGLX.so`（1 個）に 486 に無い cmov（noct の build は toolchain の扱い）。PC-98 で bluetoothd が起動し直し続ける・networkd の時間切れ・bootlog が FAT に log を作れない（Invalid argument）。graphical login の config の rootfs に、文字の login の config へ変えても greeter が残る（rootfs の木を消さないため）。
- 2026-11-09 Q1: ユーザーの報告で Pi 5 が `unhandled IRQ storm` で止まる。xHCI の DWC3 の判定（Moorefield 向けに足された）が GSNPSID でも DWC3 とみなし、RP1 の DWC3 にも DWC3 の初期化と INTx の level・active high への設定をしていた（RP1 の割り込みは MSI-X 経由）。判定を Intel の device ID だけにした（実機は未確認）。firmware: rpi4・rpi5 の defaults.mk に bcm43455・brcmbt の firmware が無かった → 足した。VF2 の defaults.mk の `CONFIG_DRIVER_VF2_GPU` → `CONFIG_DRIVER_VF2_GPU_VPU`、powervr・wave511 の firmware を足した。firmware の license の同意を Q1 が代わりに出す操作は権限の判定で止められた（ユーザーに依頼）。
- 2026-11-09 Q1: ユーザーの報告で、Pi 5 は Bluetooth の段まで進むようになったが、最後に `pci: irq … unhandled storm` で止まる（ユーザーは RPi5 の Bluetooth を config で無効にした）。2026-11-09 ユーザーから、main で動いておらず option に入れていなかった物を RPi5 の config から外す、という趣旨の指示を受けた。main の `config/ci/config-rpi5.mk` と main の Makefile の既定・`platform/arm64/vmunix.mk` と照らし、`mk/platform-rpi5/defaults.mk` で AHCI・CDC NCM/ECM・RTL815X・RTL8822BU・audio（core と RPI5_AUDIO、後者は source の無い枠）・I2C・I2C-HID・GPIO・EHCI・CCID・USB Bluetooth・Bluetooth の core・input bridge を n、rtl8822b・brcmbt の firmware を外した。CPU_PERF は kernel の本体が呼ぶので y のまま（main も常に build）。kernel の build は warning 0。名前の照合: rpi5 の source が見る macro に食い違いは無い。全体で mk が定義しない source の macro は ODROID-C5 の Mali・試験の probe・既定値のある調整値だけ。
