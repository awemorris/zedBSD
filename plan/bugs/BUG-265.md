# BUG-265: 浮いた titlebar でダブルタップからドラッグすると、ダブルクリックとして窓が最大化（dock）される

- 状態: reproduced（実機 5330、2026-10-08 午後 ユーザーの UAT） / scheduled（直しは P1 の branch、確かめ待ち）
- 由来: ユーザー「ウィンドウのフローティングタイトルバーで、ダブルタップからドラッグする標準的なモーションを行おうとすると、ダブルクリックとして認識されて、ウィンドウが最大化＝ドックされます。ダブルタップの2回目の指のタッチが離れた瞬間にダブルクリック判定すれば、回避できると思います。」

## 期待

- ダブルタップ（2 回目も離す）→ 最大化（dock）。
- ダブルタップの 2 回目で押したまま動かす（tap-and-drag）→ 窓の移動。最大化しない。
- 判定は 2 回目の指が離れた時（動きが閾値を超えていればドラッグ、超えていなければダブルクリック）。

## 担当

- 2026-10-08 午後 Q1: P1 に割当（ws189-p004 の前）。titlebar の press の扱い（compositor の titlebar か libkeiland の kl_titlebar）、touchpad の tap（WS183・native の touchpad）と touchscreen の両方で。

## 直し（2026-10-08 夕、P1）

- 原因: compositor の浮いた title bar の double click は 2 回目の press で最大化（dock）していた（BUG-179 で「押した時に」にした、shell.c `kwl_glass_button` の
  `title_clicks == 2`）。touch pad の tap and drag（touchpad.c: tap の後 TAP_DRAG_MS 以内に触れて動かすと、その press を左 button の押下として保つ）と touch screen の
  2 回目の touch も同じ press なので、動かす前に最大化された。title bar の double click は compositor だけが扱う（libkeiland の kl_titlebar は double click を見ない）。
- 直し（ユーザーの案）: 2 回目の press では決めず、その press を普通の移動として始め、離した時に決める（`wayland/title-tap.c`・`.h`、新）:
  離した所が 2 回目の press から `TITLE_TAP_SLOP`（8 px）以内なら double click（窓を press の時の位置に戻して dock、3 回目の press での取り消し
  `click_docked_third` は離した時から DOUBLE_CLICK_MS）、越えていれば移動（click の続きは終わり、3 回目は triple click にならない）。slop の中の間は窓を動かさない
  （指の揺れで窓が震えない）。mouse・touch pad の tap・touch screen は同じ press と release を通るので同じ規則（mouse の click の release は press の 50〜100 ms 後で、
  BUG-179 の 0.2 秒の目標の中）。log `KWL GLASS double-click wait surface=S`・`KWL GLASS double-click moved surface=S`、dock は今と同じ `via=double-click`。
- 範囲外のまま: system bar の中の docked の title の double click（元へ戻す）は press で決めたまま（今回の報告は浮いた title bar。docked の title を押して動かすと
  pull になる）。
- 試験: host `plan/bugs/BUG-265/title-tap-host.sh`（ASan・UBSan、release での判定、揺れ、tap and drag、離す前に戻った時、窓の消滅、大きな座標の overflow）PASS。
  シナリオ `desktop.windows.maximize-double-click` に手順 3（2 回目で押したまま 80 px 動かす → 移動、dock しない）を足し、log の接頭辞を今の `KWL` に直した。
- 確認: build（amd64 wayland、Linux all）warning 0、style の新しい指摘 0。QEMU と実機（5330 の touch pad・touch screen）は T1 とユーザーの UAT へ。
