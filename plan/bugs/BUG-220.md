# BUG-220: Files の詳細の list で Name・Size・Date の列の幅を drag で変えたい

Reproduction: reproduced（ユーザー、実機 5330、2026-10-06 UAT）
Disposition: tracking
Discovery: 2026-10-06 ユーザーの UAT のコメント
Handling: WS127（Files）

## 観測（ユーザー）

「Filesの詳細リストビューのとき、Name,Size,Dateのカラム幅をドラッグで変更できるとうれしいです。」

## 次（未確認の見込み）

列の境の drag で幅を変える（幅は保存するかは実装の時に決める）。

## 実装（2026-10-06 P2、q798）

- `userland/desktop/files/ui-list.c`: list の header の各列（名前を除く）の左の境に 10 px の grip（`FM_HIT_COLUMN_EDGE`）と細い縦の線。境を drag すると、境の右の列が狭く・左の列が広く（左が名前なら名前は残りを取る）、どちらも 60 px より狭くならない、名前は 200 px を保つ（入らない列は今までどおり出ない）。幅は Files が動いている間だけ保つ（`column_widths`、保存はしない: 実装の時の判断。保存が要るならユーザーに）。離した時の log `ZFILES COLUMN width column=N width=W`。
- `ui-input.c`（press・motion・release）、`files.h`（hit の種類と状態）、`ui.c`（初期値）。
- build: zedBSD・Linux の warning 0、style-check 新しい指摘 0。QEMU は撮影の確認が要るので UAT（人の手で drag）か T1 の撮影。

## 2026-10-06 ユーザーの決定

列の幅は「保存する」: Files の設定（`~/.config/keiland/files.conf`）に残し、次に開いた時も同じ幅。

## 保存の実装（2026-10-06 P2、q803）

- `userland/desktop/settings-keys/settings-keys.c`: Files の設定の key を 7 つ足した。`files.column-width.kind`・`.size`・`.modified`・`.changed`・`.owner`・`.location`・`.deleted`。どれも Files の key（RESOLVER_APP）の整数で、0〜2000、既定は 0（その列の元の幅）。
- `userland/desktop/files/ui-list.c`: 境を離した時（`fm_list_edge_release`）に、drag した列と左の列（名前でない時）の幅を `kl_settings_set_int` で残す（libkeiland が `~/.config/keiland/files.conf` に `column-width.size=180` の形で書く）。log `ZFILES COLUMN saved column=N left=L error=E`。起動の時（`ui.c` の初期値の後、`fm_list_widths_load`）に読む。60 px（`LIST_LEAST`）より狭い値と 0 は元の幅のまま。log `ZFILES COLUMN kept column=N width=W`。
- host 試験: `plan/ws127/tests/host-column-widths.sh` で 19 項目が pass。7 つの key の型と範囲、files.conf への書き込みと読み戻しを確かめた。open-with の行が残ることも確かめた。
- build: zedBSD の files・settings・wayland と keiland-linux の warning 0、style-check 0。settings の host 試験（`plan/tools/settings/host-settings.sh`）は 38 項目が pass。
- 未実施: QEMU・実機（人が drag して Files を開き直し、同じ幅で出ること。log の `saved … error=0` と `kept` で確かめられる）。
