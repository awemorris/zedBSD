# BUG-052: tmpfs の容量が mount ごとに 32 MiB・1024 node で固定

Bug ID: `BUG-052`
Reproduction: reproduced（QEMU、決定的）
Disposition: tracking
Date: 2026-09-25
Source: ws061-p003 で expat を `/tmp` に 3 つ展開して build しようとしたとき（`No space left on device`）。
Owner: 未定
Queue: なし

## 期待と観測

期待: design policy 10（現代の機械、4 GiB の memory と 16 GiB の swap を前提に、cache の大きさを i386 の時代の値から上げる）に沿い、`/tmp` の tmpfs は Linux の既定（物理 memory の半分、node は page 数の半分）程度。memory は commit の会計（swap の裏打ち）で守られる。

観測: `src/kern/tmpfs.c` の `TMPFS_DEFAULT_BYTES` が 32 MiB、`TMPFS_DEFAULT_NODES` が 1024 で、mount の option も無い。`/tmp` に source tree を 3 つ置けず、1024 file を超える build は ENOSPC になる。

## 再開の条件

既定を物理 memory の半分（下限 32 MiB）と、その page 数の半分の node（下限 1024）にする。mount の option（`size=`・`nr_inodes=`）は後で。

## 追記（2026-09-26、ws061-p009）

実際の限界は node の quota（1024）より先に、inode の共通の pool（`src/kern/inode.c` の `INODE_COMMON_MAX` 512）に来る。tmpfs と devfs は `alloc_inode` を持たず、この pool を共有する（`inode_alloc(NULL)` の pipe・socket も）。`/tmp` に約 490 の file を置くと pool が尽き、tmpfs の作成が ENOSPC になるだけでなく、devfs の node を作り直せず `2>/dev/null` の redirect も ENOSPC になり、sshd が落ちて SSH が切れる（QEMU で再現、serial console で `rm` すると戻る）。make の差分試験を `/tmp` に展開すると 72/91 になった（`/root` なら 91/91）。

再開の条件に追加: tmpfs（と devfs）の inode を共通の pool から出す（F-013 の動的確保）か、pool を tmpfs の node の上限より大きくする。
