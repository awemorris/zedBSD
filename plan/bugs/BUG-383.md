# BUG-383: libbrowser が http の page からも file: の副資源（画像・script・style・font・media）を読む（local の file が web の page から読める）

- 状態: closed（2026-11-01 06:14 Q1 の判定、main 81d028d39。P3 の d3f41f695: file: の副資源は local の page からだけ、pushState で file: にできない。host の試験 host-file-subresource 11/11 ほか PASS。QEMU のブラウザの中の確かめは未実施）
- 中身: `page/link.c` の `page_fetch` は、file: の URL の副資源を http・https の page からも読む。frame だけが止められている。web の page が利用者の local の
  file を読める（POSIX）。Windows では UNC の file: の URL（`file://host/share`）で利用者の NTLM の認証が漏れ得る（WS334 の契約では `wb_os_path_from_url` が
  host 付きを ENOENT にして閉じた）。
- 直す方針（案）: file: の副資源は file: の page からだけ許す（他のブラウザと同じ）。WS074 の領域。
- 影響: 安全（local の file の読み出し）。

## 2026-11-01 P3（q1812）: 原因・直し・確かめ

- 原因: 副資源の local の読みは全部 `page/link.c` の `page_fetch`（images.c の画像と CSS の url()、sheets.c の style sheet と @import、fonts.c の
  @font-face、media.c、script.c の script・同期と非同期の XHR・fetch）を通り、`page_fetch` は解決した target が file: なら page の場所を見ずに
  file を読んでいた。他の道は別に閉じている: module script・JSON module（module.c `module_same_origin` が両方 http(s) の同じ origin だけ）、frame
  （frame-load.c `frame_load_allowed`、file の親と file の子だけ）、web の URL は loader（net/）。top-level の読み込み（page.c）は利用者の操作。
  worker は無い。
- 直し:
  - `page/link.c`: `page_fetch` は target が file: で、page の場所（base）が local（絶対 path か file: URL、`link_base_local`）でない時に EACCES を
    返し、何も読まない（web・data:・about: の page から local の file は読めない。他のブラウザと同じ）。
  - `page/script.c` `script_url_set`（history の pushState・replaceState・fragment の URL の書き換え）: local でない page が file: の URL に
    なる書き換えを EACCES で拒む（page の場所が local の判定に使われるので、script が page を local に見せかけて上の確かめを越えない）。
- host 試験 `plan/ws074/tests/host-file-subresource.c`（host-build.sh が build）: local の page（path と file: URL）から絶対と相対の file を読める、
  http・https・data:・about: の page からは file:（大文字の FILE:、相対の file:LICENSE も）が EACCES で 0 byte、file の top-level の読み込みは
  読める。11/11。
- 確かめ（host、`BROWSER_HOST_BUILD=build/p024/bh sh plan/ws074/tests/host-build.sh plain` warning 0、build/ws074-host はその link）:
  host-file-subresource 11/11、run-resource-tests（host-resource）105/105、run-frame-load-tests 52/52、run-fetch-tests blocking 38/38・--async 38/38、
  run-stylesheet-mime-tests pass、run-object-fallback-tests pass、run-loader-tests 11/11、host-base 2038/0、run-dom-tests 38/41（main の tree の写しの
  build も同じ 3 つ computed・exception・performance-observer で 38/41、前からの失敗）。zedBSD の `dynamic/libbrowser.so`（config-amd64）warning 0。
- 未実施: 実機・QEMU の browser での確かめ（http の page に file: の img・link・script・XHR を置いて読まれない事）。
