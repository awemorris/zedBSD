# BUG-405: ブラウザ: Google の「Googleについて」の頁で画像が出ない

- 状態: open（原因が分かった。直すには WebP の decoder の新しい module が要り、この Queue の bug の直しを越えるので、進め方は Q1 の判断を待つ。2026-11-02 P8 q1924-i01）。前: open（2026-11-02 08:19 Q1 が起票、P8 の待ち行列）
- 発見: 2026-11-02 08:19 ユーザーの Windows での OmniGrammaton の UAT（BUG-397〜399 の直しの後）。
- 中身: Google の top の「Googleについて」（about.google）の頁で画像が表示されない。
- 扱い: P8（ブラウザの担当、ユーザーの決定）。BUG-401 の後に順に。

- （2026-11-02 11:31 Q1）ユーザーの決定で、自前の WebP の decoder を [WS344](../ws344/ws.md) で作って直す。
## 原因（2026-11-02 P8）

Windows に固有ではない。about.google の頁の写真と絵（hero と 3 列のカードなど、`<img srcset=… src=…>` の 9 枚のうち SVG の logo 以外の全部）は、`www.gstatic.com/marketing-cms/…=n-w543-…-rw` の URL で、`-rw` で WebP に変換して返す画像サーバーの物。拡張子が `.jpeg`・`.jpg`・`.png` の物も含めて、中身は `image/webp`（curl で Accept を `image/png,image/jpeg` にしても、`*/*` にしても WebP で返った）。libbrowser の画像の decoder（`image/decode.c` の `img_decode`）は JPEG・PNG・GIF（と SVG）だけで、WebP は `ENOTSUP` になり描かれない。Linux の host build でも同じ（`build/tmp/p8u/drive.c` で about.google を描くと、カードの枠だけで画像が無い）。

別件（この Bug とは別、未調査）: 頁の script が `Cannot read properties of undefined (reading 'unobserve')` と `… (reading 'split')` で落ちる。IntersectionObserver・ResizeObserver・MutationObserver は在る。
→ 直した（2026-11-02 P8 q1941-i01、agent/p8-uat3 の 43a07b8956）。`unobserve`: observer の callback が observer を 2 番目の引数と this で受けていなかった（`bind/environment.c` の `environment_observer_job`、MutationObserver も同じ）。`split`: `HTMLElement.lang` が無く、cookie の通知の bar の既定の言語（`document.documentElement.lang`）が undefined だった（`bind/element.c` に lang の反映）。host の live の about.google で 2 つの誤りが出なくなった。試験 `plan/ws074/tests/dom/observer-arguments.html`（期待値は host の Chromium、前は FAIL、後は pass）。

## 要る判断（Q1）

WebP の decoder が要る。VP8 の lossy の key frame（boolean decoder、intra の予測、DCT・WHT、loop filter、YUV → RGB）、VP8L の lossless（Huffman、変換、color cache）、ALPH の alpha、RIFF の container。数千行の新しい module になる見込み。進め方の案は次のどちらか。

- libbrowser の `image/` に自前の `webp.c`（と小さい module 群）を足す。外部の標準仕様（RFC 9649 WebP、RFC 6386 VP8）に基づく module なので、標準廉価実装手順（設計の担当 → 実装の担当、host の単体試験と libwebp の出力との比較）に向く。
- 外部の libwebp（BSD）を `userland/packages` の取得・検証・patch の流儀で取り込む。libbrowser の Windows の 1 つの .exe（static link）にも入れる。

どちらでも `img_sniff` に RIFF/WEBP を足し、`img_decode` から呼ぶ。
