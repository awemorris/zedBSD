# BUG-034: `POSIX-R2.ELF` が `realtime-signal-capacity` で失敗する

Bug ID: `BUG-034`
Reproduction: reproduced（QEMU、amd64 guest）
Disposition: resolved（ws056-p001。`RTSIG_MAX` を 33 に。`POSIX-R2.ELF` の `realtime-signal-capacity` は通る）
Date: 2026-09-24
Source: ws046-p007（q411-i01）の回帰で、kernel の fault の試験の代わりに `userland/base/tests/posix-r2.c`（`$(BUILD)/POSIX-R2.ELF`）を guest で走らせたとき。
Owner: WS056 p001
Queue: q423-i01。

## 期待と観測・影響

期待: `POSIX-R2.ELF` が status 0 で終わる。

観測: `POSIX_R2_FAIL: realtime-signal-capacity`、status 1。この検査は `sizeof(sigset_t) == 8`、`RTSIG_MAX >= 8`、`sysconf(_SC_RTSIG_MAX) == RTSIG_MAX`、
`sysconf(_SC_SIGQUEUE_MAX) >= _POSIX_SIGQUEUE_MAX` のどれかが偽のとき。どれが偽かは未調査。

ws046-p007 の変更（libc の allocator、kernel の buffer cache の hash）の前の image（`build/ws053-fulllto-guest`、WS053 p001）でも同じ ELF が同じく失敗するので、p007 の前からある。
この ELF はどの image にも入っておらず、定まった回帰に使われていない（いつから失敗しているかは不明）。ws035-p035 で `limits.h` に `RTSIG_MAX`・`SIGQUEUE_MAX` を置いた記録がある。

影響: 実時間 signal の限界値を問う program が誤った値を得るかもしれない。他の試験は通る。

## 再開の条件

libc の `sysconf`・`limits.h`・signal を扱う WS で。受け入れ案: どの条件が偽かを特定し、`POSIX-R2.ELF` が status 0。
