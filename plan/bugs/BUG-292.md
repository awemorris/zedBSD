# BUG-292: compositor が frame callback を 10 秒以上保留すると、libvulkan の WSI が SURFACE_LOST になり app が終了する

- 状態: fixed（2026-10-31 P2 q1757-i01。WSI の FIFO の待ちを失わせない形に、libkeiland の acquire を期限なしに。QEMU で再現し直りを確かめた。libkeiland を使わない app の自前の acquire の期限は残る）
- 発見: 2026-10-12 design-reviewer（WS210 p014 F2 review-2 の M4(c)、plan/ws210/phase014/review-2.md）。F2 以前からある問題。
- 経路（source）: compositor は compose が起きない時（sleep_hold `userland/desktop/wayland/display.c:162`、出力の喪失、image が無い window）に frame callback を保留する。その間に app が present を続けると、zedBSD の libvulkan の WSI の worker が前の callback を最大 10 秒待つ（`WAYLAND_WAIT_NS`、`userland/desktop/libvulkan/wsi-wayland.c:25,776`）。swapchain の 3 枚が尽きると app の main thread が `vkAcquireNextImageKHR` で最大 10 秒止まり（`PRESENT_TIMEOUT` `userland/desktop/libkeiland/ui/present.c:31`、`wsi-swapchain.c:3054-3110`）、超えると `SURFACE_LOST` が残る。Settings は EIO を `VK_ERROR_DEVICE_LOST` として受けて終了する（`userland/desktop/settings/present.c:101-104`）。
- 影響（推測）: sleep の解除が遅い時、出力を抜いて 10 秒以上たった時などに、描き続けていた app が終わる可能性。
- 再現の案: QEMU で app（Settings）を開いたまま sleep_hold を 15 秒、または出力を外して 15 秒、その後の app の生存と log（T1）。
- 直す案: WSI の callback の待ちの timeout を SURFACE_LOST にしない（保留中は待ち続ける・commit を飛ばす）、または compositor が保留中も一定の間隔で callback を返す。WS210 p014 の F2（frame の pacing）の設計と合わせて判断。

## 2026-10-31 P2（q1757-i01）

### 再現（QEMU、Venus、lean の image `build/tmp/q1757/config-q1757.mk`）

- 最小化（`KWL GLASS minimize`）では再現しない: compositor は最小化した窓の frame callback も返し続けた（wltest、FIFO、500 ms ごとの 60 frame が最後まで、間隔 550 ms 前後）。
- compositor を `kill -STOP` で 15 秒止め（callback も buffer の release も止まる。BUG-306 の候補の「compositor の main thread が 12 秒止まる」の形）、libkeiland の窓（`kuidemo` の Dialogs 頁の Working を on にして進捗の棒が動き続ける）の生存を見た（`build/tmp/q1757/kui-run.sh`・`stall2.sh`、判定は SSH の ps と client の stderr の file）:
  - 前の libvulkan（main 802e620f9 の `libvulkan.so` を `/tmp/old` に、`LD_LIBRARY_PATH`）: 2 回とも `KEILAND PRESENT_FAILED call=kl_window_present operation=vkAcquireNextImageKHR result=-1000000000`（SURFACE_LOST、connection=0）で kuidemo が終わった。2 回目は compositor は生きたまま。ticket の経路（WSI の worker が前の callback を 10 秒待って surface を lost に latch）どおり。Terminal（自前の present）も同じく `ZTERM FAILED operation=vkAcquireNextImageKHR result=-1000000000` で tab が閉じた。

### 修正

- `userland/desktop/libvulkan/wsi-wayland.c` `wayland_commit`: FIFO の前の frame の callback の待ちを 10 秒の terminal な watchdog（時間切れで `surface->lost` を立て SURFACE_LOST）から、1 秒（`WAYLAND_PACE_NS`）待って来なければ pacing なしで commit する形に。compositor は commit が採用前の queued の image を置き換えると前の image を release する（`protocol.c` の commit）ので、image は回り続ける。surface を失うのは connection が壊れた時だけ（`wayland_wait` の他の誤り）。1 秒は app の acquire の 10 秒の期限より十分短い。
- `userland/desktop/libkeiland/ui/present.c`: `vkAcquireNextImageKHR` を `PRESENT_TIMEOUT`（10 秒、時間切れは EIO で Settings の -4）から期限なし（`UINT64_MAX`）に。止まった・忙しい compositor は待つ。connection が閉じれば WSI の acquire が誤りで返る（新しい run で compositor が終わった時は `connection=44` の SURFACE_LOST で終わった）。GPU の fence の待ちは 10 秒のまま。

### 確かめ

- build: `build/amd64/dynamic/libvulkan.so`・`build/amd64/dynamic/libkeiland.so`（config-amd64）→ warning 0。
- QEMU（新しい `libvulkan.so` と `libkeiland.so` を `/tmp/new` に）: compositor が止まりから戻った回（1 回）で kuidemo は生き、棒は動き続けた（止めの後の 2 枚の写真が違う。`build/tmp/q1757/evidence/kui-new2-after.png`・`kui-new2-later.png`、worktree の中で git に入れていない）。他の 3 回は compositor 自身が止めの後に `KWL FAILED site=compose_draw ... result=-4`（自分の Venus の device lost）で終わり、kuidemo は disconnected で終わった（client の側の PRESENT_FAILED は connection の切れの 1 回だけ）。compositor の死は前の libvulkan の回（1 回目）でも起きており、SIGSTOP という試験の作り方の副作用（止めた producer の GPU の仕事の期限）と見る。新しい lib の「compositor が生きたまま 15 秒止まる」は 1 回だけ確かめた。
- 未実施: sleep_hold・出力の喪失そのもの（testing の compositor は sessiond が無く sleep しない）。Settings そのもの（lean の image に無い。Settings は libkeiland の `kl_window_present_parts` を通るので同じ経路）。実機。

### 残り（範囲の外、Q1 へ）

- libkeiland を通らず自前で `vkAcquireNextImageKHR` に 10 秒の期限を付け、時間切れを致命とする app がある: terminal（`render.c`）、monitor、notes、browser の shell、imageview、videoplayer、libegl。新しい WSI では compositor が採用を続ける限り（sleep_hold の形）image は戻るので時間切れにならないが、compositor が 10 秒以上まるごと止まると、Terminal は `result=2`（VK_TIMEOUT）で tab を閉じた（新しい lib の回）。直すなら各 app の acquire を期限なしにする（libkeiland と同じ）。
