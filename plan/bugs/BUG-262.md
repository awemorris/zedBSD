# BUG-262: アクセントカラーを既定（青）に戻しても desktop の Files（icon の選択の色）が追従しない疑い

- 状態: reproduced（QEMU、T1-396 の log） / scheduled
- 発見: 2026-10-08 T1-396（desktop.appearance.accent）の Q1 の判定。
- 観察: Purple を選ぶと `ZSETTINGS ACCENT index=1`・`KWL THEME ... accent=1`・`ZFILES ACCENT index=1` が出る。Blue に戻すと `ZSETTINGS ACCENT index=0`・`KWL THEME ... accent=0` は出るが、`ZFILES ACCENT` の行が出ない（record の step 9）。userland/desktop/files/main.c の main_desktop_accent_changed は呼ばれれば必ず log を出すので、watch が来ていない。Settings・system bar の色は青に戻る（PNG build/review/t1-39x/desktop.appearance.accent-blue.png）。
- 推定（未確認）: Settings は既定を選ぶと key を消す（設定を既定に戻す）、kl_settings_watch が key の削除で callback を呼ばない。
- 影響: desktop の icon の選択の pill などが前の accent のまま残る。

## 次

- Settings の accent の書き方（既定で key を消すか）と libkeiland の kl_settings_watch の削除の扱いを読み、host で再現して直す（削除でも callback を呼ぶか、Settings が既定でも値を書く）。AAT desktop.appearance.accent の step 9 で ZFILES ACCENT index=0 を必須にする。
