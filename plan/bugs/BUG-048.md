# BUG-048: `mmap`・`munmap`・`mprotect` などの長さが 4 GiB で切り捨てられる（page mask が 32 bit）

Bug ID: `BUG-048`
Reproduction: reproduced（QEMU、amd64 guest 8 GiB、probe で決定的）
Disposition: resolved（ws057-p002。mask を 64 bit に。128 GiB の reserve、5 GiB の mapping の offset 4 GiB + 4 KiB、9 GiB は ENOMEM を probe で確認）
Date: 2026-09-25
Source: ws057-p001（q425-i01）で、VM の reserve（`PROT_NONE` で 64 GiB）が EINVAL になり、9 GiB の RW の mapping が「成功」したとき。
Owner: WS057 p002
Queue: q426-i01。

## 期待と観測・影響

期待: 64 bit の ABI では `mmap` の長さは `size_t`（64 bit）どおりに扱われる。

観測（`/tmp/vitest/commit/commitprobe{2,3,4}`）:
- `mmap(PROT_NONE)` 1・2 GiB は成功、4・8・16・32・64・128 GiB は **EINVAL**。RW の 6・7 GiB は成功、8 GiB は EINVAL、**9 GiB は成功**（commit は 1 GiB しか増えない）。
- 4 GiB + 4 KiB の mapping は offset 4 GiB を触ると SIGSEGV（実際は 4 KiB）。5 GiB は 1 GiB、9 GiB は 1 GiB しか map されない。
- 2 GiB の region に `mprotect(len = 4 GiB + 4 KiB)` が **成功**（4 KiB と解釈）、`munmap(len = 4 GiB)` は EINVAL。
原因: `src/kern/syscall.c` の `#define SYSCALL_PAGE_MASK (KERN_PAGE_SIZE - 1U)`（`4095U`、32 bit）で、`(args[1] + SYSCALL_PAGE_MASK) & ~SYSCALL_PAGE_MASK` の `~` が `0xFFFFF000U`（32 bit）になり、64 bit の長さの上位 32 bit が落ちる（9 箇所）。HAL の `PAGE_SIZE`（`4096`、int）で `& ~(PAGE_SIZE - 1U)` と丸める kernel の他の箇所も同じ危険がある。

影響: 4 GiB 以上の mapping を作る program（大きな allocator の reserve、大 file の mmap、data base）が silent に短い mapping を得て SIGSEGV するか、EINVAL で失敗する。commit の会計も実際より小さい長さで課金する（over commit の穴ではないが、program の期待と違う）。design policy 10 の「reserve は無制限」を満たせない。

## 再開の条件

ws057-p002 で直す: mask を `((uintptr_t)KERN_PAGE_SIZE - 1U)` にし、kernel の他の丸めも 64 bit に。受け入れ: 64 GiB の `PROT_NONE` の reserve が成功し、5 GiB の RW の mapping の offset 4 GiB + 4 KiB を触れる、8 GiB の RW は ENOMEM。
