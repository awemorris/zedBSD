# BUG-051: `sshd-session` の子が SIGSEGV（NULL の読み）で 1 度落ちた（ws061-p003 の image）

Bug ID: `BUG-051`
Reproduction: unreproduced（1 回観測。同じ操作の 3 回と make の差分試験（crash 0）では出ない）
Disposition: tracking
Date: 2026-09-25
Source: ws061-p003（q435-i01）。fault-around と TLB の invalidation の変更の後の image で、SSH 越しに expat の configure を走らせた session の終わり。
Owner: 未定
Queue: なし

## 期待と観測

期待: SSH の session は正常に終わる。

観測（QEMU、amd64 8 GiB、guest の `/var/log/messages`）:

```
sshd-session[5584]: error: mm_reap: child terminated by signal 11
kern: pid 5586 killed by signal 11 (vector 14) at 0x000000010030f437, address 0x0000000000000000
```

privsep の非特権の子（pid 5586）が、user の address `0x10030f437`（`sshd-session` の image の外、共有 library の中）で address 0 を読んで落ちた。host 側の SSH は「Connection closed by remote host」。guest は動き続け、次の session は通った。

疑い: ws061-p003 の変更（fault-around: 隣の cache の page を read-only・COW で map、`hal_space_map` の shootdown の削除、32 page 以下の invalidation の `invlpg`）か、以前からある sshd の競走。ws046-p014 の image では同じ操作で出ていない（2 回）。

調べていないこと: 落ちた library と関数（guest に `/proc`・`ldd` が無い。load address を lldb で取る必要がある）。並列の負荷での再現（ユーザーが止めた）。

## 再開の条件

再現したとき、または WS062 の後に並列の build の負荷で調べる。落ちた address の library を lldb で特定し、fault-around の page（`VM_MAPPING_COW` の object page）か TLB（`invlpg`）かを切り分ける。
