# BUG-275: Settings の Bluetooth の頁で 5330 に Bluetooth の device が無いと出る

Reproduction: reproduced（ユーザー、実機 5330、2026-10-10 UAT）
Disposition: tracking
Discovery: 2026-10-10 ユーザーの 5330 の UAT のコメント（image はユーザーの 5330 に入っていた物、版は未確認）
Handling: WS143（release の config に intelbt を入れた後の image か要確認。controller の attach・firmware の load・bluetoothd の起動の順に SSH で見る）

## 観測（ユーザー）

「Settingsで、Bluetoothデバイスがないと言われる」

## 経路の見直しと原因の候補（2026-10-10、P1、source だけ。5330 に SSH が届かないので実機の log は無い）

経路: release（`config/release/config-amd64-beta2.mk`）と UAT（`config/current-uat.mk`）の config は CI の config（`CONFIG_DRIVER_USB_BT := y`、`bluetoothd`・`bt`）に `intelbt-firmware`（`/lib/firmware/intel/ibt-0040-0041.sfi` ほか、Solar の 3 組）を足す。
base の `/etc/passwd`・`/etc/group` に `_bluetooth`、`rc.conf` で `bluetoothd` enabled。kernel の `usb-bt` は interface の class E0/01/01 で付き（vendor の表ではない）、`bt-hci` が `/dev/bluetoothN` を作る。
bluetoothd の子は 2 秒ごとに `/dev/bluetooth0..15` を親に開けさせ（`privsep_open_node`）、開けたら Intel の版を読み、bootloader なら `.sfi` を送り、controller の再起動（USB の付け直し）を 10 秒待つ。
Settings の言葉は `userland/desktop/settings/page-bluetooth.c` の `bluetooth_state_words`: socket に届かない「Bluetooth is not available on this computer.」、STATE none「No Bluetooth adapter was found.」、firmware「The adapter's firmware is missing.」、compositor に Bluetooth が無い「This desktop has no Bluetooth.」。
ユーザーの「デバイスがない」は none の言葉の見込み（言葉の確認はユーザーか PNG で）。

none になる道（可能性の高い順）:

1. **firmware の load の後に controller が戻らない・start が 3 回失敗**: 5330 の実機の load は一度も確かめていない（WS143 p003 i02 と p005 i04 は未着手、T1-378 も未実施）。load の後 controller は USB で付け直る（`BTD_REAPPEAR_MS` 10 秒）。xHCI がこの付け直し（同じ port の disconnect と connect）を拾わなければ node が消えたまま none。start が `BTD_FAILURES_MAX`（3）回 ERROR なら止まる（その間は none と error を行き来）。
2. **usb-bt が付かない**: 5330 の 8087:0033 が zedBSD の xHCI に列挙されているかの証拠が無い（Linux では列挙、plan/ws075/phase011）。CNVi の Bluetooth は AX211 の Wi-Fi の半分と同じ包みで、`intel-ax211` の Wi-Fi の driver の reset が Bluetooth の USB の側を切る可能性も（推測）。
3. **古い image**: ユーザーの 5330 の image が `intelbt-firmware` を足す前（2026-10-09 より前）なら firmware の言葉か none。

確かめ（5330 に SSH が届いた時、Q1 か T1）: `uname -a`（image の版）、`lsusb`（8087:0033 の有無）、`dmesg | grep -i -e usb-bt -e bt-hci -e 8087`、`ls -l /dev/bluetooth*`、`grep bluetoothd /var/log/messages | tail -30`（`state=` の行と `closed` の行、secure send の答え）、`bt show`、`ls /lib/firmware/intel/`、`service status bluetoothd`。
候補 1 なら `bluetoothd: /dev/bluetooth0 state=lost …` の後に node が戻らない行、候補 2 なら dmesg に usb-bt の行が無い。

直し: source だけでは原因を決められないので、この時点では直していない（上の log の後に直す。WS143 の p003 i02 の実機の門と同じ作業）。
