# BUG-282: bluetoothd の HID が page の途中に同じ機器の Connection Request を断ると、page の失敗と取り違える（潜在）

Reproduction: unknown（source の読み、2026-10-10 P1 の WS197 p003 の設計の review で見つけた）
Disposition: tracking（ベータ3。release の bluetoothd にある潜在の競合、起きる条件は狭い）
Discovery: 2026-10-10 P1（WS197 p003 の設計）
Handling: WS143（hid.c）、WS197 p003 の linkmgr の page と受けの交差の直しと同じ形で直す

## 内容

userland/base/bluetoothd/hid.c の hid_request（1259〜1266 行あたり）: PAGING の間に同じ機器から来た Connection Request を Reject すると、Core 7.1.9 によりローカルの Connection Complete（失敗 0x0D）が来て、router が linkmgr の page の token を外し、HID はそれを自分の page の失敗と見る。controller の Create Connection はまだ出ていて、後の成功は route が無く切られ得る。

## 2026-10-10 P1（WS197 p003 i03 で見た）

- phone 側は同じ交差を設計 §5.3 の形で直した（PAGING 中の Connection Request は先に Create Connection Cancel、その status が 0x0B なら Reject して Reject の自分の Connection Complete を 3 s の間 1 回だけ吸う、他は Accept、cancel した page の失敗の Connection Complete 0x02・0x04・0x0B を page の終わりとして吸う）。host 試験は plan/ws197/tests/bt-phone-link-host-test.c の test_crossing。
- HID の hid_request（hid.c 1243 行あたり）にも同じ形は当てられるが、router が最初に来たその address の Connection Complete で linkmgr の page の token を終える所（router.c）も合わせて変える要があり、release の HID の回帰の範囲が広いので、i03 では当てない。ベータ3 の WS143 で、phone と同じ形（Cancel を先に・Reject の自分の Connection Complete の吸い込み）と router の token の終わりの直しを一緒に行う。
