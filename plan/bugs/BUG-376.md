# BUG-376: PS/2 の mouse の port（aux）が、mouse が無いのに node を作り、open のたびに約 80 ms 待って EIO を返す

- 状態: closed（2026-10-31 Q1 の判定、main に merge。2026-10-31 P6 q1743、commit 933563341。QEMU と実機 10.0.10.3 で確かめた。merge は Q1）
- 発見: 以前の調べ（master.md の未決に残っていた物）。kernel の PS/2 の driver（src/kern/platform/pcat.c の drv_pcat_ps2_8042_init の辺り）。
- 影響: mouse の無い機械で、input の device を開く program（compositor など）が、open のたびに約 80 ms 待たされる。
- 直す方針（案）: 8042 の aux の port の存在を初期化の時に一度だけ確かめ（aux の test の command と、mouse の reset への応答）、無ければ node を作らない。あれば今どおり。
- 2026-10-31 ユーザーから、PS/2 の aux は Bug の ticket を起票してどこでもいいので割り当てる、という趣旨の指示を受けた。

## 原因

- `src/drivers/isa/ps2-8042.c` の `drv_isa_ps2_8042_init` が、aux の port に mouse が居るかを確かめずに mouse の input device を publish していた。
  open のたびに `mouse_start` が aux の port を有効にして mouse に命令を送り、答えが無いと `read_output` が `PS2_WAIT_LOOPS`（100000 回の inb、約 80〜100 ms）を
  回り切って ETIMEDOUT → ENODEV を返していた。

## 直し（commit 933563341）

- 初期化で 1 度だけ `mouse_probe`: 割り込みを止めた（config の AUX_IRQ を落とした）まま aux の port を有効にし、config の disabled の bit が落ちるか
  （aux の port の無い controller は落とさない）と、mouse が DISABLE_STREAM に ACK を返すかを見る。最後に port を無効に戻して出力を捨てる。
- mouse が居なければ、mouse の IRQ も input device（node）も作らず、`i8042: no mouse on the auxiliary port` を kernel の log に 1 行出す。keyboard は今までどおり。
  居れば今までどおり（open で `mouse_start`）。PS/2 は hot-plug しないので、後から挿した mouse は見ない。
- controller の自己試験（0xa9）は使わない: 誤った値を返しても mouse は動く controller がある（Linux の i8042 も失敗を無視して続ける）。決め手は mouse の ACK だけ。

## 確かめ

- build: kernel の flag での ps2-8042.c の compile は warning 0。image（`plan/bugs/BUG-376/config-amd64-ps2.mk` = BUG-370 の AAT の config + evdev-probe）の build が通った。
- QEMU（`sh plan/bugs/BUG-376/ps2-guest.sh build/bugs-img build/bug376-run1`、2026-10-31 02:45〜02:52、`bug376: PASS`）:
  - q35 の PS/2 mouse あり: `evdev-probe -l` に `phys=pcat/i8042/aux0` が 1 つ（mouse の node は残る）、keyboard の node も 1 つ。
  - `-machine i8042=off`（controller が無く、port に何も答えない）: aux0 の node が 0、keyboard の node は 1（controller の無い時の keyboard は今までどおり）。
  - 20 回の `evdev-probe -l`（各 node を開く）を host から計った値: mouse あり 339 ms、無し 268 ms（ssh 1 回 約 230 ms を含む）。直す前の値は取っていない（未実施）。
- 実機（10.0.10.3、PS/2 の mouse の無い desktop、ws291-p014 の計測で私の branch の kernel を入れた時）: SSH の `dmesg` に
  `i8042: no mouse on the auxiliary port`（2026-10-31 01:59・02:06・02:41 の 3 回の起動）。その後の mview・desktop の計測は動いた。
- 未実施: 直す前の kernel で open が約 80 ms 待つ事の計測（再現の数値）、PS/2 の mouse の付いた実機、sun4u（同じ driver を polled で使う）の起動。
