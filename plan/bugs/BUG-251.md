# BUG-251: Ctrl+Shift を押したまま起動すると内蔵 keyboard（PS/2）の割り込みが来ず使えない（5330・5320）

- 状態: reproduced（実機 5330・5320、ユーザー 2026-10-07） / resolved（2026-10-08 夜 ユーザー「下記は実装の変更が多かったので、いったんすべてcloseします。」、Q1 の中継）
- 発見: 2026-10-07 ユーザー「キーボードの割り込みがうまくいかない起動になることがあります。その場合は内蔵キーボードが使えないです。5320でもありました。Ctrl+Shiftで起動するとそうなるように見えます。」

## 疑い（Q1、未確認）

- WS174 の起動の key（Ctrl で kernel の message、Shift で console の login）を押したまま起動すると、i8042 の output buffer に scancode が残ったまま keyboard の IRQ1（edge）が有効になり、以後割り込みが来ない（8042 の古典的な詰まり）。IRQ を有効にした後に output buffer を読んで空にする（status 0x64 の OBF を見て 0x60 を読む）か、初期化の時に flush する。
- src/drivers の i8042（PS/2）の初期化と、WS174 の起動の key の読み方（firmware の BIOS の key の状態か、kernel の早い段階の poll か）を確かめる。

## 原因（P2、2026-10-07、source を読んで特定。実機での観測は未実施）

- WS174 の Ctrl・Shift は UEFI の loader が SimpleTextInputEx で読む（`bootloader/uefi/boot-keys.c`）。kernel は 8042 を poll しない（8042 に触るのは `src/drivers/platform/pcat/ps2-8042.c` だけ）。
- `drv_pcat_ps2_8042_init()` は IRQ1 を mask したまま handler を登録し、最後に unmask するだけで、8042 の output buffer を空にしていなかった。key を押したまま loader から kernel に移ると、firmware が読まなくなった後の scan code（押したままの typematic）が output buffer に残る。IRQ1 は edge で、mask 中の edge は失われ、buffer が満ちたままの 8042 は次の edge を作らない → keyboard の割り込みが二度と来ない。mouse を開く時の `mouse_start()` は flush するが、keyboard の側には無かった。

## 修正（P2、2026-10-07）

- `drv_pcat_ps2_8042_init()` で IRQ1 を unmask した後、`controller_lock` の下で `flush_output()` を 1 回呼び、残った byte を捨てる（読むと線が下がり、次の byte が handler に見える edge を作る。unmask の後なので、その間に来た byte も取りこぼさない）。
- 確認: `make ZEDBSD_CONFIG=config/current-uat.mk BUILD=build/bug250 vmunix`（warning 0、include check・vmunix check PASS）。QEMU・実機は未実施。

## 次

- 実機 5330（できれば 5320 も）で、Ctrl+Shift を押したまま（Space を叩いて）起動し、console の login で内蔵 keyboard が効くこと（ユーザー）。普通の起動でも keyboard が効くこと。

## 2026-10-08 P2 の確認（q869）

- 実装済み（9a42683c9）: src/drivers/platform/pcat/ps2-8042.c で unmask の後に `flush_output()`（BUG-251 の注記）。
- 証拠: kernel の build の warning 0、include check・vmunix check PASS。QEMU（T1）の試験は無い。
- 残り: 5330・5320 で Ctrl+Shift を押したまま起動し、console の login で内蔵の keyboard が効くこと。普通の起動でも効くこと（ユーザー）。
