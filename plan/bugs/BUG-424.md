# BUG-424: VMD の裏の disk がある機械（5330）が S0 idle に入れない（`vmd_suspend()` が常に EBUSY）

- 状態: open（2026-11-13 Q1 が起票、WS333 p027 の P3 の案から。2026-11-13 P2: 実装と host 試験、5330 の S0 idle は未達、下の「経過」）
- 発見: 2026-11-13 P3（WS333 p027）。5330 で `sleepctl s0idle`（Wi-Fi の radio を落とした後）が `result=17`（EBUSY）、`device=pci 0000:00:0e.0 vmd`。NVMe・HDA・xHCI の suspend は済み、VMD で止まって全部 resume した。
- 原因: `src/drivers/pci/pci-vmd.c` の `vmd_suspend()` が常に EBUSY を返す（裏の root port の bus 番号と window を D3 の間 保存・復元する driver が無いので、suspend すると disk を失うため）。5330 の root の NVMe（10000:e1:00.0）は VMD（00:0e.0）の裏の root port（10000:e0:06.0）の先。
- 要る物: VMD の suspend・resume（VMD の CFGBAR・MEMBAR の設定、裏の root port の bus 番号・window・command の保存と D0 への復元、NVMe の resume の順）。
- 確かめ: 5330 で S0 idle に入り RTC の alarm で起きる（`plan/ws333/tests/hw5330/5330-p027-s0.sh`・`s0idle-wake.patch`、watchdog の下）、resume の後に disk・GPU・session が使える。
- 関係: intel-ax211 の radio が on の時の EBUSY は設計どおり（sessiond の sleep が networkd に radio を落とさせる）。

## 経過

### 2026-11-13 P2（q2041-i01、worktree `agent/p2-bug424`、基点 main 57fafdd191）

#### 設計（本来の形）と根拠

- **共通の PCI の電源の枠組みで直す**（VMD に閉じない）。PCI の core が全部の function の config の保存・復元と順を持ち、VMD の driver は自分の register だけを持つ。
  1. `pci.c`・`pci.h`: root bus を出す PCI function を bus に記録する `drv_pci_bus_set_host_function()` と、function の真上の function（bus の bridge か root bus を出す function）を返す `drv_pci_device_upstream()`。VMD の attach が root bus を作った後に呼ぶ。bus と function の繋がりは電源でなく topology の事実なので `struct drv_pci_bus` に置いた。
  2. `pci-power.c`: 深さを upstream で数える（NVMe 3、隠れた root port 2、VMD 1）ので、子が先に suspend、親が後、resume は逆が明示になる（今までは VMD の root bus が list の先頭にある偶然）。driver の無い function でも、上に driver の付いた function（D3 に入りうる）があれば config を保存・復元する（D3 にはしない）。保存に PCIe の Slot Control（slot のある port）・Root Control（root port・RCEC）を足し、Slot Control は今と違う時だけ書く（書きは slot の controller への命令）。LnkCtl は ASPM を外して書き、L1SS の後に元の値（PCIe Base 4.0 §7.8.3.3: L1SS は ASPM L1 が無効の間に設定）。bus 番号を失った root・downstream port は Data Link Layer Link Active を最大 1 s 待ち 100 ms（PCIe Base 4.0 §6.6.1）、報告できない port は 100 ms。
  3. `pci-vmd.c`: suspend で VMCONFIG（0x44、bus の範囲と MSI の bypass）を保存、resume で違えば書き戻し、bus の始まり・window・第 1 の bus の function（root port）の Vendor ID を確かめ、だめなら EIO と log。**PMCSR に No_Soft_Reset の無い VMD は `drv_pci_device_keep_d0` で D0 に残す**（PCI Bus PM 1.2 §3.2.4: No_Soft_Reset が無ければ D3hot → D0 で内部の reset を受け、VMD の header と VMCONFIG の外にある firmware の設定（どの root port を隠すか等、公開の資料に無い）を driver は書き戻せない）。log「vmd: ffff: sleeps in D0／D3hot」。
- HAL の API・Makefile・mk/ は変えていない。

#### WS300（agent/p6-ws300、2026-10-29、実装済み・試験未実施）との比べ

- WS300 p002 は VMD の driver が隠れた root port を自分で集めて save・D3hot・restore し、`pci-power.c` に root bus の「持ち主」の固定 8 の表を足す形。p003 は NVMe の SHN の前に HMB を止める、p004 は VMD の下の ASPM L1・L1SS・LTR（既定 off、`pci.vmd.aspm=on`）、p005 は NVMe の APST（既定 off、`nvme.apst=on`）。

#### 見立て（code の解析）と次

- VMD・隠れた root port・NVMe の devices の往復は 5330 で通った（上の b424d）。VMD の suspend・resume の code の問題は見つかっていない。
- 残りの 2 つは VMD の外: (a) **xHCI の port 3 の USB の NIC が resume で戻らない**（`xhci: port 3 did not resume (42)` → `usb-rtl815x: ue0 receive stopped (5)`）。5330 の SSH の路が切れるので、S0 idle の試験は戻った後に確かめられない。別の Bug の案（Q1 へ: xHCI の resume の port の再開と usb-rtl815x の受信の再開）。(b) b424b の 3 回目（s0idle）は約 10 分後（watchdog=600 と合う）に TCO で reset された。S0 idle に入って RTC の alarm で起きなかったのか、suspend・resume の途中で CPU が止まったのか、log が残らず分からない（devices の往復は通るので、S0 idle の段（LPS0・GPE・CPU の idle・RTC の起き）か、その後の (a) の network の喪失と区別が要る）。
- TCO の watchdog の案（WS333 p028 の driver、この Bug では変えていない）: (1) 今の `tco_suspend()` は PCI の suspend の順（SMBus 00:1f.4 は最初の方）で counter を halt するので、その後の device の suspend・resume で止まっても reset しない（試験の kernel は `s0idle-wake.patch` で halt を外していた）。本来は PCI の順でなく、全 device の suspend の後・CPU が idle に入る直前に halt し、起きた直後に re-arm する（sleep の core の段に hook、SMBus は `keep_d0`）。devices だけの往復では halt しない。(2) watchdog の thread は CPU が止まる事しか見ないので、sleep の thread が suspend・resume の中で待ち続ける（眠る）と叩き続ける。sleep の coordinator が「suspend か resume が N 秒（例えば 60 s）を超えたら叩くのをやめる」期限を持つ形が要る。(1)(2) が入れば、次の 5330 の試験は止まった時に watchdog で戻り、どの段かは段ごとの kernel の log を CMOS 以外の持続する所に残す工夫と合わせて絞れる。
- 次の 5330 の試験（Q1 の判断の後）: network の路を xHCI の port 3 の NIC に頼らない形（(a) を直すか、試験の結果を p4 に書いて次の Debian で読む形）で、s0idle を 1 回。Wi-Fi は新しい userland（SLEEP_PREPARE を知る networkd）か networkd を止めて。試験の起動に置く時間切れの reboot（2400 s）は今回効いたので続ける。
