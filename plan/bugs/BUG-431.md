# BUG-431: venus の display の事象を取りこぼす（idle の間の head の抜き差しが topology の番号に出ない）、IRQ の経路が事象を clear しない

- 状態: open（2026-11-14 Q1 が起票。WS353 p002 の P1 の報告から）
- 発見: 2026-11-13 P1（q2057-i01）、QEMU（Venus、2 head、D-Bus display）。`plan/ws353/tests/qemu-display-fence.sh` の latency の step。
- 観測（P1、2 回とも同じ）: head を挿して 20 s の間、guest の `GPU_DISPLAY_EVENTS` の番号が動かない（12 のまま）。抜き差しが番号に出るのは、guest で venus の queue の割り込みが起きた時だけ。
- code の読み（P1、未確かめ）: MSI-X の時、IRQ の経路（`src/drivers/gpu/venus/transport.c`）は events_read を読むが clear しない（clear は `display.c:1502` の query だけ）。一度立つと以後の全部の割り込みで番号が上がる（余計な signal の元）。config の変化の割り込みそのものが来ていない疑い（QEMU の側か driver の側かは未確認）。
- 影響: WS353 の hotplug の fence（p002）と今の POLLPRI の経路の両方。venus では QEMU で「抜き差しから 1 s 以内」を判定できない。
- 扱い: 考える Phase（code と virtio-gpu の仕様で原因を突き止めて直す）。直したら `qemu-display-fence.sh` の latency の step を流し直し、WS353 p002 の受け入れを判定する。
