# BUG-404: ブラウザ: 頁の取得中の視覚的な反応が無い（address の欄を進み具合の表示に、押した時点で URL を更新）

- 状態: fixed（2026-11-02 P8 q1924-i01、agent/p8-uat2。Wine（x86_64）の OmniGrammaton で、押した時点の URL と箱の塗りを画面で確かめた。zedBSD は build の warning 0 までで、QEMU の画面は未実施。本物の Windows も未実施）。前: open（2026-11-02 08:19 Q1 が起票、P8 の待ち行列）
- 発見: 2026-11-02 08:19 ユーザーの Windows での OmniGrammaton の UAT（BUG-397〜399 の直しの後）。
- 中身: 取得は裏で黙って進むので、押してから表示まで何の反応も無く不安になる。address の欄の背景を progress bar のように色付けして進み具合を示す。遷移が終わる前の、押して取得を始めた時点で address の欄の URL を新しい頁の物に更新し、遷移中である事が分かるようにする（ユーザーの要望）。
- 扱い: P8（ブラウザの担当、ユーザーの決定）。BUG-401 の後に順に。

## 原因（2026-11-02 P8）

機能が無かった。shell は load の始まり（`BROWSER_LOAD_STARTED`）を log に書くだけで、題の帯の location の箱は頁が commit されて初めて新しい URL になり、取得中を示す物も無かった。libbrowser には load の進み具合を問う口が無く、libkeiland の breadcrumb の値は箱にするか（`KL_BREADCRUMB_BOXED`）だけだった。

## 直し（2026-11-02 P8、agent/p8-uat2。Q1 が KL_VERSION 107 と kl_titlebar_v1 version 7 を割り当てた）

- libbrowser: `browser_view_load_progress(view)`（`include/browser/browser.h`、`view/view.c`）。進み具合を千分率で返す。文書の取得中 150、文書が着いて script と sheet を先に取る間 500〜850（着いた数による）、sheet を待つ間 900、load が無ければ -1。1 つの load の間は減らない。
- shell（`browser/shell/shell.c`・`titlebar.c`・`internal.h`。zedBSD と Windows で共通）: load の始まりの callback で、その URL を location の箱に出す（押した時点）。止まったか失敗したら今の頁の URL に戻し、commit で新しい頁になる。NAVIGATE の行は今まで通り commit の時だけ書く。main loop は `browser_view_process` の後に進み具合を問い、変わった時だけ箱の値を `KL_BREADCRUMB_BOXED | KL_BREADCRUMB_PROGRESS(千分率)` にする（log の `ZBROWSER PROGRESS value=`）。
- libkeiland（KL_VERSION 107）: `KL_BREADCRUMB_PROGRESS(t)`・`_MASK`・`_SHIFT`（`include/keiland/keiland_titlebar.h`）。Wayland（`libkeiland/titlebar.c`）は protocol の version 7 を結び、version 6 以前の compositor には箱だけを送る。Win32（`libkeiland/win32/titlebar.c`）は箱の地を左から進み具合の分だけ選択の色で塗る。
- compositor（`wayland/protocol.c` で `kl_titlebar_manager_v1` を version 7 に、`wayland/titlebar.c`・`titlebar.h` で version 7 の箱の値を受ける、`titlebar-shell.c` の `shell_draw_crumb_box` で箱の地を左から文字の色で薄く塗る）。
