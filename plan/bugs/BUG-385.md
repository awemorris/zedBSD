# BUG-385: VF2 が SD card の誤りで root を読みだけ（ro）で mount して起動した

- 状態: fixed（2026-11-01 08:50 P1 q1826-i01、e176325ed: SD の retry と root の rw の mount の retry を補強。ro になった起動の原因は log が無く未確定、補強した経路は板では誤りが出ず未踏）← open（2026-11-01 06:07 Q1 が起票）
- 発見: 2026-11-01 06:07 ユーザーの実機の目視。SwitchBot のプラグ 3（AC276E432AE6）につなぎ直した後の起動で、SD card の誤りが出て root が ro で mount された。
  network（10.0.30.2）にも答えなかった（同じ時刻の Q1・P4 の確かめ）。
- 起動した kernel: 未確認（P4 の q1817 の新しい kernel はまだ置いていない。SD の上の前の kernel のはず）。
- 関係: 閉じた [BUG-340](BUG-340.md)（SD の 32 block の読みの data CRC の誤り）・[BUG-343](BUG-343.md)（SD からの起動で root が live にならない）と同じ系統かは未確認。
- 次: P4 が serial（/dev/ttyUSB0）か SSH で、起動した kernel・SD の誤りの行・mount の状態を取る。SD が誤りを出している間は SD に書かない。
- 2026-11-01 ユーザーから、VF2 の SD はまだ安定していないので、再起動して通れば気にせず作業してよい、SD の読み書きの retry を補強して root が ro にならない改修は後で行う、という趣旨の指示を受けた。直しの担当は VF2 の計測（q1817）の後に Q1 が割り当てる。

## 調べと直し（2026-11-01 P1、q1826-i01）

### 誤りの経路の調べ

- 板の boot log（`/boot/boot0/log/boot-000244〜268.txt`、25 起動、bootlog が FAT に書く。写しは P1 の worktree の build/tmp/q1825/boardlogs/、git の外）を数えた:
  SD の読みの失敗は起動ごとに 0〜17 回、同じ run の失敗は最大 try 2（boot 256・259・261・264 に 1 つずつ）。try 3 以上・`moved a block at a time`・`did not come back`・
  `ufs:` の行・`read-only` は 25 起動とも 0。各 log の頭の行は全部 `/ mounted read-write`。→ 記録のある起動では、retry の後の EIO が file system に届いた事は無い。
- ro になった起動（06:06 以前）の log は無い。番号は 262（10-31 18:30 頃）→ 263 で連続していて、263〜265 は時計が 2026-01-01 のまま（network 無し、線が en1 だった
  [BUG-386](BUG-386.md) の起動）で、どれも rw。init は root が ro だと何より先に `/sbin/fsck -y` を走らせ、直したら reboot する（`userland/base/init/root-check.c`）ので、
  bootlog が始まる前に止まり log が残らない、と読める（推測）。その間は networkd も上がらないので「network に答えない」とも合う。
- よって ro の原因（SD の I/O の誤りか、プラグのつなぎ直しで電源が sync なしに切れた後の volume の状態か）は確定できなかった。root が ro になる経路は kernel の
  `vfs_mount_root_volume`（rw の mount の失敗 → ro の mount）か、動作中の ufs の `stop_writing`（`refuses writes`）の 2 つで、後者は log に出ていない。
- 気づき（範囲の外、直していない）: 板の root（mmcblk0p4、256 MiB）は使用 95%（残り約 15 MiB、`df`）。bootlog は 266 以降 `the file or the volume is full` で一部を落としている
  （FAT は 84%）。init の fsck の後の reboot が VF2 で効くかは未確認（2026-10-20 の記録では `sudo reboot` が効かなかった）。

### 直し（補強）

- `src/drivers/mmc/dw-mmc.c`: 1 block ずつに落としても全 try（5 回）に失敗した block、または 1 block の run の失敗は、card clock を半分にして try し直す
  （24.75 → 12.375 → 6.19 MHz、5 MHz を下回る所で止める。`dw-mmc: a block failed every try, card clock down to N Hz`）。下げた clock は attach し直すまで保つ。
  [BUG-340](BUG-340.md) の原因（PIO の FIFO が満ちて card clock が止まり data CRC の誤り）では、遅い card ほど FIFO が満ちるまでの時間が長い。これまでは 24.75 MHz で
  全 try に失敗すると EIO が file system に届いた。
- `src/kern/vfs.c`: root の rw の mount が EIO で失敗した時は 3 回まで mount し直してから ro の mount へ（`vfs: the root on … met an I/O error mounting read-write, try N of 3`）。
  失敗した mount は後始末されて root の枠を返す（mount_root_create）ので、もう一度 mount してよい。EIO 以外の失敗（volume の不整合など）は前と同じくすぐ ro へ。
- host 試験 `plan/tools/vf2-host/dw-mmc/dw-mmc-host-test.c` に 3 case: 12 回の CRC の誤り → 12.375 MHz で通り data 一致／1 block の書きに 8 回 → 6.19 MHz で通り card が data を持つ／
  毎回 → EIO、clock は 6.19 MHz より下げない。直す前の dw-mmc.c で 3 つとも FAIL、直した後に PASS を確かめた。
