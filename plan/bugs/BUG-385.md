# BUG-385: VF2 が SD card の誤りで root を読みだけ（ro）で mount して起動した

- 状態: open（2026-11-01 06:07 Q1 が起票）
- 発見: 2026-11-01 06:07 ユーザーの実機の目視。SwitchBot のプラグ 3（AC276E432AE6）につなぎ直した後の起動で、SD card の誤りが出て root が ro で mount された。
  network（10.0.30.2）にも答えなかった（同じ時刻の Q1・P4 の確かめ）。
- 起動した kernel: 未確認（P4 の q1817 の新しい kernel はまだ置いていない。SD の上の前の kernel のはず）。
- 関係: 閉じた [BUG-340](BUG-340.md)（SD の 32 block の読みの data CRC の誤り）・[BUG-343](BUG-343.md)（SD からの起動で root が live にならない）と同じ系統かは未確認。
- 次: P4 が serial（/dev/ttyUSB0）か SSH で、起動した kernel・SD の誤りの行・mount の状態を取る。SD が誤りを出している間は SD に書かない。
- 2026-11-01 ユーザーから、VF2 の SD はまだ安定していないので、再起動して通れば気にせず作業してよい、SD の読み書きの retry を補強して root が ro にならない改修は後で行う、という趣旨の指示を受けた。直しの担当は VF2 の計測（q1817）の後に Q1 が割り当てる。

## 起動の記録（2026-11-01 P4 q1817-i01）

判定は SSH（`kei@10.0.30.2`）で。serial（/dev/ttyUSB0、115200）は電源の入れ直しの間だけ手がかりとして残した（build/tmp/q1817/vf2-cycle1/serial.txt・vf2-cycle2/serial.txt）。
serial は入力を受けない（Enter・命令に echo も応答も無い）ので、serial では uname・mount を取れない。SD には何も書いていない（2 回目の入れ直しまで）。

| 起動 | 結果 | SD の読みの失敗（retry で通った） | root | network |
| --- | --- | --- | --- | --- |
| 06:06 以前（ユーザーがつなぎ直した後の起動） | 悪い | 未確認（P4 の serial の読みは buffer の残りだけで、SD の行は取れなかった） | ro（ユーザーの目視） | SSH 無し（06:06〜06:13 の P4 の確かめ。05:5x の P4 の入れ直しの時はプラグの電流 0 で、板に電気が来ていなかった） |
| 06:12（P4 の入れ直し） | 悪い | 11 回（status a4 が 10、408c が 1、1 つは try 2 で通った）、24.75 MHz に下げ、sample phase 16 | serial では `vfs: runtime filesystems mounted` の後に init・sshd・getty・`login:`。ufs の refuse・ro の行は見えない（serial の文字が混ざるので無いとは言えない） | en0 は `RX/TX enabled` まで、240 s で `link up` が無い。SSH 無し・subnet に新しい host 無し |
| 06:26（P4 の 2 回目の入れ直し） | 良い | 11 回（a4 が 10、408c が 1）、全部 try 1 の後に通った、24.75 MHz に下げ | `/dev/mmcblk0p4 on / type ufs (rw)`、dmesg に ufs・EIO・refuse の行 0 | `en0 link up 1000 Mbps full duplex`、SSH は入れ直しから約 3 分 |

- 06:26 の起動の kernel: `/boot/boot0/vmunix` 2825517684（vmunix.p2old・vmunix.q1772orig と同じ）、uname `1.0.0-beta2+g5c83c16 (5c83c16 2026-10-21)`（userland の版の文字。kernel の tree は uname からは分からない）。
- [BUG-340](BUG-340.md) との比べ: 閉じた時の記録（直した kernel の 10 回の起動で毎起動 5〜17 回の読みの失敗、全部 retry で通る）と同じ程度。全部 retry で通り、EIO は file system に届いていない。
  root が ro になった起動（ユーザーの目視）の SD の行は取れていないので、BUG-340 の残り（PIO の FIFO の溢れ）か [BUG-343](BUG-343.md) の系統（retry の後の EIO が file system に届く）かは未確認。
- 06:12 の悪い起動は SD でなく Ethernet の link が来ない事で SSH が無かった。ユーザーがつなぎ直した時の cable・PHY の可能性（未確認、Q1 がユーザーに聞く）。
- 06:26 の後の計測の 7 回の起動（06:31〜06:46、`plan/tools/vf2/run.sh` の電源の入れ直し、SD に kernel を書いた）: 7 回とも SSH が戻った（入れ直しの retry 0）、root は rw、en0 は link up。
  SD の読みの失敗（retry で通った、各起動の dmesg の数え）: b2392803f の kernel（3220583395・3758577736）と p015 の kernel（1381433670）で 0・0・0・1・0 回、板の元の kernel（2825517684）に戻した起動で 0（dmesg の採りが短い）と 20 回（try 2 が 2 つ、ufs・EIO の行 0）。
- 数え（2026-11-01、つなぎ直しの後）: 悪い 2（06:06 以前の ro、06:12 の link 無し。後者の原因は線が en1 の口だった事、[BUG-386](BUG-386.md)）、良い 8（06:26 と計測の 7 回）。
