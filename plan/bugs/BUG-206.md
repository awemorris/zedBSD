# BUG-206: Browser で URL を編集すると https:// の前に file:// が付く

Reproduction: reproduced（ユーザー、Windows の QEMU（Venus）で uat-0505g、2026-10-05 夜 UAT）
Disposition: tracking
Discovery: 2026-10-05 夜 ユーザーの UAT のコメント
Handling: WS074（browser）

## 観測

ユーザー「ブラウザでURLを編集しようとするとhttps://の前にfile://がついてしまう。」

## 原因（2026-10-06 P1、source の読みで確認）

`userland/desktop/browser/shell/titlebar.c` の `titlebar_state()` が、titlebar の location の欄が編集する URL を、page の location が何であっても
`"file://" + location` で作っていた（file の path しか開けなかった頃の名残）。https: の page では `file://https://…` になる。breadcrumb も `https:` を
最初の部分に出していた。

## 修正（2026-10-06 P1、agent/p1）

- location が scheme（RFC 3986: 英字で始まり英数字・`+`・`-`・`.` が続き `:` で終わる）で始まるなら URL としてそのまま編集させ、scheme が無い（file の path）
  ときだけ `file://` を前に付ける。breadcrumb は scheme の後（host と path の部分）から作る。欄の placeholder を「URL or file path」に。
- 確認: zedBSD の build（`build/p1-zed/bin/browser`）warning 0。scheme の判定を host で単体に確かめた（https・about・file・data は scheme、`/usr/…`・`/a:b`・`1abc:x` は無し）。
- 未実施: QEMU（T1）。

## T1 への依頼（未実行）

- image: agent/p1 の commit（merge 後の main）、browser 入りの image（CI の config）。
- 試験と合否: browser で https の page（network が無ければ about: の page か、location が URL の任意の page）を開き、Ctrl+L（または location の click）で
  編集に入る → 欄が `https://…` で始まり `file://` が付かない（PNG）。file の page（例 `/usr/share/tests/first.html`）では `file:///usr/…` が出る。
  Enter で同じ page が開く。
- 結果の返し先: Q1。

## 2026-10-08 P2 の確認（q869）

- 実装済み（P1 d0a0e016）: browser/shell/titlebar.c の location は、scheme があれば URL のまま、path の時だけ file:// を付ける。
- QEMU: T1-219（2026-10-06）で期待どおり（file の頁は `file:///usr/...`、https の頁は `https://...`、Enter で同じ頁）。
- T1-219 で見つかった別の 2 点は BUG-240・BUG-241。
