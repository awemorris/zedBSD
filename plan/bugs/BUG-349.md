# BUG-349: venus は strict の queue が無くても GPU_CAP_JOB を返すが、GPU_JOB_RESERVE は ENOTSUP

- 状態: fixed（2026-10-31 P4 q1753-i01、e8c67ac77、source の読みと build。QEMU の Venus での確かめは未実施、main に未 merge）
- 発見: 2026-10-29 P5（q1666、DOC-54 の設計の review）。source の読みで、実行での再現は未実施。
- 観測: venus の driver（`src/drivers/gpu/venus/venus.c:29`）の capability に GPU_CAP_JOB があり、GET_INFO の bit は `ops->capabilities` で上書きされる（`src/drivers/gpu/gpu.c:2523` 付近）。一方 strict の queue が無い時、`transport.c:179`・`:408` の GPU_JOB_RESERVE は ENOTSUP を返す。
- 期待: GET_INFO が GPU_CAP_JOB を示すのは、その device で GPU_JOB_RESERVE が使える時だけ（または RESERVE が strict の queue なしでも動く）。
- 影響: GPU_CAP_JOB を見て job の API を使う client が venus（QEMU）で失敗する。

## 直し（2026-10-31 P4 q1753-i01、e8c67ac77）

- 原因: venus の `venus_get_info`（`src/drivers/gpu/venus/venus.c` 612〜616）は strict の queue が無い時に GPU_CAP_JOB・GPU_CAP_JOB_CAPACITY を落としていたが、core の `gpu_info_ioctl`（`src/drivers/gpu/gpu.c`）が backend の値を `device->ops->capabilities` で上書きしていた。
- 直し: core は backend の報告を登録の bit と AND する（`information.capabilities &= device->ops->capabilities`）。backend は登録より少なく報告できるが、多くはできない。他の backend（amdrdna・nvrtx・i915・ghci・mali・powervr・bcm2711 の render と display）の get_info は登録と同じ値を書くので、出る bit は変わらない（各 file を読んで確かめた）。libvulkan は venus の strict queue と JOB の両方を見るので動作は変わらない。
- 文書: `docs/reference/gpu-capabilities.md` の規則 4（「Venus は常に両方の bit を立てる」）を新しい動作に直した。
- 確かめ: amd64 の vmunix の build（warning 0）。
- 未実施: QEMU の Venus で strict でない renderer（stock の virglrenderer）の時に GET_INFO が JOB を出さない事の観察（strict でない host の用意が要る）。
