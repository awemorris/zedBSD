# BUG-289: xHCI の suspend の wait_idle が失敗した道で doorbell が鳴らず、GATED の間に積んだ転送が止まりうる

- 状態: closed（2026-10-31 Q1 の判定、main a2a9fca00。2026-10-31 P2 q1757-i01。wait_idle の失敗の道は 2026-10-16 の d3b388354 で既に鳴らしていた。残っていた競合（鳴らしてから門を開けるまでの隙）を直した。QEMU の回帰は PASS、失敗の道そのものは未再現）
- 発見: 2026-10-11 ws197-p007 の設計 2.1a の review（第 4 回、[review-4](../ws197/phase007/review-4.md)）。
- 観察（source）: `src/drivers/pci/pci-xhci.c` の enqueue は suspend の GATED の間 TD を積んでも doorbell を鳴らさない（4215-4216）。wait_idle が失敗した時の `xhci_suspend_end`（7286-7307）も鳴らさない。そのため GATED の間に積まれた TD は、次の doorbell まで動かない。isoch では FIFO が満ちて流れが永久に止まる。bulk OUT も同じ形の見込み（推測）。
- 直す案: wait_idle 失敗の道で `xhci_suspend_end` の前に `xhci_resume_endpoints`（7240）を呼ぶ。ws197-p007a1 の中で isoch と一緒に直し、bulk の再現は T1 の ktest で。

## 2026-10-31 P2（q1757-i01）

- **今の source**: 書かれた案（wait_idle の失敗の道で `xhci_resume_endpoints` を呼ぶ）は 2026-10-16 の d3b388354 で入っていた（stop_endpoints・halt の失敗の道も同じ）。
- **残っていた穴（source）**: どの道も `xhci_resume_endpoints(c)`（active_lock を取って全 endpoint の doorbell、離す）の後に `xhci_suspend_end(c)`（active_lock を取って NONE、離す）を呼んでいた。その間に来た submission は state が GATED なので TD を積むだけで doorbell を鳴らさず、後で鳴らす者がいない（次の doorbell まで止まる）。
- **修正**（`src/drivers/pci/pci-xhci.c`）: `xhci_suspend_end(c, ring)` が、ring の時は同じ active_lock の保持の中で全 endpoint を鳴らしてから NONE にする（`xhci_resume_endpoints_locked`）。suspend の 3 つの失敗の道と通常の resume は ring=true、reset の後（device を数え直す）と quarantine は ring=false（前と同じく鳴らさない）。
- **確かめ**: `make ZEDBSD_CONFIG=config/ci/config-amd64.mk build/amd64/vmunix` → warning 0。QEMU（lean の image `build/tmp/q1757/config-q1757.mk` を BUILD=/tmp/p2-bugs3/lean で、Venus 無しの guest.py の guest、SSH の adapter は xHCI の usb-net）: `build/tmp/q1757/xhci-sleep.sh` → `xhci-sleep: PASS`（`sleepctl -x` refusals ok、`sleepctl devices` を背景で走らせ、その間に 4 MiB を SSH で guest へ送る（bulk OUT、rc 0）、SSH が戻る、`sleep result=0 resume=0 device=-`、dmesg に `xhci: suspended` と `xhci: resumed after a reset`、resume の後の 4 MiB の copy の SHA-256 一致）。
- **未実施**: wait_idle の失敗の道そのもの（QEMU では transfer が時間内に終わり、失敗を起こせない）。QEMU の xHCI は Restore State が無いので resume は reset の道（ring=false）を通り、通常の resume の ring=true の道は実機（Restore State のある controller）でしか通らない。実機の試験は未実施。Venus のある guest では venus が suspend を断り（EOPNOTSUPP）xHCI の手前で止まる（設計どおり、低い slot の xHCI は suspend と resume をした）。
