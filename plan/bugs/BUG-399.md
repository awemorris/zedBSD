# BUG-399: Windows 版ブラウザ: Google の検索の入力欄を click すると、入力できる範囲が右へ窓の幅いっぱいに伸びる

- 状態: fixed（2026-11-02 P4 q1915-i01、agent/p4-bug397 32e6e318f9（2 件の修正と試験を 1 つの commit に）。Linux の host build で再現と修正を確かめた。本物の Windows は未実施）
- 発見: 2026-11-02 06:16 ユーザーの Windows での OmniGrammaton（WS334 の Windows 版ブラウザ）の UAT。
- 中身: 検索の欄を click して focus と caret を置くと、入力できる範囲（入力欄）が右側に非常に長くなる。窓の幅いっぱいまで伸びているらしい。
- 扱い: P4（q1915）。このセッションで直す（ユーザーの指示）。描画と JavaScript の全般の改善はクラウドのセッションの libbrowser を待つが、この Bug はこのセッションで直す。
- 補足（2026-11-02 Q1）: ユーザーの click の前の画面でも、検索の欄の右端（丸い端と icon）が x≈1150 で切れていた。

## 原因（2026-11-02 P4）

Windows に固有ではなく、libbrowser の flex の layout の誤り。Linux の host build でも同じで、Google の top の `<textarea class=gLFyf>` の box は幅 262144 px（layout が content の幅を測る時の幅 `POSITION_MEASURE_WIDTH`）になり、検索の欄の右の icon 群はその先（x≈262489）に置かれていた。click で focus の枠と入力の範囲がこの box で描かれるので、窓の右端まで伸びて見える。

最小の形: flex の行 > `flex:1; display:flex` の項目 > `flex:1` の項目 > `width:100%` の textarea または input。祖先の max-content を測る時（容器を 262144 px の幅で layout する）、`flex_base_size` は置換の項目（form の control）を `layout_block(child, 容器の幅)` で置き、その `width:100%` を測る幅に対して解いていた。その幅が flex の基の大きさになり、祖先の大きさに入る。同じ関数の box model（`layout_box_model`）は、測っている最中の容器の % を循環とみなして 0 に対して解いていたが、置換の項目の幅だけその扱いが抜けていた。

## 修正（2026-11-02 P4、`userland/desktop/libbrowser/layout/flex.c`）

`flex_base_size` の行の置換の項目で、測っている最中（`tree->measuring != 0`）で容器の幅が px でない時、項目の % の幅を auto として layout する（control は自然の幅になる）。最終の layout の % は今まで通り容器の幅に対して解く。
