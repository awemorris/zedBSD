# BUG-411: ブラウザの JavaScript の engine が重い頁で遅い（property の探しが線形、layout）

- 状態: open（2026-11-02 P8 q1941-i01、agent/p8-uat3 で一部を直した。store.google.com の 1 回の最長の呼び出し 40〜42 秒・21 秒 → 9.7〜10.0 秒・9.2〜9.7 秒（Linux の host、live）。目標の 2 秒は未達: 残りは layout そのもので、layout の結果の cache は Q1 が別の項目にする）。前: open（2026-11-02 10:47 Q1 が起票、P8 の待ち行列）
- 発見: 2026-11-02 10:47 P8（BUG-403 の調べ）。store.google.com で、頁が出た後に 1 つの callback が約 17〜21 秒かかる。CPU の 30% が vm_shape_find（property の線形の探し）、23% が layout。
- 直す形の案: shape の property の探しに hash か inline cache を入れる。layout の重い所を測って減らす。
- 扱い: P8（BUG-402・404・405・406 の後）。

## 測った事（2026-11-02 P8、Linux の host、plain build、`perf record --call-graph fp`）

live の store.google.com（`https://store.google.com/JP?hl=ja-JP`、host build の view を shell と同じに回す一時の driver `build/tmp/p8v/drive.c`、40 秒）。頁が出た後の 2 つの呼び出しが 21〜22 秒と 40〜44 秒。

- `vm_shape_find` が CPU の 12%（呼び出し元は `vm_get` → `vm_object_get_own`）。property の 650 万回の探しのうち 45 万回が 2048 個以上の property の shape、17 万回が 512〜2047 個（一時の計数）。
- 40 秒の呼び出しの 33 秒は layout（36 回、1 回 0.8〜1.0 秒）。その 76% は `getComputedStyle(…).display`・`content`・`background-image` と `::before`・`::after` の読み取りが、DOM の変更の後に頁を全部 layout し直していた物（`page_computed_style` → `geometry_layout`）。
- 以下も熱い所だった: `page_needs_layout` が毎回 DOM の全体を歩く `frame_generation_walk`（10%、3 万回の読み取りの度）、`vm_heap_remove_root` が根の一覧を先頭から探す（4%）、JS の compiler の `scope_find` の線形の探し（4%）。

## 直し（2026-11-02 P8、agent/p8-uat3）

1. shape の key の hash 表（`vm/shape.c`）: 8 個以上の property の shape は、初めて探された時に道の key の hash 表を作る。表は道の前の shape と共有し、slot が shape の数より小さい項目だけがその shape の物。表の最後の shape から作った shape は表を 1 項目長くして引き継ぐ（1 つずつ property を足す object の表は 1 つ）。同じ key が道に 2 回ある時は印を付け、前の shape は道を歩く。property の順・削除（作り直し）・prototype の鎖・accessor・Proxy は変えていない（探す所だけ）。
2. layout に依らない getComputedStyle は layout し直さない（`bind/computed.c`、`page/geometry.c` の `page_cascaded_style`、`bind/bind.h` の `cascaded_style`）: 幅・高さ・min・margin・padding・inset（論理の名前を含む）・grid の template 以外は、layout が古い時に cascade の style を返す（layout が今の時は今まで通り box の style）。layout が style を変える・決める場合は layout する: query container を見た style（`css/cascade.c` の `css_engine_computed_contained`、cache の項目ごとに記録）、縦書き、view transition の間。root は body の writing-mode・direction を box と同じに受ける。`::before`・`::after` も要素の style を同じ道で取る（`page/transition.c`、pseudo の style が container を見た時は layout の後に取り直す）。layout の値の property だけ `node_box` を呼ぶ。
3. `page_needs_layout` は、前の layout の時に iframe が無く DOM が変わっていない頁では DOM を歩かない（`page/frame-load.c`・`page/script.c`）。
4. `vm_heap_remove_root` は最後に足した根から探す（`vm/heap.c`）。
5. JS の compiler の scope は 16 個以上の binding で hash の索引を持つ（`js/scope.c`・`js/compile.h`）。

## 残り（目標 2 秒は未達）

store の 9〜10 秒の呼び出しの中身（一時の計測、layout の呼び出し元ごと）: 1 つは offsetWidth・clientWidth・scrollLeft・scrollHeight などの読み取りが DOM の変更の後に強いる layout 6 回（5.1〜5.3 秒）と rAF の rendering 2 回（1.8 秒）、もう 1 つは query container を見た style の読み取り 3 回（5.0 秒）と他 3 回（2.5 秒）。残りの JS は 1 回 2 秒弱。layout は 1 回 0.8〜0.9 秒で、1 回の layout が 2.4 千個の box に約 42 万回の `layout_block` を呼ぶ（約 176 倍、73% が intrinsic の測り: 入れ子の flex・grid の min-content・max-content・`flex_content_height`・`layout_shrink_to_fit` の最後の layout が部分木を何度も layout し直す）。`layout_narrowest` の保った幅は 236 万回当たり、76 万回外れる（containing block の高さの definite の違い 28 万、box の高さの indefinite の違い 19 万、size の違い 26 万）。DOM が変わる度に style の engine を作り直すので style の計算もやり直し（layout の 20%）。

layout の結果の cache に要る事（Q1 が別の項目にする）:

- `layout_block` の入力の鍵: containing の幅、`tree->containing_height` と definite、`tree->measuring`、論理の mode、一時に変える style の幅・高さ・min・max・box-sizing、float の context（自分の formatting context を作らない box は外の float に依る）。
- 出力: box とその部分木の geometry 全部（呼び出し元は `layout_content_width` で子孫も読む）。部分木を丸ごと持つか、測りの時だけ（`measuring`）の scalar（幅・高さ）の cache にして最後の layout は必ず通すか。
- 無効にする時: DOM・style の変更（今は layout ごとに box の木を作り直すので、木を保つなら style の差分の invalidation が要る）、画像・font の到着、container の大きさ。
- それより小さい一歩の案: `layout_narrowest`・`layout_max_content` の保った値を鍵ごとに複数持つ、`flex_content_height` の結果を (幅、containing の高さ) で保つ。

ほかに見つけた事（この Bug では直さない）: `Reflect` が無い。`for` の 300 万回の空の足し算が約 3.5 秒（interpreter の速さ）。observer の最初の callback の順が Chromium と違う（ここは IntersectionObserver・ResizeObserver が MutationObserver より先）。保たない頁を離れる時の pagehide（persisted false）は fire しない。
