# BUG-416: usb-net（CDC-ECM）で長さが 64 byte の倍数の frame が届かない（xHCI が 0 長の packet の TD の Short Packet を失敗として扱う見込み）

- 状態: fixed（2026-11-02 17:50 P3 q1978-i01、QEMU amd64 で確かめた。実機は未実施。main への merge は Q1）。起票は 2026-11-02 17:09 Q1、P1 の報告から
- 発見: 2026-11-02 P1（ws335-p033 の QEMU amd64 の guest の試験）。qemu-xhci の usb-net（ue0）で、bulk-OUT の最大の packet（64 byte）の倍数の長さの TCP の frame（例: 5030 byte の TLS の record の最後の 704 byte）が host に届かず、接続が止まる。再送のたびに console に `xhci: transfer completion=13 residual=0 length=704 ... endpoint=4 direction=out` が出る。
- 見込み: usb-cdc-ecm.c（1207〜1210 行付近）がその frame に DRV_USB_URB_ZERO_PACKET を付け、pci-xhci.c（3175 行付近）が 0 長の packet の TD の完了の code 13（Short Packet）を失敗として扱う。
- 再現: P1 の worktree の plan/ws335/tests/run-guest.sh で run-interop.sh の「1.2 non-blocking」を size 5000 にする（P1 は TLS の試験がこれに依らないよう 5003 に替えた）。成果物は /home/awe/zedBSD-worktrees/p1-ws335/build/tmp/ws335-interop/case-10・case-16。
- 扱い: P3（q1978-i01）。

## 原因（2026-11-02 P3）

- pci-xhci.c は DRV_USB_URB_ZERO_PACKET の 0 長の packet を、payload の最後の TRB に Chain を付けて繋いだ 0 長の Normal TRB にしていた（payload の TD Size も +1）。これは payload と同じ TD の一部で、packet を足さない。
- QEMU の xhci は 1 つの TD を 1 つの USB packet にして device に渡す。usb-net（QEMU 10 の hw/usb/dev-network.c、usb_net_handle_dataout）は CDC-ECM の frame を、長さが 64 の倍数でない packet か 0 長の packet で送り出す。704 byte の TD は 64 の倍数なので送られず function の out_buf に溜まり、再送のたびに溜まって、溢れた時に function が受け取りを減らし、xhci が Short Packet（code 13、0 長の TRB の event なので residual 0）を出した。それを OUT の失敗として扱うのは正しい（OUT の Short Packet は普通は起きない）。誤りは TD の作りの方。
- 実の xHC でも、Chain で繋いだ 0 長の TRB は 0 長の packet にならない。Linux は 0 長の packet を別の TD にする（xhci_urb_enqueue が num_tds を 2 にし、xhci_queue_bulk_tx が長さ 0・IOC の Normal TRB 1 本の TD を置く）。

## 直し（2026-11-02 P3、q1978-i01）

- include/drivers/pci/pci-xhci-normal.h（新しい）: 0 長の TD が要るか（bulk・OUT・要求あり・長さが max packet の倍数）、payload の TRB の words（最後は IOC で Chain 無し、TD Size 0）、0 長の TD の words（長さ 0・TD Size 0・IOC）、event の分類（0 長の TD を持つ request の payload の TD の event が Success・Short Packet なら 0 長の TD の event を待つ。endpoint を止める error はその場で終える）、payload が成功しなかった時はその code で終える判定。
- src/drivers/pci/pci-xhci.c: enqueue_normal と xhci_sg_enqueue が上の words で TD を作る（0 長の packet は別の TD）。xhci_urb_enqueue が request に zero_packet を覚え、transfer_claim は payload の TD の event では request を終えずに head に残し、0 長の TD の event で終える。止めた endpoint は従来どおり Set TR Dequeue が enqueue まで飛ばすので 0 長の TD は残らない。Event Data・ED は使わない（Linux の bulk も使わない）。ISP は従来どおり IN だけ。
- BUG-412 の候補（agent/p3-bug412）とは別の file（pci-xhci-control.h・usb-hid.c は触らない）。
