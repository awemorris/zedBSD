# BUG-416: usb-net（CDC-ECM）で長さが 64 byte の倍数の frame が届かない（xHCI が 0 長の packet の TD の Short Packet を失敗として扱う見込み）

- 状態: open（2026-11-02 17:09 Q1 が起票、P1 の報告から）
- 発見: 2026-11-02 P1（ws335-p033 の QEMU amd64 の guest の試験）。qemu-xhci の usb-net（ue0）で、bulk-OUT の最大の packet（64 byte）の倍数の長さの TCP の frame（例: 5030 byte の TLS の record の最後の 704 byte）が host に届かず、接続が止まる。再送のたびに console に `xhci: transfer completion=13 residual=0 length=704 ... endpoint=4 direction=out` が出る。
- 見込み: usb-cdc-ecm.c（1207〜1210 行付近）がその frame に DRV_USB_URB_ZERO_PACKET を付け、pci-xhci.c（3175 行付近）が 0 長の packet の TD の完了の code 13（Short Packet）を失敗として扱う。
- 再現: P1 の worktree の plan/ws335/tests/run-guest.sh で run-interop.sh の「1.2 non-blocking」を size 5000 にする（P1 は TLS の試験がこれに依らないよう 5003 に替えた）。成果物は /home/awe/zedBSD-worktrees/p1-ws335/build/tmp/ws335-interop/case-10・case-16。
- 扱い: P3（q1978）。
