# BUG-406: ブラウザ: 戻る button で数秒待たされる（cache で表示し、再取得は cache できない頁だけ）

- 状態: fixed（2026-11-02 P8 q1924-i01、agent/p8-uat2。戻る・進むは保った頁をその場で出す。Linux の host build と live の google.com で確かめた、本物の Windows は未実施）。前: open（2026-11-02 08:19 Q1 が起票、P8 の待ち行列）
- 発見: 2026-11-02 08:19 ユーザーの Windows での OmniGrammaton の UAT（BUG-397〜399 の直しの後）。
- 中身: 戻る button を押すと数秒待たされる。HTTP の cache（と戻る・進むの cache）で表示し、再取得は cache できない頁（no-store など）に限るのがよい（ユーザーの要望）。
- 扱い: P8（ブラウザの担当、ユーザーの決定）。BUG-401 の後に順に。

## 原因（2026-11-02 P8）

戻る（`browser_view_go(-1)`）は、history の URL を新しい load として読み直していた（network で取得、解析、script の実行）。前の頁は新しい頁が出た時に壊していた。HTTP の cache（loader の memory と disk）はあるが、Google の文書は `private, max-age=0` で毎回の再検証が要る。それに cache から読めても解析と script の実行（google.com の top で約 2.6 秒、host）はやり直しになる。

## 直し（2026-11-02 P8、`userland/desktop/libbrowser/view/view.c`・`page/page.h`・`page/page.c`）

- 戻る・進むの cache: 新しい頁を出す時、前の頁を壊さずに、その history の段の頁として最大 3 つまで保つ（`struct view_kept`、古い物から捨てる）。`browser_view_go` は保った頁があればその場で出す（文書・script の状態・scroll はそのまま、`committed` の callback）。頁の時計は離れた時の所から進む（離れていた間の timer は走らず、まとめて発火もしない）。出していた頁は、今度はその段の頁として保つ。進行中の load は止める。
- 保たない頁: 文書が `Cache-Control: no-store` で来た物（`page->no_store`。view が非同期で取った文書と、最初の同期の取得の両方で記録する）と、media を持つ頁。これらは今まで通り取り直す。同じ段の再読み込み（`go(0)`）も取り直す。
- history との整合: 新しい段を足す時に、その先の段の保った頁を捨てる。history が一杯で最古の段を捨てる時は、保った頁の段の番号を詰め、0 の物を捨てる。保った頁の URL が段の URL と違えば捨てて読み直す。
