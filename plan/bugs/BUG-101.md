# BUG-101: Windows版Venusでデスクトップのblob scanoutが表示されない

Bug ID: `BUG-101`
Reproduction: reproduced（WINQ-EMU Alpha10、Windows WHPX、2026-09-29）
Disposition: resolved（ユーザーの判断で解決済み、2026-10-04）
Source: ユーザーのWindows QEMU実行・修正の指示
Owner: WS085

## 観測

元のrendererは160B capsetでzedBSDのstrict7契約を持たず、WaylandのVulkanデバイス列挙が-3。Windows forkのrendererへstrict7を移植すると`vkdemo --offscreen`がGPU結果を返し、WaylandはOUTPUT openと合成frameまで進む。blob scanoutはSDL画面が黒い。既存copy fallbackを選ぶとWindowsのSDLにデスクトップ背景が現れるが、所有者終了後にQEMUが応答しなくなり、次の直接表示が`No such device`で失敗する。

copy fallbackは4,096,000バイト/frameのguest CPU書き込みに450〜564msを要し、1〜2fpsの報告と整合する。WINQ-EMU QEMU Alpha10のWindows `virtio-gpu-udmabuf-stubs.c`はblob scanoutで成功を返すだけで表示を更新しない。ユーザー許可でforkソースを`vendor/`へ導入し、QEMUへmapped hostmem scanoutを実装した。QEMUだけが対応capsetにbit 8を広告し、guestはexact bit 8 profileで共有表示を選ぶ。WindowsビルドはPASS。flags15をkernel/libvulkanにも認識させ、OPAQUE共有画像をrendererからQEMUのpixman/SDL表示面にmapした。WHPXの実画面でデスクトップが表示され、起動中の合成は16〜34ms/frame。元のcopy表示で支配的だったguest CPU書き込み450〜564ms/frameは発生しない。

## 次の確認

COM1 mirror付きイメージで共有scanoutとデスクトップ表示を確認済み。表示所有者の終了・切替とアニメーション継続性能は未検証。Linux hostのprofileは変えない。
