# BUG-032: mkdir(".") が EEXIST でなく EINVAL を返し、`mkdir -p ./x` が失敗する

Bug ID: `BUG-032`
Reproduction: reproduced（QEMU、amd64 guest）
Disposition: resolved（ws046-p006、q402-i01、2026-09-24）
Date: 2026-09-24
Source: ws046-p002（q401-i01）で、make の差分試験の automake の case（`am--depfiles`、`$(MKDIR_P) $(@D)` の `@D` が `./.deps`）が guest でだけ失敗したことから。
Owner: WS046
Queue: none（ws046-p006 として計画）

## 期待と観測・影響

期待: POSIX の mkdir(2) は、既にある path（`.` を含む）に [EEXIST] を返す。`mkdir -p` は既にある directory の成分を EEXIST で読み飛ばす。

観測（guest、`plan/tools/guest/guest.py run`）:

```
mkdir -p ./a        → mkdir: ./a: Invalid argument
mkdir -p ./.b       → mkdir: ./.b: Invalid argument
mkdir -p x/./y      → mkdir: x/./y: Invalid argument
mkdir -p .          → mkdir: .: Invalid argument
mkdir ./.c、mkdir .d → 成功
```

原因: `src/kern/namei.c` の `namei_parent_path_at()` が、最後の成分が `.` と `..` のとき EINVAL を返す（「Copies the name, refusing dot and dot-dot.」）。
mkdir・unlink・rmdir・rename などがこれを使う。`mkdir -p` の `.` の成分（`./a` の最初）で mkdir(".") が EINVAL になり、`mkdir` utility は EEXIST だけを「既にある」とみなすので失敗する。

影響: automake の依存の追跡の rule（`$(MKDIR_P) ./$(DEPDIR)`）と、`./` で始まる path の `mkdir -p` を使う script が zedBSD で止まる。WS046 の実 package の build（p004）の前に直す必要がある。

## 直し方の案

mkdir(2) で最後の成分が `.` または `..` のとき EEXIST を返す（POSIX）。rmdir(2) の `.` は EINVAL（POSIX）、`..` は ENOTEMPTY か EEXIST、unlink(2) は EPERM など、syscall ごとに POSIX の値を返す。kernel（`src/kern`）の変更で HAL ではない。

## 再開の条件

ws046-p006。受け入れ案: guest で `mkdir -p ./a ./.b x/./y .` が status 0、`mkdir .` が EEXIST、`rmdir .` が EINVAL、make の差分試験の automake の case が guest でも通る。

## 解決（2026-09-24、ws046-p006）

`sys_mutation_common()` の mkdir で、`.`・`..` が最後の成分のとき path が引ければ EEXIST を返すようにした。guest で `mkdir -p ./a ./.b x/./y . ..` が通り、
make の差分試験の automake の case が guest でも 15/15。詳細は git の履歴の ws046-p006 の phase.md。
