# BUG-045: `SMP-STRESS.ELF` が起動の直後に稀に resource-baseline（status 7）で落ちる

Bug ID: `BUG-045`
Reproduction: reproduced（QEMU、amd64 guest。ws046-p012 の probe で原因を特定）
Disposition: resolved（ws046-p012。試験が snapshot の前に cache を捨て、後の snapshot を最長 5 秒再試行。6/6 通る）
Date: 2026-09-25
Source: ws046-p009（q422-i01）の最初の回帰と ws056-p001（q423-i01）の回帰で、起動の直後に走らせた `SMP-STRESS.ELF`（`userland/base/tests/smp-resource-stress.c`）が status 7。
Owner: none（未割当）
Queue: none。

## 期待と観測・影響

期待: `SMP-STRESS.ELF` は前後の kernel の資源の数（`/dev/system` の snapshot）が一致して status 0。

観測: q422 の最初の実行（/root が満杯の guest）と q423 の kernel の thread の mask の修正の後の image の最初の実行で status 7（`SMP_STRESS_FAIL:resource-baseline`）。どちらも起動の直後（sshd・cron・networkd が動き始めた頃）。
q422 の新しい guest、q423 の新しい guest での 3 回の連続実行は全て 0。q423 の落ちた実行の delta の行は取れていない（guest を止めてしまった）。
kernel の変更（thread の signal mask の継承）との関係は、3/3 通ることから薄い。

影響: 回帰の判定が稀に揺れる。製品の影響は不明（daemon の資源の一時的な増減か、漏れか）。

## 再開の条件

次に起きたら `smp.out` の `print_resource_delta` の行（どの資源がいくつずれたか）を取る。受け入れ案: 起動の直後に 10 回走らせて全て 0、または delta の原因を特定。

## 原因と修正（ws046-p012、q430）

原因: process の後始末（vmspace・file の解放）は非同期で、`waitpid` が返った直後の `KERN_SYSTEM_GET_RESOURCES` は `file +2、vmspace +1` を見ることがある（1 秒後には戻る）。stress の「後の snapshot」がそれと競走していた。page cache の retention（ws046-p012）で後始末が伸び、間欠が増えた。
修正: 試験が snapshot の前に `KERN_SYSTEM_DROP_CACHES` を呼び、後の snapshot を最長 5 秒（100 ms 刻み）で再試行する。kernel は変えない（非同期の後始末は設計）。
