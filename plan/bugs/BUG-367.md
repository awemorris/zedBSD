# BUG-367: loopback の TCP で accept 側を先に close すると、connect 側の close(2) が戻らない

- 状態: open（2026-10-30 Q1 が登録、P3 が解析と修正）
- 発見: 2026-10-30 P2（WS327 p016 の QEMU、doc の image）。SSH の出力で確かめた（console は読んでいない）。
- 再現: `plan/ws327/phase016/tcp-close-repro.c`（P2 の branch agent/p2-ws327）の引数 `0 1`・`0 0`（order nonblocking）で "close client" の後に止まる。client を先に close すれば server・listener の close は戻る。blocking・非 blocking とも。
- 影響: 08-network の例が終わりで止まる（FINISHED が来ず、窓を閉じても join が戻らず process が残る）。Mailer など、相手が先に閉じた接続の close で止まる恐れ。
- 疑い（未確かめ）: 2026-10-30 の TCP の変更（WS315 p006: 受けの buffer の自動調整と予算の返し、送りの ring 768・送りの buffer 1152 KB）の後に出たかを先に確かめる。P2 の image は main b901b1968（受けの自動調整を含み、送りの ring の変更 bc991f3ca は含まない）。
- 直す方針: 再現を QEMU で取り、close の待ちの条件（FIN の送り・linger・送りの queue の掃き出し・相手の RST の扱い）を調べて直す。例（08-network.c）の close の順は変えない（不具合を隠さない）。
