# BUG-187: WiFi の鍵を間違えて接続に失敗した時、接続できる他の AP に自動で接続してしまい、失敗の表示も出ない（消える）

Reproduction: reproduced（実機）
Disposition: resolved（2026-10-08 夜 ユーザーの決定で close、Q1 の中継）
Discovery: 2026-10-04 夜 ad-hoc UAT-3（実機 Latitude 5330、image `build/uat-3/hdd-image.img` sha256 ada4492e…、main efe846a、[uat.md の uat-3](../uat.md)）
Handling: WS005（networkd の自動の接続、ws005-p024）・WS089（Settings）・system bar・[BUG-157](BUG-157.md)（間違えた鍵の文言、ws005-p031）

## 観測

ユーザー「WiFiパスワードが間違っていて接続できなかったとき、接続可能なほかのAPに自動で接続されている。この場合はDisconnectedの状態にするべきで、自動接続しないようにしたい。また、接続に失敗した表示がでていないか、消えてしまっているので、これも修正。」

## 次

仕様（ユーザー）: (1) 利用者が選んだ AP への join が失敗した時は Disconnected の状態にし、保存済みの他の AP へ自動で接続しない（利用者の明示の操作の失敗の後は自動の再接続を止める。どの契機で自動の接続を再開するか（次の起動・login・利用者の操作）は設計で決める）。(2) 接続の失敗（鍵の誤りなど）の表示を出し、自動の動作で消さない。networkd の join の失敗の後の auto-connect の経路（ws005-p024 の起動時・login の自動の再接続）と、Settings・system bar の失敗の状態の表示（BUG-157 の理由を保つ直し）を確かめる。 修正は P3 の q700（BUG-183・185 と同じ Wi-Fi の状態の経路）。QEMU の確認は T1（RTL8822BU の USB passthrough か networkd の模擬）、実機は次の UAT。

## 決定（2026-10-05 ユーザー、クリックの回答）

止めた自動の接続の再開: **「利用者の次の操作まで」**。利用者が AP を選ぶか WiFi を off→on するまで自動ではつながない。次の起動・login では今までどおり自動の接続をする。
## 保留（2026-10-05 未明、q703-i01 P2 generation14。ユーザーの方針「既存BUGはいったん保留して、新規実装を進める」）

- **自動の接続を再開する契機（ユーザーの決定、2026-10-05、Q1 経由）**: 利用者の次の操作まで再開しない。利用者が AP を選ぶ（join）か、Wi-Fi を off→on するまで自動でつながない。次の起動・login では今までどおり自動の接続をする（logout で利用者の join が持っていた policy は root に戻り、auto-searching になる）。
- **根**: networkd の `wifi_join_failed`（ws005-p020・q631 の「失敗した join の後は探索に戻る」）が、明示の join の失敗の後に policy を `auto-searching` に戻していた。
- **途中の差分（WIP commit 済み、未試験）**: `userland/base/networkd/main.c` の `wifi_join_failed` は状態を変えず（join が残した `manual-disconnected` のまま）、予定の自動の波を消して log に書くだけにした。networkd は build warning 0。
- **残り（再開点）**: 失敗の表示を消さない。Settings は `network_message` を次の利用者の操作まで保つか確かめる（自動の状態の変化で消す経路は今は無い見込み）。system bar は `network_open_menu` が `failure` を消すので、menu を開き直すと失敗が消える → 失敗は次の利用者の操作（join・switch・disconnect）まで保つ形に直す。試験: network-probe に鍵の誤り（EACCES）を返す AP を足し、失敗の後に他の AP へ自動でつながないこと（probe の状態が manual-disconnected のまま）と表示を T1 で撮る。実機（鍵の誤り）は UAT。

## 再開（2026-10-05、P2 / q703）

- 失敗の表示を保つ: system bar は menu を開く時に失敗を消していた（`network_open_menu`）→ 消すのは利用者の次の要求（join・switch・disconnect、`network_request`）の時だけにした。鍵の誤り（EACCES の join）は「<SSID> did not accept the key」。Settings は自動の状態の変化で message を消す経路が無いことを確かめた（消えるのは利用者の操作の時だけ）。
- 試験: network-probe に REFUSE（3 番目の引数）を足した: その AP の join は EACCES で答え、Wi-Fi を manual-disconnected のままにし、他に join しない（networkd の直しと同じ振る舞いの模擬）。`settings-wifi-bugs.sh` の step 4・5（Settings の欄と理由、probe が他に join しない、bar の失敗が menu を開き直しても残る）を T1 で。
- 未実施: 実の networkd の「明示の join の失敗の後に他の AP へ自動でつながない」（前の WIP、`wifi_join_failed`）は実機の Wi-Fi が要る → UAT。
