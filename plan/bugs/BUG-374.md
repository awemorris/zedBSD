# BUG-374: RTX（nvrtx）の画面の mouse の cursor の色が他の GPU と逆（外枠が白・内側が黒）

- 状態: fixed（2026-11-01 P2 q1827-i01、f63d8e50c。実機 10.0.10.3 の head の CRC で確かめた。画面の目視は未実施）
- 発見: 2026-10-31 ユーザーが 10.0.10.3 の RTX 2070 の zedBSD の desktop で目視。外枠が白で内側が黒。他の GPU（RDNA・i915・Pi など）では逆の見込み（ユーザーの観察）。
- 疑い（未確かめ）: nvrtx の display の cursor の plane の pixel の形（ARGB と ABGR、premultiplied alpha）か、cursor の画像の色の反転。
- 直す方針（案）: 他の GPU の cursor の plane の扱いと、compositor が渡す cursor の画像の形を比べ、nvrtx の cursor の plane の format を合わせる。画面の写真で他の GPU と並べて確かめる。

## 調べ（2026-10-31 P3、q1728、未解決）

- compositor は RTX でも cursor の plane を使う（session.log `KWL CURSOR_PLANE open plane=1 width=64 height=64 images=3 format=37`、
  format 37 = VK_FORMAT_R8G8B8A8_UNORM。BGRA の staging から blit で変換）。mview などの game の間は plane を閉じ（`KWL CURSOR_PLANE closed`）、
  その間の cursor は frame に合成される。
- nvrtx が受け取る cursor の画像は正しい: 診断の kernel（`plan/ws291/tests/nvrtx-cursor-diag.patch`、cursor の slot に読んだ 64x64 の語を数える）で
  `format 2 white 69 black 49 clear 3978 other 0`。compositor の arrow（userland/desktop/wayland/shm.c `kwl_arrow_create`）は内側の白 '.' 69・縁の黒 'X' 49
  なので、白と黒は入れ替わっていない（RGBA の R と B の入れ替えは白黒に効かない）。
- display の cursor の語は NVIDIA の open-gpu-doc classes/display/clc57d.h と一致: HEAD_SET_CONTROL_CURSOR（0x209c）= 0x800001cf
  （ENABLE、A8R8G8B8、64x64、hot spot 0）、HEAD_SET_CONTROL_CURSOR_COMPOSITION（0x20a0）= 0x000072ff（K1 255、CURSOR_COLOR_FACTOR_SELECT K1、
  VIEWPORT_COLOR_FACTOR_SELECT NEG_K1_TIMES_SRC、MODE BLEND、BYPASS DISABLE）。premultiplied の白・黒の不透明の画素は、この式では反転しない。
- 残りの候補（未確かめ）: (a) ユーザーが見たのが plane を閉じた間の合成の cursor（nvrtx の executor の draw）だったか、(b) display が slot を読む時の
  何か（cursor の surface の layout・LUT）。区別には画面を見る必要がある（10.0.10.3 に画面の取り込みの道具は無く、keiland-shot は cursor の無い frame を撮る）。
  直しは未実施。

- 2026-10-31 ユーザーから、game mode では cursor を表示しない事にする、という趣旨の指示を受けた。確かめは desktop（window mode）の cursor だけでよい。同日、ユーザーが 10.0.10.3 の画面を目視できる。

  → P3 の候補 (a)（plane を閉じた間の合成の cursor）は desktop の確かめの対象外。

### host での比べ（結果: nvrtx の値は参照と一致、直す所は見つからず）

- cursor の画像: compositor の arrow（shm.c）と形（cursor.c）は全部「白の図形・黒の縁」。nvrtx は RGBA8888 を A8R8G8B8（B, G, R, A の順）に並べ替えて
  slot に書く（`nvrtx_disp_cursor_pixel`）。白 0xffffffff・黒 0xff000000・透明 0 は byte の並びの取り違え（ARGB と ABGR、alpha の位置）では白黒が入れ替わらない
  （白は全 byte が ff）。premultiplied か straight かも不透明の白黒には効かない。→ 画素の形の取り違えでは症状を説明できない。
- display の語: HEAD_SET_CONTROL_CURSOR 0x800001cf・HEAD_SET_CONTROL_CURSOR_COMPOSITION 0x000072ff・method の位置（head の 0x088 CONTEXT_DMA・0x090 OFFSET・
  0x09c CONTROL・0x0a0 COMPOSITION）は、open-gpu-doc の clc57d.h、Linux v6.19 nouveau の headc37d_curs_set（K1 0xff、CURSOR_COLOR_FACTOR_SELECT K1、
  VIEWPORT_COLOR_FACTOR_SELECT NEG_K1_TIMES_SRC、MODE BLEND）、NVIDIA open-gpu-kernel-modules 570.144 nvkms-evo3.c の EvoSetCursorImageC3 の
  PREMULT_ALPHA と同じ。差は nvkms が HEAD_SET_PRESENT_CONTROL_CURSOR（MONO、既定値）と右目の CONTEXT_DMA・OFFSET（stereo でだけ使う）も書く事だけ。
  clc57d.h の他の cursor の method（CURSOR_COLOR_NORM_SCALE・XOR_BLEND_FACTOR）は nvkms・nouveau とも書かない。
- 残る候補（画面でしか分けられない）: display が別の memory（別の slot・古い画像）を読む、display の内部で色が演算される、ユーザーが見たのが plane でない経路。

## q1827-i01（2026-11-01 08:25〜09:10 P2、worktree p2-bug374、基点 main 143245b82）: 原因と直し、CRC で確かめ

- 承認: 2026-11-01 ユーザーから、まず open の Bug を全部直す、Bug の担当は VF2 と RTX に 1 人ずつ、という趣旨の指示を受けた（Q1 経由）。P2 は RTX の担当。

### 画面を見ずに分ける方法: head の CRC

- display の head は frame ごとに合成の段（compositor）・raster generator（RG）・出力（SOR）の CRC を notifier に書く（open-gpu-doc clc57d.h の
  HEAD_SET_CONTEXT_DMA_CRC 0x2180・HEAD_SET_CRC_CONTROL 0x2184、notifier の形は Linux nouveau dispnv50/crcc37d.h）。診断の kernel
  （`plan/ws291/tests/nvrtx-cursor-crc-diag.patch`、直しの上に当てる）は、cursor の最初の表示（中身のある画像）の後に一度だけ、node の lock の中で
  自前の pitch の frame（1920x1080）に切り替え、128x128 の一色の領域の上に cursor の plane を出して CRC を取り、比べる参照として
  cursor を隠して frame に同じ色の 64x64 の四角（と arrow の絵）を描いた時の CRC を取る。終わりに cursor と元の frame を戻す。
- 3 つの候補の分け方: 「plane が正しい色を出すか」を CRC の一致で直接見る。slot の VRAM は PRAMIN で読み返し、armed の register を読む。

### 結果（実機 10.0.10.3、RTX 2070 TU106、NVMe の zedBSD に診断の kernel を入れて、各回 Debian に戻した）

- 1 回目（08:40〜08:44、kernel 2247645020）・2 回目（08:48〜08:52、4284893946、直し無し）:
  - slot の VRAM は CPU の写しと一致（PRAMIN で読み返し、white 69 black 49 clear 3978、差 0）→「別の memory・古い画像を読む」は否定。
  - armed: CONTROL_CURSOR 800001cf、COMPOSITION 000072ff、PRESENT_CONTROL_CURSOR 0（MONO）、CURSOR_COLOR_NORM_SCALE（0x2228）**00001000**
    （nvrtx も nvkms・nouveau も書かない、RM の既定）、OLUT 00040509・ffffffff・f0000001。
  - 灰（0x80）の背景で: 白の cursor の RG・SOR の CRC = 黒の四角を描いた参照（e502357c / 319d3b6c）。赤・青（各 channel 0 か 255）も同じ黒。
    254（0xfefefe）の cursor = 白（255）の四角の参照。灰 0x80 の cursor はどの参照とも違う（窓の灰より明るい）。1（0x010101）だけ一致。
    本物の arrow の cursor = arrow の不透明の画素を全部黒にした絵（e82a2fec / 6d80ebd7）。白と黒を入れ替えた絵（c4788fab）とは違う。白の背景でも同じ。
  - NORM_SCALE を変えて（灰の背景、白・黒・灰）: 0x0ff0 で白・灰・黒の cursor の CRC が参照と合成の段から完全に一致。0x0800 で白 = 灰の参照（線形）。
    0x1000・0x0fff・0x2000・0x3c00 では白が黒のまま。
  - 原因: window の 8-bit の channel c は identity の ILUT（DIRECT10、entry i が i/1024、c の 4 倍で引く）で c/256 として合成に入るが、cursor は
    NORM_SCALE 0x1000 で c/255 になり、255 が OLUT の上端に届いて黒で出る。つまり「display の内部で色が演算される」が正しく、反転ではなく
    白（と 255 の channel）が黒に潰れていた。黒の縁は黒のまま（測った限り arrow は全部黒）。ユーザーの「外枠が白」は CRC では再現しない（目視で要確認）。
  - 2 回目の終わりの OLUT を外す試み（CONTEXT_DMA_OLUT 0）は core の update が 17 で失敗し、その起動の表示は戻らなかった（Debian に戻して終了。直しには使わない）。
- 直し（f63d8e50c、main に 09686e872 で merge 済み）: `src/drivers/gpu/nvrtx/display/disp-records.c` の nvrtx_disp_core_cursor_set が
  HEAD_SET_CURSOR_COLOR_NORM_SCALE に 0x0ff0（255/256）を書く（cursor を出す度、control と composition の後）。`nvrtx-disp.h` に method 0x228、
  `scanout.c` の語数の comment。同じ method は clc67d.h・clc77d.h にも同じ位置にある。host 試験 `plan/tools/nvrtx/nvrtx-gsp-host-test.c` の期待値を追従（a1bd9f0de）。
- 3 回目（08:57〜09:01、直し＋診断 kernel 3382545569）: armed の NORM_SCALE が 00000ff0（driver が書いた値）。灰と白の背景の両方で、cursor の
  白・黒・灰・赤・青・254・0xc0・0x40・0x01・本物の arrow の 10 種が、同じ色を frame に描いた参照と RG・SOR の CRC で全部一致（0x01 以外は合成の段の CRC も一致）。
  各 CRC は 6 frame の中の 4 つが同じ値（安定）。終わりに cursor と frame を戻した（cc end 0）。
- 4 回目（09:02〜09:07、直しだけの kernel 78357675、診断無し）: 起動し、compositor が cursor の plane を開いた（`KWL CURSOR_PLANE open plane=1 ... format=37`、
  dmesg `gpu-device ok: cursor plane 64x64 at 1e9360000`）。
- 各回の戻し: rtx-cursor-view.sh back で 10 file と NVMe の vmunix 1463007375 を cksum で照合して一致、Debian 6.12.111、RTX の 4 function は vfio-pci。
- コマンド: `sh plan/ws291/tests/rtx-cursor-view.sh build BUILD`（kernel warning 0、userland は OpenSSL の外部の warning と perl の locale だけ）、
  `RESTORE_CKSUM=1463007375 sh plan/ws291/tests/rtx-cursor-view.sh up OUT BUILD` → `aat-input move-to`（cursor の画像を出させる）→ dmesg の `nvrtx: cc` の行 →
  `sh plan/ws291/tests/rtx-cursor-view.sh back OUT BUILD`。`sh plan/tools/nvrtx/nvrtx-gsp-host-test.sh` → `PASS nvrtx gsp: 393 checks, SKIPPED 0`。
- 未実施: 画面の目視（cursor の内側が白・縁が黒に見えるか）。他の GPU の cursor は変えていない（nvrtx の core の method だけ）。

### ユーザーが拾える試験（目視、急がない）

- 入れ方: main（09686e872 以降）の tree の top で、10.0.10.3 の lock（`flock -n /tmp/zedbsd-rdna.lock`）の中で
  `sh plan/ws291/tests/rtx-cursor-view.sh build build/b374/u` → `RESTORE_CKSUM=1463007375 sh plan/ws291/tests/rtx-cursor-view.sh up OUT build/b374/u`。
- 見る所: desktop（window mode）の矢印の内側と外枠の色。
- 答えの読み方: 内側 白・外枠 黒 = 直った（他の GPU と同じ）／ 内側 黒 = 直っていない（NORM_SCALE が効いていない）／ 外枠 白 = CRC では出なかった別の経路
  （その時は plane を閉じた合成の cursor を疑う）。
- 戻し方: `sh plan/ws291/tests/rtx-cursor-view.sh back OUT build/b374/u`（file と kernel を戻して cksum を照合、Debian へ）。
