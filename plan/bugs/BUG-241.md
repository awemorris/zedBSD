## script の特定と案（2026-10-08 P2、q870）

- **□ の行は Arabic**（`<p lang=ar dir=rtl>`）。example.com の頁は `/s.js` が英語の段落の後に ar・zh・fr・ru・es の段落を足す（2026-10-08 に host から取得して確認）。T1-219 の 03-https.png で □ なのは 2 段目の ar だけで、zh・fr・ru・es は描けている。
- 載せている font の覆う範囲（fontTools で cmap を数えた）:

  | script | Mahora（keiland.ttf） | DroidSansFallbackFull（keiland-fallback.ttf） | JetBrainsMono（keiland-fallback-mono.ttf） |
  | --- | --- | --- | --- |
  | Latin-1・Greek・Cyrillic | 0（ASCII の 95 字だけ） | 0 | ほぼ全部 |
  | かな・CJK | 0 | ほぼ全部 | 0 |
  | **Arabic・Hebrew・Devanagari・Thai** | 0 | 0 | 0 |
  | **Hangul** | 0 | 1/64 | 0 |

  Arabic のほかに、Hebrew・Devanagari・Thai・韓国語（Hangul）も □ になる見込み（未確認）。
- 直すには font だけでは足りない。
  - Arabic は字の形が前後で変わる（joining）。右から左の並べ替え（bidi）も要る。
  - libbrowser・libtruetype には GSUB の shaping も bidi の並べ替えも無い。CSS の direction は block の配置だけ。
  - font だけを足すと、Arabic は「離れた形の字が左から右へ並ぶ」読めない表示になる（□ より誤解を招く恐れ）。
- **案（WS074 の新しい Phase として、Q1 の判断）**:
  - 段 1（shaping 不要）: Hebrew・Thai・Hangul の font（例 Noto Sans Hebrew・Thai・KR、OFL）を fallback の連鎖に足す。Hebrew は bidi（UAX #9 の簡約）で右から左に並べる。
  - 段 2: Arabic の font（Noto Sans Arabic、OFL）と joining。Unicode の presentation forms に写すか、GSUB の init・medi・fina・isol を読む。並べは段 1 の bidi で。
  - 段 3: Devanagari などの Indic は字の並べ替えと結合が要るので、shaper（GSUB・GPOS）が要る。
  - 判断が要る点: font の file を tree に足すか（DroidSansFallback・JetBrains・Mahora は tree にある前例。大きさは Noto Sans KR が数 MB）、と段の順。
- この Queue（q870）では code を変えていない（Phase の大きさの機能で、ベータ2 の後の Bug の扱い。2026-10-06 ユーザーの順）。
