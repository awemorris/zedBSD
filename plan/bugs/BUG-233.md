# BUG-233: Files で動画の file を開くと動画の player でなく Terminal が開くように見える

Reproduction: reproduced（ユーザー、実機 5330、2026-10-06 UAT）
Disposition: tracking
Discovery: 2026-10-06 ユーザーの UAT のコメント
Handling: WS127（Files の関連付け）・WS122

## 観測（ユーザー）

「動画のファイルのアイコンをFilesで選択したとき、動画プレーヤで素直に開けず、ターミナルが開く気がします。」

## 次（未確認の見込み）

Files の MIME の判定と関連付け（mp4 など video/* → videoplayer）。既定の open の規則で Terminal に落ちていないか。

## q782-i01（P1、2026-10-06）: 原因と直し

Status: test-wait（T1 依頼中）

原因: Files の `fm_apps_for`（`userland/desktop/files/apps.c`）は、mode に x の bit がある regular file には型に関わらず「Run in Terminal」
（`@terminal %f`）を 1 番目（既定）に置いていた。FAT の file system（USB stick など）は file の mode を 0755 で見せる（`src/drivers/fs/fat.c`、
metadata の無い file の既定）ので、stick の上の mp4 は Video Player でなく Terminal で「実行」された。Video Player の関連付け（`video/*` →
`/bin/videoplayer`、beta1 の image に入っている）は正しい。

直し（baec07a1）: 「Run in Terminal」は、x の bit があり、かつ型が program（`application/x-executable`）か script（`application/x-shellscript`）の
file にだけ出す（`apps_is_program`）。拡張子で型の決まる file（video・image・pdf など）は x の bit があっても型の app で開く。

確認: `sh plan/tools/files/host-model.sh` → files-model: PASS（新しい項目「a video with x bits does not run (BUG-233)」）。Files の zedBSD の build
warning 0、Linux の host build exit 0。QEMU（Files の image で x の bit の付いた mp4 を開く）は T1 に依頼。実機は次の UAT（FAT の stick の動画）。

## 2026-10-08 P2 の確認（q869）

- 実装済み（baec07a1 → main b1bab988）: files/apps.c の `apps_is_program`。Run in Terminal は program・script の型の file だけ。
