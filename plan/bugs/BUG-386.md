# BUG-386: VF2 の 2 つ目の Ethernet の口（en1）に LAN をつなぐと link が上がらない（認識されない）

- 状態: fixed（2026-11-01 08:38 P1 q1825-i01、c490f0466。VF2 で en1 が attach され en0 の SSH が通るのを確かめた。en1 の link up は線の挿し替えが要り未実施）← open（2026-11-01 06:31 Q1 が起票、ユーザーの実機の確かめ）
- 発見: 2026-11-01 06:31 ユーザー。VF2 の LAN の線が 2 つ目の口（en1）に挿さっていて、起動しても network に出なかった。1 つ目の口（en0）に挿し替えたら認識された。
  同じ日の P4 の serial の記録（q1817）では、en0 は dw-eqos で準備できて「RX/TX enabled」だったが link は上がらず（線が en1 側だったため）、en1 の行は未確かめ。
- 影響: VisionFive 2 の 2 つの GbE の口のうち、片方しか使えない。線を挿す口を間違えると network に出ない。
- 次: en1（2 つ目の GMAC と PHY）が attach されているか、PHY の reset・clock・RGMII の遅延の設定、DTB の node、networkd の扱いを調べる。

## serial に見えた事（2026-11-01 06:12 の起動、P4 q1817-i01、調べてはいない）

- 手がかりの serial（build/tmp/q1817/vf2-cycle1/serial.txt、P4 の worktree）: U-Boot は 2 つの口を見る（`Ethernet MAC0 address: 6c:cf:39:00:4a:8a`・`MAC1 address: 6c:cf:39:00:4a:8b`、`Net: eth0: ethernet@16030000, eth1: ethernet@16040000`）。
- kernel の行は 1 つ目だけ: `vf2-ethernet: bus clock 198000000 Hz`、`dw-eqos: en0 version 4152 irq 7`、`dw-eqos: en0 PHY 0 id 4f51e91b (YT8531)`、`yt8531: rx delay step 10, tx delay step 10, …`、
  `dw-eqos: en0 ready, MAC 6c:cf:39:00:4a:8a`、`visionfive2: Ethernet is en0`、`dw-eqos: en0 RX/TX enabled`。en1・2 つ目の GMAC（16040000）・2 つ目の PHY の行は無く、240 s の間 `link up` も無かった。
- 線を en0 に挿した 06:26 の起動では `dw-eqos: en0 link up 1000 Mbps full duplex` が出て SSH が通った。

## 原因と直し（2026-11-01 P1、q1825-i01）

- 原因: kernel が 2 つ目の口を作りとして扱っていなかった。`src/drivers/platform/visionfive2/vf2-ethernet.c` の find_port は register が 0x16030000（GMAC0）の node だけを選び、
  GMAC1（0x16040000）は飛ばしていた（comment「the second is not driven」）。`visionfive2.c` の attach_ethernet も 1 口だけ。さらに SYS の clock の生成器（`vf2-crg.c`）の
  表に GMAC1 の clock（JH7110_SYSCLK_GMAC1_* 97〜107）が無く、node の clock を lookup・enable できなかった。PHY・RGMII の遅延・networkd の側に原因は無かった。
- DTB の node（板の ESP の `jh7110-starfive-visionfive-2-v1.3b.dtb`、mainline v6.12 から、dtc で読んだ）: gmac1 は `status = "okay"`、`phy-mode = "rgmii-id"`、
  `starfive,tx-use-rgmii-clk`、`assigned-clocks = <syscrg 105>`・`assigned-clock-parents = <syscrg 101>`（gmac1_tx を gmac1_rmii_rtx へ）、clock は syscrg の 98・97・102・106・107、
  reset は syscrg の 66・67、`starfive,syscon = <&sys_syscon 0x90 0x2>`、PHY は gmac1 自身の MDIO の address 0（`rx-internal-delay-ps = 300`・`tx-internal-delay-ps = 0`）。
  dw-eqos は 2 台まで（EQOS_MAX_DEVICES 2）、yt8531 の設定は口ごと、networkd は複数の wired の口を扱う作りで、変えなかった。
- 直し:
  - `src/drivers/platform/visionfive2/vf2-crg.c`: SYS の表に gmac1_ahb（97）・gmac1_axi（98）・gmac1_gtxclk（100、速さに合わせて driver が分周を設定できる）・
    gmac1_rmii_rtx（101、入力 gmac1_rmii_refin）・gmac1_ptp（102）・gmac1_tx（105、100 と 101 の selector）・gmac1_tx_inv（106）・gmac1_gtxc（107）を足した
    （StarFive の Linux 6.12 の clk-starfive-jh7110-sys.c の定義に合わせた）。
  - `src/drivers/platform/visionfive2/vf2-ethernet.c`・`.h`: 口の表（0x16030000 → en0・TX の源 108、0x16040000 → en1・TX の源 100）にし、
    `drv_vf2_ethernet_attach(fdt, port, coherent)` で口ごとに attach。TX の源の文脈も口ごと。`DRV_VF2_ETHERNET_PORTS`（2）。
  - `src/kern/platform/visionfive2.c`: 2 口を順に attach。片方が失敗しても他方は続け、`visionfive2: Ethernet is en0`・`… en1` か `no Ethernet enN (errno)` を出す。
- 確かめ:
  - build: `make ZEDBSD_CONFIG=config/ci/config-visionfive2.mk BUILD=build/q1825 build/q1825/vmunix` rc 0、warning 0（-Werror）、`git diff --check` 空。
  - VF2 の実機（`VF2_HOST=kei@10.0.30.2 VF2_PLUG=AC276E432AE6 ORIG=vmunix.q1825orig LOAD='ifconfig -a' sh plan/tools/vf2/boot-cycle.sh build/q1825/vmunix build/tmp/q1825/en1-a 2`、
    kernel cksum 2305985498、2026-11-01 08:33〜08:35、線は en0）: 2 起動とも SSH が 36 s・31 s で戻った（en0）。dmesg（両起動とも同じ）:
    `dw-eqos: en1 version 4152 irq 78`・`dw-eqos: en1 PHY 0 id 4f51e91b (YT8531)`・`yt8531: rx delay step 2, tx delay step 0, drive clock 6 data 3`・
    `dw-eqos: en1 ready, MAC 6c:cf:39:00:4a:8b, DMA 40 bit, coherent`・`visionfive2: Ethernet is en1`・`dw-eqos: en1 RX/TX enabled`。en0 の行は前と同じで
    `dw-eqos: en0 link up 1000 Mbps full duplex`。`ifconfig -a`: en1 は `flags=UP,BROADCAST,MULTICAST`（networkd が上げた、RUNNING 無し＝線が無い）、`ether 6c:cf:39:00:4a:8b`。
    終わりに板の元の kernel（cksum 3758577736）を戻し、読み戻しで照合して起動（SSH 35 s）。
- 未実施: en1 に線を挿した時の link up・DHCP・SSH（板の LAN の線は en0 の口にあり、挿し替えはユーザーの手が要る）。
- ユーザーが拾える試験（en1 の link）: 直した kernel の板で LAN の線を en1 の口（2 つ目）に挿し替え、電源を入れ直す（または起動したまま挿す）。
  serial か画面で `dw-eqos: en1 link up 1000 Mbps full duplex` が出て、DHCP で address を得て SSH が通れば良い。en0 に戻すのを忘れない。
