# BUG-386: VF2 の 2 つ目の Ethernet の口（en1）に LAN をつなぐと link が上がらない（認識されない）

- 状態: open（2026-11-01 06:31 Q1 が起票、ユーザーの実機の確かめ）
- 発見: 2026-11-01 06:31 ユーザー。VF2 の LAN の線が 2 つ目の口（en1）に挿さっていて、起動しても network に出なかった。1 つ目の口（en0）に挿し替えたら認識された。
  同じ日の P4 の serial の記録（q1817）では、en0 は dw-eqos で準備できて「RX/TX enabled」だったが link は上がらず（線が en1 側だったため）、en1 の行は未確かめ。
- 影響: VisionFive 2 の 2 つの GbE の口のうち、片方しか使えない。線を挿す口を間違えると network に出ない。
- 次: en1（2 つ目の GMAC と PHY）が attach されているか、PHY の reset・clock・RGMII の遅延の設定、DTB の node、networkd の扱いを調べる。

## serial に見えた事（2026-11-01 06:12 の起動、P4 q1817-i01、調べてはいない）

- 手がかりの serial（build/tmp/q1817/vf2-cycle1/serial.txt、P4 の worktree）: U-Boot は 2 つの口を見る（`Ethernet MAC0 address: 6c:cf:39:00:4a:8a`・`MAC1 address: 6c:cf:39:00:4a:8b`、`Net: eth0: ethernet@16030000, eth1: ethernet@16040000`）。
- kernel の行は 1 つ目だけ: `vf2-ethernet: bus clock 198000000 Hz`、`dw-eqos: en0 version 4152 irq 7`、`dw-eqos: en0 PHY 0 id 4f51e91b (YT8531)`、`yt8531: rx delay step 10, tx delay step 10, …`、
  `dw-eqos: en0 ready, MAC 6c:cf:39:00:4a:8a`、`visionfive2: Ethernet is en0`、`dw-eqos: en0 RX/TX enabled`。en1・2 つ目の GMAC（16040000）・2 つ目の PHY の行は無く、240 s の間 `link up` も無かった。
- 線を en0 に挿した 06:26 の起動では `dw-eqos: en0 link up 1000 Mbps full duplex` が出て SSH が通った。
