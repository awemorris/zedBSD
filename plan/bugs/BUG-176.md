## 観測

A3 の後の再起動: WiFi は自動で接続したが、それまでの約 10 秒、network の service が使えない旨の表示が出た。networkd の起動の前に system bar が問い合わせ、失敗を利用者に見せている疑い。

次: system bar が networkd に接続できない時は「接続中」などの穏やかな表示にし、再試行する。

## 調べと直し（2026-10-05 q726、P2）

- 文言は system bar の network の menu の「Network service not available」（`wayland/network.c` の `network_state_text`）。backend（`libkeiland-backend-zedbsd/network-zedbsd.c`）は networkd に繋いで SUBSCRIBE を送り、最初の state が届くまで `reachable` が 0 のまま。UAT の ps では networkd は pid 6 で session（pid 16）より先に起きているので、socket が無いのではなく、起動の直後の networkd が自動の Wi-Fi の接続（`run_due_work`）の間に SUBSCRIBE に答えていない見込み（実機の log が無く未確定）。
- 直し（ticket の「次」の通り、表示を穏やかに）: desktop の開始から 30 秒（`NETWORK_START_GRACE_MS`）の間、daemon から一度も reachable の state を聞いていなければ「Starting the network service...」と出す。30 秒を過ぎても聞けなければ従来の「Network service not available」（menu を描き直す）。一度聞いた後に届かなくなった時は直ちに従来の文言。
- Settings の「The network service is not running」（Settings を起動の直後に開いた時）は変えていない。networkd が起動の直後に SUBSCRIBE へ答えるのを速くする直しは networkd の範囲（未着手）。
- 確認: build（warning 0: zedBSD の wayland、Linux の Keiland）。
- 未実施: QEMU（QEMU に Wi-Fi が無く、起動の直後の窓は再現しにくい）、実機（UAT）。
