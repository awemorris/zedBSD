# BUG-156: タッチパッドでスクロールできない

Reproduction: reproduced（S1（2026-10-03、Latitude 5330、素の USB 起動、ユーザー、[結果](../ws133/s1-results.md)））
Disposition: resolved（2026-10-08 夜 ユーザーの実機の確認「Touchpadは動作確認できたので、下記をすべてclose します。BUG-156 (scrolling), 166 (title-bar drag), 167 (physical click), 178, 190 (touch-down as a press), 211 (inertial scroll), 215, 216 (Wiseview gestures), 228, 247, 254, and the touchpad part of 218」）
Discovery: 安定版 S1 の実機試験（[WS133](../ws133/ws.md)）

pointer と click は動く。2 本指のスクロール（または edge のスクロール）を HID か evdev か compositor のどこかで落としている見込み。5330 のタッチパッドは QEMU に無いので、実装は合成の event の host 試験で確かめ、最後に実機。

## 読みでの原因の候補（2026-10-03、q638、P1。実装していない）

1. **（第一候補）PS/2 の mouse driver が wheel を扱わない。** zedBSD に I2C HID の driver は無く、5330 の touchpad は firmware の PS/2 互換で
   `src/drivers/platform/pcat/ps2-8042.c` を通っている見込み（pointer・click が動くのはこの経路）。この driver は `PS2_SET_DEFAULTS`・
   `PS2_ENABLE_STREAM` だけで 3 byte の標準 packet を読み、IntelliMouse の切替（sample rate 200・100・80 → ID 3、4 byte の packet の Z）を
   していないので `REL_WHEEL` を出さない（capability の表も REL_X・REL_Y だけ）。PS/2 互換の touchpad の 2 本指・端の scroll は IMPS/2 の
   wheel として届くのが普通。compositor（`userland/desktop/wayland/input.c` の `apply_frame`）は REL_WHEEL を axis にするので、kernel 側だけで足りる見込み。
   直し方の案: knock（F3 200, F3 100, F3 80）→ F2 で ID を読み、3（と IMEx の 4）なら 4 byte の packet にし、Z の符号を反転して REL_WHEEL（IMEx なら
   REL_HWHEEL と BTN_SIDE/EXTRA も）を出す。ID が 0 のままなら今と同じ。QEMU の PS/2 mouse は IMPS/2 を持つので、usb-tablet を外した guest で
   QMP の wheel を送れば試せる。
2. 5330 の touchpad が PS/2 互換では scroll を出さない場合（I2C HID だけ）。その時は Intel LPSS の I2C と ACPI の PNP0C50 の HID-over-I2C の
   driver が要り、規模が大きい（新しい WS）。
3. compositor の側は可能性が低い（REL_WHEEL を受けた所から先は USB の mouse の wheel と同じ経路で、M650 の wheel は S1 で問題の報告が無い）。

実機で見ること（S2）: boot の kernel log の PS/2 の mouse の行（aux port の有無）、IntelliMouse の knock の後の ID（1 を直したら log に出す）。

## 対応（2026-10-03、q640、P1）

handling: [ws081-p019](../ws081/phase019/phase.md)。第一候補（PS/2 の driver が IntelliMouse の切替をせず REL_WHEEL を出さない）を直した。
ID 3・4 の識別と 4 byte の packet、REL_WHEEL・REL_HWHEEL・BTN_SIDE・BTN_EXTRA、動きの 9 bit の符号。kernel の build は warning 0、
host-ps2-wheel PASS、QEMU の `ps2-wheel-qemu.sh` を T1 に依頼（結果待ち）。5330 の touchpad が PS/2 互換で wheel を送るかは実機で確かめる（未実施）。

## 2026-10-04 UAT（実機、[UAT 2026-10-04](../uat.md)、証拠 [uat-2026-10-04](../uat/2026-10-04/)）

**再現（実機）**: タッチパッドの 2 本指のスクロール（B2、Browser）とスワイプ（G6、System Monitor）が効かない。タップは効く。原因の候補: [BUG-165](BUG-165.md)（DSDT が読めず I2C HID の device を正しく扱えない）。

## 2026-10-04 夜 ad-hoc UAT-3（実機、uat-3 の image、main efe846a）

ユーザー「タッチパッドでのスクロール（2本指）は、少なくともSettingsでは効かなかった。」→ reopen。この image には BUG-165 の DSDT の修正（WS049 p008）が入っているので、「DSDT が読めず I2C HID が見えない」だけが原因ではない（zedBSD に I2C HID の driver が無く、5330 の touchpad は PS/2 互換で動いている見込みのまま）。次: 実機で SSH から dmesg と evdev（どの device が出ているか、REL_WHEEL・REL_HWHEEL・ABS_MT が出るか）を取り、PS/2 の IntelliMouse・Synaptics/Elantech の拡張の切替（ws081-p019）が 5330 で効いているか、compositor が wheel を Settings に渡しているかを分ける。他の app（Files・Text Editor）で scroll するかも確かめる。担当は P3 の Bug の順（q700 の窓の操作の後、BUG-166・167 の q689 と同じ入力の経路）。

2026-10-05: native のタッチパッドの WS [WS159](../ws159/ws.md) で扱う（P1 の調べ: 5330 のタッチパッドは PS/2 の互換の 3 byte の mouse、I2C-HID の driver が無い。ユーザー「2本指スクロールは取れないですね。ACPI AMLを実装したあと、I2C-HIDを実装しましょう。」）。
