# BUG-391: compositor が落ちると login の画面から出直し、keyboard の無い tablet では login できない

- 状態: fixed（2026-11-02 P8、下の「修正」。起票は 2026-11-02 01:27 Q1）
- 発見: 2026-11-02 ユーザーの Pi 5 の UAT。compositor が落ちた時に login の画面から再スタートする。tablet では keyboard の入力ができないので login できない。
- 期待（ユーザー）: いきなり desktop の表示から再開してほしい。
- Q1 の判断: 落ちた時に session の画面が lock されていなかったら、認証なしで同じ利用者の desktop から再開する。lock されていたら、lock の画面（BUG-392 の PIN の入力）から再開する（lock を飛ばさない）。sessiond が「同じ seat・同じ利用者の session の出直し」と「新しい login」を見分ける。
- 扱い: P8（q1890）。QEMU で compositor を落として確かめる。

## 修正（2026-11-02 P8、q1890-i01、branch agent/p8-bug391）

- 状態: fixed（QEMU の amd64 Venus の guest で確認。Pi 5 の実機は未実施）。
- 直し方:
  - sessiond（`userland/desktop/sessiond/`）: session の終わりを crash と見分ける（`sessiond_session_crashed`: signal か 0 でない終了で、Log Out でなく、sessiond の停止・電源の終わりでもない。起動の時間内に表示を取らずに sessiond が止めた session は crash に数えない）。crash なら login の画面を出さずに同じ利用者の session を出し直す（main.c の `main_session`）。新しい login（greeter の AUTH・起動時の自動 login）はこの出し直しと別の物で、crash の数は新しい login ごとに 0 から。
  - lock: compositor が lock の画面を出す・消す時に sessiond へ `LOCKED`・`UNLOCKED` を言う（libkeiland-backend の `kl_backend_session_lock_state`、答え無し）。sessiond は最後の状態を覚え、lock 中に落ちた session は `--locked` で出し直す。compositor の `--locked` は最初の frame から lock の画面（理由 `restart`、利用者が選んだ lock と同じ扱いで swipe の猶予が無い）。出し直した session の状態は sessiond が始めた値から始まる（compositor が言う前に落ちても lock を飛ばさない）。
  - 何度も落ちる時: 2 分（`SESSIOND_RESTART_WINDOW_MS`）の中で 3 回目の crash は出し直さず login の画面へ（`sessiond_restart_due`、fallback-rules.c）。出し直しの前に 1 秒待つ。
- 確かめ:
  - host: `sh plan/tools/sessiond/restart-rules-host-test.sh` → `restart-rules-host-test: PASS`（crash の判定と 3 回目の拒否、窓の外の数え直し）。`sh plan/tools/compositor/run-host-role.sh` → `host-role: PASS`（`--locked` の 3 件を足した）。
  - QEMU（build/p8 の graphical の image、`plan/tools/sessiond/restart-guest.sh build/review/p8-bug391` → `restart-guest: PASS`）: (a) 起動の自動 login の desktop で compositor を kill -9 → `SESSIOND SESSION restart user=user locked=0 crashes=1`、login の画面なしで desktop（`build/review/p8-bug391/desktop-restart.png`）、新しい session に lock 無し。(b) Super+L で lock（`SESSIOND SESSION locked`）して kill → `restart ... locked=1`、lock の画面から（`lock-restart.png`）、swipe で開かない（`grace=0`）、PIN 0000 で unlock（`lock-pin.png`・`unlocked.png`）。(c) 続けて kill → 2 分の中の 3 回目で `SESSIOND SESSION restart refused user=user crashes=3`、login の画面（`greeter-pin.png`）。新しい login の後の crash は `crashes=1` から出し直す（手で 1 回）。判定は guest の file（/var/log/sessiond.log・/run/user/1000/session.log・/var/log/greeter.log）を SSH で読み、console・serial の log は見ていない。
- 未実施: Pi 5 の実機（UAT）。GPU の driver が crash の後に 1 秒で使えるかは実機で見る（QEMU の Venus では問題なし）。
