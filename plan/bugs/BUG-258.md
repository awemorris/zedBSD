# BUG-258: 5330 の素の起動で USB メモリが disk にならない（USB-A でも USB-C TC2 でも）

- 状態: reproduced（5330 bare metal、2026-10-08 ユーザーの UAT） / tracking（解析中）
- 発見: 2026-10-08 ユーザーの UAT「USBメモリは認識しないですね。通知はないですしFilesでも見えないです。」「USB-AもUSB-C TC2も試しましたがだめでした。」
- 環境: Latitude 5330、zedBSD 1.0.0-beta2+g2fe4a50（2026-10-07）を USB から単独起動。
- 証拠: [dmesg-5330-20261008.txt](BUG-258/dmesg-5330-20261008.txt)（i915 の perf・vk・resident shim の行を除いた dmesg）。時刻の無い dmesg なので、どの行がどの挿し込みかは推定。
  - USB-C TC2（usb0 port 3、普段は Realtek LAN 0bda:8156 の port）: `05e3:0748` が `usb-storage: only LUN 0 of 4 is supported` → `LUN 0 has no medium; reader attached without a disk`。media が LUN 0 に無い（LUN 1〜3 にある）か、LUN 0 が最初の TEST UNIT READY で NOT READY を返すだけ（時間を置くと ready）か、のどちらか（未確認）。
  - USB-A（推定 usb1 port 2）: `usb1: port 2 enumeration failed (13)`（ENODEV）を挿す度に。
  - 以前は Kioxia `30de:6544` が usb1 port 16 で `sdb` として publish された（その後抜けた）ので、usb-storage 自体は動く。
- 未確認: ユーザーの USB メモリの型番（05e3:0748 が当の物か）、USB-A の port 2 に何が挿さったか。

## 解析（2026-10-08、bug-analyzer のやり直し。Q1 が要点を確認）

前回の仮説の訂正: `usb1: port 1/2 enumeration failed (13)` は USB-A ではなく Type-C TC1/TC2 の USB2 側の companion port（SS で link が張れると USB2 の終端が外れて ENODEV）で、無害の雑音。`LUN 0 has no medium` は LUN 0 が本当に MEDIUM NOT PRESENT（02/3A）を返した時だけ出る。USB-A に挿した物は Kioxia 30de:6544（usb1 port 16、`sdb` を publish → その後 disconnected）。

- **候補 A（USB-A、最有力）**: usb-storage（BOT）の hot-plug では partition table を一度も読まない。`partitions_pending=1` が立つのは再 probe の経路（usb-storage.c:1796）だけで、attach（`storage_attach` :1904〜、publish :1977 付近）では 0 のまま。UAS は attach で立てる（usb-uas-disk.c:440）。kernel に disk の ADD で scan する物は無く、volumed は BLKREREADPART を呼ばず、MBR の whole disk は FS の type が無いので volume にならない → 通知も Files も出ない。dmesg でも boot 時の sda には `vfs: scan`・partition の行があるが sdb には無い。QEMU の受け入れ（ws132 p004）は partition 無しの superfloppy だったので見逃した。Q1 が `grep partitions_pending` で 1796 だけを確認。
- **候補 B（USB-C TC2）**: 05e3:0748（Genesys の多 slot の card reader、GET_MAX_LUN=3）。driver は LUN 0 しか probe しないので、media が LUN 1〜3 にあると見えない。
- 候補 C（低い）: sdb の disconnect が抜去でなく電気的な落ち。候補 A なら「認識しないので抜いた」で説明がつく。

確かめ方（実機、code の変更なし）: Kioxia を USB-A に挿して抜かずに 30 秒 → `ls /dev/sd*`（sdb だけで sdb1 が無い）→ root で `diskpart reload /dev/sdb` → sdb1 と通知・Files が出れば A 確定。

修正の方針: A は attach の publish の成功の後に `partitions_pending = 1`（UAS と同じ。superfloppy は partition_reload の EINVAL を成功扱いなので壊れない）。B は (a) 最小: LUN 0..max を順に probe し media のある最初の LUN を使う、(b) 本来: LUN ごとに disk を持つ。

## 次
