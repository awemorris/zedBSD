# BUG-057: i915 実機で、GLX の zgears が数百 frame の後に止まることがある（間欠、原因未特定）

Bug ID: `BUG-057`
Reproduction: reproduced（5330 の i915 を QEMU へ VFIO で渡した実機の GPU、capture 表示。2026-09-26〜27 の ws068-p006 の run で多数。
同じ image で止まらない run もある: run6 は 6 検査 PASS）。Venus（QEMU）では未観測。
Disposition: tracking
Date: 2026-09-27
Source: ws068-p006（q484-i01）の実機の run（`CAPTURE=zdesktop-x11 ZDESKTOP_APP=home plan/ws031/tests/vkloop-hw.sh zdesktop`）
Owner: 未定

## 期待と観測

期待: App Home から起動した Gears（zgears、Xzed --rootless と GLX）が回り続け、capture の `gears` と 5 秒後の `gears-later` が違う絵。

観測: 2 枚が同じ絵（画面全体の hash が同じ）。検査 gears_turns が FAIL。最初の frame は正しい（`ZGEARS CHECK ... failures=0`）。

## 調べたこと（ws068-p006 の中で）

- GL の描画は正しい: zgears の readback の和が frame 1・2・50 で違う。i915 の実行器で約 27 fps。
- 最後の run（`build/ws068-p006` の最後、COMMIT の log 付き）: zgears の `ZGEARS FPS` が frames=100 の 1 行で止まり、Xzed の present の数も
  止まり、zwl に Gears の surface の `ZWL COMMIT` が compose の frame 330 から 716 まで来ない。→ **zgears が止まり、Xzed には見せる物が無い**。
  zwl と GPU の道（shm の copy、sampling）は止まりの原因でない。
- 別の run では zgears の FPS は続き、zwl の copy が止まったように見えた run もあった（そのときは COMMIT の log が無く、切り分けが粗い）。
- 否定した仮説: fork の COW（止まりの時点に fork が無い、kernel の log）、zwl の画像の memory の非一貫（止まったとき kernel から見た zwl の
  画像そのものが変わっていない）、MOCS（sampled を LLC にしても同じ頻度で止まる）。
- 歯の対称で絵が 9 frame 周期だった件は zgears の回転を時間にして除いた（止まりは残った）。

## 疑い

zgears の `glXSwapBuffers` の中（glReadPixels → EGL の flush と fence の待ち、XzedPutImageRGB24 の要求ごとの XSync）か、X の要求と
返答の道（Xzed の非 blocking の socket での大きな PutImage の部分読み、返答の書き込みの EAGAIN）。実機は CPU が遅く（zwl の compose が約 10 fps）、
部分読みの時機が Venus と違う。

## 再調査の条件

次に X11・GLX の実機の Phase（ws069-p006 など）を行うとき。zgears か libGL の glx.c に watchdog（3 秒 frame が進まなければ、今どの段か
を stderr へ）を入れ、Xzed に client ごとの要求の読みと返答の書きの EAGAIN・部分の数を出し、止まった run の段を特定する。
