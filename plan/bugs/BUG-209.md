# BUG-209: Alt+Tab の順が bar の icon の並びと合わず、人間の認知に合わない

Reproduction: reproduced（ユーザー、Windows の QEMU（Venus）で uat-0505g、2026-10-05 夜 UAT）
Disposition: resolved（2026-10-08 夜 ユーザー「下記は実装の変更が多かったので、いったんすべてcloseします。」、Q1 の中継）
Discovery: 2026-10-05 夜 ユーザーの UAT のコメント
Handling: [WS142](../ws142/ws.md)（アプリの切り替え）

## 観測と決定（ユーザー）

「Alt+Tabで画面上部バーのアプリのプレビューが出る機能ですが、Alt+Tabを押すたびにアプリのnextが辿られますよね。その順番が人間の認知と合っていないと感じました。Alt+Tabで最初に出るアプリは現在のアプリにしましょう。そして、Alt+Tabが押されるたびに、そこからアイコンの並びを1つずつ右に辿りましょう。現在はコンポジタが管理しているアプリの順番で進むので、人間の認知と合わないです。その順番はコンポジタにしかわからないので。」

## 仕様（決定）

- Alt+Tab の最初の表示で選ばれているのは**今の app**。
- Alt+Tab を押す度に、**bar の icon の並びで 1 つ右**へ（右端の次は左端に戻る見込み、Shift+Alt+Tab は 1 つ左の見込み。この 2 つは実装の時に確かめる）。
- compositor の内部の順（focus の履歴など）は使わない。

## 次

WS142 の Alt+Tab の実装（p00x）の選びの順を bar の icon の列に合わせ、試験の期待を直す。

## 仮定（2026-10-06 Q1 の指示で記録。2026-10-06 ユーザーがクリックで4つとも推奨＝今の実装のとおりに決定）

- **右端の次は左端に戻る**（wrap）。左端で Shift+Alt+Tab は右端へ。
- **Shift+Alt+Tab は 1 つ左**。Shift を押したまま Alt+Tab で開いた時も、最初に選ばれるのは今の app（Alt+Tab と同じ）。
- **3 本指のタップで開く切り替え（同じ UI）も同じ**: bar の並び、今の app から始まる（ws142 の元の要望の「現在のアプリの
  1 つ次」から変わる。Alt+Tab と同じ UI なので揃えた）。
- 今の app = 一番上の窓の app（`zwl_apps_view_collect()` の `current`）。今の app が無い（全部が最小化など）時は左端から。
- 素早い Alt+Tab（押して離す）は今の app のまま（切り替わらない）。前の app へ戻るには Alt+Tab+Tab（右隣）。
- **2026-10-06 ユーザーの追加の指示**:「Alt+Tab を素早く押して離した時、切り替えモードのままにして、離されたタイミングで切り替えを終了しないでください。」→ 素早い Alt+Tab（押して離す）では切り替えの UI を開いたまま残し、Alt を離した時に確定・終了しない。残った UI の操作（Q1 の既定、ユーザーの訂正があれば従う）: Tab・Shift+Tab・矢印で選びを動かし、Enter・click・tap で選んだ app に切り替えて閉じる、Esc・UI の外の click で今の app のまま閉じる。Alt を長く押したまま Tab で選んで離す通常の使い方は、離した時に確定（今のまま）。

## 実装（2026-10-06 P2）

- `zwl_switcher_open()`（switcher.c）は引数 `current`（bar の並びでの今の app の index）を取り、key を bar の並び
  （`apps->apps[]` の順、ユーザーが drag で変えた順も含む）で写し、今の app を選ぶ。最近の使用の順（`apps->recent`）は
  使わなくなった（apps.c には残る）。
- switcher-shell.c は `view.current` を渡す。Shift+Alt+Tab で開いた時の 1 つ戻す step をやめた（開く時は今の app）。
  Tab・→・2 本指の右は +1、Shift+Tab・←・左は -1、端で回る（従来どおり）。
- 試験: host の [host-switcher.c](../ws142/tests/host-switcher.c)（bar の並び、今の app の選択、範囲外・無しは左端、
  drag の後の並び、wrap、25 checks ok）。QEMU の [p005-guest.sh](../ws142/tests/p005-guest.sh) の期待を新しい仕様に
  直した（open index=2 apps.c → Tab で apps.a へ回る → Tab apps.b → Shift+Tab apps.a、素早い Alt+Tab は今の app、
  Shift+Alt+Tab は今の app で開く）。QEMU は T1 に依頼（未実施）。
- build: zedBSD（config-amd64-zdesktop.mk）と Linux の keiland、warning 0。host: run-host-switcher・apps・gesture・super-tap ok。

## 実装（2026-10-06 P2、q787: 素早い Alt+Tab で開いたまま）

- `switcher.c`・`.h`: `struct zwl_switcher` に `opened_ms`・`steps`・`sticky`。`zwl_switcher_step` が step を数え（pad の
  travel も）、`zwl_switcher_alt_released(switcher, now_ms)` が Alt を離した時を決める: 開いてから
  `ZWL_SWITCHER_QUICK_MS`（500 ms）より前で step が無ければ開いたまま sticky にし、sticky の間は後の離しでも確定しない。
  それ以外（長押し、Tab で選んだ後）は確定。
- `switcher-shell.c`: 開いた時刻を持ち、Alt の離しで上の規則を引く。開いたままにした時 `ZWL SWITCH stay via=quick-alt
  index= app= held_ms=` を 1 回。残った UI は既存の操作: Tab（Alt なし）・Shift+Tab・矢印で選び、Enter・preview や icon の
  click・tap で切り替えて閉じる、Esc・外の click で今の app のまま閉じる。pad で開いた switcher は Alt と関係なし（従来）。
- 試験: host の host-switcher.c に 7 checks（素早い離しで sticky、sticky の後は確定しない、500 ms 以上・step の後は確定、
  pad の travel も step、時計の逆行は素早い扱い、閉じた後は何もしない、32 checks ok、ASan・UBSan でも）。QEMU の
  p005-guest.sh の 3. を新しい仕様に（素早い Alt+Tab → `stay`、Tab で apps.b、Alt をもう一度離しても確定しない、Enter で
  apps.b、もう一度素早く → Esc、長押しの Alt+Tab+Tab で apps.c、Shift+Alt+Tab は apps.c で開く）。QEMU は T1 に依頼（未実施）。
- build: zedBSD（config-amd64-zdesktop.mk）と Linux の keiland、warning 0。style-check 指摘 0。
