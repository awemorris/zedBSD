# BUG-381: libvulkan が native の OOM の返事で job を CANCEL するが、nvrtx では前の command buffer がもう GPU に送られている事がある

- 状態: open（2026-10-31 22:32 Q1 が起票、P3 の job-submit の設計のレビュー（BL1）で見つかった）
- 中身: libvulkan の `sync.c`（749 行あたり）は、native の reply が確かな拒否（OOM）の時に GPU_JOB_CANCEL（fault でない取り消し）をする。nvrtx の queue_submit は
  失敗した command buffer の前で止まるが、それより前の command buffer と早めの push は GPU で走っている。取り消しは「何も走っていない」証明にならず、
  fence・timeline の完了の順が崩れうる。
- 直す方針（案）: driver が GPU に送った数を数え、何も送っていない時だけ CANCEL、何か送った後の失敗は CANCEL_FAULT（または完了を待つ）。
  WS291 の job-submit（GPU_JOB_SUBMIT）では P3 が同じ規則で作る。今の 3 本の ioctl の道も合わせて直す。
- 影響: nvrtx で GPU の memory が足りない時（まれ）。他の driver は未確かめ。
