# BUG-409: ld.so（src/rtld）が DF_1_NODELETE を守らず、dlclose で参照が 0 になると unload する

- 状態: fixed（2026-11-02 P3 q1930-i01、agent/p3-bug409 95dfedaf3d。QEMU amd64 の guest で rtld-nodelete・rtld-many・ws073 p038 の TLS の試験が PASS。実機は未実施）。前: open（2026-11-02 10:21 Q1 が起票、P3 q1930）
- 発見: 2026-11-02 10:21 WS335 p039 の Sonnet。libcrypto-compat.so は `-z nodelete` で link し FLAGS_1 に NODELETE を持つが、`src/rtld/rtld.c` の `__rtld_dlclose` は参照が 0 で object を unload し、`src/rtld/` に DT_FLAGS_1 を読む所が無い。dlopen・dlclose で使うと、thread の終わりの destroy の関数の code が unmap された後に呼ばれる恐れがある（DT_NEEDED で link する使い方では起きない）。
- 直す形: rtld が DT_FLAGS_1 を読み、DF_1_NODELETE の object（とそれが依存する object）は dlclose で unload しない。RTLD_NODELETE の dlopen の flag も同じ扱いにする（POSIX の範囲で）。
- 扱い: P3（q1930）。

## 原因（2026-11-02 P3）

`src/rtld/rtld.c` の `parse_dynamic` は DT_FLAGS_1 を読まず（`src/rtld/elf.h` に定義も無い）、object を残す印は起動の時に読み込んだ object の `permanent` だけだった。dlopen した object は参照（handle の `direct_refs` と依存の `dependency_refs`）が 0 になると `unload_object_locked` が destructor を走らせて unmap した。`-z nodelete` の library が dlclose の後に残す code（pthread の key の destructor、atexit の関数）は unmap の後に呼ばれうる。dlopen の flag にも RTLD_NODELETE が無かった（`include/libc/dlfcn.h`）。

## 直し（2026-11-02 P3、95dfedaf3d）

- `src/rtld/elf.h`: `DT_FLAGS_1`（0x6ffffffb）と `DF_1_NODELETE`（0x8）。
- `src/rtld/rtld.c`: `parse_dynamic` が DT_FLAGS_1 に DF_1_NODELETE を見たら `permanent` を立てる（起動の時の object と同じ印）。`unload_object_locked` は permanent の object を離さないので、dlclose は handle を閉じるだけになり、その object が数える依存（DT_NEEDED）の `dependency_refs` も減らず依存も残る（他の ELF の loader と同じ）。初期化の list にも残るので、destructor（fini_array・DT_FINI）は exit の時の `__rtld_process_fini` で、初期化の逆の順に一度だけ走る。
- `__rtld_dlopen` が `RTLD_NODELETE` を受け、開いた object（新しい物、既に読み込んだ物）に `permanent` を立てる。
- `include/libc/dlfcn.h`: `RTLD_NODELETE 0x1000`（FreeBSD・glibc と同じ値、POSIX の外の拡張と注記。Q1 が承認）。

## 確かめ（2026-11-02 P3）

- build（BUILD=build/amd64・arm64・riscv64、config は `plan/tools/rtld/config-amd64-rtld.mk`・`config/ci/config-rpi4.mk`・`config/ci/config-riscv64-virt.mk`）: `dynamic/ld.so`・`dynamic/libc.so` が 3 つの arch で warning 0。`tools/build/check-dynamic-elf.py` の interpreter と libc の role が 3 つの arch で通る。image の build で rtld・libc の warning は 0（package の warning は別）。
- 試験の追加: `plan/tools/rtld/rtld-nodelete.sh`（`build-nodelete.sh`・`rtld-nodelete.c`・`nodelete-lib.c`・`nodelete-dep.c`、README に段の説明）。library は `-z nodelete` の keep（FLAGS_1 = NOW NODELETE、dep を DT_NEEDED）、RTLD_NODELETE で開く flag、対照の plain。
- QEMU amd64（`plan/tools/guest/test-image.sh plan/tools/rtld/config-amd64-rtld.mk build/amd64` の image、guest.py の SSH）: `rtld-nodelete: PASS`。plain は dlclose で unload され destructor がその時に走った。keep と flag は dlclose の後も object の数・dladdr で残り、保存した関数が答え、dlclose の後に終わった thread でその library の key の destructor が 1 回走り、開き直すと同じ mapping。atexit の関数と destructor は program の最後の行の後（exit の時）に flag・keep・dep の順で走り、exit=0。同じ guest で `rtld-many: PASS`（16 段）、`plan/ws073/tests/p038/run-tls-check.sh` の status=0（tls-check の動的・静的、dyntest の DL:01〜06）。
- 未実施: 実機。arm64・riscv64 の guest での実行（compile と ELF の検査だけ）。直す前の ld.so でこの試験が落ちる事は流していない（直す前は RTLD_NODELETE が「invalid dlopen flags」で断られ、keep は close で unload されて keep-close の段で落ちる筈）。

## 残り（2026-11-02 P3 の所見、この Bug の範囲の外）

- `src/libc/stdlib-extra.c` の `atexit` は登録した関数がどの object の物かを持たず、`__cxa_finalize` の注記は「共有 object を静的な object が生きている間に unload しない」としている。NODELETE でない library が atexit を呼んで dlclose で unload されると、exit の時に unmap された code を呼ぶ（glibc は atexit を `__cxa_atexit` と dso handle で登録して dlclose の時に走らせる）。今の使い方（`-z nodelete` の libcrypto-compat.so）では起きない。
