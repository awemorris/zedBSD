# BUG-276: Terminal で文字をドラッグで選ぶのに touchpad の押し込みが要り、タッチだけ（tap の後のドラッグ）で選べない

Reproduction: reproduced（ユーザー、実機 5330、2026-10-10 UAT）
Disposition: tracking
Discovery: 2026-10-10 ユーザーの 5330 の UAT のコメント（image はユーザーの 5330 に入っていた物、版は未確認）
Handling: WS183 p002（tap-drag）と Terminal の選択（WS190 の指での選択との関係）

## 観測（ユーザー）

「Terminalのテキストのドラッグは、タッチパッドの押し込みが必要になっていて、タッチだけでできない。これはダブルタップからできるようにしてほしい。」（title bar の tap-drag は動いた: 「ダブルタップからウィンドウタイトルバーをドラッグで移動できた」）

## 解析と直し（2026-10-10、P1、source）

compositor の touch pad の tap（`userland/desktop/wayland/touchpad.c`）は、2026-10-08 の UAT（tap の遅れ）の後、指を離した時に click（press と release を同じ時刻で）をすぐ出し、TAP_DRAG_MS（300 ms）の内に次の指が 1 mm 動くと左 button の press を出して指を離すまで持つ（tap-and-drag）。
client から見ると「click の後に同じ所で press」で、Terminal（`userland/desktop/terminal/main.c` `main_pointer_press`）は 400 ms・同じ cell の 2 度目の press を double click と数え、**単語の選択と単語ごとの drag** になる（文字の drag の選択にならない）。title bar の tap-drag は compositor の中の扱いなので動く。
押し込み（click pad の press）は 1 回目の press なので文字の drag になる。ユーザーの「タッチだけでできない」はこの差の見込み（実機で単語ごとの選択になっていたかは未確認）。

直し（Terminal）: release の時刻が press と同じ click を tap とみなし（手の click は数 ms 以上押される）、tap の直後の 2 度目の press が cell を出て動いたら、double click の単語の drag でなく、tap の cell からの文字の drag にする（`main_last_tap`・`main_tap_drag`）。2 度目も tap（double tap）なら今どおり単語の選択、mouse の double click の drag も今どおり単語ごと。
確かめ: `make BUILD=build/amd64 build/amd64/bin/terminal` warning 0、style-check の指摘は変更の前と同じ（0）。
残り: compositor の tap の click が client に double click に見えることは Text Editor などでも同じ（各 app の double click の扱い）。全体の直し（libinput のように tap の release を drag の時間だけ待つ）は 2026-10-08 の UAT の「tap が遅い」と逆なのでユーザーの判断が要る（Q1 へ）。
未実施（T1）: QEMU の touch pad の tap-and-drag の注入は今の道具に無い。実機 5330 の UAT（Terminal で tap の後に指を置いて動かすと文字単位で選択）。

## 読み直しと直し直し（2026-10-10、P1、Q1 経由のユーザーの説明）

ユーザー:「Terminalで問題にしているのはそういうことではなく、範囲選択した状態でダブルタップしようとすると、最初のタップで選択が解除されるバグです。」
原因: Terminal（`main.c` `main_pointer_release`）は範囲の上の click（press から動かずに release）で範囲をすぐ消す。touch pad の tap-and-drag は compositor が tap の click を先に出し、その後に press を出すので、範囲を drag（WS189 の app の間の drag and drop）しようとすると最初の tap の click で範囲が消え、続く press は範囲の外になる。押し込みは 1 回の press なので範囲を保って drag できる。

直し（Terminal）:
- 範囲の上の click が tap（release の時刻が press と同じ）なら範囲をすぐ消さず、350 ms（compositor の TAP_DRAG_MS 300 と余白、`MAIN_TAP_DRAG_MS`）待つ（`main_tap_clear_at`、main の loop の timeout と `main_tap_expire`）。
- その間に範囲の上で press が来たら、double click の扱いにせず範囲の drag の構え（`main_drag_armed`、`main_tap_second`）: 動けば範囲の text を drag して出す（DnD）、動かずに離せば double tap なので単語を選ぶ（`main_select_word`）。範囲の外の press なら待ちを終え範囲を消して今どおり。
- 手の click（release に時間がある）は今どおりすぐ消す。

8e274b3c6（範囲の無い所の tap-and-drag を単語ごとでなく文字の drag にする）は症状とは別だが、tap-and-drag を押し込みと同じに振る舞わせる直しなので残す（double tap と mouse の double click の drag は今どおり単語ごと）。
libkeiland の文字の欄と Text Editor: 選択の text を drag して出す機能（範囲の上の press を drag の構えにする扱い）が無く、範囲の上の click は押し込みでも tap でも caret を置いて選択を外すので、同じ不具合は無い（Files の ui-drag.c・Photos は file の drag で別）。
確かめ: `make BUILD=build/amd64 build/amd64/bin/terminal` warning 0、style-check 0。QEMU で touch pad の tap を注入する道具は無い → 実機の UAT（範囲を選び、範囲の上で tap → 指を置いて動かすと範囲の text が drag される、double tap で単語）。
