# BUG-419: riscv64 で noct の JIT が使えない（builtins が PIC でなく、`__clear_cache` に zedBSD の実装が無い）

- 状態: open（2026-11-11 11:27 Q1 が起票、ユーザーの指示から）
- 発見: 2026-11-11 Q1。VF2（riscv64）の userland で noct を build すると、JIT の `__clear_cache` の link が `relocation R_RISCV_HI20 cannot be used against symbol '.L.str'; recompile with -fPIC` で失敗した。当座は riscv64 だけ noct の JIT を切って interpreter で動かす（`userland/base/noct/Makefile` の `NOCT_JIT`）。
- 扱い: 2026-11-11 ユーザーから、下の 2 つの Phase の形で BUG の ticket にしておく、という趣旨の指示を受けた。担当は未定。

## 原因

1. **link の失敗**: `libclang_rt.builtins.a` は compiler-rt の source を `mk/platform-*/libc.mk` で静的な libc の flag（`LIBC_STATIC_CFLAGS`、`-fno-pic -fno-pie`）で compile している。program は PIE なので、data を絶対番地で指す builtins の object は link できない。多くの builtins は data を指さないので今まで表に出なかった。全機種で同じ flag なので、他の機種にも同じ潜在の問題がある。
2. **呼べても abort する**: compiler-rt の `clear_cache.c` は riscv64 を Linux（`riscv_flush_icache` の system call）と OpenBSD（`sysarch`）だけで実装し、他は `compilerrt_abort()` に落ちる。その macro が `__FILE__`・`__func__` の文字列を渡すので、1 の data への非 PIC の参照が出た。libc に `__compilerrt_abort_impl` の定義も無い。arm64 の `__clear_cache` は user mode の命令で cache を扱い data を指さないので、問題は出ていない。
   RISC-V の `fence.i` は実行した hart の命令 cache しか揃えないので、thread が動きうる全 hart に効かせるには kernel が SBI の `remote_fence_i` を呼ぶ必要がある。

## Phase

| Phase | 内容 | 目的 |
| --- | --- | --- |
| 1（build の修正） | `mk/platform-*/libc.mk` で builtins を `-fPIC` で build する。 | PIE の binary との link の失敗（原因 1）を根から無くす。 |
| 2（OS・libc の実装） | 1. zedBSD の kernel に SBI の `remote_fence_i` を呼ぶ `sys_riscv_flush_icache` を足す。2. libc に `__clear_cache` を足す。 | riscv64 で noct の JIT を完全に、安全に動かせるようにする。 |

- 受け入れ: VF2 で `NOCT_JIT` を ON に戻した noct が build でき、JIT を通る script が実機で正しく動く（複数の hart で動く thread を含む）。Phase 1 は他の機種の userland の build も warning 0 で通る。
- 注意: Phase 1 は Makefile の変更なので、概要と差分をユーザーに示して OK の後に当てる（plan/makefile-style.md）。compiler-rt 自体に zedBSD の分岐を足す形にする時は toolchain の変更で、ユーザーの許可が要る。
