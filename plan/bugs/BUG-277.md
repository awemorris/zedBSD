# BUG-277: Settings の Ethernet が接続しているのに No Cable と出る

Reproduction: reproduced（ユーザー、実機 5330、2026-10-10 UAT）
Disposition: tracking
Discovery: 2026-10-10 ユーザーの 5330 の UAT のコメント（image はユーザーの 5330 に入っていた物、版は未確認）
Handling: WS089 Settings の Network と networkd の carrier の状態（BUG-222 の link の速度の表示の変更の後か）

## 観測（ユーザー）

「SettingsのEthernetは、接続されてるのに No Cableになった。」

## 解析と直し（2026-10-10、P1、source。5330 の log は無い）

Settings の Ethernet の card（`userland/desktop/settings/page-network.c` `network_link_card`）は、interface が up で `IFF_RUNNING` が無いと「No cable」と書く（BUG-213 の前は同じ状態を「No address」と書いていた: BUG-213 の「address があるのに No address」も同じ根の見込み）。
`IFF_RUNNING` は kernel が up と carrier から作る（`src/kern/net/net-device.c` `device_update_running_locked`）。USB LAN の carrier は driver が device の NetworkConnection の通知で付ける（`usb-cdc-ncm-net.c` `ncm_notification_process`、`usb-cdc-ecm.c` も同じ）が、
**interface の down（`ncm_stop`・`ecm_stop`）が carrier を 0 にしていた**。device は link が変わった時だけ通知するので、cable が入ったまま down・up されると carrier は 0 のまま戻らない。
networkd は cable が抜けた事象で `ifconfig down` し、すぐ up し直す（`lan_take_down`→`lan_raise`、BUG-213・BUG-168）。cable の抜けと戻りが速い（link の張り直し、BUG-222 の速さの交渉、port の差し直し）と、戻った後に networkd の down・up が走り、carrier が 0 に固まる → 「No cable」、DHCP も走らない。

直し:
- `src/drivers/usb/usb-cdc-ncm-net.c`・`usb-cdc-ecm.c` の stop: carrier を消すのは stop が失敗した（quarantine）時だけ。管理の close では device の最後の言葉のまま（cable が down の間に抜けたら、device が持つ通知が次の open で届く）。
- `userland/base/networkd/main.c` `lan_raise`: up の後に interface を読み直す（`lan_snapshot`）。carrier が残っていれば事象が来ないので、running の flag で configure へ進む。

確かめ: `make BUILD=build/amd64 build/amd64/vmunix build/amd64/bin/networkd` warning 0、`plan/ws004/tests/run-usb-cdc-ncm-wire-test.sh` PASS（codec の host 試験、carrier の流れは含まない）。
未実施（T1）: `plan/ws033/tests/lan-link-down.sh`（cable を抜く・戻す: 抜けて No cable、戻って Connected と address）と `lan-hotplug.sh`、`tcp-receive-speed.sh`。実機 5330 の UAT（接続中に Connected、抜き差しで戻る）。
