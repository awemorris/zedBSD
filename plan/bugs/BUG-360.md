# BUG-360: live の session の入力欄で Backspace が空白を消さない（「11986 MiB」で Backspace を押すと「11986 」で止まる）

- 状態: fixed（2026-10-31 P2 q1757-i01。原因は installer の大きさの欄の既定値の詰め直し。QEMU の確かめは下）
- 発見: 2026-10-30 P4（q1665-i10、WS307 p011 の 8・9 回目、QEMU、installer の「他の OS」の S4 の大きさの欄）。
- 観測（probe `build/ws307-test/probe.yn1k2eex`・`probe.tpf72ugd`、P4 の worktree）: 「11986 MiB」の欄で Backspace を押すと「MiB」は消えるが空白で止まり、ゆっくり 12 回押しても「11986 」のまま。Left＋Delete なら空白も消える。Ctrl+A の後に打てば置き換わる。QMP の key で欄を消すと「7890 MiB1 GiB」のように前の文字が残る。
- 見立て（未確定）: libkeiland の field.c の Backspace の処理は読む限り正しい。IME（ja の direct）か key の経路の見込み。
- あわせて見つけた事: 大きさとして読めない値で「作成」を押すと、installer は何もせず、知らせも log の行も出さない（入力の誤りを示すべき）。
- 回避: WS307 の試験の installer_walk の set_field を Ctrl+A と打ち込みに変えた。
- 未確認: 実機の keyboard、ほかの app の欄、IME を外した時。

## 解析と修正（2026-10-31 P2、q1757-i01）

- **原因（source）**: Backspace でも IME でもなかった。installer の S4（`userland/desktop/installer/screens.c` の `screen_edit`）は、毎 frame「大きさの欄が空なら最大の空きの既定値（例「11986 MiB」）を入れる」をしていた。欄を Backspace で全部消すと、次の frame で既定値が入り直す。9 文字の「11986 MiB」で 12 回押すと、9 回で空 → 既定値が戻る → 残りの 3 回で「MiB」が消え「11986 」で止まって見える。QMP の key で消して「1 GiB」を打つと「7890 MiB1 GiB」になったのも同じ（空になった所で既定値が戻り、その後ろに打った）。Left＋Delete・Ctrl+A の後の打ち込みは欄を空にしないので起きない。libkeiland の field.c・ja の IME（何も組んでいない時の Backspace は app に渡す）は正しい。
- **修正**: 既定値は disk ごとに一度だけ入れる（`struct inst_app` に `create_size_disk`、入れた disk の番号。S10 の「最初から」で 0 に戻す）。利用者が空にした欄は空のまま。
- **「読めない大きさで作成が無言」**: 2026-10-30 の 67a3dd649（P4、この ticket の登録の 8 分後）で log の行 `INSTALLER EDIT refused reason=size` が入り、画面の知らせ（赤の「Type a size such as 20 GiB or 512 MiB.」）は前からあった。p011 の `size-refused` の STEP が PASS（P4 の worktree の `build/ws307-test/p011.9yb97ua0/steps.txt`、写真 `19-other-s4-size-refused.png` に赤の知らせ）。空の欄で作成を押しても同じ知らせになる（`inst_size_parse` が EINVAL）。追加の修正は無い。
- **build**: `make ZEDBSD_CONFIG=config/ci/config-amd64.mk ZEDBSD_IMAGE_PROFILE=installer build/amd64/bin/installer` → exit 0、warning 0（-Werror）。
