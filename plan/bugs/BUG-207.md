# BUG-207: Browser が通信中に UI に応答しない

Reproduction: reproduced（ユーザー、Windows の QEMU（Venus）で uat-0505g、2026-10-05 夜 UAT）
Disposition: tracking
Discovery: 2026-10-05 夜 ユーザーの UAT のコメント
Handling: WS074（browser）

## 観測

ユーザー「ブラウザは通信中にUIにレスポンスしないようです。」

## 原因（2026-10-06 P1、source の読みと host の試験で確認）

2 つ目以降の http/https の page の文書は非同期の loader（`net/loader.c`、main loop が poll する）で取るが、文書が届くと loader の callback の中で
`page_load_bytes()` が HTML を parse し、parser が `<script src>` に当たるたびに `script_run_file()` → `page_fetch()` → **同期の `net_http_fetch()`**
（DNS・connect・TLS・受信を UI の thread で待つ、keep-alive も無し）で script を 1 つずつ読んでいた。外部 script の多い page では、その間 window の
入力・描画が全部止まる。画像・stylesheet・font・動的 script・Fetch API は既に loader で非同期。

## 修正（2026-10-06 P1、agent/p1。最小の正しい変更として）

- 文書が届いたら、parse の前にその markup を軽く走査して（`page_scan_scripts()`、comment の中を除き、type が JavaScript の `<script src>` の
  web の URL、`&amp;` などの文字参照を解く、重複なし、最大 64）、それらを loader で**並行に先読み**し、全部が終わってから page を作って parse する
  （`view/view.c` の `view_prefetch_*`）。parser は `script_fetch_file()` で先読みの結果（bytes、または失敗の errno）を使い、見つからない物
  （script が書いた script、local の file）だけ従来どおり即時に読む。待つ間も表示中の page と UI は動き、Stop・別の navigation は先読みを cancel する。
- 実行の順・意味は変わらない（parser は同じ順に script を走らせる。結果の body は同期の fetch と同じく status を問わない）。
- file: `userland/desktop/libbrowser/page/script.c`・`page/page.h`・`view/view.c`。試験: `plan/ws074/tests/http-server.py`（`/scripts-ahead`・`/slow.js`・
  `/second.js`）、`plan/ws074/tests/run-http-tests.py`（async-scripts-ahead）。
- 確認: host の `run-http-tests.py --async` 20/20（新しい async-scripts-ahead: 0.6 s かかる script と次の script の request が重なる =
  先読みされた「slow then second overlapped」。`&amp;` の解読も確認）、同期の mode 15/15（最初の page を即時に読む mode では「sequential」= 試験が差を見分ける）、
  ASan/UBSan の build でも async 20/20、`host-view` 59/59。zedBSD の build（libbrowser・browser）warning 0。
- 残る block（範囲外、記録のみ）: shell の起動の最初の page は window を開く前に即時に読む（BROWSER_FETCH_DEFAULT）、`document.write` などで後から
  入る script と同期の XHR は即時のまま、parse と script の実行の CPU 時間は UI の thread。
