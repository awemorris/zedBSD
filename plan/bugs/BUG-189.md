# BUG-189: Settings の Network の頁で、WiFi と USB LAN の両方が接続している時、Active Network に WiFi が出る（有線が優先のはず）

Reproduction: reproduced（実機）
Disposition: resolved（2026-10-10 ユーザーの 5330 の UAT「BUG-189はOK」）
Discovery: 2026-10-04 夜 ad-hoc UAT-3（実機 Latitude 5330、image `build/uat-3/hdd-image.img` sha256 ada4492e…、main efe846a、[uat.md の uat-3](../uat.md)）
Handling: WS089（Settings の Network の頁）・WS005（networkd の有線優先の route、ws005-p019 の B3）・WS131（状態の経路）

## 観測

ユーザー「Settingsのネットワークタブで、WiFiとUSB LANが両方接続されているとき、WiFiがActive Networkで表示されます。これはUSB LANになるべきだし、USB LANが実際にdefault routeになるかも、テストしておくべきですね」

## 次

1. 仕様（ユーザー）: 両方が接続している時の Active Network は USB LAN（有線が優先、ws005-p019 の B3 の「有線優先の route/DNS」と同じ）。
2. 実際の default route が USB LAN になっているかを試験する（ユーザーの指示）: 実機で SSH から `route`・`net show` 相当で default route と DNS の出所を見る。QEMU では virtio-net（有線）と RTL8822BU の USB passthrough（WiFi）か networkd の模擬の WiFi を同時に立てて、route の表と Settings の表示を比べる試験を作る（T1）。
3. 表示の誤りか route の誤りかを分ける: route が有線なら Settings の Active Network の決め方（どの interface の状態を見ているか）を直す。route が WiFi なら networkd の有線優先（metric）の不具合。修正は P3 の q700 の Wi-Fi・network の束と一緒。

## 保留（2026-10-05 未明、q703-i01 P2 generation14。ユーザーの方針「既存BUGはいったん保留して、新規実装を進める」）

- **根**: route ではなく表示の誤り。networkd は有線優先で default route を張る（ws005-p019 B3、`apply_network_preference`）が、libkeiland-backend-zedbsd の `network_parse_state` は Wi-Fi が connected で online なら Wi-Fi を接続（Active network）としていた（有線より先に判定）。
- **途中の差分（WIP commit 済み、未試験）**: networkd の watch の状態に `route default=IF` の行を足す（default route の通る interface、無い時 `-`。`deliver_state_changes` が route の表を比べて変われば通知）。backend は default route の通る interface を接続とし、route の行が無い時は networkd と同じく有線を先に選ぶ。networkd・backend の object は build warning 0。
- **残り（再開点）**: (1) Linux・FreeBSD の wpa の backend（`kwpa_links`）は今も Wi-Fi を先に選ぶ（OS の route の metric に依る。揃えるかは別に決める）。(2) 試験: QEMU で virtio-net（有線）と network-probe（模擬の Wi-Fi、`route default=em9` を出す形を足す）か RTL8822BU の passthrough を同時に立て、Settings の Active network と guest の route の表（`route`・`net show`）を比べる（T1）。実機は UAT（USB LAN と Wi-Fi の両方）。

## 再開（2026-10-05、P2 / q703）

- 試験を足した: network-probe は前から `route default=em9`（有線）を出す。`settings-wifi-bugs.sh` の step 2 の後に、Wi-Fi（Kei Lab）と有線 em9 の両方が up の時に Settings の state が `connected=1 kind=1 interface=em9`（有線が Active）であることを見る（T1）。実の networkd の route の行は ws089-p021 の試験（`net watch` の `route default=IF`）で見ている。
- 残り: Linux・FreeBSD の wpa の backend（`kwpa_links`）は今も Wi-Fi を先に選ぶ（OS の route の metric に依る）→ 揃えるかは別に決める（Q1）。実機（USB LAN と Wi-Fi）は UAT。

Q1（2026-10-05）: Linux・FreeBSD の wpa の backend が Wi-Fi を先に選ぶ件は、ベータ1 では Linux・FreeBSD の backend は不要（2026-10-05 ユーザー）なので WS131 の p010（Linux・FreeBSD の実装）で有線を優先に揃える。zedBSD は有線が優先。
