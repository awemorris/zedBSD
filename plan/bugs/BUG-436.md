# BUG-436: 5330 で、既定の program の一式を敷いた後の起動が間欠に止まる（watchdog の reset まで答えない）

- 状態: open（2026-11-15 Q1 が起票。WS353 p016 の 5330 の試験で P1 が観測）
- 観測: 2026-11-14 23:20 頃、5330（Latitude 5330）に WS353 の後の main の kernel（k-plain 6286bbd6）と既定の program の一式の rootfs を NVMe に敷いて起動したところ、5 分 SSH に答えなかった。Debian の journal では、zedBSD の起動（BootNext）から約 10 分後に Debian が起動しており、watchdog=600 の TCO の reset と読める（reload は各 CPU の kernel の thread なので、ある CPU が 600 s 走れなかった＝ kernel の停止か livelock の疑い）。一式を敷かない起動（同じ kernel・古い userland）は 22 s で答えた。同じ kernel・同じ一式での 2 回目の起動（ping と SSH を 5 s ごとに記録）は 23 s で答え、止まらなかった。
- 疑い（未確定）: 新しい userland で起動する物（WS353 の後の compositor・libvulkan の i915 の経路、sessiond）と kernel の待ち方の変更の組み合わせ。
- 扱い: 5330 を何度も使わず、code（WS353 の kernel・libvulkan・compositor の変更、i915）と記録で考える。次に 5330 で止まった時は、止まった時刻と network の生死、gdbstub・QMP は使えないので画面の撮り（HDMI capture）と watchdog の後の Debian の journal を残す。
- 関係: [WS353](../ws353/ws.md) [p016](../ws353/ws.md)、[BUG-429](BUG-429.md)（TCO）。
