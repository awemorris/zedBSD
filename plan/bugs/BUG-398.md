- 状態: fixed（2026-11-02 07:42 P7 q1916-i01。Linux の host の build と Wine（x86_64）で、live の google.com の button を押すと一覧が描かれる事を確かめた。実機の Windows は未確認）。前: open（2026-11-02 06:16 Q1 が起票、P7 q1916）

- 中身: 右上の app の一覧の button を click しても一覧がうまく出ない。JavaScript と描画の両方に問題がある（ユーザーの見立て）。

## 再現（2026-11-02 P7）

- host の build（`plan/ws074/tests/host-build.sh plain`）の engine に link した小さな道具（`<browser/browser.h>` で頁を読み、click し、PPM と DOM を出す。worktree の `build/tmp/p7/clickprobe.c`、commit しない）で、live の `https://www.google.com/`（1280×800）の (1157, 28) を click。
- 直す前: 一覧の枠は開くが、中身は「読み込んでいます」の placeholder のまま。枠の中の `<iframe src="https://ogs.google.com/widget/app/so?...">` は `visibility: hidden` のまま。
- 参照: host の Chromium 156 の headless（CDP で同じ click）では 3 列 × 5 行の app の icon。Google の頁の資源の写しは worktree の `build/tmp/p7/fx/`・`site3/`（local の fixture、commit しない）。

## 原因

一覧は別の origin（ogs.google.com）の iframe で、iframe の中の頁が描けたら親へ message を送り、親が iframe を見せる作り（子は `parent.postMessage("ogi_app", origin, [port])` で MessagePort を渡し、その port で `_startuploaded`・`_renderstart` を送る）。libbrowser では次の所で止まっていた。

1. `HTMLScriptElement.src` の getter が `<img>` の getter を呼んでいて、`<script>` に対して「Illegal invocation」を投げた（`bind/element.c`）。widget の base の script が `script.src` を読む所で落ち、widget の body が無くなっていた（http で読んだ時。file: では出なかった）。
2. iframe は同じ origin の頁しか読まなかった（`page/frame-load.c` の `frame_load_allowed`）。ogs.google.com の文書は読まれなかった。
3. 別の origin の window どうしの見え方: main（クラウドのセッションの最後の origin/main を含む 12f6cb1e11）には window の proxy（`frame_proxy_maker`）・制限した見え方（`window_wrapper`）・送り手（`realm->caller`）・`window_message_ports` があったが、対象は opaque な origin（sandbox）だけで、別の origin は同じ origin と同じに扱われていた。
4. MessagePort（prelude）の `postMessage` が transfer の list を event の `ports` にせず、`onmessage` を付ける前（start の前）に来た message を捨てていた。子は親が port を受け取る前に `_startuploaded` を送るので、親は何も受け取らなかった。
5. `HTMLIFrameElement` に `name`・`frameBorder`・`scrolling`・`width`・`height`・`allow` の反映が無く（Google は property で `frameBorder=0` などを設定する）、UA に `frameborder="0"` で枠線を消す規則も無かった（2px inset の枠線が出る）。

## 残り

- 実機の Windows の OmniGrammaton での確認（ユーザーが拾える試験）。
- 一覧の下の端: Chromium では widget の枠が 612px あたりで丸く終わるが、こちらは iframe の高さ（570px）で切れ、下の丸みと影が見えない（widget の中の高さの計算の差。未調査）。
- 一覧の中の app の click（`target=_top` の link）と、子の frame に script が後から足す script（`ck=` の module）は未確認・未対応（子の frame の script は parser が出会った物だけを同期で取得する）。一覧の表示には要らない。
- Google の頁の `xjs.hd` の chunk が `for await` の SyntaxError で読めない（JS の engine に async iteration が無い）。一覧には効かない。Queue の (c)「小さければ」は、compiler と async iterator の protocol と close の作りが要り小さくないので、この Queue ではしていない。
- 直す前から、fetch が DEFAULT（window と同じ）の時は google.com の右上の「Gmail」「画像」の link が出ない（AT_ONCE では出る。main でも同じ）。別の件。
- 子の frame の外部 script は同期の `page_fetch` で取る（読む間は page が止まる）。
