# BUG-266: 拡張で eDP を off にすると Wayland の session が落ちる（USB-C の DP に 1 出力で移す時に失敗）

- 状態: **resolved（2026-10-08 夕 ユーザーの UAT「eDPオフが機能しました。USB-C DPだけの出力ができました。」）**。抜いた後の eDP の戻りの遅さは BUG-268
- 由来: ユーザー「拡張モードで、eDPをオフにする操作をしたところ、Waylandセッションが落ちました。SSHでログを見てください。」「eDPをオフにするとWaylandが落ちる問題をまず解決しましょう。そのあとマルチタッチ。」
- 同じ UAT で: USB-C の DP（TC2）の出力・拡張・mirror は動いた（BUG-256 の直しが効いた）。
- kernel: main 932b07bb4 の build（Q1 が 5330 に入れた vmunix cksum 567766690、wayland 2020052779、libkeiland 3875603912、settings 552170007）。
- 証拠: [BUG-266/](BUG-266/) の kernel.log・session.log（compositor）・sessiond.log・messages・greeter.log・displays.conf。

## 観察（Q1）

- displays.conf: `mode=extended`、`anchor=…dp:TC2`、`off=…edp:A`。
- session.log の最後: `KWL OUTPUT display index=0 …dp:TC2 shown=1`、`index=1 …edp:A shown=0` → `KWL VULKAN_ERROR operation=submit result=-4`（DEVICE_LOST）→ `KWL FAILED site=compose_draw errno=5` → clients の cleanup → `KWL EXIT … error=5 cleanup_failed=1`。sessiond は `SESSION end … status=256` で greeter に戻った。
- kernel.log（4128 行の前後）: eDP を off にして DP だけにする時、resident display を TC2 に移す経路（ws113-p011a の 1 出力の付け替え）が `resident display: ended FAIL (show rc=5; … first anomaly: WARN_ON(!intel_tc_port_in_legacy_mode(dig_port)))` → `resident display: the moved output failed; the firmware's output (eDP panel) is the output again, and the lease's presentations fail until the next claim`。同じ行が 1955・2873 行にもある（3 回）。
- → 2 つの欠け（Q1 の見立て）: (1) i915 の 1 出力の付け替えが TC の port を legacy の mode と仮定していて、DP-alt の port で失敗する。(2) 付け替えが失敗した時、compositor が present の失敗を DEVICE_LOST として受けて session ごと終わる（eDP に戻して続けるべき）。

## 担当

- 2026-10-08 午後 Q1: P2（BUG-256 の担当）に割当、WS191 より先。

## 原因（2026-10-08 夜 P2、kernel.log と source）

1. **i915: 1 出力の付け替え（resident の run）で Type-C の hook が run log に止められていた。** resident の run は `drv_i915_lcd_kernel_bind_ops` で TC の hook（`tc_get_link`・`tc_mode`・`tc_set_fia_lane_count`・`tc_pin_assignment`・`tc_put_link`）と DKL の hook を束ねるが、その上に重ねる run log（`display/diagnostics.c` の `drv_i915_lcd_trace_init`）がこれらを転送していなかった。そのため run の中では TC の port が mode なしとして扱われた: `LCD-B UNRESOLVED step reached: intel_tc_port_get_link / _in_mode / _set_fia_lane_count / _get_pin_assignment_mask`（kernel.log 1532〜1544）。PHY も取られず、FIA の lane も設定されず、pin assignment は 0 になり、`WARN_ON(!intel_tc_port_in_legacy_mode)`（ddi.c 4449〜4451、pin 0 は legacy の固定接続だけ）が出た。link training は失敗した（`FALLBACK … not ported`）。AUX のたびに `TC2: mode none -> dp-alt` が出ていたのも、link を持たないため。2 つ目の出力（head.c）は run log を通さないので、同じ TC2 で点いていた（kernel.log 1104）。
2. **compositor: 付け替えの最初の frame の失敗で session が終わった。** 失敗の後、kernel は「lease の presentation を次の claim まで失敗させる」。その present の errno は窓の外で EIO（worker.c）で、WSI は DEVICE_LOST に写す。compositor は `compose_draw` の失敗として `server->failed` を立てた。

## 直し（2026-10-08 夜 P2）

- `src/drivers/gpu/i915/display/diagnostics.c`: run log が backend に TC と DKL の hook がある時、それらを転送する（model の backend では NULL のまま、step を記録する）。
- `src/drivers/gpu/i915/worker.c`・`display/present.c`・`present.h`: 付け替えに失敗した lease の窓の外の presentation は ENXIO を返す（`drv_i915_present_lease_failed`）。WSI は SURFACE_LOST に写すので、出力が無くなった扱いになる。panel が点かない時は今までどおり EIO。
- compositor（`userland/desktop/wayland/`）:
  - `output-switch.c`: 付け替え（reopen でない move）は最初の frame まで「未証明」（`switch_proving`）とし、元の display を覚える。
  - `compose.c`: 未証明の間の present が SURFACE_LOST・OUT_OF_DATE・DEVICE_LOST を返したら、move の失敗（`switch_failed`）として session を落とさない。
  - `output-switch.c` の `output_fail_back`: 次の tick で元の display へ戻る。失敗した display は次の hotplug まで move の先にしない（`move_failed`。`limited` と違い head にはなれる）。
  - `heads.c` の `kwl_displays_move_failed`: 元の display を anchor・on に戻して displays.conf に書き、Settings に snapshot を送る。
  - `displays-shell.c`: apply・set_shown が出力を動かした時、その result を最初の frame まで保留する。成功なら OK、失敗なら FAILED（Settings は「The displays could not be changed.」などを出す）。3 秒経っても来なければ OK。object が消えたら捨てる（`objects.c`）。
- 試験の追従: `plan/ws113/tests/host-output-switch.c` に stub 3 つと、失敗した move の場面を足した。
