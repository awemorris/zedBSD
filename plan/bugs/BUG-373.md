# BUG-373: 今の main の kernel で networkd の初期の Wi-Fi の正規化が EINVAL になり、networking が上がらない（Wi-Fi の無い機械でも）

- 状態: open — 修正済み・QEMU で確認・実機未確認（2026-10-31 登録、同日 P7 が修正、q1732-i01。closed は Q1 の merge の後）
- 発見: 2026-10-31 P2（WS291 p020、VF2 の serial）。VF2 の userland を main（780e7349b）の rootfs に揃え、main＋P2 の差分の kernel で起動しても `networkd: initial Wi-Fi normalization: Invalid argument` → `init: networkd: FAIL 3 wifi-normalize` → `init: skipped networking`。古い userland と main の kernel でも同じ。10.0.10.3（RTX の機械、userland は 10-28）でも main の kernel で ue0 が上がらない（P3、同じ原因の見込み）。P7 の 5aca73738 の kernel では上がる。
- 疑い（未確かめ）: 5aca73738..main の kernel の変更（WS332 b3b05b2be の wlan の UAPI・wlan.c、WS331 の driver の整理）で、networkd の retire_managed_policy の enumerate_wlan_radios か stop_wlan_radios が EINVAL を受ける。VF2 には Wi-Fi が無い。
- 影響: main の kernel で、実機の network（SSH）が上がらない。BUG-371（Wi-Fi の失敗で有線まで飛ぶ）と重なって、全ての network が止まる。
- 関係: [BUG-371](BUG-371.md)、[BUG-372](BUG-372.md)。

## 原因（2026-10-31 P7、QEMU で確かめた）

- `src/kern/net/inet-socket.c` の `inet_ioctl_wlan()` は、要求の header の版（`WLAN_ABI_VERSION`）と大きさを、名前の device を探して WLAN の
  能力を確かめるより前に検査していた。b3b05b2be（WS332 p002）で版が 1→2 に上がったため、版 1 で build した userland（networkd）は、
  Wi-Fi でない interface（lo0・en0・ue0、存在しない名前も）に対しても `SIOCGWLANSTATUS` で EINVAL（zedBSD の 3）を受ける。
- networkd の `enumerate_wlan_radios()` は EOPNOTSUPP・ENOTTY だけを「radio でない」と読み、他の error は「radio でないと言えない」として
  失敗する。→ `retire_managed_policy()` が失敗 → `FAIL 3 wifi-normalize` → init が networking を飛ばす（[BUG-371](BUG-371.md)）。
  Wi-Fi の無い VF2 でも起きるのはこのため。kernel と userland が共に版 2 なら起きない。
- 版の上げ自体は設計どおり（plan/ws332/design.md §2）だが、Wi-Fi でない interface に版の不一致を EINVAL で返すのは誤り（その interface は
  どの版の要求にも答えないので、EOPNOTSUPP が正しい）。
- 「main の userland に揃えても」の VF2: P2 の記録 `/home/awe/zedBSD-worktrees/p2-ws291v/build/ws291/board-sums*.txt`（2026-10-31 00:00）では、
  板の `/sbin/networkd` は cksum 241526979・205248 B で、main の build（`vf2b/rootfs/sbin/networkd`、cksum 3095223911・206984 B、
  `include/uapi/wlan.h` の版 2 で compile、main.d で確認）と違い、`diff-files.txt` にも `/sbin/networkd`・`/sbin/wifi` が載る。
  その時点の板の networkd は版 1 の古い物だった見込み（その後の入れ替えは未確認）。10.0.10.3 は P3 が userland を main（9a5a7fc22）に
  入れ替えて素の main の kernel で ue0 が上がった（Q1 の連絡）。arch ごとの sysroot の `uapi/wlan.h` は main の checkout で版 1 のままだが、
  user の program は `-Iinclude` が `-isystem` の sysroot より先に探されるので、tree の版 2 を使う（P2 の riscv64 の sysroot は版 2）。

## 直し（P7、WIP 30fd47a4f）

- `src/kern/net/inet-socket.c`: 検査の順を「名前（空・終端なしは EINVAL）→ device の検索（無ければ ENODEV）→ 生きているか（ENODEV）→
  WLAN の能力（無ければ EOPNOTSUPP）→ 版と大きさ（EINVAL）」に変えた。`inet_ioctl_wlan_validate()` を名前の検査
  `inet_ioctl_wlan_validate_name()` と版・大きさの検査に分けた。WLAN の device への要求の扱い（版 2 だけを通す、wlan.c の
  `header_validate()` も版を見る）は変えていない。UAPI・HAL は変えていない。
- networkd 側は [BUG-371](BUG-371.md)（正規化の失敗で networking を止めない）。
