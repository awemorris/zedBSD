# BUG-268: eDP を off にして USB-C の DP だけで出している時、DP を抜くと eDP が戻るまで約 10 秒かかる

- 状態: reproduced（実機 5330、2026-10-08 夕 ユーザーの UAT） / scheduled
- 由来: ユーザー「eDPオフが機能しました。USB-C DPだけの出力ができました。ただ、USB-C DPを切断したあと、eDPが回復するのに10秒ほどかかりました。」（BUG-266 の直しの確認と同じ回）
- 証拠: [BUG-267/kernel.log](BUG-267/kernel.log) の 6066 行の前後（`resident display: ended FAIL (… first anomaly: the sink lost the link while the picture was up)` → `the moved output failed; the firmware's output (eDP panel) is the output again` → `lease 7 claimed` → `picture up` → `first frame 1920x1080 … shown on the 1920x1080 panel`）と [BUG-267/session.log](BUG-267/session.log)。
- 疑い（未確認）: 抜いた時に link の失敗の検出（HPD の後の 2 秒の再確認、presentation の timeout など）を待ってから eDP に戻している。抜いた（HPD の disconnect）時点で直ちに eDP へ戻すべき。
- 担当: 2026-10-08 夕 Q1: P2（BUG-266 の担当）に割り込みで。

## 原因（2026-10-08 P2、BUG-267 の log から）

kernel の待ち（compositor ではない）。
1. HPD の disconnect（kernel.log 4333〜4345）で TC2 の topology は disconnected になるが、i915 の resident output（窓の中で TC2 を灯したまま）は止めなかった。Type-C の link の reset は「2000 ms 後に見る、output はここでは止めない」だけ（4343・4359）。
2. 表示の一覧の index 0（resident output）は常に `GPU_DISPLAY_CONNECTED` なので、compositor は TC2 が残っていると見て（session.log 7870〜7872）、presentation の ESTALE・ENXIO のたびに TC2 を開き直した（lease 4・5・6、7887〜7928）。
3. ENXIO の presentation は worker に届かないので、release の後の hold（`I915_PRESENT_HOLD_MS` = 10000 ms、present.c）は次の lease の最初の frame で終わらず、10 秒の満了で窓を出た（4386 → 6066 `ended FAIL … the sink lost the link`）→ `the moved output failed` で eDP に戻った。
4. 戻った後も topology の通知は無く、compositor が気付いたのは次の presentation の失敗（7972、idle の desktop では人の操作まで）。
5. 窓を出た run は FAIL なので、run log の全部（約 1700 行）を kernel の log に書いていた。

## 直し（2026-10-08 P2、agent/p2）

- `display/hotplug.c`: connector が connected から外れた時、resident output がその connector に移って灯っていれば `drv_i915_present_unplugged` を呼ぶ。`drv_i915_hpd_topology_touch` を足す（connector の変化を伴わない一覧の変化の通知）。
- `display/present.c`: `drv_i915_present_unplugged`（`window.unplugged` を立てて worker を起こす。移った output・灯っている・その connector の時だけ）、`drv_i915_present_unplug_pending`。`drv_i915_present_hold_over` は unplugged なら hold の有無に関わらず 1。窓の終わりで unplugged を取り、再試行をせず、移った output なら fail back（run が PASS でも）。output が firmware の物に戻ったら `drv_i915_hpd_topology_touch` で display の session に知らせる（idle の desktop でも compositor が一覧を読み直し、`lost operation=hotplug` → eDP へ）。
- `worker.c`: 窓の中の loop の頭で unplugged なら窓を出る（待っている presentation は残り、fail back の後は lease_failed で ENXIO）。
- `display/modeset.c`: unplugged の run の FAIL では run log を出さない（`run log not printed: its display was unplugged`）。`i915.debug=display` なら出す。
- `display/internal.h`: `window.unplugged`。
