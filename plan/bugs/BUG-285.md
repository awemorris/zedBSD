# BUG-285: ログイン画面・ロック画面で、PIN を設定してあっても PIN でログインできない

Reproduction: reproduced（ユーザー、実機 5330、2026-10-10）
Disposition: scheduled（ベータ2、P1 最優先）
Discovery: 2026-10-10 ユーザーの UAT
Handling: WS172（ws172-p007 の方式の選択）・WS187（ロック画面）・sessiond・/sbin/passkey

## 観測（ユーザー）

「ログイン画面、ロック画面で、ユーザのPINが設定されていても、PINログインができないバグを発見。」

## Q1 の SSH（5330、2026-10-10）

- /var/log/sessiond.log: `SESSIOND ENROLL pin ok user=kei`（1791547886）の後、`UNLOCK`・`LOGIN` の style=pin の行が **1 つも無い**（fido2 の UNLOCK ok・fail はその前にある）。→ PIN の試みが sessiond に届いていない: greeter・lock が PIN の方式を出さない（styles の問い合わせを起動の時だけして cache している等）か、PIN の欄の送信が sessiond へ行かない見込み（未確認）。
- /etc/passkey は 12:11 に更新（PIN の登録）。
- 別件の見つけ: sessiond.log に `net: networkd is unavailable: No such file or directory`（session の開始の直前）。
- QEMU の T1-520 では /sbin/passkey で PIN を登録した後に lock の画面が `styles=3` で PIN の欄を出した（その試験は PIN の欄に password を入れて失敗、試験の側）。
