# BUG-393: Pi 5 の GPU の driver が起動時にテストの描画（自己試験）を行う

- 状態: fixed（2026-11-02 P3 q1891-i01、agent/p3-bug393 2e722eb3d0・bd25d03c3c・4bd4bf34da。build は warning 0、Pi 5 の実機で確かめた（下の「実機」）、Pi 4 の実機は未実施）
- 発見: 2026-11-02 ユーザーの Pi 5 の UAT。起動時に GPU の driver がテストの描画を行っている。削除してほしい。
- 関係: P3・P4 の記録では、Pi 5 の起動時に GPU の self-test（V9 の hang と reset を含む）が流れ、dmesg に fault の行が出る（WS291 p021・BUG-387）。
- Q1 の案: 起動時の自己試験を既定で off にし、開発の時だけ config か起動の parameter で on にできる形にする（試験の道具は残す）。Pi 4（同じ bcm2711 の code）も同じに。
- 扱い: P3（q1891）。

## 修正（2026-11-02 P3 q1891-i01）

- 原因: bcm2711 の driver（Pi 4 の V3D 4.2 と Pi 5 の V3D 7.1・HVS6 で共有）は、起動のたびに次の自己試験を流していた。
  - V3D の試験の job（Pi 4 は V7〜V10、Pi 5 は V5〜V9）。描画先は memory で画面には出ないが、最後の段は bin の list をわざと止め（hang）、engine を reset する。dmesg に hang・reset の行が出る。
  - 画面の試験の絵: 共有の display-device.c の P2（上端の緑と紫の縞の 2 枚の frame）・P3（右上の半透明の checker）、Pi 5 の hvs6.c の R2（64x64 の四角を 30 回動かす）。ユーザーが見た「テストの描画」はこれ。各段に 100 ms の待ちもある。
- 直した事（2e722eb3d0、基点 main 0b3dfac40）:
  - 起動の parameter `rpi4gpu.selftest=1` を足した（stage.c の `bcm2711_stage_selftest`。`rpi4gpu.off=1` と同じく driver 全体の prefix、Pi 4 と Pi 5 の両方に効く）。無い時（既定）は上の job と絵を流さない。ある時は今までと同じに全て流す。
  - 自己試験が無い時、TFU（texture の形の変換の unit）は既定で使う（`v3d.tfu=0` で CPU）。今までは V7/V9 の UIF の照合が通った時だけ使っていた。Pi 4・Pi 5 とも実機の記録で照合は毎回通り（plan/agents/T1・T2 の dmesg、WS291 p021）、Mesa の v3dv も照合なしに使う。`rpi4gpu.selftest=1` の時は今までどおり照合の結果で決まる。`v3d.tfu_probe=1`（Pi 4）は自己試験の中で動くので `rpi4gpu.selftest=1` と一緒に使う。
  - `*.stop=<段>` の parameter はそのまま効く。
- 起動の時間（2026-11-02 Q1 から、P7 の計測で自己試験が Pi 5 の起動の最大の待ち、BUG-394 の背景で起動の時間が製品の要件、R1 と P1 も起動の道から外すように、という趣旨の追加の依頼。bd25d03c3c・4bd4bf34da）:
  - Pi 5 の R1（refresh の測定、R3 と flip の予算が使う）: 1 秒の数えをやめ、7 回の vblank を monotonic の counter（`kern_rtc_read_counter`）で時刻を取り、6 frame の median から refresh を決める（約 100 ms、整数 Hz に丸めるのは今まで通り）。counter が無い・1 秒で 7 回来ない時は 1 秒の数えに戻る。最初の版（5 回の両端の差、clock の tick）は IRQ の遅れで 61 Hz・65 Hz と出たので median にした。
  - 共有の P1（display の node を出す前に vblank が来る事を確かめる）: 最初の frame が来たら終わる（8 ms）。1 秒の数えは `rpi4gpu.selftest=1` の時だけ。
  - 写真のための 100 ms の pause（`bcm2711_stage_pause`、Pi 4 の V1・R0 と自己試験の各段）は `rpi4gpu.selftest=1` の時だけ。
  - Pi 5 の display の終わりの行を `display self-test ok` から `display ready` に。header・comment と docs/reference/gpu-drivers.md の render node の行を直した。
  - 利用者が呼ぶ試験の道具（userland/tests/gpu-selftest など）は変えていない。
- 確かめ（build）: `make ZEDBSD_CONFIG=config/ci/config-rpi5.mk BUILD=build/p393-rpi5 build/p393-rpi5/vmunix` と config-rpi4.mk の同じ物、どちらも rc 0・warning 0・`arm64 vmunix check: PASS`（Pi 5 は 4bd4bf34da の source、Pi 4 は bd25d03c3c の source で、その後の変更は Pi 4 に入らない hvs6.c・hvs6.h だけ）。変えた file を使う host の試験は無い。

## 実機（Pi 5、10.0.30.7、2026-11-02 01:53〜02:10、P3）

- 板はユーザーの UAT の CI の image（1.0.0-beta2+g8f91a0d、`login=graphical rpi5gpu.start=boot`）。script（P3 の scratchpad の p393-pi5.sh、利用者 user と sudo）が /boot/boot0/vmunix と cmdline.txt の写しを取り、kernel を置いて再起動 → dmesg・ps・mview（ws291 の build の mview と tree の test の model、窓、FIFO 300 frame、10 copies）→ cmdline.txt に `rpi4gpu.selftest=1` を足して再起動 → 同じ → 写しを mv で戻して再起動し cksum を比べる。出力は build/tmp/p393-check2・p393-run・p393-run2・p393-run3（各 summary.txt）。
- 元（CI の kernel、8f91a0d）: 自己試験の行あり（self-test 3、V9 5、TFU UIF 8、R2 2、P2/P3 9）、`R1 64 vblanks in 1065 ms`、`P1 frames 117 in 1s`、**boot storage discovered 6315 ms**。
- 4bd4bf34da の kernel（cksum 2887926735）、既定: self-test・V9・TFU UIF・R2・P2/P3 の行は全て 0、fault・hang・reset の行は PCIe と xHCI の reset の 3 行だけ。`R1 7 vblanks in 105 ms, median frame 16666 us` → `R3 ... 60000 mHz`、`P1 frames 1 in 8 ms`、`P5 display node ready`、`display ready`、`v3d: ready: V3D 7.1.10, 12 QPUs, 1150000000 Hz`。desktop の wayland（--session）が上がる。mview `MVIEW DONE frames=300`、その後の GPU の fault の行 0。**boot storage discovered 1203 ms**（前の版の 2 回は 926 ms）。
- 同じ kernel、`rpi4gpu.selftest=1`: 自己試験の行が元と同じ数だけ出る（`v3d: self-test ident ok mmu ok irq ok noop ok clear ok tfu ok csd ok reset ok`）、P1 は 1 秒で 120 frame、60000 mHz、desktop と mview DONE、fault の行 0。boot storage discovered 5483 ms。
- 戻し: vmunix cksum 2112791070・cmdline.txt cksum 3178356281 で元と一致（`RESTORED OK`）、板に p393 の file は残っていない、CI の kernel で起動を確かめた。
- 未実施: 画面の写真（CI の image は screen capture が無い）、Pi 4 の実機、TFU を使った mview の絵の正しさの目視。

## 他の GPU の driver（調べただけ、直していない）

- amdrdna: 画面の試験の絵（色の bar・cursor の四角）は既に呼ばない（display.c の `display_check_bars`・`display_check_cursor` は残すが未使用、`amdrdna.disp.test=` は保持の秒数だけ）。直す物なし。
- PowerVR（VF2）: 起動時に queue の短い自己試験（空の job と fence、render.c）。描画なし。trace は `CONFIG_POWERVR_DEBUG`。
- Mali（ODROID-C5）: 起動時に queue の自己試験（NOP と SYNC_ADD64、mali-queue.c）。描画なし。
- nvrtx: VRAM の窓の自己試験（vram.c、page entry の読み戻し）。描画の試験は `nvrtx.draw=1`・`nvrtx.gr=1`・`nvrtx.compute=1` の時だけ（既定は off）。
- i915: 起動時の試験の描画・自己試験は見つからない（default の context の image の記録だけ、詳しくは未確認）。
- どれも画面に絵を出さず、dmesg の hang・reset の行も出さない。bcm2711 と同じ形（parameter で on）にするかは、それぞれの短い queue の試験に起動の時間の値打ちがあるかで決める事で、今は直さない（報告だけ）。
