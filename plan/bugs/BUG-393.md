# BUG-393: Pi 5 の GPU の driver が起動時にテストの描画（自己試験）を行う

- 状態: fixed（2026-11-02 P3 q1891-i01、agent/p3-bug393 2e722eb3d0。build は warning 0、Pi 5 の実機は下の「実機」）
- 発見: 2026-11-02 ユーザーの Pi 5 の UAT。起動時に GPU の driver がテストの描画を行っている。削除してほしい。
- 関係: P3・P4 の記録では、Pi 5 の起動時に GPU の self-test（V9 の hang と reset を含む）が流れ、dmesg に fault の行が出る（WS291 p021・BUG-387）。
- Q1 の案: 起動時の自己試験を既定で off にし、開発の時だけ config か起動の parameter で on にできる形にする（試験の道具は残す）。Pi 4（同じ bcm2711 の code）も同じに。
- 扱い: P3（q1891）。

## 修正（2026-11-02 P3 q1891-i01）

- 原因: bcm2711 の driver（Pi 4 の V3D 4.2 と Pi 5 の V3D 7.1・HVS6 で共有）は、起動のたびに次の自己試験を流していた。
  - V3D の試験の job（Pi 4 は V7〜V10、Pi 5 は V5〜V9）。描画先は memory で画面には出ないが、最後の段は bin の list をわざと止め（hang）、engine を reset する。dmesg に hang・reset の行が出る。
  - 画面の試験の絵: 共有の display-device.c の P2（上端の緑と紫の縞の 2 枚の frame）・P3（右上の半透明の checker）、Pi 5 の hvs6.c の R2（64x64 の四角を 30 回動かす）。ユーザーが見た「テストの描画」はこれ。各段に 100 ms の待ちもある。
- 直した事（2e722eb3d0、基点 main 0b3dfac40）:
  - 起動の parameter `rpi4gpu.selftest=1` を足した（stage.c の `bcm2711_stage_selftest`。`rpi4gpu.off=1` と同じく driver 全体の prefix、Pi 4 と Pi 5 の両方に効く）。無い時（既定）は上の job と絵を流さない。ある時は今までと同じに全て流す。
  - 自己試験が無い時、TFU（texture の形の変換の unit）は既定で使う（`v3d.tfu=0` で CPU）。今までは V7/V9 の UIF の照合が通った時だけ使っていた。Pi 4・Pi 5 とも実機の記録で照合は毎回通り（plan/agents/T1・T2 の dmesg、WS291 p021）、Mesa の v3dv も照合なしに使う。`rpi4gpu.selftest=1` の時は今までどおり照合の結果で決まる。`v3d.tfu_probe=1`（Pi 4）は自己試験の中で動くので `rpi4gpu.selftest=1` と一緒に使う。
  - 残した物（絵を出さない測定）: Pi 5 の R1（vblank を 1 秒数えて refresh を決める。R3 と flip の予算が使う）、共有の P1（vblank が来る事を 1 秒見る、display の node を出す前の確かめ）。`*.stop=<段>` の parameter はそのまま効く。
  - Pi 5 の display の終わりの行を `display self-test ok` から `display ready` に。header・comment と docs/reference/gpu-drivers.md の render node の行を直した。
  - 利用者が呼ぶ試験の道具（userland/tests/gpu-selftest など）は変えていない。
- 確かめ: `make ZEDBSD_CONFIG=config/ci/config-rpi5.mk BUILD=build/p393-rpi5 build/p393-rpi5/vmunix` と config-rpi4.mk の同じ物、どちらも rc 0・warning 0・`arm64 vmunix check: PASS`。変えた file を使う host の試験は無い。

## 他の GPU の driver（調べただけ、直していない）

- amdrdna: 画面の試験の絵（色の bar・cursor の四角）は既に呼ばない（display.c の `display_check_bars`・`display_check_cursor` は残すが未使用、`amdrdna.disp.test=` は保持の秒数だけ）。直す物なし。
- PowerVR（VF2）: 起動時に queue の短い自己試験（空の job と fence、render.c）。描画なし。trace は `CONFIG_POWERVR_DEBUG`。
- Mali（ODROID-C5）: 起動時に queue の自己試験（NOP と SYNC_ADD64、mali-queue.c）。描画なし。
- nvrtx: VRAM の窓の自己試験（vram.c、page entry の読み戻し）。描画の試験は `nvrtx.draw=1`・`nvrtx.gr=1`・`nvrtx.compute=1` の時だけ（既定は off）。
- i915: 起動時の試験の描画・自己試験は見つからない（default の context の image の記録だけ、詳しくは未確認）。
- どれも画面に絵を出さず、dmesg の hang・reset の行も出さない。bcm2711 と同じ形（parameter で on）にするかは、それぞれの短い queue の試験に起動の時間の値打ちがあるかで決める事で、今は直さない（報告だけ）。
