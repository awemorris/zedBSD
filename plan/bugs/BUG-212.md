# BUG-212: 有線 LAN の接続中に WiFi に接続し、有線を link down すると WiFi が切れ、WiFi を off・on するまで再接続できない

Reproduction: reproduced（ユーザー、実機 5330、2026-10-06 UAT）
Disposition: resolved（2026-10-10 ユーザーの 5330 の UAT「BUG-212はOK」）
Discovery: 2026-10-06 ユーザーの UAT のコメント
Handling: WS005・WS033（networkd）

## 観測（ユーザー）

「有線LAN接続中にWiFi接続を行い、さらに有線LANをリンクダウンすると、WiFiの接続がされていない状態になりました。WiFiをオフにしてオンにしなおすまで、再接続うまくいかず、APをクリックしてもConnectingになってすぐ接続に失敗しているようでした。」

## 次（未確認の見込み）

有線の link down の時の networkd の経路・既定の経路の切り替えと wlan0 の状態の扱い。

## 2026-10-06 ユーザーの回答（Q1 経由）

「有線LANは大本のルーター10.0.0.1に直接ぶらさがっています。WiFiは大本のルーターに、WiFiルーター10.0.30.1がぶらさがっており、NATです。WiFiはAX211を使いました。再現のログは了解です。」
→ 有線（10.0.0.x）と WiFi（10.0.30.x、NAT の内側）は別の subnet。WiFi は内蔵の AX211。

## q780-i01（P1、2026-10-06）: 調べと直し

Status: test-wait（T1 依頼中。QEMU は有線の側だけ、本命の WiFi の側は次の UAT の log が要る）

source の読み（networkd・kernel の route・AX211 の recovery）:

1. **有線の撤回は wlan0 に触れない。** 有線の cable が抜けると `lan_take_down` が `ifconfig ue0 down`、`lan_l3_forget(ue0, 1)` で ue0 の default
   （`delete_interface_default_exact`: flags・ifindex・宛先・gateway・mask が一致する 1 本だけを `SIOCDELRT`、kernel も ifindex の device の route だけを消す）、
   `apply_network_preference` で WiFi の lease の default（10.0.30.1 via wlan0、join の時の snapshot、flags は RTF_UP|RTF_GATEWAY|RTF_DYNAMIC で
   kernel が受ける）と resolver を張り直す。WiFi の join の時に有線が優先で撤回された WiFi の default は、snapshot が撤回の前なので
   `default_route_owned` のまま残り、張り直しの対象になる。ue0 の event は managed-wlan の側では ifindex で弾かれる。→ 読みの範囲では、別の subnet の
   今回の構成で networkd が WiFi の状態を CONNECTED から外す経路は無い。
2. **見つけた欠陥（直した、e2d6099b）**: 有線の cable が抜けても ue0 の IPv4 address と subnet の route が残っていた（kernel は down の device の
   route も検索で選び、networkd は ue0 をすぐ up し直す）。同じ subnet の WiFi なら LAN 宛が死んだ ue0 へ向かう。今回の構成（別 subnet）の症状の説明には
   ならないが、BUG-213 と同根なので直した: `lan_take_down` で netmask・broadcast・address を 0 にする（`lan_clear_address`）。
3. **本命の見込み（未確認）: AX211 の recovery。** networkd の WiFi が CONNECTED から外れる経路は wlan0 自身の carrier down（`RECOVER` → 同じ profile の
   reconnect → 失敗で retire → 自動の検索）だけ。AX211 は firmware・DMA の失敗で recovery を latch し（`ax211_pci_recovery_latch_locked`）、recovery の
   間は connect の admission を ENETDOWN で断る（ws005-p031 の残り）。「AP を押すと Connecting になってすぐ失敗し、WiFi の off・on（radio の down・up で
   firmware を始め直す）まで戻らない」はこれと合う。有線の down で traffic が WiFi に移った時の送信の経路、または有線の間に idle だった WiFi の
   association がその前に切れていた可能性がある（どちらも log で分かる）。

直し（commit、base 1303ddbb）: e2d6099b（address の消去、Settings の Status）、dfc36f2f（networkd の log: `networkd: IF: cable out; taking it down`、
`networkd: wlan0: Wi-Fi link lost; reconnecting`、`networkd: wlan0: Wi-Fi reconnect failed; searching again`）。
