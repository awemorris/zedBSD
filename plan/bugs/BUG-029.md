# BUG-029: tmpfs に約 230 個の file を作ると、system 全体で file を開けなくなる

Bug ID: `BUG-029`
Reproduction: reproduced（QEMU、amd64 guest）
Disposition: tracking
Date: 2026-09-24
Source: ws043-p011（q388-i01）で、差分試験の case（約 900 file）を guest の `/tmp` に展開したとき `pax` が `No space left on device` で止まったことから観測。
Owner: none（未割当）
Queue: none。

## 期待と観測・影響

期待: `/tmp`（tmpfs、32 MiB）に、容量の範囲で何千もの小さい file を作れる（Linux の tmpfs の既定の file 数の上限は memory に比例して大きい）。

観測（起動直後の guest、`plan/tools/guest/guest.sh run`）:

```
mkdir /tmp/c; i=0; while [ $i -lt 1100 ]; do echo x > /tmp/c/f$i || break; i=$((i+1)); done
→ sh: cannot create /tmp/c/f230: No space left on device（230 個で止まる。df は 1% 使用）
echo y > /tmp/after      → No space left on device
: < /dev/null            → cannot open /dev/null: No space left on device
```

230 個を作った後は、tmpfs の外の `/dev/null` を開くことさえ ENOSPC になり、shell も先へ進めなくなった。消した後に作り直しても 196 個ほどで止まった（前の実験の残り）。

影響: 多くの一時 file を作る処理（configure の conftest、展開、試験の harness）が止まる。ws043-p011 は case を 40 件ずつに分けて回避した。

## 見立て（未検証）

- `src/kern/tmpfs.c` の node の上限は `TMPFS_DEFAULT_NODES`（1024）で、230 ではない。
- `src/kern/inode.c` の `INODE_COMMON_MAX`（256）が system 全体の in-core inode の表で、tmpfs の file が inode を常に占め続けるなら、
  system が使う inode と合わせて約 256 で尽き、どの file system でも新しい inode を得られなくなる（`/dev/null` も）。
- 検証していない。gdbstub で `ENOSPC` を返す場所を確かめるのが次の手。

## 次の条件

kernel の inode と file の上限を扱う作業（WS を立てるか、既存の kernel の WS）を選ぶときに再開する。受け入れの案: tmpfs に 10000 個の file を作って消せ、その間も他の file を開ける。

## 追記（2026-09-24、ws043-p012）

guest で sh の差分試験を 40 件ずつ（各 batch で展開して消す）36 回続けると、18 番目の batch あたりから status 2（file を作れない等）で落ちる case が増えた。
同じ case は起動直後の guest では通る。消した file の分が戻らず、長く使うと資源が減っていくことを示す（この bug と同じ原因かは未確認）。
