# BUG-188: Settings の WiFi の AP の一覧で、シングルタップでは接続されず、ダブルタップで接続される

Reproduction: reproduced（実機。2026-10-09 T1-491 の AAT settings-wifi-click-tap（QEMU）でも再現: 1 回の tap で join の要求が出ない）
Disposition: scheduled（2026-10-09 Q1、P1 q916）
Discovery: 2026-10-04 夜 ad-hoc UAT-3（実機 Latitude 5330、image `build/uat-3/hdd-image.img` sha256 ada4492e…、main efe846a、[uat.md の uat-3](../uat.md)）
Handling: WS089（Settings の Wi-Fi の頁の touch の扱い）

## 観測

ユーザー「SettingsのWiFi AP一覧で、タップで接続されない。ダブルタップでは接続される。シングルタップでも接続するべき。」

## 次

仕様（ユーザー）: シングルタップで接続する（マウスの 1 回のクリックと同じ）。1 回目のタップが行の選択（focus・highlight）に使われ、2 回目で活性化になっている、または touch の down・up を click に変換する所で 1 回目を捨てている疑い。マウスのクリックで 1 回で接続するかと比べる。他の一覧（Files など）の touch の扱いと揃える。修正は P3 の q700（Settings の Wi-Fi の BUG-183〜187 と一緒）。

## 保留（2026-10-05 未明、q703-i01 P2 generation14。ユーザーの方針「既存BUGはいったん保留して、新規実装を進める」）

- Settings 側を読んだ結果（差分なし）: Settings は wl_touch の down を press、up を release に変える（`window.c` の `window_touch_*`）。press と release が同じ領域なら click（`ui.c` の `ui_button`）で、マウスと同じ経路。1 回目のタップを選択に使う処理は無く、マウスの 1 回のクリックで join する。Settings 側に 1 回目のタップを捨てる経路は見当たらない。
- 根は [BUG-190](BUG-190.md)（compositor・タッチパッドの tap が press を出さない、P1 の q700）の可能性が高い（Q1 了承、2026-10-05）。再開点: BUG-190 の修正の後に、AP の一覧のシングルタップを一緒に確かめる。

## 再開（2026-10-05、P2 / q703）

- 変更なし。BUG-190 の判断（touchpad の tap は離した時の click、ws159-p004）を待つ。Settings 側は press と release が同じ領域なら click で、1 回目を捨てる経路は無い（前の記録のとおり）。再開点: ws159-p005 の UAT で AP の一覧のシングルタップ（touchpad の tap と touchscreen）を確かめる。
