# BUG-180: 最大化した窓を上部のバーからドラッグで外すと、いったん外れた後に一度最大の大きさに戻ってから小さくなる

Reproduction: reproduced（実機）
Disposition: tracking（優先度: 高）
Discovery: 2026-10-04 夜 ad-hoc UAT-3（実機 Latitude 5330、image `build/uat-3/hdd-image.img` sha256 ada4492e…、main efe846a、[uat.md の uat-3](../uat.md)）
Handling: WS099（compositor の窓の操作）

## 観測

ユーザー「最大化したウィンドウを、スクリーン上部バーからドラッグで外すとき、いっかいスムーズに外れるが、さらにドラッグすると一度最大サイズになってからまだ小さくなる。この問題を修正して。」

## 次

unmaximize の時に client へ送る configure の順（元の大きさ）と、ドラッグ中の位置の更新が、client の古い大きさの buffer（最大のまま）を一度表示している疑い。unmaximize の configure の ack を待ってから元の大きさで描く、または古い buffer を縮めて見せない。 修正は P3（Bug の修正の担当、phase-runner-mid）の Queue で。QEMU の確認は T1、実機は次の UAT。

## 原因と修正（2026-10-05 P1 generation17 / q700-i01。build まで、QEMU・実機は未実施）

- 原因 1: pull（上部の bar から下へ引く）では、窓は引いた距離に合わせて docked の大きさから自分の大きさへ縮む（`pulled_rect`）。外れる時の `window_undock` は animation を **docked の空間（最大）から**始めていた（`docked_rect`）。さらに呼ぶ前に `pull_distance` を 0 にしていた。そのため、一度小さくなった窓が最大に戻ってから縮んでいた。報告の「いったん外れた後に一度最大の大きさに戻ってから小さくなる」と一致する。
- 原因 2: animation の後、client が元の大きさで描き直すまで、最大の大きさの古い image がその大きさのまま描かれていた（`body_rect` は浮いた窓を image の大きさで描く）。
- 修正（`shell.c`・`zwl.h`・`display.c`）: `window_undock` の始点を今描いている矩形（`body_rect`、pull の終わりなら自分の大きさ）にし、`pull_distance` は undock の後に 0 にする。dock・undock で `resized_ms`・`resized_serial` を記録する。戻した窓は、client が configure を ack して docked の大きさ以外の image を描くまで（最長 1 秒、`RESIZED_HOLD_MS`）、送った大きさで描く。描き終わりは `zwl_glass_committed`（commit の時）で、log `GLASS resized … docked=0`。
- 残り: QEMU の確認（T1、docked の窓を bar から下へ drag して undock via=pull の後の画面に最大の大きさが出ないこと。p030-drag の pull、p013）、実機の UAT。
- 2026-10-05 ユーザーの方針で保留（差分は WIP commit 済み）。
