# BUG-421: 新しい checkout で NoctLang の patch が当たらず `make sysroot` が止まる

- 状態: fixed（2026-11-12 ユーザーが直した、0958bc742e）
- 発見: 2026-11-12 Q1。BUG-420 の確かめで、main から作った新しい worktree（`build/` は空）で `make CONFIGMK=<PLATFORM := i386> sysroot` を流した。
- 起きた事: `mk/noct/noct.mk` が `userland/base/noct/distfiles/NoctLang-d198b952dec90120c3d0e7987dd12af06911478e.tar.gz` を codeload.github.com から取得し、`build/NoctLang` に展開して `userland/base/noct/patches/*.patch` を当てる所で、`CMakeLists.txt` の hunk（:741）が FAILED、`.patched` の規則が Error 1。main の checkout は `build/NoctLang` が既にあるので（`CMakeLists.txt` が在れば展開も patch もしない、`noct.mk:39-46`）、表に出ていなかった見込み。
- 見込み（未確認）: codeload の tarball の中身が、patch を作った時の source と違う（commit の固定は同じでも生成の差か、patch が別の版の source に合わせて作られた）。main の `build/NoctLang/CMakeLists.txt` と取得した tarball の物を比べれば分かる。
- 影響: 新しい checkout・CI・新しい worktree で sysroot（と userland）を作れない。
- 確かめていない事: 取得した tarball の SHA-256（`noct.mk` は確かめていない）、他の patch が当たるか。

## 経過

- 2026-11-12 ユーザー: NoctLang の patch は上流に入っているので消した（`mk/noct/noct.mk` の `NOCT_PATCHES` を空に、tarball の置き場を `build/` に、0958bc742e）。
- 2026-11-12 Q1 の確かめ（main から作った新しい worktree、i386）: `make llvm-toolchain-cached` rc 0 → `make sysroot` rc 0 → `make BUILD=build/i386 build/i386/vmunix` rc 0・warning 0。
