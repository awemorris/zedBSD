# BUG-208: 最大化（dock）中の Terminal で F11 を押すと bar が消えるだけで窓の content の領域が変わらない

Reproduction: reproduced（ユーザー、Windows の QEMU（Venus）で uat-0505g、2026-10-05 夜 UAT）
Disposition: scheduled（修正 2026-10-06 P2、QEMU の確認は T1 待ち）
Discovery: 2026-10-05 夜 ユーザーの UAT のコメント
Handling: WS099（compositor）・BUG-194（Terminal の全画面と F11・Super+↓）の続き

## 観測

ユーザー「ターミナルアプリでウィンドウ最大化（ドック）中にF11を押すと、画面上部のバーが消えるだけで、ウィンドウのコンテント領域が変わらない。バーの部分はデスクトップが見える。」

## 次（未確認の見込み）

docked の窓が fullscreen に入る時、compositor が bar を隠すが、窓に全画面の大きさの configure を送らない（または docked の geometry が fullscreen より優先される）。BUG-194 の試験（bug194-guest.sh）は浮いた窓で F11 を確かめていて、dock の中からの F11 を含まない。dock → fullscreen → 戻ると dock に戻ること、を試験に足す。

## 原因（2026-10-06 P2、source を読んで）

Terminal の F11 は Terminal の set_fullscreen で、compositor の `zwl_window_enter_fullscreen()`（protocol.c）は
`fullscreen = 1` にして全画面の configure（1280x800、fullscreen state）を送っていた。しかし dock の印（`maximized`）が
残ったままで、shell.c の `body_rect()` は `maximized` を先に見て窓の body を dock の領域（bar の下）に描いていた。
bar は fullscreen の窓のために隠れるので、bar のあった所に desktop が見えた。`maximized` の判定は shell.c の多くの
所（pull、title、hit test）にあり、fullscreen を除く確かめが揃っていない。

## 修正（2026-10-06 P2）

- `zwl_object` に `fullscreen_docked` を足した（zwl.h）。dock 中の窓が fullscreen に入ると `maximized = 0`・
  `fullscreen_docked = 1` にし（dock の animation が残っていれば終える）、浮いた窓の fullscreen と同じ経路で置き・描く。
- fullscreen を出る時（`zwl_window_leave_fullscreen()`、Terminal の unset・F11・Super+↓・下端の swipe の全部）、
  `fullscreen_docked` なら dock に戻す: x=0、y=`ZWL_GLASS_DOCK_TOP`、大きさは bar の下から on-screen keyboard の panel を
  除いた領域（keyboard.c・`docked_rect()` と同じ式）、configure は maximized state。dock の前の浮いた場所（restore_*）は
  触らないので、その後の undock は元の場所へ戻る。log の `ZWL WINDOW unfullscreen` の末尾に `docked=` を足した。
- `window_dock()`（shell.c）は fullscreen の窓を dock しない（maximized と fullscreen が同時に立つ状態を作らない）。
