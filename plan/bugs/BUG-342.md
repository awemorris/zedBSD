# BUG-342: PowerVR の session の GPU の VA に mainline の static data area（MCU fence・VDM sync・EOT 等）が無い

- 状態: unknown / resolved（2026-10-31 P2、VF2 の実機で fault 無し。closed の案）
- 発見: design-reviewer の design-p010 の版 2 の差分の確認（plan/ws269/design-p010-review-2.md の M-4、2026-10-20）。
- 中身: mainline v7.3 は各 VM の heap の先頭に固定の区画を出す（`pvr_vm.c:912-943`）: GENERAL+0 MCU fence（「must point to valid physical memory」、`pvr_drm.h:346-352`）、GENERAL+128 YUV の係数、PDSCODEDATA+0 VDM sync の PDS、PDSCODEDATA+128 EOT の PDS、USCCODE+0 VDM sync の USC。各 heap の割り当てはその後ろの page から。Mesa は VM ごとにこの区画を埋める（`pvr_winsys_helper.c:281-350`）。zedBSD の session の GENERAL の割り当ては base+0 から（`render.c:587`）、PDS・USC の program は base+0x10000（`vk-queue.c:63-67`）。
- 起こる事（推測）: cache の flush の時に MCU の fence が session の最初の resource を上書きするか、未写像で fault する。p009 の実機の compute（beta2 U35 の vkcompute）に関わり得る。
- 関係: WS269 p006・p009・p010d。

## 修正（2026-10-20、bug-fixer、実機は未確認）

- 状態は scheduled のまま（VF2 の実機で compute を流して確かめるまで resolved にしない）。
- 出典（取得して読んだ物）: Linux v7.3（`c03c1a14507dfaf8b856c2608f9ac216021fc222`）の `drivers/gpu/drm/imagination/pvr_vm.c:912-945`・`pvr_fw.c`（`fw_sysinit_init`）・`include/uapi/drm/pvr_drm.h:330-412`。Mesa 26.2.5（`ddaf85e353442d9d7f192fdcf1823e652e3f2ee3`）の `src/imagination/vulkan/winsys/pvr_winsys_helper.c:207-350`・`vulkan/pds/pvr_pds.c`（`pvr_pds_kick_usc`・`pvr_pds_generate_pixel_event`・`pvr_pds_setup_doutu`）・`pco/usclib/common.cl`（`vs_nop_common`）・`pco/uscgen/pco_clc.c`・`pco/pco_end.c`・`pco/pco_map.py`・`pco/pco_map.h.py`・`pco/pco_group_instrs.c`・`pco/pco_binary.c`・`csbgen/rogue/pds.xml`。取得物は worktree の `build/bug342/ref/`（git に入れない）。
- 変更:
  - 新しい `src/drivers/gpu/powervr/fixed-area.h`・`fixed-area.c`: 5 区画の offset・size（GENERAL+0 fence 128、GENERAL+128 色の係数 1024、PDS+0 VDM sync 128、PDS+128 EOT 128、USC+0 VDM sync 128）と各 heap の予約（最後の区画の終わりを page に切り上げ、3 heap とも 0x1000）。`powervr_fixed_area_write()` が PDS と USC の page に program を書く。
    - VDM sync の PDS（PDS+0）: data 8 word（先頭 64 bit が DOUTU の task word = USC の offset 0・temps 0・INSTANCE の rate → 0）、code は data の後（+32）に DOUTU 1 word（end、src0 = 定数 0）= `0xf4000002`。
    - EOT の PDS の code（PDS+128）: emit word の無い pixel event の code = DOUTU 1 word（end、src0 = 定数 0）= `0xf4000002`。
    - VDM sync の USC（USC+0）: Mesa の `VS_NOP_COMMON`（空の vertex program）を pco が作る形 = main の group 1 つ（back end だけ、`uvsw.emit.endtask`、end、cc e1_zx、rpt 1）。p008 の usc-encode で書けた（8 byte: `44 a0 80 05 00 00 00 ff`）。0 の page で代える必要は無かった。
    - GENERAL の page（fence と色の係数）は 0 のまま（fence は中身を読まない。色の係数は YCbCr の sampler だけが読み、この driver は出していない）。
  - `render-queue.c`: `powervr_session_fixed_make()`（3 page を作り program を書く、core の lock の外）・`map_fixed_area()`（`powervr_session_firmware_create` の中で mmu の init の直後に 3 heap の base に予約の bytes だけ写像、SLC bypass）・`powervr_session_fixed_drop()`（`firmware_destroy` で table を返した後）・`keep_fixed_area()`（`firmware_discard` で kept buffers に移し、reset が続けて解放。core の lock の下で buffer guard を取らない）。
  - `render.c` `render_open`: session の GENERAL の space を `base+0x1000` から（大きさも 0x1000 減らす）。page を作ってから lock を取り、失敗の時は drop。
  - `vk-queue.c`: comment だけ（executor の PDS・USC の program の置き場所 base+0x10000 は予約の外）。`compute-check.c` の置き場所（GENERAL+0x100000・+0x400000、PDS/USC+0x10000）も予約の外で変更なし。
  - `firmware-boot.c` の sysinit: 変更なし。`pds_exec_base`・`usc_exec_base` に PDSCODEDATA・USCCODE の heap の base を入れている点は mainline の `fw_sysinit_init` と同じで、区画はこの base からの offset。
  - `platform/riscv64/vmunix.mk` に `fixed-area.c` を足した。
- 推測のまま残る点:
  - `VS_NOP_COMMON` の temps（Mesa の precomp の `temps`）は空の program なので 0 とした（Mesa の build の生成物は見ていない）。
  - FW・硬がこの区画をいつ使うか（VDM sync は geometry の段、EOT は fragment の段と読める）は未確認。compute だけの今の道で使われるのは fence（cache の flush）だけと推測。
  - 色の係数の表（Mesa の `pvr_setup_static_yuv_csc_table`）は入れていない。YCbCr の sampler を出す時に要る。
- 確かめ（host・build のみ。QEMU・実機は未実施）:
  - `plan/tools/powervr/p006/run.sh`: PASS 95 FAIL 0（足した case: 区画が予約に収まる、session の最初の割り当てが base+0x1000、区画の写像と最初の割り当て・executor の PDS/USC+0x10000 が衝突しない、区画の上に重ねると EEXIST、program の中身の word・byte）。
  - `plan/tools/powervr/p009/run.sh`: spirv 69 passed 0 failed、executor 112 passed 0 failed（足した case: executor の写像が各 heap の予約の外、resource が GENERAL の予約の外）。
  - build: `config/ci/config-visionfive2.mk` から `powervr-firmware` を外した config で VF2 の vmunix rc=0・warning 0・error 0、`config/ci/config-riscv64-virt.mk` の vmunix rc=0・warning 0（powervr は入らない）。
- 残り: VF2 の実機で vkcompute（p009）と gpu-selftest を流し、fault・FW の page fault（FWCCB 112）が無い事を T1 で確かめる。確かめたら resolved。

## 実機の確認（2026-10-31 P2、q1772-i01）

- kernel: main cf41e7630 を `plan/ws291/tests/config-vf2.mk` で build（cksum 2495964150、warning 0）。userland は板の物（gpu-selftest・vkcompute は /bin）。
- `plan/tools/vf2/boot-cycle.sh`（GPU=1）の 1 回目の起動の後: `sudo gpu-selftest` → `13 ok, 0 fail, 0 skip`、`sudo vkcompute` → `PASS, 4096/4096 words`。
  その間に kernel が足した行は 2 行（compute の shader の compile の報告）だけで、fault・lost・reset・hang・FWCCB の page fault は 0。
- 証拠: `/tmp/p2-vf2bugs/runA/boot1/`（gpu-selftest.txt・vkcompute.txt・gpu.kernel）。git の外。
- 読み: session の GENERAL・PDS・USC の heap の先頭の固定の区画を写像した後も compute・3D の試験が通り、FW の fault は出ない。
  区画を FW が実際に使ったか（MCU の fence の書き込み）は観測していない。
