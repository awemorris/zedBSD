# BUG-030: amd64 の起動時に USB mass storage の読み取りが時々 error 42 で失敗する

Bug ID: `BUG-030`
Reproduction: reproduced（QEMU、間欠）
Disposition: tracking
Date: 2026-09-24
Source: ws042-p008（q395-i01）の boot test の画面。同じ症状が ws042-p005（q392）の boot test の画面（`build/boot-test-amd64-p005/login.txt`）にもあった。
Owner: none（未割当）
Queue: none。

## 期待と観測・影響

期待: `plan/tools/boot-test.sh`（`BOOT_MODE=uefi-usb`、QEMU の xHCI に usb-storage）で、root の image を読み取り error なしに起動する。

観測（boot test が撮った画面。serial log ではない）:

```
usb-storage: BOT CSW error=42 actual=0 status=0 tag=0 expected-tag=366
usb-storage: sda op=28 lba=148360 blocks=16 error=42 sense=unavailable
loop0: read block=9456 count=16 flags=0 error=42
init: exec /usr/libexec/sshd-start: Connection timed out
```

p005 の回では `BOT data dir=in error=42` も出て、`chmod` と `/bin/login` の exec が `Connection timed out` になった（getty は再起動して login prompt に届いた）。
error 42 は ETIMEDOUT（`Connection timed out`）と表示される。どちらの回も login prompt までは届き、boot test は PASS。

影響: 起動の途中の file の読み取りが失敗し、その file を使う service（sshd など）が起動に失敗することがある。

## 再現の条件

- amd64、`build/ws043-guest/hdd-image.img`（q395）と p005 の image、`BOOT_MODE=uefi-usb`（既定）、KVM。
- 毎回ではない。q395 の guest の起動（`guest.py start`、別の disk 構成）ではこの症状は見ていない（未確認: guest.py の起動の画面は撮っていない）。
- 頻度・QEMU の版との関係・host の負荷（並行の build）との関係は未調査。

## 調べたこと

- なし（記録だけ）。vi mode の変更（sh の行編集）は USB の経路と関係が無い。p005 は vi mode の変更の前。

## 再開の条件

USB storage・xHCI を扱う WS か、boot test の失敗として現れたとき。受け入れ案: boot test を 20 回続けて、画面に usb-storage の error が出ない。
