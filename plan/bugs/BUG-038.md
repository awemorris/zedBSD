# BUG-038: UFS の directory が 1 block（8 KiB）を超えて育たず、ENOSPC になる

Bug ID: `BUG-038`
Reproduction: reproduced（QEMU、amd64 guest）
Disposition: resolved（WS054、q414〜q416、2026-09-25）
Date: 2026-09-24
Source: ws046-p008（q412-i01）で、guest で coreutils 9.12 の source を UFS（1 GiB、inode 16384）に展開したとき。
Owner: WS054
Queue: none（WS054 として計画）

## 期待と観測・影響

期待: directory に file を足し続けられる（空きがある限り）。

観測（guest の UFS、block 8192 byte）:

- coreutils の `m4/`（492 の file）の展開が 370 番目の file で `No space left on device`。directory の大きさは 8192 byte のまま、空きは 917 MiB、inode も余っている。
- 空の directory に短い名前の file を作り続けると 670 番目で `No space left on device`。

原因（source を読んだ）: `src/drivers/fs/ufs.c` の `dir_add()` は directory の最初の block（`direct[0]`）だけを編集し、
「A directory that would outgrow one block cannot be extended here.」で ENOSPC を返す。`dir_find_record()`・`dir_remove()`・`dir_replace()`、
journal の group（`creation_group`・`link_group`・`rename_group`・`remove_group`）、`initial_block_locked()` も `direct[0]` だけを扱う（`direct[0]` の参照 36 か所）。

影響: 数百を超える file を持つ directory を作れない。guest で coreutils（`m4/`・`lib/`・`tests/`）などの大きな package を展開・build できない（ws046-p008）。

## 再開の条件

WS054（UFS の directory を複数の block に）。受け入れ案: 1 つの directory に 1 万の file を作り・探し・消し・rename でき、再起動（再 mount）の後も同じ、journal の復旧も正しい。

## 直した（WS054、2026-09-25）

directory が直接の 12 block（bsize 8192 で 96 KiB）まで育つ。journal 無しの経路（`dir_add()` ほか）は q414、journal の group は q415、回帰は q416。
guest で 1 つの directory に短い名前 4031（12 block）まで作れ、越えると ENOSPC。coreutils の source の展開が通った。間接 block まで育てるのは F-010。
