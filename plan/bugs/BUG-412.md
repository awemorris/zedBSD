# BUG-412: Pi 5 の desktop で click が効かない（button を 1 秒以上押したまま動かさずに離すと初めて click になる）

- 状態: open・再現せず（2026-11-02 11:02 Q1 が起票、P3 q1936-i01。13:13 P3: 注入でも実の mouse でも、新旧どちらの kernel でも短い click が効いた。原因は未特定）
- 発見: 2026-11-02 11:02 ユーザーの Pi 5 の UAT。Settings で click が効かない。desktop 全体で効かないらしい。mouse の button を押して 1 秒以上保ち、動かさずに離すと初めて click として認識される。
- 疑い: 長押しの判定（touch 向けの long press・右 click の代わり）や、押した後の微小な移動・時刻の扱いが mouse に誤って効いている。USB の mouse の report の時刻、compositor の pointer の button の処理、libkeiland の click の判定のどれか。
- 扱い: P3（q1936、Pi 5）。

## 2026-11-02 P3 の調べ（q1936-i01、Pi 5 10.0.30.7）

結論: **再現しない**。短い click（38〜67 ms）が、注入の入力でも実の Logitech の mouse でも、board の image の kernel（8f91a0d）でも main の kernel（8e5e20cec）でも Settings の list の行を押し、page が変わった。原因・修正は無し。

- 機器: mouse は Logi Bolt の受信機 046d:c548（usb0、interface 1、report ID 2 = button 16・X/Y 16 bit、`/dev/input/event0`）。keyboard は有線の Keychron C3 Pro（usb1）。
- 注入（AAT の kernel、`plan/tools/aat/config-rpi5-aat.mk` を 8e5e20cec で build、`aat-input`）: 絶対の pointer の button、相対の mouse の button（`aat-input` に足した `mouse-down`・`mouse-up`）、
  押す間 0・30・60 ms と 1300・1500 ms、押す間の 1〜3 px の移動、相対の移動の直後の click で、Settings の list の行の click は約 40 回とも page が変わった（`plan/bugs/BUG-412/trial.sh`）。
  初めの「相対の短い click が効かない」は行の間を押した誤りだった（取り消し）。
- 実の mouse（ユーザーの click を Q1 が頼んだ。`/dev/input/event0` を `dd` で並行に読み、`plan/bugs/BUG-412/evdump.py` で解いた。Settings の `session.log` と照合）:
  - kernel 8e5e20cec（AAT の注入と usb-hid の時刻の記録の入り）: 9 回。728 ms（title bar の list の切り替え → activate）と 45〜67 ms の 8 回。8 回とも Settings に press が届き（`KWL PING pong` 8 回）、7 回 page が変わった（残り 1 回は表示中の行か行の間）。押す間に 6〜24 count の移動が入った click も効いた（`real-clicks-8e5e20cec.txt`）。
  - kernel 8f91a0d（board の image の物、13:10）: 5 回。255 ms（title bar）と 45・38・60・52 ms の 4 回。4 回とも press が届き page が変わった（`real-clicks-8f91a0d.txt`）。
- kernel の USB HID の経路: 一時の記録（`plan/bugs/BUG-412/usb-hid-timing.patch`、commit していない）で、完了から再 arm まで 1 ms 以下。受信機の keyboard の interface 0 は idle の report を 500 ms ごとに送る（SET_IDLE(0) を送っていないため。害は見えない）。
- 起票の 11:0x の session（`/run/user/1000/session.log` を P3 が回収）も、Settings に届いた press 5 回は全部 page を変えていた。短い click が効かなかったのなら、その press は compositor から Settings に届いていない（それを示す log の行は compositor に無い）。
- 起票の時の別の状態: 起動の直後に Ethernet の link が上下を繰り返し（`gem: en0 link up/down`）、Settings の network の状態が 1〜2 秒ごとに変わっていた。これが click に効くかは未確認（注入の試験の時は止んでいた）。
- 未実施: 起票の時と同じ状態（起動の直後、Welcome、link の上下の最中）での実の mouse の短い click。compositor が press を自分で取った時の log が無いので、次に再現した時のために、その記録を足すかは Q1 の判断。
- board: 13:12 に元へ戻した（`pi5-aat-board.sh restore` → RESTORED OK、vmunix=2112791070 cmdline.txt=3178356281 config.txt=2738850246）。deploy が書いた `~/.ssh/authorized_keys`（user）は残る。
