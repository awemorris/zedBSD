# BUG-412: Pi 5 の desktop で click が効かない（button を 1 秒以上押したまま動かさずに離すと初めて click になる）

- 状態: open・再現せず（2026-11-02 11:02 Q1 が起票、P3 q1936-i01。13:13 P3: 注入でも実の mouse でも、新旧どちらの kernel でも短い click が効いた。原因は未特定）
- 発見: 2026-11-02 11:02 ユーザーの Pi 5 の UAT。Settings で click が効かない。desktop 全体で効かないらしい。mouse の button を押して 1 秒以上保ち、動かさずに離すと初めて click として認識される。
- 疑い: 長押しの判定（touch 向けの long press・右 click の代わり）や、押した後の微小な移動・時刻の扱いが mouse に誤って効いている。USB の mouse の report の時刻、compositor の pointer の button の処理、libkeiland の click の判定のどれか。
- 扱い: P3（q1936、Pi 5）。2026-11-02 13:30 P3 q1945-i01: compositor に、client に届かなかった press の log（`KWL PRESS`）を足した（下の節）。次に起きたら Pi 5 の `/run/user/1000/session.log` の `KWL PRESS` の行を回収する。

## ユーザーの観察（2026-11-02 14:05）

ユーザーから、押した位置から少しずらして離すと、短い押しでも click として認識される、という趣旨の観察を受けた。動かさずに短く押して離す click だけが効かない形。

## Q1 の判断（2026-11-02 13:17）

再現しないので、compositor が自分で受け取って client に渡さない press（title bar・menu・glass・gesture など）を、理由と座標・時刻付きの 1 行の log に出す口を足す（P3 q1945）。次に起きた時に、press が compositor で止まったかを log で分けられるようにする。

## 2026-11-02 P3 の診断の log（q1945-i01）

compositor（`userland/desktop/wayland/`）の通常の build に、client が聞かなかった pointer の button の 1 行の log を足した。動作は変えていない（各 handler の戻り値は同じで、理由の名前を返すだけ）。

- どこで出すか: すべての pointer の button（mouse・touch pad、touch と pen が左 button として通る物も）が通る `seat.c` の `kwl_seat_button_shell`（compositor の取り分）と `kwl_seat_button_deliver`（client への配達）。
- 行の種類（`KWL PRESS <fate> reason=<理由> ...`）:
  - `press-kept`: compositor が押下を取り、client に渡さなかった。
  - `release-kept`: 押下は client に渡ったが、離しを compositor が取った（client には押しっぱなしに見える。短い click が効かない時に疑う所）。
  - `press-lost`・`release-lost`: compositor は取らなかったが、届け先が無い。`no-surface`（focus の surface が無い）、`client-gone`（client が死んだ・fatal）、`no-pointer`（client に生きた wl_pointer が無い。この時も配達の処理自体は今まで通り走る）。
  - client に普通に届いた press と release は何も書かない。client 側の受け取りは今まで通り Settings の `KWL PING pong` などで見る。
- `reason=`（取った物）: `seat.c` の `lock`・`drag-and-drop`・`window-operation`（client が頼んだ move・resize の最中）・`resize`・`popup-grab`。glass の look（`shell.c` の `kwl_glass_button`）の `greeter`・`bluetooth-ask`・`power-dialog`・`notify`・`switcher`・`wiseview`・`third-click`・`corner`・`keyboard`・`band`・`home`・`status-panel`・`media`・`ime`・`volume`・`network`・`bluetooth`・`arrange`・`menu`・`apps-bar`・`titlebar`・`desktop-swipe`・`home-edge`・`pull`・`title-tap`・`arrange-move`・`move`・`system-bar`・`head-bar`・`docked-space`・`sheet`・`other-button`（body 以外の右・中 button）・`desktop`・`frame`・`close`・`maximize`・`minimize`・`triple-click`・`title-move`。fullscreen の window の上（`kwl_glass_edge_button`）の `unfullscreen`・`wiseview`・`corner`・`keyboard`・`band`・`home`・`home-corner`。名前の無い取り方は `glass`・`fullscreen-edge` になる。
- 他の field: `button=`（evdev の code、左 272・右 273・中 274）、`source=`（pointer・touch・pen）、`x=`・`y=`（compositor の座標）、`output=`、`under=`・`part=`・`under_app=`（その点の一番上の window の surface の ID、title・body・frame・none、app_id。glass の look の時だけ）、`focus=`・`role=`・`client=`・`app=`（focus の surface、toplevel・popup・subsurface・other・none、client の番号、app_id）、`pointer=`（pointer の event の届け先の surface の ID）、`time=`（event の時刻 ms、client に渡す物と同じ）、`at_ms=`（compositor の monotonic の時計 ms）、`held_ms=`（release の行で、client に渡った press からの時間）、`skipped=`（1 秒に 20 行の上限で書かなかった行の数。次に書いた行に出る）。
- 例: `KWL PRESS release-kept reason=title-tap button=272 source=pointer x=400 y=300 output=0 under=21 part=body under_app=org.example.settings focus=21 role=other client=7 app=org.example.settings pointer=21 time=5147 at_ms=5147 held_ms=52 skipped=0`（host の試験の出力）。
- 読み方: 再現した時刻の前後の `KWL PRESS` を見る。押した点の `press-kept` があれば、その `reason=` が click を取った物。`release-kept` で `held_ms` が短いなら、短い click だけが壊れる候補。`press-lost` なら focus か wl_pointer が無い。どの行も無く、Settings の `KWL PING pong` も無いなら、press は compositor の seat まで来ていない（入力の thread・kernel の側を疑う）。
- 変えた file: `userland/desktop/wayland/seat.c`（log・上限・記録。`kwl_seat_button_shell` の本体を static の `button_shell` に移し、公開の関数は理由を受けて log を書く）、`shell.c`（`kwl_glass_button`・`kwl_glass_edge_button` に `const char **by` を足し、取った所ごとに名前を入れる。点の window と部分を返す `kwl_glass_part_at`）、`kwl.h`（その宣言）。

## 2026-11-02 P3 の調べ（q1936-i01、Pi 5 10.0.30.7）

結論: **再現しない**。短い click（38〜67 ms）が、注入の入力でも実の Logitech の mouse でも、board の image の kernel（8f91a0d）でも main の kernel（8e5e20cec）でも Settings の list の行を押し、page が変わった。原因・修正は無し。

- 機器: mouse は Logi Bolt の受信機 046d:c548（usb0、interface 1、report ID 2 = button 16・X/Y 16 bit、`/dev/input/event0`）。keyboard は有線の Keychron C3 Pro（usb1）。
- 注入（AAT の kernel、`plan/tools/aat/config-rpi5-aat.mk` を 8e5e20cec で build、`aat-input`）: 絶対の pointer の button、相対の mouse の button（`aat-input` に足した `mouse-down`・`mouse-up`）、
  押す間 0・30・60 ms と 1300・1500 ms、押す間の 1〜3 px の移動、相対の移動の直後の click で、Settings の list の行の click は約 40 回とも page が変わった（`plan/bugs/BUG-412/trial.sh`）。
  初めの「相対の短い click が効かない」は行の間を押した誤りだった（取り消し）。
- 実の mouse（ユーザーの click を Q1 が頼んだ。`/dev/input/event0` を `dd` で並行に読み、`plan/bugs/BUG-412/evdump.py` で解いた。Settings の `session.log` と照合）:
  - kernel 8e5e20cec（AAT の注入と usb-hid の時刻の記録の入り）: 9 回。728 ms（title bar の list の切り替え → activate）と 45〜67 ms の 8 回。8 回とも Settings に press が届き（`KWL PING pong` 8 回）、7 回 page が変わった（残り 1 回は表示中の行か行の間）。押す間に 6〜24 count の移動が入った click も効いた（`real-clicks-8e5e20cec.txt`）。
  - kernel 8f91a0d（board の image の物、13:10）: 5 回。255 ms（title bar）と 45・38・60・52 ms の 4 回。4 回とも press が届き page が変わった（`real-clicks-8f91a0d.txt`）。
- kernel の USB HID の経路: 一時の記録（`plan/bugs/BUG-412/usb-hid-timing.patch`、commit していない）で、完了から再 arm まで 1 ms 以下。受信機の keyboard の interface 0 は idle の report を 500 ms ごとに送る（SET_IDLE(0) を送っていないため。害は見えない）。
- 起票の 11:0x の session（`/run/user/1000/session.log` を P3 が回収）も、Settings に届いた press 5 回は全部 page を変えていた。短い click が効かなかったのなら、その press は compositor から Settings に届いていない（それを示す log の行は compositor に無い）。
- 起票の時の別の状態: 起動の直後に Ethernet の link が上下を繰り返し（`gem: en0 link up/down`）、Settings の network の状態が 1〜2 秒ごとに変わっていた。これが click に効くかは未確認（注入の試験の時は止んでいた）。
- 未実施: 起票の時と同じ状態（起動の直後、Welcome、link の上下の最中）での実の mouse の短い click。compositor が press を自分で取った時の log が無いので、次に再現した時のために、その記録を足すかは Q1 の判断。
