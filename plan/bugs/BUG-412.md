## 2026-11-02 14:34 実の mouse の session の解析（P3 q1955-i01）

ユーザーが Pi 5 で click の session をした（kernel は修正の候補の build、vmunix cksum 1081511815、dmesg に vendor の interface 2 つの `drained`）。Q1 が `sh /tmp/collect.sh 80` を回収し、P3 が board の `session.log` と HID の dump（起動から 300 report）を足して解いた（`build/q1955/s2/` の `dump.txt`・`log.txt`、git に入れない）。

- 押しと離しの組 21 回。どれも compositor（`KWL FRAME`・`KWL BTN`）と Settings に届いた。
- 静止の click（押しと離しの間に動きの report が無い。HID の dump では押しの report `02 01 00 00 00 00 00` の次が離しの `02 00 ...`）: 5/5 で page が変わった（45 ms が 3 回、233 ms、841 ms）。**起票の症状（静止の短い click が効かない）はこの session では出なかった。**
- 押す間に動いた click（ユーザーが比べに少し動かした物）: 16 回、9〜76 px 動いた。12 回は効き、4 回は効かなかった（534270 の (436,331)→(512,350)、535110 の (507,345)→(467,324)、540150 の (466,261)→(509,272)、541913 の (464,263)→(487,269)）。4 回とも押した行と離した行が違う（行の境は Ethernet と Bluetooth の y≈262〜270、VPN と Network の y≈337〜345）。効いた 12 回は同じ行の中で離した。Settings の list は押した行の上で離した時だけ click にする（`settings/ui.c` の `ui_button`、GTK・WinUI の list と同じ決まり）ので、この 4 回は行の外への drag で、click が落ちたのではない。
- 動きの大きさ: 手の動きで、揺れでも decode の誤りでもない。534270 は押している間の report が 21 個、x に +1〜+6 count ずつ一方向（合計 dx=47、dy=12）、535110 は 20 個で -1〜-2（合計 -25、-14）。47 count が 76 px で 1 count が 1.6 px、既定の `mouse.speed` 150 % と acceleration strong（この遅さでは gain 約 1.1）のとおり。report の間隔・16 bit の decode に異常は無い。
- 押しの `placed=0`: 押しの report に動きが無い（押しの report は常に `02 01 00 00 00 ...`）という意味で、位置はその前の report までに当てた今の位置。古い位置ではない。離しの `placed=1` は離しの report にも動きがあった物で、`apply_frame` は動きを button より先に当てる（HID の report の順として正しい）。
- 修正の候補の kernel が効いたか: 分からない。前の kernel（8f91a0d・8e5e20cec）での実の mouse の session でも静止の click は全部効いており、記録を取っている間に症状が出たことは一度も無い。分けるには、同じ session を元の kernel（`vmunix.aatold`）と同じ診断で行う。
- 判断の案（Q1 へ送った）: Settings・compositor は変えない（他の desktop と同じ）。usb-hid の vendor の interface を読んで捨てる変更は害が無く Linux・Windows と同じ扱いなので残す。BUG-412 は観察を続ける。必要なら製品の判断として、既定の `mouse.speed` 150 % と strong の acceleration で手の小さな動きが 1 count 1.6 px になる点。
