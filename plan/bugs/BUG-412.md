## 2026-11-02 P3 の修正の候補（q1970-i01、build と host の試験だけ、Pi 5 には置いていない）

Pi 5 は q1967 の記録の kernel のまま（ユーザーの普段の使用、触らない）。3 つの候補を作り、build と host の試験までした。

1. xHCI の interrupt の endpoint context（`include/drivers/pci/pci-xhci-control.h` の `drv_xhci_endpoint_context_encode`、全 platform）: SuperSpeed より遅い interrupt の endpoint に、Max ESIT Payload と Average TRB Length を Max Packet Size ×（Max Burst + 1）で入れる（今までは Max ESIT Payload が 0、Average TRB Length が Max Packet Size）。full・low speed の Interval は bInterval × 8 microframe を 2 の冪に切り下げ（要求より遅く回らない）、3〜10 に収める（今までは切り上げで上限 15）。high speed は bInterval − 1 のまま、wMaxPacketSize の bit 12:11 の追加の transaction を Max Burst に入れる（予約の 3 は 2 と読む）。control と bulk は変えていない。根拠は xHCI 1.2 の 6.2.3.4・6.2.3.6・6.2.3.8 と Linux の `xhci_get_endpoint_interval()`・`xhci_get_max_esit_payload()`。試験: `sh plan/bugs/BUG-412/host-xhci-interrupt.sh`（plain と ASan/UBSan）20/20 PASS、既存の `plan/ws282/tests/run-xhci-hb-host-test.sh` と `plan/ws197/tests/run-xhci-isoch-test.sh` も PASS。
2. RP1 の DMA の coherence（確かめただけ、修正なし）: Pi 5 の device tree（`build/sources/firmware/rpi5-boot/3d301dd9…` の `bcm2712-rpi-5-b.dtb` と `bcm2712d0-rpi-5-b.dtb` を `dtc` で読んだ）にはどこにも `dma-coherent` が無く、`drv_fdt_dma_coherent` は 0、RP1 の USB は coherent でない device になる。その時 `drv_dma_alloc_coherent` は uncached の写像を返し、xHCI の ring・event ring・staging はすべてそこにある。`hal_pmem_map_uncached`（`src/hal/arm64/space.c`）は写像の前に direct map の行を `dc civac` で書き戻して捨てる（HAL の契約どおり）。streaming の写像は使っていないので、`drv_dma_sync_*` が空でも食い違いは無い。Linux も Pi 5 で同じ扱い（Normal non-cacheable の写像）。
3. usb-hid の再 arm（`src/drivers/usb/usb-hid.c`）: 完了した report を `report` の写しへ取り（時刻と host controller の値も）、transfer を endpoint に戻してから、写しを input の glue（raw なら hidraw）に渡す。endpoint に TD が無いのは写しの間だけになる。再 arm に失敗した時も report は渡してから止める（今までと同じ止め方）。stall は今まで通り。試験: `sh plan/bugs/BUG-412/host-hid-rearm.sh`（usb-hid.c を丸ごと include し、worker を stand-in で回す。plain と ASan/UBSan）9/9 PASS（押しと離しで submit → publish の順、次の transfer が buffer に書いても渡す bytes は元の report、時刻はその transfer の物、短い report、再 arm の失敗、stall）。古い順（publish の後に再 arm）に戻すと 3 つが FAIL することも確かめた。
