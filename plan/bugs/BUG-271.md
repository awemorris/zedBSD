# BUG-271: PDF を受けない IPP の printer（Brother MFC-L3770CDW）へ印刷すると format で失敗する（raster への変換が無い）

- 状態: reproduced（T1-458） / scheduled（P2、IPP の document-format を octet-stream に）
- 観察: printer の Get-Printer-Attributes（host から読み取りだけ）: make-and-model `Brother MFC-L3770CDW series`、document-format-supported は `application/octet-stream`・`image/urf`・`image/jpeg`・`image/pwg-raster`（`application/pdf` が無い）。`printtest add ipp 10.0.30.6 631` は error=0、`printtest print /tmp/sample.pdf` は `job=1 state=5 detail=format`。LPD（515、raw）は state=4 で終わった（PDF をそのまま送った。紙に何が出たかは未確認）。
- 不足: printd は PDF をそのまま送るだけで、printer が PDF を受けない時に PWG raster か URF（Apple raster）へ変える道が無い。IPP Everywhere の printer の多くは PDF を受けないので、ベータ2 の印刷（WS145）の実用に関わる。
- 次: ユーザーに優先度を確かめる（WS145 の続きの Phase か WS177 の案 Q の続き）。

## ユーザーの確認（2026-10-08 夜）

- ユーザー:「プリンタから2枚出力され、AAT Page 1, AAT Page 2と書かれています。これは成功では？この機種はPDFを受け付けます。ただ、そのPDFのバージョンとかはあるかも。」→ LPD（raw）で送った PDF は正しく 2 頁印刷された＝この機種は PDF を中身で受ける。
- → 見立ての直し（Q1）: raster への変換は要らない。IPP の document-format-supported に `application/pdf` が無く `application/octet-stream` がある printer へは、document-format を `application/octet-stream`（printer の自動判別）で送れば良い。printd の IPP の format の選び方を直す（P2、小さい）。

## T1-460 の後（2026-10-08 夜 P2）

- 観察: IPP で `queued job=7`・state 1→2→3（waiting＝printer が受けて Get-Job-Attributes で見ている）まで進み、`PRINTTEST failed step=timeout`。printtest の既定の待ちが 30 秒で、実の printer（2 頁、warm-up）の完了（job-state 9）より短かった。その後の `printtest remove 1` が終わっていない job を取り消した（backend の規則: 消した printer の job は取り消す）ので、compositor の state=6。
- printd は 5 秒ごとに Get-Job-Attributes で job-state を見ており、9 で done、7 で cancelled、8 で failed、job-state を返さない printer は done unconfirmed、30 分で done unconfirmed（`printd/ipp.c`）。完了を見ない不具合ではない。
- 直し: printtest の `print` の既定の待ちを 300 秒に（他の command は 30 秒のまま、`--timeout-s` で変えられる）。`userland/tests/printtest/main.c`。
- 再試験の案（T1、紙を 1 枚使う、ユーザーの許可が要る）: `printtest print /tmp/aat-samples/sample.pdf 'AAT IPP'` を 1 回、`PRINTTEST done job=… state=4` まで待ってから `printtest remove`。log の `as octet-stream` は printd の log（session.log でない所）に出る可能性。

## ユーザーの確認（2026-10-08 夜、Cancel-Job の後）

- 「プリンタにキューが入ってなかったよ。たしかこの機種は、IPPよりLPDの方が安定するんじゃなかったかなあ。」→ printer 側の queue は空（job 213 も消えていた）。この機種では LPD が安定という利用者の経験。LPD は T1-458 で 2 頁とも印刷できた。
- Q1: IPP の chunked の直し（RFC 8010 で printer に必須、CUPS も chunked）は他の IPP Everywhere の printer のために進める。この機種の実機の IPP の再試験は直しの後に 1 回だけ、だめなら LPD を推す（Settings で printer を足す時に LPD も選べる）。
