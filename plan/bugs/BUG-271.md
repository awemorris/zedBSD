# BUG-271: PDF を受けない IPP の printer（Brother MFC-L3770CDW）へ印刷すると format で失敗する（raster への変換が無い）

- 状態: reproduced（T1-458） / scheduled（P2、IPP の document-format を octet-stream に）
- 観察: printer の Get-Printer-Attributes（host から読み取りだけ）: make-and-model `Brother MFC-L3770CDW series`、document-format-supported は `application/octet-stream`・`image/urf`・`image/jpeg`・`image/pwg-raster`（`application/pdf` が無い）。`printtest add ipp 10.0.30.6 631` は error=0、`printtest print /tmp/sample.pdf` は `job=1 state=5 detail=format`。LPD（515、raw）は state=4 で終わった（PDF をそのまま送った。紙に何が出たかは未確認）。
- 不足: printd は PDF をそのまま送るだけで、printer が PDF を受けない時に PWG raster か URF（Apple raster）へ変える道が無い。IPP Everywhere の printer の多くは PDF を受けないので、ベータ2 の印刷（WS145）の実用に関わる。
- 次: ユーザーに優先度を確かめる（WS145 の続きの Phase か WS177 の案 Q の続き）。

## ユーザーの確認（2026-10-08 夜）

- ユーザー:「プリンタから2枚出力され、AAT Page 1, AAT Page 2と書かれています。これは成功では？この機種はPDFを受け付けます。ただ、そのPDFのバージョンとかはあるかも。」→ LPD（raw）で送った PDF は正しく 2 頁印刷された＝この機種は PDF を中身で受ける。
- → 見立ての直し（Q1）: raster への変換は要らない。IPP の document-format-supported に `application/pdf` が無く `application/octet-stream` がある printer へは、document-format を `application/octet-stream`（printer の自動判別）で送れば良い。printd の IPP の format の選び方を直す（P2、小さい）。
