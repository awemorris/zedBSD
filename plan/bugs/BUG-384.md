# BUG-384: arm64 の kernel の Image の header の image_size が BSS を含まない（arm64 の boot の約束に反する）

- 状態: in-progress（2026-11-01 05:06 P1 q1810）。元: open（2026-11-01 03:37 Q1 が起票、Pi 5 の黒い画面の解析（bug-analyzer）の副次の発見）
- 中身: Pi 5 の kernel（tree fba292f54）で、header の image_size は 0x409000 だが、BSS は 0x489000 から 0x6f8ac0 まで。Linux の arm64 の boot の約束は
  image_size が BSS を含む全体の大きさであること（boot loader がその範囲に他の物（DTB・initrd）を置かないため）。
- 影響: 今は DTB が 0x2efec600 に置かれ重ならないので症状は無い。boot loader が kernel の直後に DTB などを置くと BSS の初期化で壊れ得る。Pi 4・Pi 5・ODROID-C5 など arm64 の全部。
- 直す方針（案）: link の script で image_size を BSS の終わりまでにする。

## 原因（2026-11-01 P1、q1810-i01）

- header は `src/hal/arm64/locore.S` の `_start` の 64 byte。image_size の欄は `.quad 0` で、build の `platform/arm64/vmunix.mk` が objcopy の後に
  `platform/arm64/tools/check-arm64-vmunix.py --fix-image` で raw の file の長さを書き込んでいた。BSS（NOLOAD）は file に入らないので、image_size は BSS を含まない。
  check も `image_size == file の長さ` を確かめていたので、誤りが PASS になっていた。
- rpi5 と s905x5m（ODROID-C5）の locore-board.h の、image を link の位置へ移す stub は、写す長さに header の image_size を読んでいた（`ldr x6, [x1, #16]`）。
  image_size だけを直すと、読み込まれていない BSS の分まで写すことになる。
- 関係する観察（直していない）: `.vfs_bss`（src/kern の file.c・inode.c・mount.c）と `.kernel_heap` は PROGBITS の orphan で、linker が `.data` の後に置く。
  vmunix.ld の `__arm64_image_end`（どこからも使われていない）は `.data` の直後で、これらより前を指す。rpi5 の build で file の約 2.5 MiB はこの 0 の section。

## 修正（HAL の実装・linker script・bsp・build の check だけ。HAL の API は変えない）

- `platform/arm64/vmunix.ld`: `__arm64_image_size = ALIGN(__kernel_vma_end, 4096) - __kernel_vma_start`（BSS の終わりを 4 KiB に揃えた image の大きさ）と
  `__arm64_image_file_size = __bss_start - __kernel_vma_start`（BSS の前の全部、raw の file を覆う）。`_start == __kernel_vma_start` の ASSERT。
- `locore.S`: image_size の欄を `.quad __arm64_image_size`（link の時に決まる。ELF と raw の file の両方が正しい値を持つ）。
- `bsp-rpi5/locore-board.h`・`bsp-s905x5m-common/locore-board.h`: 移す stub の長さを `ldr x6, =__arm64_image_file_size` に（literal は先に写す stub の中）。
- `check-arm64-vmunix.py`: `--fix-image` を外し、ELF の symbol 表を読んで、image_size が BSS の終わり以上で `__kernel_vma_end` を 4 KiB に揃えた値と等しいこと、
  file の長さ以上であること、`__arm64_image_file_size` が file の長さ以上で image_size 以下であることを確かめる。`vmunix.mk` から `--fix-image` の段を外した。
- 他の header の欄（Linux の arm64 の boot の約束と照らした）: text_offset 0x80000（2 MiB に揃えた RAM の基点 0 からの位置、全部の board で DRAM は 0 から）、
  flags 0（bit 0 little-endian で正しい、bit 1-2 の page size は 0 = 未指定で約束の上は許される、bit 3 = 0 は「DRAM の基点の近くに置く」で、0x80000 にしか置けない
  この kernel に合う）、magic `ARM\x64`、予約の欄 0。誤りは見つからず、変えていない。page size の欄を 1（4 KiB）にする余地はあるが必須でない。
