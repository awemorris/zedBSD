# BUG-413: Settings の Ethernet の頁の IPv6 が「Not available on zedBSD yet」と固定の文のまま

- 状態: fixed（2026-11-02 12:16 P1 q1942-i01。QEMU amd64 で確かめた、実機（Pi 5）は未実施）
- 発見: 2026-11-02 11:42 ユーザーの Pi 5 の UAT。zedBSD は IPv6（networkd の RA・SLAAC）を持つのに、Settings の Ethernet の頁は IPv6 の欄に固定の文「Not available on zedBSD yet」を出す（userland/desktop/settings/page-wired.c の 93・119〜121 行）。
- 直す形: その interface の IPv6 の address（link-local と global、prefix の長さ）と既定の router を、system の情報（ifconfig と同じ口・networkd の状態）から読んで出す。無い時は「なし」。編集は IPv4 と同じ範囲で（自動・手動の選択が既にあればそれに合わせる。無ければ表示だけ）。
- 扱い: P1（q1942）。

## 修正（2026-11-02 P1 q1942-i01）

- 情報の経路: Settings の頁の情報は compositor から kl_system_network_v1 で来る（backend → wayland/system.c → libkeiland system.c → kl_network_link）。IPv4 と同じ経路に IPv6 を足した。
  - zedBSD の backend（network-link-zedbsd.c）: ifconfig と同じ SIOCGIFADDRS_IN6 で address（global を先、link-local を後、duplicated は除く）、route -6 と同じ SIOCGRTENTRY_IN6 で既定の route の router（RA から networkd が作った物）。どちらも誰でも読める query。
  - Linux・FreeBSD の backend: getifaddrs の AF_INET6（共通の kwpa_link_inet6、netmask から prefix の長さ）。Linux は router を /proc/net/ipv6_route から。FreeBSD の router は空（IPv4 の router も空のまま）。
  - protocol: kl_system_manager を version 35 に、network の event 11 link_inet6(name, "ADDRESS/LENGTH")・12 link_router6(name, router) を since 35。compositor は object の version が 35 以上の時だけ送る（古い client は従来どおり）。新しい client が古い compositor に繋ぐと event が来ず、IPv6 は「None」。
  - kl_network_link に inet6_count・inet6[4]・router6（KL_VERSION 108）。
  - Settings（page-wired.c）: card の題を「IP (ue0)」に。行は IPv4 configured by・IPv4 router・IPv6 address（global）／IPv6 link-local（各 ADDRESS/LENGTH、無ければ「None」）・IPv6 router（無ければ「-」）。編集の時も同じ IPv6 の行を薄い label で出す（IPv6 は編集しない: networkd の設定の要求に IPv6 の口が無いため。net.conf の ipv6: は networkd が持つが Settings からの変更の経路は無い）。network.c の log の行 `NETWORK wired-link` に inet6=・first6=・router6= を足した。
  - 日本語の訳: page-wired.c の文字列は元から kl_tr を通していないので、訳の catalog は変えていない。
- 確かめた事:
