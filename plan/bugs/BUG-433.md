# BUG-433: WS131 の system の host の回帰試験（plan/ws131/tests/host-system.sh）が link できない

- 状態: fixed（2026-11-14 P2 q2077-i01、agent/p2-bug433、88d72e5df3。host で link と PASS、わざと壊した system.c で FAIL を確かめた）。前: open（2026-11-14 Q1 が起票。WS353 p006 の P1 の報告から）
- 観測（P1、WS353 p006 の基点 2c1152a565）: 40 余りの関数の偽物が無く link できない。
- P1 の判断: system の拡張の protocol と libkeiland の view を両端で確かめる本当の回帰試験（WS113・132・142・172・191・314、BUG-222・413 が使う）。消さずに直す。推しの形は、偽物を 1 つの file に分け、system.c の依存を link の境で切る。
- 扱い: 担当が空いた時に直す（WS353 の compositor の変更が落ち着いた後、p008 の後が良い）。

## 原因（2026-11-14 P2）

試験は 10-08 から直されておらず、その後の compositor の変更に追従していなかった。基点 d22a73bbaa で数えた欠けた関数は 46:

- event loop の補助（main.c）: `kwl_timer_set`・`kwl_soon`・`kwl_watch`・`kwl_client_fail`。
- thread と timer（threads.c）: `kwl_timer_init`・`kwl_timer_armed`・`kwl_timer_disarm`・`kwl_thread_start_detached`・`kwl_thread_wake`・`kwl_thread_ended`。
- I/O の thread（io.c）: `kwl_io_file_submit`・`kwl_io_device_submit`。
- media library（media-library.c）: `kwl_media_library_create`・`_request`・`_tick`・`_close`。
- greeter・通知: `kwl_greeter_keys_changed`・`kwl_notify_app_post`。
- backend: `kl_backend_notify_open`・`_activated`・`_closed`、`kl_backend_phone_*` 16 個、`kl_backend_session_key_info`・`_key_info_get`・`_key_pin`・`_key_removed`・`_key_reset`・`_methods_get`・`_options_get`・`_set_methods`・`_set_options`。

link の前に、`printers-shell.c` の `kwl_printers_prepare` の使われない引数 `server` が `-Wextra -Werror` で止まっていた（compositor の側。Q1 が main の 23a9da01e5 で直した）。

link の後に 12 の FAIL が出た。どれも試験が書かれた後の compositor の意図した変更によるもので、compositor の誤りは見つからなかった:

- network.c は daemon の答えの後に `kwl_system_network_free` を呼び、system bar に止められた鍵の段（profiles・join）をそこで送り直すようになった。試験の event loop の代わりがそれを呼んでいなかった（9 件）。
- PIN は 4〜6 桁になった（11-02 の変更、`docs/architecture/security.md` と一致）。試験は 5 桁を拒まれる例にしていた。また sessiond の答えの後に enrolled が問われるので、間違ったパスワードの答えの後に enrolled を待たずに次を頼むと EBUSY になった（2 件）。
- 能力の集合は manager の version 35 で増えた（鍵の操作・方式・phone の同期と連絡先と通話・media。printers は印刷の daemon の program がある時だけ）（1 件）。

## 直し（2026-11-14 P2、plan/ws131/tests/ だけ。compositor の source は変えていない）

- `host-system-stubs.c`（新）: 試験が見ない部分の偽物を 1 つの file に分けた。`kwl_timer_set`（main.c と同じく server の timer に掛ける）、`kwl_soon`・`kwl_watch`（何もしない。試験の loop は数 ms ごとに回る）、`kwl_client_fail`（印だけ）、`kwl_io_*_submit`（`ENOTSUP`。io.c の、thread が無い時の答えで、呼び手がその場で行う）、`kwl_greeter_keys_changed`、`kwl_notify_app_post`、session の鍵の設定 9 個（session-none.c と同じ答え）。
- `host-system.sh`: 上の file と、tree の本物の `threads.c`・`media-library.c`・`libkeiland-backend/media/media.c`・`unsupported/notify-unsupported.c`・`unsupported/phone-unsupported.c` を link する。
- `host-system.c`（event loop の代わり）: 始めに `kwl_timers_init`、wake の pipe は無し（`server.wake` を -1）。毎回の pass で `server.woken = 1` と `kwl_timers_take`（scan の 1 分、machine の読み取りの stall）。daemon の答えの後に `kwl_system_network_free`、sessiond の答えの後に `kwl_system_session_free`（network.c・handoff.c と同じ）。
- `host-system.c`（期待の値）: 能力を今の集合に（printers は `kwl_printers_available()` と一致を別に確かめる）、拒まれる PIN を 3 桁に、間違ったパスワードの後に enrolled を待つ（鍵の節と同じ形）。

## 確かめ（2026-11-14 P2、host の Debian の gcc と libwayland-client）

- `sh plan/ws131/tests/host-system.sh build/bug433/host-system`: `-Wall -Wextra -Werror`、ASan・UBSan、warning 0、`host-system: PASS`。build を 6 回、binary をさらに 5 回流して全て PASS。
- わざと壊した時: `system.c` の写しの `SYSTEM_PIN_MIN` を 4 から 3 にして build すると 3 つの FAIL（3 桁が通る・続く PIN の削除が EBUSY・PIN が残る）で exit 1。
- 未実施: QEMU と実機（host の試験だけの直し）。他の WS の host 試験は流していない。
