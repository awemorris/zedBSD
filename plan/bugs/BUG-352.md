# BUG-352: DHCP の interface が 2 つあり両方が default route を入れると、次からの net の commit が全部 `route: Device or resource busy` で失敗する

- 状態: open（2026-10-29 Q1 が登録） → closed（2026-10-31 Q1 の判定、main f81fef099。2026-10-31 P2、q1750-i01、QEMU で確かめた。実機は未実施。Q1 の判定待ち）
- 発見: 2026-10-29 P3（q1664-i03、WS221 p004 の QEMU の試験）。MTU と無関係に、MTU の設定無しでも再現。
- 再現: QEMU で ue1 を dhcp にして commit（ue0 も dhcp）→ 次の net の commit。
- 観測: reconcile の DEFAULTROUTE_CLEAR の `route delete default` が EBUSY を返し、commit が失敗、rollback も degraded。
- 期待: default route が 2 つあっても、net の commit が通る（default route の扱いを決めて消せる・置き換えられる）。

## 原因と修正（2026-10-31 P2、q1750-i01）

- 原因: kernel の `route_delete_request`（`src/kern/net/route.c`）は削除の要求が route を 1 つだけ指す事を求め、一致が 2 つだと EBUSY を返す。DHCP の interface が 2 つあると default route が 2 つになり、networkd の DEFAULTROUTE_CLEAR の `route delete default`（interface を名指さない）が EBUSY で失敗していた。
- 変更（4edbbd7dc）: networkd に `default_route_clear` を足し、route の表の最初の default route の interface を調べて `route delete default -ifp IF` で消す事を、無くなるまで（最大 NETWORKD_LAN_MAX + 2 回）繰り返す。DEFAULTROUTE_CLEAR と LAN_CONFIGURE の固定 address の道（同じ `route delete default`）の両方で使う。
- 残り: 同じ interface に gateway の違う default route が 2 つある時は `-ifp` でも EBUSY のまま（DHCP では起きない）。
- build: warning 0。QEMU（amd64、usb-net 2 つ、ue1 は 10.0.3.0/24 の DHCP、SSH と net の console を標準入力から）で、ue1 を dhcp に commit して default route が 2 つ（ue0 10.0.2.2・ue1 10.0.3.2）になった後、次の commit（ue1 の mtu 1400）が「Commit complete.」で EBUSY・失敗の文字が無く、net.conf に残り、default route が戻り、SSH が答えた。confirmed の rollback の道は未実施。
- 試験の script（tree の外、P2 の worktree の build/tmp/q1750/）: qemu-bugs.sh（6 件）・qemu-bugs2.sh（366・354 の再試験）・bugcheck.c（guest の確かめの program、build/llvm の clang で sysroot に対して compile して scp）。
