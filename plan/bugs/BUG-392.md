# BUG-392: 初期の PIN を 0000 にし、login の画面と lock の画面で PIN の入力を既定にする

- 状態: fixed（2026-11-02 P8、下の「修正」。起票は 2026-11-02 01:27 Q1、ユーザーの UAT の要望）
- 発見: 2026-11-02 ユーザーの Pi 5 の UAT。tablet では keyboard が無く password を打てない。
- 期待（ユーザー）: 初期の PIN を 0000 にする。compositor の login の画面と lock の画面は、PIN の入力を既定で選択肢に入れ、PIN の入力を既定で促す。
- 扱い: P8（q1890、BUG-391 と一緒に）。passkey（WS172）の PIN の仕組み（/sbin/passkey・/etc/passkey）を使う。画面の keyboard（OSK）か数字の pad で PIN を入れられる事も確かめる。

## Q1 の判断（2026-11-02）

P8 の問い（PIN の規則が要望と当たる 4 点）に Q1 が決めた。ユーザーの要望（初期の PIN 0000、login の画面で PIN を既定、keyboard の無い tablet で login できる事）から直に出る変更として扱う。

1. PIN は 4〜6 桁を受ける（passkey・compositor・Settings で新しく決める PIN）。弱まる点: 4 桁は 1 万通り（6 桁は 100 万通り）。
2. 起動直後から PIN を出す（今までは sessiond の起動の後に password か key で一度通るまで出さなかった）。5 回続けて誤ると止める状態を root だけの file（/var/db/sessiond/pin-tries）に残し、password か key で通るまで再起動の後も止めたまま。弱まる点: 起動直後に PIN を試せる。
3. account-admin の add（Settings）と user-add（root の useradd）で PIN 0000 の行を /etc/passkey に書く。image の既定の利用者 user にも 0000 の行（top の Makefile の ZEDBSD_ACCOUNT_FILES）。弱まる点: 既定の PIN を知る人は、PIN を変えていない account に login できる。
4. docs/architecture/security.md の該当の箇所は P8 が直す（今の決定として、理由に keyboard の無い tablet）。

## 修正（2026-11-02 P8、q1890-i01、branch agent/p8-bug391）

- 状態: fixed（QEMU の amd64 Venus の guest で確認。Pi 5 の実機は未実施）。
- 直し方:
  - passkey（`userland/base/passkey/`）: PIN は 4〜6 桁（`PASSKEY_PIN_MIN`）。
  - sessiond（`auth-policy.c`・`auth.c`）: 「password で一度通るまで PIN を出さない」規則を外した。PIN の誤りの数（続けての数）は memory に加えて `/var/db/sessiond/pin-tries`（root、0600、directory 0700、`UID TRIES` の行）に、passkey を走らせる前に書き、成功で消す。起動の後に最初の要求で読む。5 回で止め、password・key・password で確かめる変更で戻る。案（止めた印だけを残す）より強く、誤りの回数そのものを残すので、再起動で試行が増えない。
  - account-admin: add・user-add で、人の account（uid 1000〜59999）に PIN 0000（SHA-512 crypt）の行を書く（名前の残りの行は今どおり消す）。system の account には書かない。password の reset は今どおり PIN を消す。
  - image: `userland/base/etc/passkey`（user:1000 の 0000）を /etc/passkey（0600）に入れる（top の Makefile）。
  - compositor（`userland/desktop/wayland/`）: PIN の入力は 4〜6 桁（greeter.c・system.c、訳 `A PIN has four to six digits.`）。sessiond が PIN を出すので、login の画面と lock の画面は PIN の欄と数字の pad（既存の lock-keypad）を既定で出す（既存の規則: PIN が出ていて何も打っていなければ PIN が先）。
  - Settings（`page-users-pin.c`）: 新しい PIN は 4〜6 桁、「再起動の後は password で一度」の文を外した。
  - docs/architecture/security.md: PIN の桁、起動直後からの PIN と誤りの file、初期の PIN 0000 とその弱さ、account の追加。
- 確かめ:
  - build: `plan/ws035/tests/build-login-image.sh build/p8 graphical`（graphical の image）、自分の変えた source の warning 0（出た warning は openssl・openssh の package だけ）。account-admin は `ZEDBSD_USER_PROGRAMS=account-admin` で target の build も warning 0。
  - host: `plan/ws172/tests/sessiond-auth-host-test.sh` → `sessiond-auth-host-test: ok`（起動直後の PIN、誤りの file への書き込みと消去、file の 5 回で PIN が出ない、text の読み書きを足した）。`plan/ws172/tests/passkey-host-test.sh` → PASS（4〜6 桁）。`plan/tools/accounts/account-admin-root-host-test.sh` → PASS 91（user-add の PIN 0000 の行・0000 の照合・mode 600・削除で消える、を足した）。`plan/tools/accounts/user-commands-host-test.sh` → PASS 148。`plan/ws172/tests/passkey-linux-host-test.sh` → PASS。
  - QEMU（`plan/tools/sessiond/restart-guest.sh`、PASS）: (d) 新しい image で lock の画面の数字の pad で 0000 → `SESSIOND UNLOCK ok user=user style=pin`、login の画面で 1111（誤り、file に `1000 1`）の後に pad の 0000 → `SESSIOND AUTH ok user=user uid=1000 style=pin`、file の行が消える。(e) login・lock の画面が `KWL GREETER styles=3`（password と PIN）と `KWL GREETER keypad keys=12` を出す（`build/review/p8-bug391/greeter-pin.png`・`lock-pin.png`・`pin-login.png`）。
