# BUG-246: 整列の popup の開く animation と、整列した窓の入れ替えの animation が、pointer の事象が無いと進まない（5320 実機）

- 状態: reproduced（実機 5320、ベアメタル、ユーザーの UAT 2026-10-07） / resolved（2026-10-07 cfdb21813、5320 にユーザーが確認「Arrangement Popupの描画の問題（マウスイベントが必要）が治っているように見えます。」）
- 発見: 2026-10-07 ユーザーの ad-hoc UAT（5320、i915、zedBSD を USB から起動）。QEMU（Venus）の T1-349 では menu-settled まで進んだ。

## 観察（ユーザーの文）

「Arrangement Popupは、最初の1コマが表示されたあと、マウス入力のイベントがないと続きが描画されないようです。しかも、最初にクリックするまで、マウス移動のイベントのたびにアレンジされたウィンドウが再描画されるのかちらついています。」
「アレンジしたウィンドウを入れ替える操作のとき、マウス移動がないと移動のアニメーションが完了しないようです。上記バグと関連すると思います。」
「これらは5320実機でベアメタル起動での結果です。」

## 疑い（Q1、未確認）

- i915 の表示では、compositor の animation の次の frame を pointer の事象だけが起こしている（animation 中に再描画を予約する口、または i915 の present の完了・vblank の事象が compositor を起こさない）。Venus では別の経路で frame が回るので QEMU では出ない。
- 最初の click までの「ちらつき」は、pointer の移動のたびに整列の窓の層を描き直している疑い。

## 次

- P2（WS181 の作者）: 5320 で `sshpass -p kei ssh kei@10.0.30.5` の /run/user/1000/session.log を読み（ユーザーに再現してもらう時は Q1 経由）、原因を特定して直す。i915 の present の事象の側なら Q1 に返す。

## 原因と直し（2026-10-07 P2）

- 原因: 整列のメニューの開く・閉じる animation（ws181-p007）と、整列の窓が枠へ滑る glide（ws181-p004、入れ替えの後も）は、次の frame を **描画の中で** `server->dirty = 1` にして頼んでいた（`arrange_menu_grown`・`arrange_menu_view`・`kwl_arrange_glide`）。`compose.c` は frame を submit した後で `server->dirty = 0` にする（`compose.c:402`）ので、描画の中の頼みは消え、次の frame は入力（pointer の移動）が来た時だけ描かれた。他の animation（`server->anim`・Home など）は tick で頼むので進む。QEMU の試験では wltest の client が絶えず commit して frame が回り、隠れていた。5320 の session.log でも `menu open` の後 `menu settled ms=193` は出るが、その間の frame は入力の時だけ（ユーザーの観察どおり）。「最初の click まで移動のたびにちらつく」は、止まった glide が pointer の移動ごとに 1 歩ずつ進んで窓が跳ぶのと同じ原因と見る（未確認、直しの後に実機で見る）。
- 直し（`userland/desktop/wayland/arrange-shell.c` だけ）: `kwl_arrange_tick` が、メニューが開いて広がり終わっていない間・閉じて fade の間・どれかの窓が glide の間（新しい `arrange_moving`）は毎回 `server->dirty = 1` にする（`server->anim` と同じ形）。i915 の present の側は変えない。
- 確かめ: zedBSD の compositor と Linux の Keiland の build warning 0。実機（5320）で: 整列のメニューが pointer を動かさずに約 0.2 秒で広がり切る、整列と入れ替えの窓が pointer を動かさずに枠へ滑り終わる、ちらつきが無い（ユーザーの UAT か T1 の 5320 の撮影）。QEMU では wltest の commit を止めないと再現しない。

## 2026-10-08 P2 の確認（q869）

- 実装済み（cfdb21813）: wayland/arrange-shell.c の `kwl_arrange_tick` が移動の間は dirty を立てる。
- 実機: 2026-10-07 にユーザーが 5320 で popup の描画が直ったと確認（ticket は resolved の記録）。
- QEMU: 直しの後の T1 は無い（QEMU では再現しない）。
- 残り: 入れ替えの glide と最初の click までのちらつきは、ユーザーの文で明示の確認が無い（未確認）。Bug Board の行（scheduled）を resolved に直す（Q1）。
