# BUG-378: arm64 の kernel の text が物理の 2 MiB を越えると、越えた所の関数で実行の許可の fault で止まる（Pi 4）

- 状態: open（2026-10-31 18:51 Q1 が起票）
- 発見: 2026-10-31 ユーザー（Pi 4、WS309 p015 の試験の image `p2-ws309v2/build/p015rpi4/hdd-image.img`）。画面の写真 `build/review/bug378-pi4-panic.jpg`。
- 症状: `ARM64 TIMER TICK` の後に `ARM64 sync vector=0 ec=21 esr=8600000e elr=far=ffff000000201f28` → `fatal: src/hal/arm64/int.c:178: unhandled AArch64 synchronous exception`。
  ESR は命令の abort（同じ EL）、IFSC 0x0e は level 2 の許可の fault。
- Q1 の読み（kernel.elf の記号）: elr は `kern_boot_parameters_token_present` の先頭（`arm64_cmain` から呼ばれる）。`__kernel_text_start` 0xffff000000080000、
  `__kernel_text_end` 0xffff0000002038a8 で、text が物理 0x200000 を越えている。`src/hal/arm64/space.c` の `arm64_space_init` は RAM の最初の 2 MiB だけを
  page ごとに（text は実行可、rodata は読みだけ）写し、他の 2 MiB の block は全部 PXN（実行不可）。よって 0x200000 以降の text は実行できない。
  rodata・data の W^X も最初の 2 MiB の外では効かない見込み（未確かめ）。
- 影響: arm64 の全部の board（Pi 4・Pi 5・ODROID-C5 など）で、kernel の text が 2 MiB を越えた build は起動しない。今日の追加で越えた。
- 直す方針（案）: kernel の image（text・rodata・data）に掛かる全部の 2 MiB の block を page ごとに写す（L3 の table を必要な数だけ）。HAL の実装の直しで、HAL の API は変えない。
