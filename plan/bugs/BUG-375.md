# BUG-375: direct scanout の後に window mode へ戻る時、compositor が display の lease の解放より先に swapchain を作り EBUSY で終了する（VF2）

- 状態: open — 修正済み・VF2 の実機で確認（2026-10-31 登録、同日 P7 が修正、q1732。closed は Q1 の merge の後）
- 発見: 2026-10-31 P2（WS291 p020、VF2）。scanout の import の直し（GPU_IMPORT_SCANOUT、P2 の branch d983c4ee5、main に未 merge）で VF2 の direct scanout が動くようになった後、2 回目の game mode の終わりで `KWL SCANOUT direct=0 reason=no-window` → compositor の display の swapchain の作成が `VULKAN kernel error errno=17 device lost`（EBUSY）→ `KWL MODE_ERROR errno=5` → `KWL FAILED site=window_mode` → `KWL EXIT error=5`。1 回目は間に合った（競合）。
- 疑い（未確かめ）: scanout の backend の lease の解放（kl_backend_scanout_close、display の thread で present の後に非同期）より先に、compositor の VK_KHR_display の swapchain が lease を取りに行き、powervr/display/display.c:914 の「owner が居る」で EBUSY。
- 影響: VF2 で game（fullscreen の app）を閉じると desktop が落ちうる。d983c4ee5 を main に入れると表に出る（今の main は direct が import で拒まれるので出ない）。
- 直す方針（案）: compositor が window mode に戻る時に、scanout の lease の解放の完了を待ってから swapchain を作る。

## 原因（2026-10-31 P7、bug-analyzer の読みを P7 が確かめた所と推定を分ける）

- 疑い（lease の解放の前の swapchain）は誤りだった。compositor は scanout の release（DISPLAY_SCANOUT_CLOSE）と window mode の
  open（DISPLAY_OPEN）を同じ FIFO の lane（display-thread.c・lane.c）に順に入れ、GPU_DISPLAY_RELEASE は同期で成功していた
  （`KWL SCANOUT release errno=` の行が無い）。P2 の log（`/home/awe/zedBSD-worktrees/p2-ws291v/build/ws291/run/v-s1-c1/wayland.log` ほか 3 run）では
  `output-swapchain ms=34` まで進み（display の claim は成功）、その後に `VULKAN kernel error errno=17 device lost`。
- この行は libvulkan の `context.c` の `vulkan_kernel_error` だけが出し、呼ぶのは render node（gpu1）の ioctl だけ（BLOB_CREATE・
  RESOURCE_DESTROY・READ/WRITE・MAP・COMMAND）。display node の EBUSY ではない。行の位置（swapchain の後、`CURSOR_PLANE unavailable
  step=swapchain` の前）から、cursor の plane の swapchain の image の vkAllocateMemory → GPU_BLOB_CREATE。
- その経路の唯一の EBUSY: powervr の blob の作成の MMU の flush → `powervr_command_run` → `powervr_command_send`
  （src/drivers/gpu/powervr/commands.c）の「kernel の CCB が満杯（write+1 == read）」。kick は満杯の間待つ（render-queue.c の
  `send_waiting`）のに、`powervr_command_run`（MMU の flush・SLC・cleanup など）は即 EBUSY を返していた。Linux の
  `pvr_kccb_reserve_slot_sync` は空きを待つ。libvulkan は一度の EBUSY で context 全体を lost にするので、cursor の plane も targets も
  -4 で失敗し、window mode が開けず compositor が終わる。CCB は全 session の共有なので、game の client（mview）の終わり（cleanup の
  命令）と compositor の image の作成が重なった時だけ起きる（間欠）。Venus に CCB は無いので QEMU では起きない。
- 推定（未確認）: CCB が満杯に見えた理由（本当に命令が溜まったか、firmware の書く read の index が CPU に遅れて見えたか。
  commands.c の return slot と同じく VF2 で firmware の書き込みが見えない事が既にある）。mview の終了時の EBUSY も同じ CCB と見る
  （直しの後に消えた）。

## 直し（P7）

- `src/drivers/gpu/powervr/commands.c` の `powervr_command_run`: CCB が満杯の間は、呼び手の時間の上限の中で 1 tick ごとに送り直す
  （kick の `send_waiting` と同じ形、Linux の `pvr_kccb_reserve_slot_sync` と同じ考え）。上限を過ぎたら ETIMEDOUT。HAL は変えない。
  compositor の側（lease の解放の待ち）は変えていない（既に順は守られている）。

## 追加の範囲: game mode の cursor（2026-10-31、Q1 が q1732 に足した）

- 決定: ユーザーの決定（Q1 が趣旨で伝えた）「game mode（全画面の 3D）では、platform に関わらず mouse の cursor を表示しない」。
  Q1 の技術の判断: top が fullscreen の content=game の時は pointer が動いても直の scanout を出ない。game でない fullscreen（動画など）は今の規則のまま。
  記録は [WS309 の ws.md](../ws309/ws.md) にも。
- 読んだ結果（直す前）: 直の scanout の間は compositor は合成せず、scanout の lease は cursor を set しない（powervr の claim は cursor を消して
  始まり、Venus の display に cursor plane は無い）ので cursor は出ない。ただし pointer が動くと game mode を出て合成に戻り、合成の
  cursor と cursor plane が出ていた。直の scanout ができない backend（Pi 4・Linux・FreeBSD、回された出力）では fullscreen の game の上にも
  cursor が出ていた。
- 直し: `userland/desktop/wayland/scanout.c` に `kwl_scanout_cursor_hidden`（top が fullscreen の content=game で、上に何も描かれていない
  時に 1）。`compose.c` の `compose_cursor`（合成の cursor）と `kwl_compose_cursor_source`（cursor plane の像の選び）がそれを見て出さない。
  `scanout-rules.c` の pointer の規則は content が game でない時だけ。`plan/ws217/tests/host-scanout-rules.c` を追従（動画の上の pointer は
  POINTER、game の上の pointer は DIRECT）。上に menu・App Home などが描かれている時は cursor を出す（指すため）。
- 確かめ（QEMU Venus）:
  - `sh plan/ws217/tests/host-scanout-rules.sh` → PASS（plain、ASan/UBSan）。compositor の build は warning 0。
  - `plan/tools/scanout/game-mode-cycle.sh`（4 往復）: PASS（4 回とも direct=1 → no-window → MODE window、FAILED 0）。round 1 で game の
    最中に pointer を動かしても `direct=0 reason=pointer` は 0（game mode に留まる）。`build/p7-venus-test/tool2/`。
  - 合成の fullscreen の game（`--rotate=180` で直の scanout に入らない: `KWL SCANOUT direct=0 reason=rotated`）: pointer を動かした後の画面に
    game が全面に出て cursor は無い（`/home/awe/zedBSD-worktrees/p7-bug373/build/p7-venus-test/composed2/2b-fullscreen-game.png`）。対照: desktop と
    window の game（`--windowed`）の上には cursor が出る（同じ directory の `1-desktop.png`・`3-windowed-game.png`）。
  - 直の scanout の間の画面は Venus の VNC が映さない（最後の合成の画のまま）ので、直の scanout の間に cursor が出ない事は code の読み
    （合成しない、lease が cursor を set しない）と、その間に合成が起きていない事（reason=pointer が 0）で確かめた。
- 未実施: 実機（VF2・i915 など cursor plane のある display で、game の間に cursor が出ない事の目視）。
