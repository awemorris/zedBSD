# BUG-375: direct scanout の後に window mode へ戻る時、compositor が display の lease の解放より先に swapchain を作り EBUSY で終了する（VF2）

- 状態: open（2026-10-31 登録）
- 発見: 2026-10-31 P2（WS291 p020、VF2）。scanout の import の直し（GPU_IMPORT_SCANOUT、P2 の branch d983c4ee5、main に未 merge）で VF2 の direct scanout が動くようになった後、2 回目の game mode の終わりで `KWL SCANOUT direct=0 reason=no-window` → compositor の display の swapchain の作成が `VULKAN kernel error errno=17 device lost`（EBUSY）→ `KWL MODE_ERROR errno=5` → `KWL FAILED site=window_mode` → `KWL EXIT error=5`。1 回目は間に合った（競合）。
- 疑い（未確かめ）: scanout の backend の lease の解放（kl_backend_scanout_close、display の thread で present の後に非同期）より先に、compositor の VK_KHR_display の swapchain が lease を取りに行き、powervr/display/display.c:914 の「owner が居る」で EBUSY。
- 影響: VF2 で game（fullscreen の app）を閉じると desktop が落ちうる。d983c4ee5 を main に入れると表に出る（今の main は direct が import で拒まれるので出ない）。
- 直す方針（案）: compositor が window mode に戻る時に、scanout の lease の解放の完了を待ってから swapchain を作る。
