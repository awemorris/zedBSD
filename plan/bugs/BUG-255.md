# BUG-255: 蓋を閉じると HDMI へ移るが、蓋が閉じている間 HDMI に 1 frame も出ない（5330）

- 状態: reproduced（実機 5330） / tracking（2026-10-07 ユーザー: 後回し。「そもそもハードウェアがおかしいかも。蓋を閉じても画面が消えないのに、蓋をちょっと開けると画面が消えます。」、蓋の自動の切り替えはベータ3）
- 証拠: [kernel-5330.log](BUG-255/kernel-5330.log)・[session-5330.log](BUG-255/session-5330.log)（kernel は P2 の build/bug250 の cksum 2877465438、compositor は main の cksum 184482127）

## 観察（Q1、SSH）

- 蓋の事象は届く（BUG-253 の直しが効いた）: kernel `acpi: lid events on GPE 0x18`、session `KWL EVENT lid closed`。
- compositor は HDMI へ切り替えた: `KWL OUTPUT open width=1920 height=1280`、`KWL OUTPUT resized width=1920 height=1280`、`KWL OUTPUT switch name=...:hdmi:B`、`KWL LID external: the desktop moved to the external display`。
- kernel も付け替えた: `i915: resident display: the output moves to connector 1 (HDMI, Keiland's claim)`、`lease 2 claimed`。しかし `lease 2 released after 0 frame(s)`、HDMI の modeset（preflight・picture up）の行が無い。蓋を開けると `KWL OUTPUT switch name=...:edp:A`、`the output moves to connector 0 (eDP panel)`、`lease 3` で panel に戻る。
- 疑い（未確認）: ws052-p012 の sleep.c・shell.c の「蓋が閉じている（または眠る要求の）間は frame を出さない」判断が、外部へ移った後も効いて、HDMI に最初の present を出さない（i915 は最初の present で点けるので、消えたまま）。

## 次

- compositor の frame を出さない条件を、外部の出力に出している時は蓋が閉じていても描くように直す。5330 で HDMI をつないで蓋を閉じ、HDMI に desktop が出る（ユーザー）。

## 解析（P2、2026-10-07、log と DSDT だけ。実機は未）

- 「蓋が閉じている間は frame を出さない」の疑いは log と合わない。session の `KWL EVENT lid closed` → switch（swapchain 430 ms・glass 201 ms）→ `KWL LID external` の直後に、PERF の行も compose も挟まずに `KWL EVENT lid open` が来ている。kernel の perf の窓（lease 1 の release の final で新しく始まる）は lease 2 の release まで `644 ms: 0 presents`。`KWL LID screen off` の行も無い。つまり蓋の「開」の事象が close から約 0.65 s 以内に kernel から届き、compositor は HDMI に最初の frame を出す前に panel へ戻した（i915 は最初の present で点けるので HDMI は消えたまま）。
- 「開」の事象は kernel の acpi-power.c が LID0 の Notify の後に `_LID` を読み、値が変わった時だけ出す。5330 の DSDT（`plan/ws049/tests/latitude5330/dsdt.dat`）の `_LID` は EC の bit（`ECG3` = `ECBT(0, 0x10)`）をそのまま返す。よって close の約 0.6 s 後に EC が「開」と答えた Notify があった。ちょうど i915 が eDP を止める（panel の電源と backlight を落とす）間。ユーザーが 0.6 s で開けたのでなければ、eDP の停止と同時の偽の「開」か、蓋の bounce の後に「閉」の Notify が来ない、のどちらか。今の log では区別できない。

## 診断（P2、7ddd0e9aa、Q1 の許可で acpi-power.c を範囲に足した）

- kernel: `acpi-power.c` の refresh が LID の Notify ごとに `acpi: lid notify: _LID N (posted|unchanged) at T ms` を出す（変化が無くても）。compositor: `KWL EVENT lid open ms=T`・`KWL EVENT lid closed ms=T`。
- build（warning 0）: kernel `make -j16 ZEDBSD_CONFIG=config/current-uat.mk BUILD=build/bug250 vmunix`（ws075-p007b b2 の d23a536b9 の render の 7 file を d23a536b9^ に戻して build し、build の後に戻した。include check・vmunix check PASS、BUG-249・253 の直しを含む）cksum `1085997624 3148104`。compositor `make -j16 ZEDBSD_CONFIG=plan/ws035/tests/config-amd64-zdesktop.mk BUILD=build/bug255 build/bug255/bin/wayland`（main 4be6ac8d4 の ws113-p004b を含む）cksum `1012087201 822144`。Linux の backend-host.o も warning 0。
- UAT（5330）: (a) HDMI をつないで蓋を閉じ、10 秒待ってから開ける。開けた時刻を覚えておき、kernel の `acpi: lid notify` と session の `KWL EVENT lid` の時刻と比べる。(b) 蓋を開けたまま `display-control` で HDMI を claim して present（eDP が止まる）し、`acpi: lid notify` が出るか（出れば eDP の停止が LID の Notify を起こす）。

## 診断の build の UAT (a)（2026-10-07 Q1、kernel 1085997624・compositor 1012087201）

- ユーザー: HDMI をつないで蓋を閉じ、10 秒待って開けた。
- kernel.log: `acpi: lid events on GPE 0x18`・`acpi: power-button events on GPE 0x18`・`SCI_EN 1, PM1_EN 0x20, 4 runtime GPEs`（前の起動は 5）。**`acpi: lid notify` の行が 1 つも無い**（閉じた・開けたの両方とも）。HDMI は `disconnected -> connected (CHANGED)`。`claim of connector 1 refused: the limit of outputs shown at once (1) is reached`（compositor の p004b の head が HDMI を開こうとした、p011 の前なので ENOSPC、想定どおり）。
- session.log: `KWL EVENT lid` が無い。
- 前の起動（BUG-253 の直しの kernel）では close と 0.6 s 後の open が届いていた。今回は 1 つも届かない → GPE 0x18（level の _L18）が最初の事象の前か後で mask されたまま・再び有効にされない、または起動ごとに GPE の数（4・5）が違う何かの疑い。
- 証拠: [kernel-5330-diag.log](BUG-255/kernel-5330-diag.log)・[session-5330-diag.log](BUG-255/session-5330-diag.log)。

## 調査の中断（P2、2026-10-07、ユーザーの方針の変更で）

- 止めた時点の読み（未確認）: 5330 の DSDT では蓋の事象は 2 つの道で LID0 に Notify される。EC の query `_Q66` → `NEVT`（EC の event の bit 0x04 → `EV3(3, ECG3())` → `BTNV` → `Notify(LID0)`）と、GPE 0x18 の `_L18`（EC の reg 9 の bit 1 → `EV3(3, ...)`）。前の起動で事象が届き（Intel HID の `Notify(HIDD, 0xca/0xcd)` も出ていた）、診断の起動では 1 つも届かない（HIDD の Notify も無い）ので、蓋に限らず EC・SCI の事象の道がその起動で止まっていた疑い（EC の GPE 0x6e は edge で install、`acpi-ec.c` は GPE の時だけ SCI_EVT を見る）。再開する時は SCI の数・GPE の番号・EC の query の番号を log に出して蓋を開け閉めする。

## 2026-10-09 P1: 新しい見込みと診断の行（ベータ3 の合間）

- 見込み（未確認）: 起動ごとに runtime の GPE の数が違う（BUG-253 の直しの起動は 5、診断の起動は 4）。蓋の事象が届いたのは 5 の起動だけ。`acpi-event.c` は、_PRW が名指す GPE を「wake だけ」として、走る間は mask する（`wake_visitor` → `gpes[gpe].wake = 1`、runtime の有効化から外す）。だから、ある device の `_PRW` の評価が起動によって成功・失敗すると（EC の field を読む _PRW など）、蓋の GPE 0x18 が runtime に有効だったり mask されたりする。数の 5・4 の違いと合う。
- 診断の行を足した（kernel、`src/drivers/acpi/acpi-event.c`・`acpi-ec.c`）:
  - 起動の時の `ACPI: runtime GPEs: 0x..`（有効にした method の GPE の番号）と `ACPI: wake-only GPEs with a method: 0x..`（_PRW のために mask した物）。
  - `_PRW` の評価が失敗した時の `ACPI: \...\DEV._PRW failed (error N); its GPE is not kept for waking`。
  - 各 GPE の最初の 8 回の処理の `ACPI: GPE 0x18 (level) #1`。
  - 各 EC の query の最初の 8 回の `ACPI: EC query _Q66 #1`。
- 確認: `make ZEDBSD_CONFIG=plan/ws035/tests/config-amd64-zdesktop.mk BUILD=build/p1-ws177 build/p1-ws177/vmunix`（-Werror、warning 0）。style-check の新しい指摘は 0。
- UAT（5330、ユーザー）: この kernel で 2 回起動し、それぞれ HDMI 無しで蓋を 1 回閉じて開ける。kernel の log の上の行を 2 回分比べる。runtime の GPE の list に 0x18 があるか、wake-only にあるか、`_PRW failed` の行、蓋の時の `GPE 0x18`・`EC query` の行を見る。0x18 が wake-only に入る起動で蓋の事象が来なければ、見込みが当たっている。直しは、蓋の GPE（`_Lxx` を持ち、LID の Notify を出す物）を、_PRW に名指されていても走る間に有効にする形の案（Linux の扱いを確かめてから）。
