## 原因と直し（2026-10-09 P1）

- 原因: zedBSD の kernel は新しい pty（`/dev/ptmx`）の slave の大きさを、boot の時に console の text の大きさ（例 1280 幅で 160 列）にしていた。pair を使い直す時も、前の使い手の大きさのまま戻さなかった（`src/kern/tty.c`）。REmacs の M-x shell は Noct の `Process.spawn`（`forkpty(&master, NULL, NULL, NULL)`、大きさを渡さない）で sh を動かす。そのため ls は TIOCGWINSZ で 160 列などを読み、その幅で並べた。Emacs の窓（例 80 列）では行が `\` で折り返し、列が崩れた。
- host での再現: host の REmacs（`build/NoctLang/build-static/noct` と remacs.nap）を pty の harness（`userland/base/emacs/tests/term/harness.py`、80x24）で動かした。shell は host 版の zedBSD の sh、ls は host 版の zedBSD の ls（`build/bug242/`）。M-x shell で `ls /` は、Linux の forkpty の大きさ 0 なら 80 列で揃う。`stty cols 160` の後では、行が `\` で折り返して崩れた（同じ形）。
- 直し: `src/kern/tty.c` の ptmx の open（pair の割り当て）で、slave の大きさを 0 に戻す。boot の時の console の大きさの初期値もやめた（pair 全体の memset で 0）。他の系（Linux・FreeBSD）と同じく、大きさは master の持ち主が TIOCSWINSZ で与える。Terminal・zterm は spawn の直後に与える。sshd は pty-req で与える。0 列を読む ls・sh の readline・tabs・pager・Noct の term は、それぞれ COLUMNS か 80 に落ちる（読んで確かめた）。
- AAT: `bugs.emacs-shell-ls`（`tests/scenarios/bugs/emacs-shell-ls.md`、helper `plan/tools/aat/scenarios/helpers_bugs.py`）を `stty size; ls /` にした。撮影で `0 0` と揃った列を人が見る。
