# BUG-264: login の後に現れた入力の device（USB・Bluetooth）を compositor が使うまでの遅れ（当初: node を開けない疑い）

- 状態: unknown（読みで原因を確かめた。QEMU の再現は T1 待ち） / resolved（QEMU、2026-10-08 T1-417: session-up・sessiond-subscribed・kbd・mouse が ok、compositor-alive の FAIL は試験の判定の誤りで Q1 が直した。下の「T1-417」）
- 発見: 2026-10-08 P2 の ws143-p005 の設計（Q23）の読み。
- 当初の観察（読み）: sessiond は login の時にある `/dev/input/event*` だけを seat の利用者へ chown し、hotplug を聞かない。login の後に挿した USB のキーボード・マウスや、Bluetooth で繋いだ HID の node は root のままで、利用者の compositor が開けない見込み。あわせて compositor の KWL_INPUT_MAX は 16。
- 期待: login の後に現れた入力の device も、seat の利用者の compositor がすぐ使える。
- 関係: WS143 p005（Bluetooth の HID）、WS132（PnP の通知）。

## 読みで確かめた原因（2026-10-08 P2、q888）

当初の「node が root のままで開けない」は**誤り**。sessiond は `/dev/system` を聞かないが、session と greeter の待ちの loop で毎秒 seat の device を与え直している（`userland/desktop/sessiond/session.c` の loop の末尾 `sessiond_seat_give`（1 秒の poll ごと）、`greeter.c` の `GREETER_SEAT_MS` 1000）。compositor は `/dev/system` の INPUT の event で直ちに走査し直し（`backend-host.c` の `kwl_backend_input_changed` → `input_scan_time = 0`）、加えて 2 秒ごとに走査する（`main.c` の `KWL_INPUT_SCAN_MS`）。走査で開けない node（`probe_device` の open の失敗）は覚えず、次の走査でまた試す。

実際の不具合は**遅れ**: compositor は kernel の ADD の event で直ちに走査するが、その時 node はまだ root の 0640（devfs の既定）で開けない。sessiond の毎秒の与え直しが 1 秒以内に chown しても、compositor は次の普通の走査（2 秒後）まで開かない。挿してから使えるまで約 2 秒（最大で約 3 秒）。あわせて compositor の表 `KWL_INPUT_MAX` 16 は、ws143-p005 i01a で kernel の `INPUT_DEVICE_MAX` を 8 → 32 にすると kernel より小さい（Bluetooth の HID 6 台・USB・PS/2・touchpad・pen）。

## 直し（P2、2026-10-08、q888）

- sessiond（`userland/desktop/sessiond/seat.c`・`sessiond.h`・`main.c`・`greeter.c`・`session.c`）: 起動の時に `/dev/system` を開いて INPUT と USB（smart card の slot）の class を購読し（`sessiond_seat_events_open`、log `SESSIOND SEAT events subscribed classes=0xa0`）、greeter と session の loop の poll に入れる。ADD か OVERFLOW の record が来たら直ちに与え直す（greeter は `GREETER_SEAT_MS` を待たない。session の loop は毎回与え直すので poll が起きれば足りる）。毎秒の与え直しは残す（event の無い kernel、event を出さない node（遅れて attach する display））。
- compositor（`userland/desktop/wayland/kwl.h`・`backend-host.c`・`main.c`）: 入力の device の event の後 `KWL_INPUT_SETTLE_MS`（2 秒）の間は `KWL_INPUT_SETTLE_SCAN_MS`（100 ms）ごとに走査する（sessiond が同じ event で chown した直後に開く）。`KWL_INPUT_MAX` 16 → 32（kernel の 32 に合わせる）。FreeBSD・Linux の backend の lease の数（`SEAT_LEASE_MAX`・`LINUX_SEAT_DEVICES`）17 → 33。
- 確かめ（P2）: `make -j16 ZEDBSD_CONFIG=plan/tools/aat/config-amd64-aat.mk BUILD=build/bug264 build/bug264/bin/wayland build/bug264/bin/sessiond` exit 0、自分の source の warning 0（openssl の package の既存の warning だけ）。`python3 plan/tools/style-check.py` で seat.c・backend-host.c・main.c（wayland）0 件（seat.c の既存の 1 件も直した。greeter.c 601・session.c 759 の既存の指摘は触っていない関数）。`sh plan/ws131/tests/host-seat-linux.sh` 12/12。FreeBSD の backend の compile は未実施（定数だけの変更）。QEMU は未実施（T1）。
