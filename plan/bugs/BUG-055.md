# BUG-055: `setvbuf(stream, NULL, _IOLBF, 0)` が EINVAL で失敗し、行単位の buffer にならない

Bug ID: `BUG-055`
Reproduction: reproduced（QEMU、amd64 guest、2026-09-26、決定的）
Disposition: resolved（2026-09-26、[ws035-p054](../ws035/phase054/phase.md)、QEMU で確認。実機は未実施）
Date: 2026-09-26
Source: ws035-p054（q459-i01）。zwl の `--log-frames` の log を試験が数えると、値が数秒止まってから跳んだ。
Owner: ws035-p054
Queue: q459

## 期待と観測

期待: `setvbuf(stdout, NULL, _IOLBF, 0)` で stdout が行単位の buffer になる（glibc・FreeBSD・NetBSD は buffer が NULL なら大きさを実装が決める。Linux の program はこの書き方をよく使う）。

観測: libc（`userland/base/libc/posix.c` の `setvbuf`）が `mode != _IONBF && size == 0` を EINVAL で拒み、stream は既定の全 buffer のまま。zwl（`main.c` の先頭で上の呼び出し）の log が file へ 4 KiB ごとにしか出なかった。

## 直し方

buffer が NULL で大きさが 0 なら `BUFSIZ` で確保する。buffer を渡して大きさ 0 は今まで通り EINVAL。

## 確認

直した libc の guest で、zwl の log の行数が 1 秒ごとに増える（直す前は 0 → 58 → 58 → 58 → 135 のように跳んだ）。p054・p052・p053 の試験が PASS。
