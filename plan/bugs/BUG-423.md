# BUG-423: QEMU amd64 で USB の keyboard が enumerate されない（`usb0: port 6 enumeration failed (42)`）

- 状態: fixed（2026-11-13 Q1。P2 の 1b39b8ba24 を main に merge。全 controller を「reset → event ring → vector と handler → IMAN.IE → RUN」の順に。QEMU amd64 -smp 1・4 で USB keyboard の login と uname PASS、直す前は FAIL。実機の DWC3（Moorefield）と他の xHCI は未確かめ。次に実機を使う時に確かめる）
- 発見: 2026-11-13 P2（BUG-422 の確かめ）。QEMU amd64 `-smp 4`（KVM、`plan/bugs/BUG-422/qemu-boot.sh`）で、guest の USB の keyboard が `usb0: port 6 enumeration failed (42)` で使えず、login の key が届かない。42 は `ETIMEDOUT`（`include/uapi/errno.h:83`）。画面の login prompt までは出る（boot-test PASS）。
- 回帰の見込み: 2026-10-17（BUG-333 の T1-707）には qemu-xhci の usb-kbd が enumerate していた。BUG-422 の前の kernel（sha256 716c57ba9d6c5091、WS333 p025 の c6）でも同じに失敗するので、BUG-422 の直しとは関係しない。build system の作り直し（2026-11-06）か、その後の xHCI・USB の変更の見込み（未確かめ）。
- 影響: QEMU の amd64 で key の入力を使う試験（login・guest の操作）が全部できない。実機は未確かめ。
- 確かめ: `plan/bugs/BUG-422/qemu-boot.sh` の `LOGIN=1`。QEMU の command line（`-device qemu-xhci`・`usb-kbd`、`-smp`）の違いで変わるかも見る。

## 経過

- 2026-11-13 00:50 P2（q2026-i01、branch agent/p2-bug423、基点 dd6d988449）。
  - 再現: worktree の build（`plan/bugs/BUG-423/build.sh`、config は `plan/bugs/BUG-423/config.mk`、text login と小さな userland）を `plan/bugs/BUG-423/boot.sh`（boot-test.sh の画面と key、`-smp` を `qemu-wrap.sh` で差し替え）で起動すると、`-smp 1`・`-smp 4` の両方で login の key が届かない（画面に `usb0: port 6 enumeration failed (42)`）。
  - 解析（QEMU の trace と gdbstub、`plan/bugs/BUG-423/debug.sh`）: SETUP・DATA・STATUS の転送は QEMU で成功し（`usb_xhci_xfer_success len 18`）、完了の event は ring に書かれているが、割り込みが一度も来ない。trace の順は「IMAN に IE（`runtime_write off 0x20 val 2`）→ USBCMD RUN|INTE → `msix_write_config qemu-xhci enabled 1`」で、`usb_xhci_irq_msix_use` が一度も出ない。QEMU の xHCI は IMAN.IE が書かれた時に MSI-X が有効なら vector を使用中にし、使用中でない vector の `msix_notify` は何も送らない。driver の待ちは期限で cancel し、その時に読んだ event が `xhci: cancelled request ... completion=13 residual=46`・`completion=1` として出ていた（転送の失敗ではなく完了の通知の欠け）。command は poll で完了を読むので slot の enable・address は通っていた。
  - 原因: `src/drivers/pci/pci-xhci.c` の `xhci_attach` で、IRQ の establish（MSI-X の有効化と handler）が `drv_usb_hcd_register`（中の `xhci_start` が IMAN.IE と RUN を書く）の後にあった。2026-10-17 の版（と e69f9829f0 の前）は establish → register の順。04d899bb6a（2026-11-08、Intel の DWC3 の INTx の storm への対処）が establish を register の後へ移し、その後の pci.c の main への戻し（0fe96aabce）でも pci-xhci.c のこの順は残っていた。config の macro の欠け（USB・xHCI・HID・割り込みの道の source が見る macro）は無かった。
  - 直し: IRQ の確保と establish（MSI-X → MSI → INTx の順に試し、establish に失敗したら次の種類）を `xhci_irq_setup` にまとめ、`xhci_start` の中で controller の reset と event ring の設定の後、IMAN.IE の前に呼ぶ。これで全 controller で「reset → ring → vector と handler → IE → RUN」の順になる。DWC3 で establish を後ろにした理由（reset の前の残りの割り込み・DWC3 の event）は、reset の後で IE の前という位置と、attach で先に行う DWC3 の event の mask（`xhci_dwc3_init_host`）・handler の DWC3 の event の処理で満たすと判断し、controller で分けなかった（Intel の DWC3 の実機は未確認）。stop は handler を外す（`xhci_stop_checked` → `xhci_irq_disestablish`）ので、次の start が同じ確保で張り直す。start の失敗は既存の fail の道（stop で外し、attach の fail で確保を返す）。
  - 確かめ（QEMU amd64、KVM、q35、NVMe の起動、qemu-xhci と usb-kbd を USB 2 の port 2）:
    - build: x86_64 の vmunix・programs・image が rc 0・warning 0。i386 の vmunix が rc 0・warning 0。intelmid64 の vmunix は pci-xhci.c の compile は warning 0 だが link が `kern_thermal_receiver_register`・`kern_thermal_fan_register` の未定義（`acpi-dell.c` から、CONFIG_KERN_THERMAL が n）で失敗（この変更とは無関係、未調査）。
    - trace: 直した kernel で `msix_write_config qemu-xhci enabled 1` の後に IMAN.IE が書かれ `usb_xhci_irq_msix_use nr 0` が出る。kernel の log の buffer（gdb で読んだ）に `usb0: device 1 port 6 0627:0001 ... configured`・`driver=usb-hid`・`input: /dev/input/event0: QEMU USB Keyboard`。
    - 画面と key（boot.sh、boot-test.sh の PASS）: `-smp 1`・`-smp 4` の両方で login prompt → USB の keyboard で root の login → `uname -a` が `zedBSD zedbsd unknown zedBSD x86_64` を出す。USB の stick の起動（`BOOT_MODE=uefi-usb`、`-smp 4`）も同じく PASS。対照: 直す前の image は `-smp 1` で Password の prompt が出ない（FAIL）。
  - 未実施: 実機（Intel の DWC3 の Moorefield 等、他の xHCI）。rpi4・rpi5・vf2 の build。intelmid64 の link の失敗の調査。
