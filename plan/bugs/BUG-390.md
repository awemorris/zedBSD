# BUG-390: Raspberry Pi 5 の CI の image で、App Home の項目は出るのに icon が出ない

- 状態: fixed（2026-11-02 01:42 Q1、bf6c08971 を main 3b79cca9e に merge。原因は compositor の app の tile の image（1024×256）が 21 個目の icon で溢れた事、高さを 512 に。Pi 5 の実機で直す前は icon 無し、直した後は 12 個の icon が出た。10-29 以降の全機械の問題）
- 発見: 2026-11-02 ユーザーの Pi 5 の UAT。CI の image（config/ci/config-rpi5.mk、GPU on・graphical login）で起動したら、App Home の項目は表示されるが icon が無かった。
- 未確認: 起動した image の版（main のどの commit か）、他の機械（Pi 4・VF2・amd64）の CI の image で同じか、icon の file が image に入っているか（rootfs の icon の置き場）、compositor の icon の読み込みの誤り。
- 扱い: Bug の担当（P4、q1889）。Pi 5 の板で再現して直す。

## 原因と直し（2026-11-02 P4、q1889-i01）

- 板の image: Pi 5（10.0.30.7）はユーザーの UAT の CI の image のまま動いていた（`1.0.0-beta2+g8f91a0d`、BUILD_ID 8f91a0d、vmunix cksum 2112791070、
  cmdline `login=graphical rpi5gpu.start=boot`、autologin の user の session）。既定の利用者 user の password で SSH し、root の操作は sudo。
- 原因: compositor が app の tile（App Home・system bar・Alt+Tab・通知の app の絵）を描く image が足りない。`userland/desktop/wayland/glass.c` の
  tiles_create は 4 つの大きさ（20・26・48・72 px、間 2 px）の tile を大きさごとの行に並べ、image は 1024×256（GLASS_TILE_HEIGHT）。
  Installer の絵（GLASS_ICON_APP_INSTALLER、2026-10-29 b6f9a665d）で絵が 21 個になり、48 px の段が 2 行に折れ、72 px の 2 行目が y 224 から 298 まで要って
  256 を超え、tiles_create が ENOSPC で失敗する。tiles_ready が立たないので glass_draw_app_tile は何も描かず、App Home は名前だけになる。
  UAT の image の session.log（/run/user/1000/session.log）に `KWL GLASS no tiles: errno=8`（zedBSD の ENOSPC は 8）。
  Pi 5・V3D に固有ではなく、2026-10-29 以降の全部の機械・全部の build（Linux・FreeBSD の Keiland も同じ glass.c）で起きる。icon の file は使っていない
  （絵は icons.c が描く。apps.conf は Pi 4・amd64 と同じ物が入る）。
- 直し: GLASS_TILE_HEIGHT を 512 にした（21 個で 298 行を使う。2 MB の image）。注釈に、行が足りないと tile が一つも描かれない事を書いた。
- build: `make -j16 ZEDBSD_CONFIG=config/ci/config-rpi5.mk BUILD=build/q1889-ci build/q1889-ci/bin/wayland` rc 0・warning 0。
  試験用（CI の config に CONFIG_INPUT_TEST_INJECT・ZEDBSD_TEST_SCREEN_CAPTURE・keiland-shot・aat-input を足した worktree の build/tmp の一時の config）で
  `BUILD=build/q1889-t`（直した後）と `build/q1889-t0`（直す前）の vmunix・bin/wayland・dynamic/libkeiland.so・libvulkan.so・bin/keiland-shot・bin/aat-input rc 0
  （warning は依存の OpenSSL と perl の物だけ、zedBSD の source は 0）。
- 実機（Pi 5、2026-11-02 01:35〜01:41、SSH の reboot 3 回、電源の入れ直し 0 回）。1 本の script（worktree の build/tmp/q1889/pi5-home-icons.sh）:
  板の 5 file（vmunix・cmdline.txt・/bin/wayland・/lib/libkeiland.so・/lib/libvulkan.so）を /root/q1889/orig に保存し、試験の kernel と library を入れ、
  wayland を直す前・後で替えて reboot、aat-input の Super で App Home を開き keiland-shot で撮る:
  - 直す前: session.log に `KWL GLASS no tiles: errno=8`、App Home（17 個、2 page）は名前と床だけで icon が無い（UAT の観察と同じ）。
  - 直した後: `no tiles` の行が無く、App Home の 1 page の 12 個（Files・Notes・Settings・Terminal・PDF Viewer・Image Viewer・Video Player・Music・
    Photos・Phone・Calendar・Mail）に icon が出た。
  - PNG（worktree）: `build/review/q1889-pi5-home-before.png`・`q1889-pi5-home-after.png`（960×540）、原寸は `-full.png`。
  - 戻し: 5 file を戻して reboot、cksum が試験の前と全部一致（vmunix 2112791070・cmdline.txt 3178356281・wayland 2743960399・libkeiland 536750976・
    libvulkan 4160257452）、`kern.boot.login: graphical`、uname は 8f91a0d のまま。/root/q1889 は板から消した。板は UAT の image の起動のまま
    （依頼の時の「console の login・vmunix 604485635」の状態ではなかった）。
- 未実施: 他の機械（Pi 4・VF2・amd64）の実機・QEMU での確かめ（同じ glass.c なので同じく直る見込み、未確認）、system bar・Alt+Tab・通知の app の絵の目視、
  SD に書いた新しい CI の image 全体での起動、tile の配置の host 試験（無い。溢れは `KWL GLASS no tiles` の行で分かる）。
