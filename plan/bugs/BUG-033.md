Bug ID: `BUG-033`
Reproduction: reproduced（QEMU、amd64 guest、KVM）
Disposition: scheduled（ws046-p012。主因は ws046-p007 で、region の page の探索・reclaim の queue・HAL の rdmsr は ws046-p009 で直した）
Date: 2026-09-24
Source: ws046-p004（q404-i01）で、guest で expat 2.8.5 を我々の make で build したとき。ユーザー判断（2026-09-24）: 「これはコンパイルできたとしても遅すぎます。issueとして扱います。」
Owner: WS046
Queue: none（残りは ws046-p009 として計画）

## 期待と観測・影響

期待: guest（KVM）の clang の compile が、host の同じ compile の数倍以内で終わる。

観測（`plan/tools/guest/guest.py` の既定: memory 512 MiB、4 CPU、KVM、disk は xHCI の usb-storage）:

- expat の `./configure` は約 6 分（guest の 10:00 頃〜10:06。ws042-p005 では約 270 秒）。
- `make` は 10:06 に始まり、10:57 の時点で `lib/` の 8 つの `.lo`（xmlparse・xmlrole・xmltok と random_* の小さい 5 つ）を作っただけ（約 51 分）。
  host では同じ expat の build が数十秒。
- 10:54 の時点で動いていた clang の process の CPU 時間は 25 秒（`ps -ef`）。**壁時計の時間の多くは CPU を使っていない**（待ち）。

影響: guest で package を build する WS046 の受け入れ（p004 の残り、p008）と、guest を開発に使う全般。

## 見立て（未検証、ws046-p007 で測る）

1. [BUG-027](BUG-027.md): file を裏付けにした page の fault が 1 page あたり ms かかる（先読みが無く、1 page ずつ同期の `file_pread`）。clang は 160 MiB の LLVM の library を map して起動する（`clang --version` に 11〜15 秒）。**第一の候補**。
2. memory 512 MiB: library の page と compile の作業領域で page の再読み込みや swap が起きている可能性。
3. disk が USB の mass storage（xHCI、BOT）: I/O が遅く、[BUG-030](BUG-030.md)（間欠の error 42）もこの経路。
4. libtool（我々の `/bin/sh`）の起動の多さ、fork・exec の費用。

## 調べたこと・直したこと（ws046-p007、q411-i01、2026-09-24）

- **主因は kernel ではなく libc の allocator**（`src/libc/heap.c`）: `free()`・`realloc()` が pointer を確かめるために heap の全 block の鎖をたどり、
  heap の伸長（64 KiB ずつ）も最後の block を探して鎖をたどっていた。clang の compile で 2 乗より悪い。gdbstub で vCPU の program counter を 40 回とり、
  40 回とも同じ user 空間の loop にいたことから特定した。定数時間の確かめ（両隣が指し返すこと）と `last` に直した。
- **buffer cache の hash**（`src/kern/buf.c`）: bucket が 64 で key の下位の bit が line の揃いで偏り、実際は 8 つだけ使われていた。memory を増やすと遅くなった。2^13 の bucket と乗算の hash に直した。
- 結果（guest、512 MiB）: `xmlparse.c` の compile 513・550 秒 → 6.5〜6.9 秒、expat の `make` 51 分以上（未完）→ 97 秒。2 GiB では compile 5.05 秒（host の 4.9 倍）。
- 残り（512 MiB で compile が host の 6.3〜6.7 倍、`clang --version` 0.89〜1.06 秒）: buffer cache が memory の 1/16 で LLVM の library が入らない、
  file の page を process の間で共有しない、USB の storage の完了を `sched_yield()` で待つ。ws046-p009。
- 見立ての 1（BUG-027 の file の fault）は主因ではなかった: kbench の file の fault は 1 page 約 22 µs のまま（変えていない）。
