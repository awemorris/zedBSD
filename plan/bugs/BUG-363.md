# BUG-363: zedBSD の image に /etc/hosts が無く、名前の解決で localhost が引けない

- 状態: open（2026-10-30 Q1 が登録） → fixed（2026-10-31 P2、q1750-i01、QEMU で確かめた。実機は未実施。Q1 の判定待ち）
- 発見: 2026-10-30 P2（q1697-i02、WS327 p003 の guest の試験）。`kl_socket_resolve("localhost")` が ENOENT。image に /etc/hosts が無く、DNS も localhost を答えない（libkeiland の層は正しい）。
- 影響: localhost の名前を使う program（試験・app）が名前の解決で失敗する。
- 直す方針: base の image に /etc/hosts（`127.0.0.1 localhost`・`::1 localhost`）を入れる（userland の etc の雛形）。または libc の resolver が localhost を常に答える。どちらかは直す担当が POSIX・既存の etc の扱いを見て決める。
- 回避: WS327 の guest-layers.sh は捨てる guest に loopback の 2 行を足している。
- 日程: 次のセッションの始めに取り組む（2026-10-30 ユーザー「BUG-363は、次回のセッション開始時に取り組むようにスケジュールしておいてください。」）。

## 修正（2026-10-31 P2、q1750-i01）

- 方針: libc の resolver は /etc/hosts を DNS の前に読む（`userland/base/libc/resolver.c` の gai_hosts）ので、resolver に特例を足さず base の image に /etc/hosts を入れた（BSD・Linux と同じ形）。
- 変更（8c8c556b5）: `userland/base/etc/hosts`（`127.0.0.1 localhost`・`::1 localhost`）を新設し、`Makefile` の ZEDBSD_ACCOUNT_INPUTS・ZEDBSD_ACCOUNT_FILES に /etc/hosts（0644）を足した（/etc/services と同じ道。amd64・armv7・sparcv9 ほか ZEDBSD_ACCOUNT_FILES を使う全ての root）。
- 注意: getaddrinfo の AF_UNSPEC は IPv6 の行を先に返す（::1 が先頭、127.0.0.1 が次）。
- 確かめ: QEMU（amd64、`plan/tools/guest/config-amd64-ssh.mk` の image、SSH で判定）で /etc/hosts に `127.0.0.1 localhost` があり、getaddrinfo("localhost", AF_UNSPEC) が ::1 と 127.0.0.1 を返した。再起動の後も同じ。実機は未実施。
- 試験の script（tree の外、P2 の worktree の build/tmp/q1750/）: qemu-bugs.sh（6 件）・qemu-bugs2.sh（366・354 の再試験）・bugcheck.c（guest の確かめの program、build/llvm の clang で sysroot に対して compile して scp）。
