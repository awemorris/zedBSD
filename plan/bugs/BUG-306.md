# BUG-306: Settings で回転を 0°→90° と 2 回目に選ぶと Settings の窓が消える（kl_window_present_parts が -4）

- 状態: fixed（2026-10-31 P2 q1757-i01、BUG-292 の修正で -4 の候補の経路を塞いだ。Settings の回転の再試験は未実施）。元: unreproduced（-4 は T1-613 で再現せず）/ tracking（2026-10-14 Q1: 窓の位置と選んだ絵の色は直り T1-613 で確かめた。-4 の原因は未特定。回転の ms= が 7〜10 s と長いのは別に P3 が調べる）
- 発見: ws217-p004 の T1-611（main d9e8506）。R3（90°）・R4（0° に戻す）の後、Settings で 90° を再び押す（ms=12042）と Settings の窓が消えた（`aat windows` で mapped False）。session.log に `ZSETTINGS FAILED operation=kl_window_present_parts result=-4`（1 回目の 90° では出ない）。0° に戻した後、Settings の窓が元の位置（x=50）でなく x=12 に寄った。回転の最中の `aat shot` は数秒 `no-active-compositor`。
- 証拠: T1 の worktree の build/review/t1-611/（PNG）。
- 関連: WS217 p004（Settings の回転）、p002b（turn、窓の再配置）。

## 解析（2026-10-14 P3、静的。QEMU は起動していない）

### 確かめたこと（コードと T1 の証拠から）

1. **窓が消える仕組み**: Settings の `main_frame`（`userland/desktop/settings/main.c`）は `se_present_frame` が `VK_ERROR_OUT_OF_DATE_KHR` 以外を返すと `ZSETTINGS FAILED` を書いて `-1` を返し、process が終わる（窓が消える）。`result=-4` は Settings の写し（`present.c`: libkeiland の `kl_window_present_parts` が EAGAIN 以外の 0 でない値 → `VK_ERROR_DEVICE_LOST`）で、本当の Vulkan の結果ではない。本当の結果は libkeiland が一度だけ書く `KEILAND PRESENT_FAILED call=… operation=… result=…` の行にある。
2. **その行は残っていない**: T1-611 の session.log は `/run/user/1000`（tmpfs）にあり、R5 の login し直しで消えた。T1 の disk image（`t1/build/t1-611-src/build/t1-611-run/disk.img` の UFS を host で読んだ）には `/var/log/{kernel,sessiond,greeter}.log` しか無い。よって **-4 の原因（どの Vulkan の呼び出しが何を返したか）は未特定**。
3. **窓の位置（x=12）**: compositor の `kwl_glass_output_resized`（`wayland/shell.c`）は浮いた窓を新しい大きさの空間の中へ動かすだけで、元の場所を覚えていない。90°（論理 800x1280）で 1180 幅の Settings は x=12 に寄せられ（Settings はその後 bounds で 776 幅に縮む）、0° に戻っても x=12 のまま。コードどおりの挙動で、原因は確定。
4. **選んだ角度の絵が見えない**（Q1 の追加、r3.png）: `page-display.c` の `display_rotation_tile` は選んだ角度の地を `SE_COLOR_ACCENT`、絵と文字を `SE_COLOR_ACCENT_TEXT` で描く。`accent_text` は「accent を地の上の文字の色にしたもの」（palette.c の値は accent と同じ 0x2f7cf6）なので、accent の上で見えない。原因は確定。

### -4 の候補（未確認、次の T1 の証拠で判定する）

- libvulkan の Wayland の WSI（`libvulkan/wsi-wayland.c` の `wayland_commit`）は FIFO の present で前の frame の callback を最大 10 s（`WAYLAND_WAIT_NS`）待ち、来なければ surface を恒久に lost にする（以後 `VK_ERROR_SURFACE_LOST_KHR` → libkeiland の EIO → Settings の -4）。libkeiland の acquire・fence の待ちも 10 s（`PRESENT_TIMEOUT`、`VK_TIMEOUT` は EIO になる）。
- Q1 の伝えた `ms=12042` が compositor の `KWL OUTPUT rotate … ms=`（回転の処理の長さ）なら、2 回目の 90° で compositor の main thread が約 12 s 止まり、その間 Settings の frame callback が 10 s を超えて来なかった、で説明がつく（`aat shot` の数秒の `no-active-compositor` とも合う）。何が 12 s かかったか（新しい turn・壁紙の画像、render thread の park、`vkDeviceWaitIdle`、窓の合わせ・保存）は今の log では分からないので、回転の段ごとの時間を log に足した（下）。

### 直したこと（agent/p3 66a2bc2ef）

- compositor: 浮いた窓が出力の新しい大きさで動かされたら、元の場所と動かした先を覚え（`struct kwl_fit_home`、`rotate.h` の `kwl_rotate_fit_window`）、窓がその場所に居るままなら次の大きさの変化では元の場所から合わせ直す。90°→0° で x=50 に戻る。利用者が動かした窓は動かした所から。log `KWL OUTPUT window … state=floating x= y= w= h= moved= home=x,y`。
- compositor: 回転の段ごとの時間の log `KWL OUTPUT rotate times prepare_ms= park_ms= idle_ms= swap_ms=`（`output-rotate.c`、診断。-4 の判定のため）。
- Settings: 選んだ角度の絵と度数を theme の `accent_ink`（accent の上で読める白か黒）で描く。
- -4 そのもの（Settings が消えること）は、原因が未特定なので直していない。

- 各回の後: `aat windows` で Settings が mapped True、PNG を撮る。選んだ角度の絵は accent の地の上に絵と度数（「90°」など）が白（または黒）で読める（r3.png のような塗りつぶしでない）。

## 2026-10-14 T1-613: PASS（-4 は再現せず）

- 90°→0°→90°→270°→0° の 5 回とも Settings は残り、FAILED の行 0。0° で x=50 に戻る。選んだ絵は白で読める。
- 回転の ms= は 9830・8795・7285・100（270°、大きさが同じ）・2386。rotate times の prepare と swap は各 1 s 前後で、残りの数秒の内訳は未特定。回転の約 3 s 後の最初の撮影は窓が崩れた位置。

## 2026-10-14 P3: 回転の ms= の内訳と修正（静的、QEMU は起動していない）

- 内訳（T1-613 の log と source）: 大きさが変わる回転の turn の分は約 2.1〜2.35 s（壁紙の作り直し約 0.9 s、device を止めた間の Vulkan の object の作り直し約 1.2 s）。残りの 5〜7.5 s は turn の後の displays.conf の保存の `fsync`。zedBSD の UFS の fsync は volume 全体を書き出して disk に flush を求め、QEMU では host の image の fdatasync になる（host の負荷で 32 ms〜7.5 s に揺れる）。回転の間 main thread が止まる（-4 の候補の 12 s も同じ経路の可能性がある）。
- 直した事（agent/p3 777da859b・e8762528e・e9d61dada）: displays.conf を thread で書く。回転の壁紙の layout の移動を 1 回の submit にまとめる。回転の後、窓が新しい大きさを描くまで（最長 1 s）回転の前の frame を出し続ける（崩れた絵の対策）。段ごとの時間の log。詳しくは [ws217-p004](../ws217/phase004/phase.md) の「回転の遅さと回転の直後の古い絵」。
- 次の T1 の依頼の文は同じ節にある（ms= と times の行、回転の 1 s・3 s 後の PNG、`KWL DISPLAYS saved by=writer` の ms=）。

## 2026-10-14 T1-614 と P3 の修正（静的、QEMU は起動していない）

- T1-614（main `f66e92abe`）: 回転の `ms=` 1825〜1938（目標どおり）、displays.conf も正しい。大きさが変わる 4 回のうち 3 回は保持が時間切れ（`late=1`）、回転の約 3 s 後に古い 1180x680 の Settings が縦の画面で切れて見え、約 8 s 後に正常。30 s ごとの `clients_us` 約 1.9 s は回転の request の処理そのもの（at_ms が 4 回の回転と一致、間隔は T1 の操作）。
- 原因（session.log と source）: 新しい bounds の configure が回転の**後**の pass で出る。Settings はその前に古い大きさの frame を 1 枚描き、configure を受けてから swapchain の作り直しに約 1.2 s、compositor の import に約 0.3〜0.6 s。回転 5 の `late=0` は ack の後に commit された古い大きさの frame を新しい大きさと誤って見た。
- 直した事（agent/p3 02c02dbf4）: 回転を begin と end に分け、render thread を park したまま新しい大きさを設定した所で窓の fit・wl_output・bounds の configure を**すぐ送る**（窓は compositor の image の作り直し約 1.1 s と並んで作り直せる）。保持は回転の終わりから数え、大きさを変えねばならない窓は大きさが変わった画像が来るまで待つ。Settings に `ZSETTINGS RESIZE … at_ms=` の行。詳しくは [ws217-p004](../ws217/phase004/phase.md) の「回転の後の窓の描き直しの遅れ」、T1 の再試験の依頼の文も同じ節。

## 2026-10-31 P2（q1757-i01）

- -4 の候補の経路（compositor の main thread が 10 秒以上止まる → libvulkan の Wayland の WSI が前の frame の callback を 10 秒待って surface を lost に latch → `kl_window_present_parts` が EIO → Settings の -4）を、compositor を `kill -STOP` で 15 秒止める形で QEMU で再現した（libkeiland の窓 kuidemo、前の libvulkan で 2 回とも `KEILAND PRESENT_FAILED ... operation=vkAcquireNextImageKHR result=-1000000000`）。詳細は [BUG-292](BUG-292.md)。
- BUG-292 の修正（WSI の FIFO の待ちは 1 秒で pacing なしの commit に、surface を失わせない。libkeiland の acquire は期限なし）で、同じ止めの後も窓は生きて描き続けた（1 回）。回転の時間は P3 の修正で約 1.9 s になっており、Settings の -4 は T1-613・614 で再び出ていない。
- Settings での回転の再試験は未実施（lean の image に Settings と session が無い）。T1 の回転の試験で -4 が出なければ閉じてよい見込み。
