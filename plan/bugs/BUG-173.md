## 観測

F10: 上下の矢印で履歴は出る（BUG-103 は直っている）が、長めの日本語の文字列の行を呼ぶと、表示に改行が入り、行頭から表示されて prompt が見えなくなる。行の編集が全角の文字の幅（2 桁）を 1 桁と数えている疑い。

次: `/bin/sh` の行の編集の桁の計算（wcwidth）を読む。host で再現できる。

## 原因と修正（2026-10-05 P1 generation17 / q725）

- 原因: sh の行の編集（`userland/base/libedit/readline.c`）は、cursor を byte の数で動かしていた（`ESC [ n D` を byte 数ぶん）。日本語の 1 文字は UTF-8 で 3 byte・表示は 2 桁なので、行の頭へ戻る時に表示の桁より多く左へ動き、画面の左端で止まって、その位置（prompt の上）から行を書き直していた。terminal の幅を超えて折り返した行は、`ESC [ n D` では上の段へ戻れない。左右・Backspace・Delete も byte 単位で、日本語を 1 byte ずつ消していた。
- 修正（`readline.c`、emacs mode）:
  - 位置を「prompt の始めからの段と桁」で数える（`text_advance`・`line_position`）。文字の幅は UTF-8 を解いて libc の `wcwidth` と同じ表（全角 2・結合 0・制御 0、`ESC [` の列は 0）、端に入らない全角は次の段へ（terminal と同じ）、行が右端ちょうどで終わったら `\r\n` で次の段へ進めて pending wrap を残さない。terminal の幅は `TIOCGWINSZ`（無ければ 80）。
  - cursor は段と桁で動かす（`cursor_to`: `ESC [ n A/B` で段、`ESC [ n C/D` で桁）。変わった所から行末まで書き直し、行が短くなった時だけ `ESC [ J` で残りを消す。Enter・Ctrl-C の前に行の最後の段へ移る。補完の一覧の後も prompt から描き直す。
  - 左右・Backspace・Delete・Ctrl-D は 1 文字（UTF-8 の連続 byte を含めて）ずつ。打ちかけの多 byte の文字の途中では描かない。
- 範囲外で残す: vi mode の動き（`h l w b x` など）は今も byte 単位（README の vi mode の節）。prompt が列の途中から始まる場合（前の出力が改行で終わらない時）は、最初の描き直しで prompt の頭がずれうる（他の小さな行編集と同じ前提: prompt は行頭から）。
- 確認:
  - `python3 plan/ws073/tests/host-bug173.py build/bug173/host-sh`（`plan/tools/sh/build-host-sh.sh` の host の sh を 40 桁の pty で動かし、UTF-8・全角 2 cell・autowrap と pending wrap・CR・LF・CSI A B C D J K の terminal の模型に描く）8 checks ok: 打った日本語の長い行が折り返し prompt が残る、Up で呼んだ行が prompt の段から描かれる、Ctrl-A が prompt の後へ・Ctrl-E が最後の段へ、Backspace と Left が 1 文字、編集した行が走る。直す前の readline.c では 3 つが FAIL することを確かめた。
  - 既存の pty の試験: `plan/tools/sh/complete-host.py` 29/29、`history-host.py` 17/17、`prompt-host.py` 8/8、`vi-host.py` 33/33。
  - amd64 の `bin/sh` warning 0、style-check 指摘 0。
