# BUG-344: libc の fscanf・vfscanf・scanf が 1 行しか読まず、行の残りを stream に戻さない

- 状態: reproduced（2026-10-21、VF2 の gpu-selftest の present の段）/ tracking → closed（2026-10-31 Q1 の判定、main f81fef099。2026-10-31 P2、q1750-i01、QEMU で確かめた。実機は未実施。Q1 の判定待ち）
- 発見: WS269 q1487〜q1489（P1）。gpu-selftest が vkdemo の frame の header `"P6\n320 240\n255\n"` を `fscanf(f, "P6 %u %u %u", …)` で読むと 1 しか返らず、正しい 320x240 の PPM を「PPM でない」と判定した（板 83）。
- 原因: `src/libc/stdio-extra.c` の vfscanf が `fgets`（4096 byte の buffer）で 1 行を読んで `vsscanf` に渡すだけ。書式の空白は改行を跨いで読み飛ばさず、変換が使わなかった入力は `ungetc` で戻されず捨てられ、4095 byte を超える行は切れる。
- 期待: 書式の空白は改行を含む任意の空白を読み飛ばし、使わなかった入力は stream に残る（C の標準。glibc では上の例で 3 が返る）。
- 再現: 上の 3 行の file を `fscanf(f, "P6 %u %u %u", …)` で読む → zedBSD は 1、glibc は 3（glibc の値は標準からの推定、未実行）。
- 影響: 複数行の入力を fscanf で読む program 全般。gpu-selftest は q1489（b70559027）で fscanf を使わず header を自前で読む形に回避済み。
- 関係: WS269 p010q。libc の修正は別の WS（libc の stdio）で。
- 再調査の条件: libc の stdio の WS で vfscanf を stream から直接読む実装に直した時に、上の再現で 3 が返る事。

## 修正（2026-10-31 P2、q1750-i01）

- 変更（b69021a4b）: scanf 系を `src/libc/scan.c` に新しく書いた（`src/libc/stdio-extra.c` の fgets + vsscanf と古い vsscanf を削除し、`src/libc/libc.mk` の 2 つの source の一覧に scan.c を足した）。stream と string の両方を 1 つの scanner で読み、1 文字ずつ取り、先読みの 1 文字だけを ungetc で戻す。書式の空白は改行を含む空白を読み飛ばし、使わなかった入力は stream に残る。行の長さの制限は無い（数の item の text は 128 byte を超えると heap に移る）。stream は呼び出しの間 flockfile で保つ。
- 併せて直した事: 空の入力・空白だけの入力で EOF（ISO C、今までは 0）、`%[a-z]` の範囲、`%zu`・`%jd`・`%td` の格納の幅（32 bit の platform で long long を書いていた）、`%lc`・`%ls`・`%l[` を byte ごとの mbrtowc で。
- glibc と違う点（ISO C に従った）: `"100ergs"` を `%f` で読むと 0（ISO C の例の通り、glibc は 1）、`"0x"` を `%x` で 0、`"2.5e"` を `%lf` で 0。
- 確かめ: host 試験 `tests/scanf-host-test.c`（`make ZEDBSD_CONFIG=… BUILD=… scanf-host-test`、上の再現を含む 55 の確かめ）が PASS、ASan・UBSan でも PASS。amd64 の libc.so の build は warning 0、i386・armv7・riscv64・aarch64 の clang で scan.c の compile も warning 0。QEMU（amd64、SSH）で guest の program が上の 3 行の file を `fscanf(f, "P6 %u %u %u", …)` で読んで 3（320・240・255）、次の fgetc が改行、`"12abc\n7\n"` を `%d` で 12 の後に 'a' が残る事を確かめた。gpu-selftest の回避（b70559027）は戻していない。実機は未実施。
- 注意: libc の source を変えたので、各 worktree の sysroot（build/amd64/sysroot など）が作り直される。
- 試験の script（tree の外、P2 の worktree の build/tmp/q1750/）: qemu-bugs.sh（6 件）・qemu-bugs2.sh（366・354 の再試験）・bugcheck.c（guest の確かめの program、build/llvm の clang で sysroot に対して compile して scp）。
