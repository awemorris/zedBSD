# BUG-407: ブラウザ: Google の検索の top で「Google 検索」「I'm Feeling Lucky」「AI モード」の button を押しても反応が無い

- 状態: fixed（2026-11-02 P8 q1924-i01、agent/p8-uat2。Linux の host build と live の google.com で、3 つの button と Enter が遷移を始める事を確かめた。本物の Windows は未実施。検索の結果の頁は Google の JavaScript の確認（下の「残り」）で reCAPTCHA の頁になる）。前: open（2026-11-02 08:22 Q1 が起票、P8 の待ち行列）
- 発見: 2026-11-02 08:22 ユーザーの Windows での OmniGrammaton の UAT。
- 中身: 検索語を入れて「Google 検索」の button を押しても反応が無い。「AI モード」「I'm Feeling Lucky」の button も反応が無い（form の submit、button の click の handler、遷移の経路を疑う）。
- 扱い: P8（ブラウザの担当、ユーザーの決定）。BUG-401 の後に BUG-402〜406 と一緒に。

## 原因（2026-11-02 P8）

Windows に固有ではなく libbrowser の問題で、Linux の host build でも同じだった（`build/tmp/p8u/drive.c`、P4 の drive.c に Enter・eval を足した道具、commit しない）。重なった 5 つ。

1. 「Google 検索」の click が button に届かない（時々）: 検索の欄の「AI モード」の button の中に、光る効果の飾りの箱（`pointer-events:none` の親の中の `scale` の大きい絶対配置の子）があり、子は `pointer-events:none` を継承する。libbrowser は `pointer-events` を知らず、hit test は飾りの子を click の的にした。飾りの形が効果の段で変わるので、button に届く時と届かない時があった（gdb で的の element を出して確かめた、4 回中 2 回が飾りの div）。
2. 「AI モード」と Enter に反応する Google の script（xjs の chunk）が読めない: `for await` を JavaScript の compiler が知らず SyntaxError で chunk 全体が落ちていた（BUG-398 で P7 が見た物）。読めた後も `Node.compareDocumentPosition`・`document.getElementsByName`・`Element.getAttributeNS` が無く、chunk の初期化と頁の側の script（LCP の走査）が TypeError で止まっていた。
3. script からの遷移が実装されていなかった: Google の script は Enter・button で `form.submit()` を呼ぶが、prelude の遷移は frame だけを動かし、top-level の window では「ここでは読まない」で何もしなかった（`location.href =`・script の `a.click()` も同じ）。
4. `form.submit()` の entries が空: prelude の FormData は control の `name`・`value` の property を読むが、textarea・select・button に `name`（と `disabled`）の反映が無く、select に `value`、option に `value`・`text` が無かった。検索語（textarea の q）が送られなかった。
5. （4 の結果）手で押した submit の button の既定の動作（native）は送れたので、1 が起きない時だけ「Google 検索」は遷移していた。

## 直し（2026-11-02 P8、agent/p8-uat2）

- `pointer-events`（継承、auto と none。SVG の値は auto と同じに扱う）: `css/internal.h`・`css/css.h`・`css/values.c`・`css/cascade.c`、`getComputedStyle` は `bind/computed.c`。hit test（`layout/hit.c`）は `pointer-events:none` か `visibility:hidden` の box を的にせず（子は的になりうる）、その下を探す。
- `for await`（async function の中）: `js/compile.c` の `compile_for_await`。iterator は新しい命令 `async_iter_start`（`vm/spread.c` の `vm_async_iter_start`、Symbol.asyncIterator、無ければ Symbol.iterator で同期の iterator の値を await する）、結果が object でなければ `check_object` が TypeError。break・return・throw は return を呼んで await し（throw の時は return の誤りを捨てる）、next・await の誤りでは return を呼ばない。
- `Node.compareDocumentPosition` と `DOCUMENT_POSITION_*`（`bind/node.c`）、`Element.getAttributeNS`・`hasAttributeNS`（`bind/element.c`）、`document.getElementsByName`（prelude、querySelectorAll による生きていない NodeList）。
- top-level の script の遷移: prelude の `leaveForDocument` が frame の無い window で新しい native `navigateTop(url, replace)`（`bind/prelude.c`）を呼び、window に要求を置く。view（`view/view.c`）は `browser_view_process` でそれを取り（`bind_take_navigation`）、link と同じく link の callback を通して follow する。要求がある間は `browser_view_timeout` が 0。POST・download・history の traversal は今まで通り何もしない。replace も新しい history の段になる（view の history に置き換えの口が無いため）。
- 反映: textarea・select・button・fieldset・output の `name`・`disabled`、textarea・select の `type`、select の `multiple`・`value`、option の `value`・`text`（prelude）。
