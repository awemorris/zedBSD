# BUG-370: Photos で全面表示の写真を回転・お気に入りなどで保存すると、約 1 秒後に全面表示が閉じて Timeline に戻る

- 状態: closed（2026-10-31 Q1 の判定、main に merge。2026-10-31 P6 q1740、commit acf7ff71a。QEMU の scenario apps.photos.browse で確かめた。merge は Q1）
- 発見: 2026-10-30 P5（WS327 p016 の QEMU の回帰 run 3、q1710-i01）。scenario apps.photos.browse で、全面表示で R（回転）の保存の後の F で fail。
  画面: `/home/awe/zedBSD-worktrees/p5-ws327/build/ws327-p016-apps3/aat/png/apps.photos.browse-turned.png`（全面表示が Timeline に戻っている）。
- 影響: Photos で写真を回転・お気に入り・album に入れると、見ていた写真が閉じる。scenario apps.photos.browse がこの所で fail する。
- 原因（P5 の読み、未修正）: Photos 自身の保存で compositor が全ての watcher に CHANGED を送り、`userland/desktop/photos/main.c` の 728〜732 行の
  refresh → `ph_media_results` → `ph_view_reset`（`view.c` の 254〜263 行）が open と slideshow を条件なしに消す。`main.c` の 404 行の comment
  「without disturbing the currently browsed library」と食い違う。e654733f1（2026-10-10）から。WS327 は photos の main.c・view.c を変えていない。
- 直す方針（案）: 自分の保存による CHANGED では view を reset しない、または reset の後に開いていた写真と slideshow を戻す。

## 原因（確かめた）

- P5 の読みのとおり。Photos 自身の保存（回転・お気に入り・album）で compositor が CHANGED を送り、`main.c` の `ph_refresh` → 読み直し → `ph_media_results` が
  library を読み直した後に `ph_view_reset` を呼び、全面表示（open）・slideshow・list・選択を条件なしに消していた。読み直しの後は写真の index が変わり得るので、
  index のままでは残せない。

## 直し（commit acf7ff71a）

- `userland/desktop/photos/view.c`・`app.h`: `ph_view_remember`（library を手放す前に、list と album を album の id で、全面・選択・album の card・drag の写真を
  写真の id で、全面の picture（回したもの）、slideshow とその時刻、grid の scroll を覚える）と `ph_view_restore`（`ph_view_reset` の後に、library に残る物を
  新しい index で戻す。消えた album は Timeline、消えた写真は閉じる。picture は写真の今の回転との差だけ回す。戻さなかった picture は放す）。
- `main.c` の `ph_media_results` が読み直しの前後でこの 2 つを呼ぶ。他の読み直し（別の Photos・CLI の取り込み）でも同じく view が保たれる。
- 試験の文書の古い記述（「読み直しで Timeline に戻す」）を直した: `tests/scenarios/apps/photos/browse.md`、`plan/tools/aat/scenarios/helpers_photos.py`。
