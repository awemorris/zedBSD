# BUG-372: VisionFive 2 の今の main の kernel で、serial の console が入力を受けない

- 状態: closed（2026-10-31 Q1 の判定、30fd47a4f。VF2 の実機で serial の login が通った）
- 発見: 2026-10-30 P2（WS291 p020、VF2 の serial /dev/ttyUSB0）。main の kernel で `login:` まで出力は出るが、CR や文字を送っても echo も応答も無い。
- 疑い（未確かめ）: WS331 p005 で VF2 の console を共通の boot-fb・fb-text に移し、ns16550 を「serial の送信」に渡す形にした時に、受信（入力の thread）を繋いでいない。Pi の rpi-console.c は UART の送受信と入力の thread を持つ。
- 影響: VF2 で network が上がらない時に、serial から操作できない。
- 直す方針（案）: VF2 の platform の glue（src/kern/platform/visionfive2.c）で、Pi と同じく UART の受信を tty の入力に繋ぐ。

## 原因（2026-10-31 P7）

- 退行ではなく未実装。5aca73738（WS331 の前）の `src/kern/platform/visionfive2.c` でも `kern_platform_input_init()` は USB keyboard だけを繋ぎ、
  comment は「the board's UART does not type into it yet」だった。console の UART（/chosen/stdout-path）は `drv_ns16550_probe_console()` で
  map するだけで、`drv_ns16550_start_input()` を誰も呼ばない。WS331 p005 で console が boot-fb・fb-text に移っても、この点は変わっていない。
- riscv-virt（`src/kern/platform/riscv-virt.c`）は同じ ns16550 の driver で `drv_ns16550_start_input(&uart, drv_serial_console_receive)` を呼んでいる。

## 直し（P7、WIP 30fd47a4f）

- `src/kern/platform/visionfive2.c` の `kern_platform_input_init()`: console の UART があれば `drv_ns16550_start_input(&console_uart,
  drv_serial_console_receive)`（UART の受信の割り込みで、CR→LF・DEL→BS の変換の後に `tty_console_input_byte()`）。失敗は log して errno を返す
  （riscv-virt と同じ）。file の先頭と `probe_console_uart()` の comment を今の形に直した。
- `platform/riscv64/vmunix.mk`: VF2 の source の一覧に `src/drivers/generic/serial-console.c` を戻した（WS331 で外れていた。受信の変換の
  `drv_serial_console_receive()` を使う。出力の表は使わず link で落ちる）。
- 割り込みの番号は device tree の `interrupts`（uart0 は 32）を PLIC の source としてそのまま登録する（vf2-ethernet と同じ扱い）。
  DesignWare の busy detect は ns16550 の driver が扱う。fb-text の serial の出力（`drv_ns16550_putc_polled`）と受信の割り込みの並行は driver の
  output_lock と割り込みの禁止で守られる。

## 確かめ

- build: `make ZEDBSD_CONFIG=config/ci/config-visionfive2.mk BUILD=build/p7-vf2 build/p7-vf2/vmunix`（warning 0、error 0）。
- QEMU: VF2 は無い。riscv64 virt は同じ関数の組（ns16550 の start_input と drv_serial_console_receive）を以前から使っており、VF2 の固有の部分
  （DW UART・PLIC の 32・fb-text の出力との並行）は QEMU では確かめられないため、riscv64 virt の試験は流していない。

## 実機の確かめ（VF2、2026-10-31 03:00〜03:20、P7 専用、Q1 の割当）
