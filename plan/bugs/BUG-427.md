# BUG-427: Wi-Fi の PIN の設定中に ARM64 SError が 1 回出た（Pi 500、bcm43455）

- 状態: fixed（2026-11-13 Q1 が起票。2026-11-13 P1: Pi 5 で再現し、原因を特定して直した。Pi 500 での確かめは未実施。下の節）
- 発見: 2026-11-13 外部の利用者の Raspberry Pi 500（BCM2712 D0、8 GB）での報告（source c4cede8、2026-11-03）。
- 起きた事: Wi-Fi の PIN の設定中に ARM64 の SError が 1 回出たが、そのまま動き続けた。
- 確かめ: 今の main の rpi5 の image で再現するか（Pi 5 の実機、10.0.30.5）。再現しなければ、直した commit を探して記録し閉じる。

## 2026-11-13 P1 の確かめと修正（q2042-i01）: 再現し、直した

- 「Wi-Fi の PIN の設定中」は、起動の時の Wi-Fi の pin（端子）の設定の段の事だった。Pi 5（10.0.30.5、D0 の chip）で、元の kernel でも main の kernel でも毎起動、dmesg に `rpi5: SError pending after rpi5-wifi: routing the pins` と `ARM64 SError 1 esr=be000011 ... in the kernel at pc ...`（pc は `drv_rpi5_serror_check` の中、保留の SError を受ける所）が 1 回ずつ出る。Wi-Fi はその後も動く。
- 絞り: 段を細かく分けた診断の kernel（commit しない、source は戻した）で、`drv_rpi5_pinctrl_report` の直後に SError が保留になると分かった（pin の設定の書き込みの後ではない）。report の読みを 7 word（0x00〜0x18）に限ると SError は出なかった。D0 の pin controller は 0x00〜0x18 の 7 register だけを実装し、`PINCTRL_D0_BYTES` が 0x20 だったので report が 8 word 目（0x1c）を読んでいた。
- 修正: `src/drivers/platform/rpi5/rpi5-pinctrl.c` の `PINCTRL_D0_BYTES` を 0x1c に（出典と実機の根拠を block の comment に）。書き込みの範囲の検査（`write_field`）も同じ値を使うので、0x1c 以降には触れない。
- 確かめ: `make CONFIGMK=config/config.rpi5.mk BUILD_JOBS=4 -j4 vmunix` rc 0、warning 0、`arm64 vmunix check: PASS`。その kernel（cksum 1246177996）を Pi 5 に置いて起動し、dmesg の `serror` は 0 行、`SDIO and WL_ON pins routed`・`SDIO card: 3 functions`・bcm43455 の firmware の版の行が出た。試験の後に元の kernel（cksum 3179780313）へ戻して起動を確かめた。
- 未実施: Pi 500 の実機（Pi 500 の device tree も D0 の pin controller を 0x20 byte と書くので、同じ修正で消える見込み）、C1 の chip（C0 の block の大きさは変えていない）。
