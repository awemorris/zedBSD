# BUG-047: disk の無い file system（overlay・tmpfs・devfs）の `st_dev` が全て 0 で、mount をまたいで (st_dev, st_ino) が一意でない

Bug ID: `BUG-047`
Reproduction: reproduced（QEMU、amd64 guest）
Disposition: resolved（ws059-p001。disk の無い mount に `0x80000000 | (1 + slot)` の `st_dev`。`df` が全 mount を出す）
Date: 2026-09-25
Source: ws046-p013（q424-i01）で、cross build した GNU coreutils の `df` が引数無しでは root の overlay と tmpfs を出さなかったとき。
Owner: WS059 p001
Queue: q429-i01。

## 期待と観測・影響

期待: POSIX では (st_dev, st_ino) が file を一意に表す。別の mount の file は別の `st_dev` を持つ。

観測: guest で `stat -c %d` は `/`（overlay）・`/tmp`・`/run`・`/dev`・`/dev/shm`・`/shm` の全てで **0**（root の inode も全て 1）。disk の mount（`/work`、ufs）は 2。`statvfs` の `f_fsid` は disk が無い mount にも slot 番号を返しているので、kernel は区別を持っている。
GNU `df` は `stat(mountdir).st_dev` で mount を同一視するため、`df` は `/dev/shm`（bind の `/shm`）と `/dev/nvme0n1` しか出さず、`df -a` は overlay・tmpfs・devfs の行を出すが大きさは `-`。`df -h /` は正しく出す。

影響: `df` の既定の出力が root と tmpfs を欠く。`find -xdev`・`cp -x`・`du -x`・rsync など、`st_dev` で mount の境界を見る program が誤る。同じ inode 番号（root の 1）の file を同一と誤認しうる。

## 再開の条件

kernel の VFS を扱う WS で。案: disk の無い mount にも `st_dev` を与える（`statvfs` の `f_fsid` と同じ「1 + slot」を device 番号に使う、または擬似 device 番号を採番）。受け入れ: 全 mount で `st_dev` が異なり、`df` が全ての mount を大きさ付きで出す。
