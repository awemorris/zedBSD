# BUG-252: App Home の animation が pointer の事象が無いと終わらない（Calendar の icon の位置で止まる、i915 実機）

- 状態: reproduced（実機 5330、ベアメタル、i915、ユーザーの UAT 2026-10-07） / resolved（2026-10-08 夜 ユーザー「下記は実装の変更が多かったので、いったんすべてcloseします。」、Q1 の中継）
- 発見: 2026-10-07 ユーザー「App Homeで、マウスを動かしてイベントループを回さないと、アニメが終わらないです。Calendarのアイコンの位置でアニメがとまります。i915実機ベアメタルです。」

## 疑い（Q1、未確認）

- BUG-246（整列の animation、cfdb21813）と同じ種類: App Home の animation（ws181-p008 の奥へ・奥からの遷移、または app を開く時の icon からの拡大）が次の frame を描画の中で `dirty` にして頼み、compose.c が submit の後で消すので、次の frame は入力の時だけ。Venus の QEMU では client の commit で frame が回り隠れる。
- 「Calendar の icon の位置で止まる」: icon から窓が広がる（または縮む）animation の途中で止まっている可能性。

## 次

- compositor の全ての animation（Home の開閉・頁・app の起動の拡大・閉じる・整列・desktop の切り替え・OSK・popup）について、frame の頼み方を tick（`kwl_glass_tick` 等）からに揃えているか洗い出して直す。5330 の session.log を SSH で読める。

## 原因と直し（2026-10-07 P2、q854-i01）

- 原因: App Home の content（icon が順に 30 ms ずつ遅れて 180 ms で浮き上がる、BUG-225・ws099-p035c の `home_content`）は、次の frame を **描画の中で** `server->dirty = 1` にして頼んでいた。`compose.c` は submit の後で `dirty = 0` にするので、この頼みは消える。Home 自体の開く animation（`home_moving`、280 ms）は `kwl_home_tick` が頼むので、その間は frame が回るが、280 ms を過ぎると 5 番目（order 4: 4×30+180=300 ms）以降の icon は入力が来た時だけ進んだ。「Calendar の icon の位置で止まる」はこの 5 番目あたりの icon。BUG-246 と同じ種類。QEMU（Venus）では client の commit で frame が回り隠れる。
- 直し（`userland/desktop/wayland/home.c` だけ）: `home_open` が content を animate する時に `home_content_rising` を立て、`kwl_home_tick` が立っている間は毎回 `dirty = 1` にし、新しい `home_content_coming`（画面に出る icon の数から最後の icon が来終わる時刻を出す。Home が閉じに向かう・drag・即時表示の時は 0）が 0 になったら下ろす（下ろした pass の frame が全ての icon を最後の形で描く）。`home_content` の中の描画中の頼みは消した。
- 洗い出し（compositor の animation の frame の頼み方、2026-10-07 P2 の読み）: Home の開閉と奥へ・奥からの遷移（`home_moving`、`kwl_home_tick`）、頁（`home_page_moving`、同）、app の起動の icon からの拡大・dock・undock（`server->anim`、`kwl_glass_tick`）、desktop の切り替え（`desktop_moving`、同）、Wiseview（`wiseview_moving`、同）、system bar の dock の移り（`bar_dock_follow`、tick）、整列のメニュー・glide（`kwl_arrange_tick`、BUG-246 で直した）、OSK の slide（`kwl_keyboard_tick`）、power dialog（`kwl_power_dialog_tick`）、右上の corner の hint（`kwl_corner_tick`）、media の点滅（`kwl_media_tick`）、greeter の spinner（`kwl_greeter_tick`）は全て tick から頼んでいる。描画の中だけで頼んでいたのは `home_content` だけだった（整列の 3 つの関数は描画の中でも頼むが tick が頼むので害は無い）。popup・menu・switcher は時刻の animation を持たない（事象で頼む）。時刻で変わるが animation でない物として `body_rect` の `RESIZED_HOLD_MS`（1 秒、client が新しい大きさを描かない時の予備）は期限の時に frame を頼まない（client が描けば消える。今回は直さない）。
- 確かめ: zedBSD の compositor（`make -j16 ZEDBSD_CONFIG=plan/ws035/tests/config-amd64-zdesktop.mk BUILD=build/ws181 build/ws181/bin/wayland`、-Werror）と Linux の Keiland（`make -f userland/desktop/keiland-linux.mk KEILAND_LINUX_BUILD=build/ws181-linux all`）warning 0。host の試験は無し（frame の頼みは event loop と描画の間の事なので host で試せない）。実機（5330、i915）: pointer を動かさずに Home を開き、全ての icon が浮き上がり終わること（未実施、Q1 経由で入れ替え）。

## 2026-10-08 P2 の確認（q869）

- 実装済み（e1d330ed1）: wayland/home.c の `home_content_rising`・`home_content_coming`、`kwl_home_tick` が浮き上がりの間 dirty を立てる。
- 証拠: build の warning 0（zedBSD と Linux）。host では試せない（frame の要求）。QEMU（T1）も無い（Venus では隠れる）。
- 残り: 5330 の i915 で、pointer を動かさずに Home を開き、全ての icon が浮き上がり終わること。5330 の compositor の入れ替えは未実施。
