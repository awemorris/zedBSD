# BUG-362: 共有の shader の frontend が SPIR-V の NoContraction（GLSL の precise）を受けず、precise を含む shader が compile されない

- 状態: fixed（2026-10-31 P4 q1753-i01、f97f13268、host 試験。main に未 merge）
- 発見: 2026-10-30 P5（q1693-i01、WS291 の nvrtx の FFMA の融合を調べた時、source の読み）。
- 場所: `src/drivers/gpu/compiler/spirv.c` が NoContraction を「decoration that is not interpreted」として module ごと拒否する。frontend は decoration を IR に運ばない。
- 影響: GLSL の `precise`（SPIR-V の NoContraction）を使う shader は、共有の frontend を使う全ての GPU の executor（nvrtx・mali など）で compile に失敗する見込み（未確かめ）。
- 直す方針: frontend が NoContraction を受け、IR の命令に「融合しない」印を運ぶ。各 backend はその印のある演算を FMA に融合しない（nvrtx は 374eb20c3 で module に NoContraction があれば融合を全部止める暫定の扱い）。

## 直し（2026-10-31 P4 q1753-i01、f97f13268）

- frontend（`src/drivers/gpu/compiler/spirv.c`）: NoContraction を id の記録に受け、浮動小数の算術（OpFAdd・OpFSub・OpFMul・OpFDiv・OpFNegate・行列とベクトルの積・OpDot・OpExtInst など）の結果が NoContraction の時、その SPIR-V の命令から下ろした IR の命令すべてに `no_contraction` の印を付ける（`ir.h` の `struct drv_gpu_shader_ir_inst` に field を足した）。`DRV_GPU_SPIRV_FEATURE_NO_CONTRACTION` の bit は要らなくなったので消し、mali の feature の一覧からも外した。
- inline（`spirv-inline.inc`）: 呼ばれる関数の中の precise の結果の新しい id に OpDecorate NoContraction を書き直す（module の最後の decoration の後、spirv-val が通る位置）。前は呼ばれる関数の id の decoration を全部落としていた。
- optimizer（`optimize.c`）: 共通の部分式をまとめる時、残す命令の印に消す命令の印を足す（OR）。
- backend: nvrtx（`sm75/registers.c` の FFMA への融合）と i915（Gen12 の MAD）が、積か和のどちらかに印があれば融合しない。nvrtx の module の走査による暫定の扱い（374eb20c3）は戻した。amdrdna・ghci・bcm2711・mali は IR の積と和を融合しないので変更なし。
- 確かめ（host）: `plan/tools/nvrtx/nvrtx-sm75-host-test.sh` 308 checks 0 failures（precise.comp が compile され FFMA 0・FMUL 1・FADD 1。試験は「拒まれても可」を「compile される事」に改めた）。`plan/ws313/tests/spirv-inline-host-test.sh 10` PASS（pair 3・spirv-val 3・same 80/80）。`plan/ws313/tests/mali-compiler-host-test.sh 20` PASS（35/35）。`plan/tools/gpu-compute/host/run.sh` の compile・lower の段は PASS（後の executor-test.c は `i915-vk-render-stubs.inc` の `hal_physaddr_t` で compile できず、この直しと無関係の既存の失敗）。使い捨ての host 試験で、precise.comp の FMUL・FADD に印、contract.comp に印なし、precise を含む helper 関数（glslc -O なし）を inline すると印が 1 組残り、書き直した module が spirv-val を通る事を見た。amd64 の vmunix は warning 0。
- 未実施: 実機の GPU（nvrtx・i915）で precise を含む shader を走らせる確かめ。`plan/tools/v3d-qpu/shader-host-test.sh` は Mesa の一時の tree（plan/ws141/temp）が無く走らない。
