# BUG-420: LLVM の source の展開が file の時刻で繰り返され、build が source を上書きする

- 状態: fixed（2026-11-12 Q1。修正を当て、main と新しい worktree で確かめた）
- 発見: 2026-11-12 WS333 の P1（q2012）。worktree で i386 の vmunix を build すると、LLVM の tarball を取得し、`build/llvm-source`（main の checkout への symlink だった）に `tar -x` と `patch` を走らせた。

## 原因

1. 全機種の libc は compiler-rt の builtins を LLVM の source（`build/llvm-source/compiler-rt/lib/builtins`）から compile する（`mk/platform-*/libc.mk` の `LLVM_BUILTIN_DIR`）。i386・pc9821 の vmunix はその `libclang_rt.builtins.a` を link する（`mk/platform-pc9821/vmunix.mk:96-98`）。
2. builtins の source は `$(LLVM_SOURCE)/.patched` を待つ（`mk/libc.mk:117`、order-only）。`.patched` の規則（`mk/llvm/llvm.mk:119-123`）は **tarball と patch の file の時刻**に依る: tarball が無いと取得し、取得した tarball は `.patched` より新しいので、既にある source の上に `tar -xf` と `patch` をもう一度走らせる（2 回目の patch は「Skipping」で exit 1）。
3. worktree は tarball（`mk/llvm/distfiles/`、git に入らない）を持たないので、必ずこの道に入る。以前の運用で `build/llvm-source` を main の checkout への symlink にしていたため、main の source を上書きした。
- 付け足し: `mk/llvm/Makefile:11` の `llvm-source-verify` は定義が無く、`:5` の `toolchain/llvm/llvm.mk` は存在しない（作り直しの前の名前）。

## 修正案（Makefile の変更、ユーザーの確認の後に当てる）

source を時刻でなく**中身の識別子**（tarball の SHA-256 は `mk/llvm/version.mk` の `ZEDBSD_LLVM_ARCHIVE_SHA256`、patch は SHA-256）で見る。一致すれば何もしない（tarball も取らない）。違う・無い時だけ、新しい directory に展開して patch し、置き換える。

```diff
--- a/mk/llvm/llvm.mk
+++ b/mk/llvm/llvm.mk
@@
 llvm-download: $(LLVM_DISTFILE)

 $(LLVM_DISTFILE):
 	@mkdir -p $(dir $@)
 	curl --fail --location --output $@ "$(ZEDBSD_LLVM_ARCHIVE_URL)"
+	@echo '$(ZEDBSD_LLVM_ARCHIVE_SHA256)  $@' | sha256sum -c -

 llvm-source: $(LLVM_SOURCE)/.patched

-$(LLVM_SOURCE)/.patched: $(LLVM_DISTFILE) $(LLVM_PATCH)
-	@mkdir -p $(LLVM_SOURCE)
-	tar -xf $(LLVM_DISTFILE) --strip-components=1 -C $(LLVM_SOURCE)
-	patch -d $(LLVM_SOURCE) -p1 < $(LLVM_PATCH)
-	@touch $@
+# The extracted source is named by the archive's hash and the patch's hash,
+# not by file times: a source that matches is used as it is, and the archive
+# is fetched only when the source has to be made again.  A new source is
+# extracted and patched beside the old one and then takes its place.
+LLVM_SOURCE_ID := $(ZEDBSD_LLVM_ARCHIVE_SHA256) $(firstword $(shell sha256sum $(LLVM_PATCH)))
+ifneq ($(shell cat $(LLVM_SOURCE)/.patched 2>/dev/null),$(LLVM_SOURCE_ID))
+$(LLVM_SOURCE)/.patched: llvm-source-stale
+endif
+.PHONY: llvm-source-stale
+llvm-source-stale:
+
+$(LLVM_SOURCE)/.patched:
+	@[ -f $(LLVM_DISTFILE) ] || $(MAKE) -f $(LLVM_DIR)/llvm.mk REPO_ROOT=$(REPO_ROOT) llvm-download
+	rm -rf $(LLVM_SOURCE).new
+	mkdir -p $(LLVM_SOURCE).new
+	tar -xf $(LLVM_DISTFILE) --strip-components=1 -C $(LLVM_SOURCE).new
+	patch -d $(LLVM_SOURCE).new -p1 < $(LLVM_PATCH)
+	echo '$(LLVM_SOURCE_ID)' > $(LLVM_SOURCE).new/.patched
+	rm -rf $(LLVM_SOURCE)
+	mv $(LLVM_SOURCE).new $(LLVM_SOURCE)
--- a/mk/llvm/Makefile
+++ b/mk/llvm/Makefile
@@
-include $(ZEDBSD_REPO_ROOT)/toolchain/llvm/llvm.mk
+include $(ZEDBSD_REPO_ROOT)/mk/llvm/llvm.mk
@@
-patch: llvm-source-verify
+patch: llvm-source
```

- 今の main の `build/llvm-source/.patched` は空の file なので、当てた後の最初の build で一度だけ作り直す（約 2.6 GB の展開）。それ以後は、tarball の有無・時刻に関わらず展開しない。
- 確かめる事（当てた後）: (1) main で 2 回目の `make` が展開しない、(2) tarball を touch しても展開しない、(3) patch を変えると展開し直す、(4) 新しい worktree（tarball 無し）で i386 の vmunix が自分の `build/llvm-source` に展開して通る、(5) `make -C mk/llvm patch`。
- `$(MAKE) ... llvm-download` の呼び方は、`mk/llvm/llvm.mk` を include している上の Makefile からの呼びで変数が揃うかを、当てる時に確かめる（揃わなければ同じ recipe の中で curl と sha256sum を直に書く）。

## 運用の側（2026-11-12 ユーザーの指示）

- build system の作り直しで LLVM の build も別物になったので、worktree の `build/` に main の共有の tree（build/llvm・llvm-source・llvm-build・NoctLang）を symlink する運用はやめる。古い worktree は消して作り直す。共有の tree の lock は作ってよいが本質的には要らない。

## 経過

- 2026-11-12 ユーザーが修正案を承認し、Q1 が当てた（`mk/llvm/llvm.mk`、`mk/llvm/Makefile`）。取得の後の SHA-256 の確かめは、recipe の中で curl と `sha256sum -c` を直に書く形にした（下の make の呼びは使わない）。
- 確かめた事（main の checkout）: (1) `make llvm-source` が一度だけ展開し直した（12 s、`.patched` に archive と patch の SHA-256）。(2) 2 回目は「Nothing to be done」。(3) tarball を touch しても「Nothing to be done」。(4) `.patched` を違う値にすると `make -n` が展開を出し、戻すと出さない。`build/llvm-source.new` は残らない。
- 新しい worktree（main から detach で作成、`build/` の symlink 無し、tarball 無し）: tarball を取得して SHA-256 が OK、自分の `build/llvm-source` に展開（`.patched` 16:25）、main の `build/llvm-source/.patched` は 16:16 のまま（触られていない）。`make llvm-toolchain-cached` → `make libc`（`libclang_rt.builtins.a` を自分の source から）→ `make sysroot-platform` → `make BUILD=build/i386-t build/i386-t/vmunix` が rc 0・warning 0。
- この確かめで見えた別の事（この ticket の外）: (1) 新しい checkout では kernel の build が toolchain（`build/llvm/bin/clang`）を自分で入れず、先に `make llvm-toolchain-cached` が要る。(2) i386 の kernel は `mk/platform-i386/vmunix.mk:9` の `-Ibuild/i386/sysroot/usr/include` で、`BUILD` に依らず `build/i386` の sysroot の header を読む（先に `make sysroot-platform` が要る）。(3) `make sysroot` は NoctLang の patch が新しい tarball に当たらず止まる（[BUG-421](BUG-421.md)）。`mk/llvm/Makefile` の `build: llvm-build` は定義の無い target のまま（今回の範囲の外）。
