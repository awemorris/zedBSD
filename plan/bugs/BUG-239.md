# BUG-239: compositor が死んだ client を手放すのに QEMU で 1 個あたり約 1 秒かかる

Reproduction: reproduced（QEMU、AAT の apps.terminal.type-command、T1-232）
Disposition: tracking
Discovery: q788-i02（P2、2026-10-06）
Handling: WS099（compositor）

## 観測

20 個の Terminal を kill した後、compositor が全部の client を手放すまで 23 秒（`ZWL PERF 22690ms work 94.1%`、その間の compose は 2.3 秒だけ）。その間は key の処理も遅れ、Windows キーの App Home が間に合わなかった。log は `/home/awe/zedBSD-worktrees/t1/build/t1-232/logs/apps.terminal.type-command.log`。

## 次

client の後始末（objects.c の zwl_client の破棄、buffer・surface・import の解放、Vulkan の待ち）のどこで時間を使うかを host か gdb で測る。UAT 以外の Bug なので、ベータ2 の実装より後（2026-10-06 ユーザーの順）。

- 証拠: T1-232（2026-10-06）の QEMU で、20 個の kill から全部の client を手放すまで約 23 秒。
- 残り: 測定（client の破棄・buffer の解放・Vulkan の待ちのどこか）と直し。ユーザーの順ではベータ2 の実装の後。

## 測定の準備（2026-10-08 P2、q870）

- T1-232 の log（`t1/build/t1-232/logs/apps.terminal.type-command.log`）には `CLIENT gone` と `CLEANUP` の行だけで時刻が無く、どこで時間を使うかは読めなかった。`KWL PERF` は work 94%（待っていない、何かを実行している）。
- code を読んだ範囲: `kwl_client_destroy`（objects.c）は、最初に `kwl_compose_quiesce`（frame の fence を待つ）を行い、続けて surface・shell の役・残りの object（import の Vulkan の image と memory、`kl_backend_gpu_resource_free`）の順に壊す。1 client あたり 37 object。後始末の中に `vkDeviceWaitIdle`・`vkQueueWaitIdle` は無い（create の時だけ）。Venus では destroy・free の呼び出しが host との往復になりうる。
- 足した物:
  - `objects.c`: 後始末ごとに 1 行 `KWL CLEANUP done client=N ms=全体 quiesce= surfaces= shell= objects=`（ms）。
  - AAT の `desktop.session.release-clients`（tests/scenarios/desktop/session/release-clients.md、helpers_desktop.py）: Terminal を 20 個起動して `pkill -x terminal`、20 行の `KWL CLEANUP done` と全体の秒数を記録する。目標は 10 秒以内（今は FAIL の見込み、測定を兼ねる）。
- build: zedBSD の compositor と keiland-linux は warning 0。check-scenarios PASS。
- 次: T1 の結果の内訳を見て直す（quiesce なら frame の待ち方、objects なら import の解放をまとめるか後回しにする、など）。
