# BUG-267: USB の外付けの touchscreen（HID の digitizer）で multitouch が効かない、触ると mouse の cursor が飛ぶ

- 状態: reproduced（実機 5330、2026-10-08 午後 ユーザーの UAT、USB-C の DP の monitor の touch） / scheduled
- 由来: ユーザー「USB-Cディスプレイでタッチ操作できました。しかし、マルチタッチが使えませんでした。また、タッチするとマウスカーソルが飛んで動いて見え、不格好でした。まずUSB-HIDの10点マルチタッチが動くようにして、そのあと、タッチパネルにタッチされたらマウスカーソルを非表示にして、マウスかトラックパッドが動かされたらマウスカーソルを表示するように、改修したいです。でも、タッチパネルとトラックパッドって、区別できるんですかね？」「eDPをオフにするとWaylandが落ちる問題をまず解決しましょう。そのあとマルチタッチ。」
- 証拠: [BUG-266/kernel.log](BUG-266/kernel.log)・[BUG-266/session.log](BUG-266/session.log)（同じ UAT）。

## 観察（Q1）

- kernel: `input: /dev/input/event3: Pen and multitouch sensor Touchscreen`、`usb-hid: event device usb1 device=5 interface=0 endpoint=81 report-bytes=40`、**`usb1: device 5 interface 1 class 03/00/00 driver=usb-hid attach-failed error=3`**。
- compositor: `KWL TOUCH added device=/dev/input/event3 x=0..10368 y=0..6912`、`KWL INPUT … kind=touch abs=1`。touch の down は全部 `contact=0`（2 本目以降が来ない）。
- 疑い（未確認）: Windows 向けの multitouch の digitizer は (a) 2 つ目の interface に multitouch の collection があり、それが attach-failed、(b) Feature report の Input Mode（Digitizer 0x0D の usage 0x52）に 2（multi-input）を書かないと 1 点の mouse の互換の report しか出さない、(c) Contact Count Maximum（0x55）・Contact Identifier（0x51）・hybrid の report の扱い。cursor が飛ぶのは、touch が mouse の互換の report（pointer の絶対位置）として入っているか、compositor が touch で cursor を動かしているため。

## 区別できるか（ユーザーの質問への答え）

- できる。HID の digitizer の application collection の usage が Touch Screen（0x0D の 0x04）と Touch Pad（0x0D の 0x05）で違う。evdev では INPUT_PROP_DIRECT（画面に直に触る）と INPUT_PROP_POINTER（touchpad）で分かれる。compositor は device ごとに kind=touch と touchpad を既に分けている。

## 範囲（ユーザーの順）

1. USB の HID の 10 点の multitouch（hid-input の glue、Linux の hid-multitouch に合わせる）。
2. touchscreen に触れたら cursor を隠し、mouse か touchpad が動いたら出す（compositor）。

## 担当

- 2026-10-08 午後 Q1: P1 に割当（WS190 より先、BUG-266 の後の順だが担当が別なので並行）。

## 調べ（P1、2026-10-08）

- `attach-failed error=3` は EINVAL。usb-hid の attach の中の EINVAL は、HID の class descriptor の長さ（`usb_hid_report_descriptor_length`）、endpoint の容量（`usb_hid_endpoint_capacity`）、report descriptor の parse（`drv_hid_report_layout_parse` の item ごとの検べ、全体の検べ）、glue の記述（`hid_input_describe` の report・capability・axis の数）のどれか。descriptor が無いと決められない。
- zedBSD に HID の report descriptor を読む道具は無い（lsusb は ID と class、hidraw は FIDO だけ）。5330 は UAT 中で Linux に切り替えられない（Q1）ので、診断を kernel に足した（commit e4722c840）:
  - attach が失敗した時、いつも: `usb-hid-diag: usbB device D interface I attach error=E stage=S`（S は endpoint・descriptor-length・descriptor-read・prepare・capacity・report-size・raw・protocol・resources・activate）。prepare（parse か記述）で断った時は descriptor の hex（`usb-hid-rdesc: … length=N` と 32 byte ずつの `usb-hid-rdesc: … OOOO: xx xx …`）と、`usb-hid-diag: … refused error=E stage=parse item=0xOOOO prefix=0xPP`（parser が断った item の offset と prefix の byte、全体の検べなら item は長さ）か `stage=describe`。
  - boot の行に `usbhid.dump=1` がある時: 全部の HID の interface の descriptor の hex（attach の成功の時も）と、各 interface の最初の 300 個の input report の hex（`usb-hid-report: usbB device D interface I length=N` と `… 0000: xx …`）。
  - parser には `drv_hid_report_layout_diagnose`（同じ parse をして断った item の offset を返す、hid-report.c）を足した。既存の host 試験（run-hid-touch 193・run-hid-scantime 62・run-host-ptp 35）は ok。
- **2（cursor）**: compositor の今の `pointer_unmoved`（起動から pointing device が動くまで cursor を描かない、ws035-p116）を使う。touch screen の指の始まり（touch.c `contact_begin`）で `pointer_unmoved` を立てて cursor の所を描き直す（log `KWL CURSOR hidden by=touch`）。mouse・tablet の報告（input.c の `apply_frame`、log `KWL CURSOR shown by=pointer device=…`）と touch pad の動き（`pointer_move`、`KWL CURSOR shown by=touchpad`）が今のまま `pointer_unmoved` を下ろして cursor を出す。drag and drop の icon は今のまま描く（compose.c で unmoved の検べより前）。区別は device の種類（evdev の touch screen = INPUT_PROP_DIRECT の multitouch は touch.c、touchpad は input.c の touchpad の node）。注意: touch screen が mouse 互換の報告（絶対の pointer）も出す device では、その報告が cursor を出す（multitouch の Input Mode に切り替えれば出なくなる見込み、1 の結果で確かめる）。commit は下の merge 依頼。build（amd64 wayland・Linux all）warning 0、style の新しい指摘 0、keiland-os-boundary PASS。compositor の touch の host 試験は無い（実機で確かめる）。
- **1 の最初の直し（descriptor を見る前に、Linux の hid-multitouch と同じ）**: usb-hid の attach で、touch screen か touch pad の descriptor が Feature の Device Mode（Digitizer 0x52）を持てば、その feature report を SET_REPORT（他の field は 0）で 2（touch screen）か 3（touch pad）にする（`usb_hid_set_device_mode`、log `usb-hid: usbB device D interface I device-mode=M report=R bytes=N error=E`）。失敗しても attach は続ける。commit 22619533d・4517cb254。2 つ目の interface の attach の失敗と contact が 1 つだけの理由は、診断の log（上）で確かめる。
