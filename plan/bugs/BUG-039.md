# BUG-039: UFS の host 試験（WS001 の directory-fsync の試験）が build できない

Bug ID: `BUG-039`
Reproduction: reproduced（host）
Disposition: tracking
Date: 2026-09-25
Source: ws054-p002（q414-i01）で UFS の host 試験を使おうとしたとき。
Owner: none（未割当）
Queue: none。

## 期待と観測・影響

期待: `make -f plan/ws001/tests/directory-fsync-host-test.mk run` で UFS・VFS・overlay の host 試験が通る。

観測:

1. `src/kern/io-stats.c` を link しようとして失敗（refactor `abb8b256` で `io.c` に統合された）。参照を外すと（ws054-p002 で外した）、
2. `vfs-test` の link で `file_fsync_backend` が二重定義（`src/kern/file.c` と試験の両方が定義する）。
3. `ufs-test` は `plan/tools/driver-fragments/prepare.py --source src/drivers/fs/ufs.c` の断片（`build/driver-fragments/src/drivers/fs/ufs/ufs-vfs.c` ほか）から build するが、
   `prepare.py` が `Missing or ambiguous production section: src/drivers/fs/ufs/ufs-allocation.inc` で止まる（`ufs.c` から断片の区切りが無くなった）。
   全体では `src/drivers/disklabel/pc98-auto.c` で同じく止まる。

影響: UFS の driver を host で試験できない（WS001・WS004 の AX211・xHCI の host 試験も同じ道具を使う）。ws054-p002 は guest の試験と、image を host の検査（`tools/build/check-ufs-image.py` の fsck 相当）で確かめる方法に替えた。

## 再開の条件

host 試験の土台を扱う WS で。受け入れ案: `prepare.py` が今の source から断片を作れる（または断片に頼らない host 試験の build）、`directory-fsync-host-test.mk run` が通る。
