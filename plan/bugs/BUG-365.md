# BUG-365: GPU の文書の調べで見つかった header・comment と code の食い違い（一括）

- 状態: partly fixed（2026-10-31 P2 q1757-i01。食い違いの header・comment と小さな code を直した。残りは「要判断」と「設計どおり」、下の表）
- 発見: 2026-10-30 WS009 p010〜p023（DOC-54）。一覧の本体は [plan/ws009/phase023/phase.md](../ws009/phase023/phase.md) の結果の Bug の候補 2〜23。
- 主なもの: 最初の flip で text console が終わり lease の後も戻らない（gpu-display.h・powervr の log は戻ると書く）、kernel が終えた fence の binding が slot を持ち続ける、`_SYNC` が BIND だけの fence を待たず EAGAIN、venus の JOB の bit を `gpu_info_ioctl` が上書き、venus の capset の 168/176 byte、i915 の capset が id・version を見ない、submit・reserve が driver の受け入れの前に sequence を書く、display の wait の EINTR の約束、driver ごとに違う lease の errno、古い comment（gpu-op.h・sysctl.h・amdrdna・i915 present.c）、`CONFIG_DRIVER_PCI_AMDRDNA` の既定の食い違い。
- 直す方針: 一つずつ、code が正しければ header・comment を直し、header が正しければ code を直す（HAL は関係しない）。小さな物はその場で直す。文書（docs/reference/gpu*.md）は今の動きを書いているので、code を変えたら文書も合わせる。
- 2026-10-30 追加（WS009 p024 の正確さの review、詳細は plan/ws009/phase024/phase.md の結果）: 多くの driver が GPU_BLOB_SHAREABLE の無い blob も export し core は見ない（断る driver は errno が違う）、amdrdna・nvrtx・i915 の resource_map が GPU_BLOB_MAPPABLE を見ない、bcm2711 の output_query が GPU_DISPLAY_BLOB を立てず ACTIVE を常に立てる、`gpu_fence_binding_add` が記録の誤りでなく ENODEV で open だけの失敗を見ない、bcm2711 の output_mode が ENOTSUP（他は EINVAL）・output_wait が出していない sequence を timeout まで待つ、`bcm2711_display_flip_commit` の EFAULT、`gpu_dependency_ioctl`（PRESENT_SYNC）で途中で open が失敗すると frame は出て EPERM・console の引き継ぎを飛ばす、GPU_FENCE_SIGNAL の返事が 2 回目の問い合わせで reset を挟むと ESTALE、`gpu_job_action_ioctl` が終わっただけの record にも fault の cancel で open を EIO に、bcm2711 render-device.c の bind_render の前の comment が古い、`gpu_submit_ioctl` が stream の長さの 4 の倍数を見ない、`gpu_export_install` が descriptor を確定する前に fd の番号を写す、executor の reply flag の端の EINVAL。（src/kern/devfs.c の管理情報の comment は Q1 が 2026-10-30 に消した。）

### 要判断（直していない。設計か利用者の判断が要る）

- p023-2・p024-5 fence の binding: kernel が失敗で終えた binding が open を閉じるまで slot を持つ。文書（gpu-fences.md）は今の動きを約束として書いている（EPERM・ESTALE の場合分けもそれに依る）。直すなら失敗の通知の時に slot を空け、文書の errno の節を書き直す。
- p023-3 BIND だけの fence を `_SYNC` が待たず EAGAIN: header に書くか、待てるようにするかの判断。
- p023-11 他の open の lease の errno（EBUSY・EPERM・EINVAL）、i915 の mode の ENOENT、bcm2711 の plane_index の EBUSY、p024-6 bcm2711 の output_mode の ENOTSUP・output_wait: driver を揃えるかの判断（header には違いを書いた）。
- p023-12 wait の 1 秒の上限を core に置くか。p023-10 の signal を全 driver で効かせるか。
- p023-14 GPU_COMMAND（EINVAL）と SUBMIT（E2BIG）の errno、PRESENT の不明な handle の EINVAL、poll の POLLHUP、p024-12 SUBMIT の長さの 4 の倍数を core で見るか。
- p023-17 nvrtx・i915 の DISPLAY_CONTROL と POWER の EOPNOTSUPP: 文書は output ごとの `GPU_DISPLAY_POWER_CONTROL` で分かると書く。設計どおりと見るか。
- p023-22 PRESENT がいつ返るかを示す output の flag を足すか（UAPI の追加）。
- p024-2・3 `GPU_BLOB_SHAREABLE`・`GPU_BLOB_MAPPABLE` を守らない driver（6 driver の export・3 driver の map）と拒む errno の違い。
- p024-4 bcm2711 の output_query の BLOB・ACTIVE の flag。p024-7 bcm2711 の flip_commit の EFAULT。
- p024-8 PRESENT_SYNC の途中の故障で EPERM・console の引き継ぎを飛ばす。p024-9 FENCE_SIGNAL の返事の ESTALE。p024-10 job_action の fault cancel。
- p024-15 executor の reply flag の端の EINVAL（文書は触れない）。
- i915 の capset の vendor flags 7（`i915/vk/vk.c` の XXX: retire・recovery の契約が未実装）。

### 設計どおり・済み
