# BUG-371: Wi-Fi の初期化の失敗だけで init が有線を含む networking 全体を飛ばす

- 状態: open — 修正済み・QEMU で確認・実機未確認（2026-10-30 登録、2026-10-31 P7 が修正、q1732-i01。closed は Q1 の merge の後）
- 発見: 2026-10-30 P2（WS291 p020、VF2 の serial）。板の userland が古く（10-21）、kernel が新しい（WLAN の ABI 2）時に、networkd の初期の Wi-Fi の正規化が EINVAL になり、`init: networkd: FAIL 3 wifi-normalize Invalid argument` → `init: skipped networking: required dependency failed`。有線の en0 は link up しているのに、DHCP も SSH も上がらない。
- 影響: Wi-Fi が使えない（driver・firmware・ABI の食い違い）だけで、有線の network も上がらず、遠隔から入れなくなる。
- 直す方針（案）: Wi-Fi の正規化の失敗は networkd の中で Wi-Fi だけを使えない状態にして続け、有線の設定と init の依存は止めない。

## 原因（2026-10-31 P7）

- `userland/base/networkd/main.c` の `main()` は、起動の時の `retire_managed_policy()`（全ての radio を止めて Wi-Fi の policy を disabled に
  正規化する）が失敗すると、init に `FAIL <errno> wifi-normalize` を送って終了していた。init の networking は `requires=networkd`
  （`userland/base/init/services/networking`）なので、Wi-Fi の失敗だけで有線を含む networking が飛ばされた。
- 正規化が失敗する例: kernel と userland の WLAN の版の食い違い（[BUG-373](BUG-373.md)）、radio の driver の error。

## 直し（P7、WIP 30fd47a4f）

- 起動の時の正規化の失敗は `networkd: initial Wi-Fi normalization: <error>; Wi-Fi stays disabled` を出すだけにし、READY を送って続ける。
  managed の Wi-Fi の状態は起動の初期値（disabled）のまま。Wi-Fi を有効にする要求（`net startup` の WIFI_ENABLE など）は
  `enumerate_wlan_radios()` で radio を見直し、自分の error を返す（Wi-Fi だけが使えない）。終了の時の正規化（失敗で exit 1）は変えていない。

## 確かめ（QEMU amd64、修正の kernel、SSH と画面の PNG で判定）

- 試験の作り方: radio の列挙が必ず EINVAL で失敗する networkd を作った（tree の main.c と dc9fb84fc の main.c の写しで
  `enumerate_wlan_radios` を EINVAL を返す関数に差し替え、ABI 2 で build。`build/p7-abi/build-inject.sh`）。有線の policy の
  radio の判定（`lan_interface_is_radio`、実の ioctl）はそのまま。`test-image.sh --file /sbin/networkd=…` で入れ、image の中の sha256 を確認。
  - I0（対照、dc9fb84fc の networkd）: SSH DOWN（240 秒）。画面に `networkd: initial Wi-Fi normalization: Invalid argument`・
    `init: networkd: FAIL 3 wifi-normalize`・`init: skipped networking`。`/home/awe/zedBSD-worktrees/p7-bug373/build/p7-abi/result-I0/screen.png`
  - I1（修正の networkd）: SSH UP。画面に `…normalization: Invalid argument; Wi-Fi stays disabled`、`Wi-Fi WIFI_ENABLE failed at
    enumerate WLAN radios: Invalid argument` の後に ue0 の DHCP（10.0.2.15）。init.log「done networking」、`net show` で ue0 online、
    `net wifi list` は state=disabled と `enumerate WLAN radios: Invalid argument`。`/home/awe/zedBSD-worktrees/p7-bug373/build/p7-abi/result-I1/screen.png`
- 範囲の外の観察（直していない）: kernel が全ての interface に EINVAL を返す場合（BUG-373 の直しの前の kernel と版 1 の userland）は、
  修正の networkd でも有線が上がらない。有線の policy の `lan_interface_is_radio()` が EOPNOTSUPP・ENOTTY 以外の error を「radio かも
  しれない」と読んで ue0 を Wi-Fi の側に残すため（QEMU で確認: networking は done、ue0 は unconfigured のまま、`net up ue0` で手で上がる）。
  BUG-373 の kernel の直しの後は、Wi-Fi でない interface は EOPNOTSUPP を返すので起きない。Wi-Fi の無い sleep の準備
  （`sleep_radios_off`）も列挙の失敗で止まる点は未確認・未修正。
- 未実施: 実機（Wi-Fi のある機械で radio が失敗する時に有線が上がる事）。
