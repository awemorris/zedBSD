# BUG-328: 静的な設定の default route と DNS が起動の後に入らない（net startup が address だけを送る）

- 状態: reproduced（QEMU）/ tracking → fixed（2026-10-31 P2、q1750-i01、QEMU で確かめた。実機は未実施。Q1 の判定待ち）
- 発見: 2026-10-16 P4（WS255 試験機の静的な IP）。/etc/net.conf の静的な設定で、起動の後に address と prefix は入るが default route が無く /etc/resolv.conf も無い。
- 原因: `net startup`（userland/base/net/main.c の startup_command → lan_send_policy）が networkd に interface の address だけを送り、route と DNS は console の `commit`（reconcile.c）だけが入れる。
- 影響: 静的な route・DNS を commit した利用者も、再起動の後に失う（推定、実機は未確認）。試験機は host と同じ subnet なので ssh は届く。
- 回避: 起動の後に `net defaultroute 10.0.0.1`・`net dns 1.1.1.1`（QEMU で確認）。
- 関連: [WS255](../ws255/ws.md)。USB の NIC は遅れて現れるので、route を入れる時機は設計の判断。

## 修正（2026-10-31 P2、q1750-i01）

- 設計の判断（担当の判断、Q1 の確認を待つ）: networkd の LAN の protocol（record に gateway を足す）は変えず、`net startup` が wired の policy を送った後に、net.conf の IPv4 の default route と DNS を別の process（detached の worker）で入れる。DNS はすぐ書き、route は gateway に届く（policy が interface に address を付ける）まで 1 秒ごとに最大 120 秒（NET_STARTUP_ROUTE_SECONDS）試す。route が入ったら DNS をもう一度書き、その間に取れた lease の server より file の server を勝たせる（commit と同じ）。起動は待たせない。
- 変更（7e22a31c9）: `userland/base/net/main.c` の startup_command → startup_send_routing・startup_routing_worker・startup_quiet_backend。失敗は syslog に。
- 残り: 120 秒より後に現れる USB の NIC には route が入らない（その時は `net defaultroute`）。IPv6 の route（ROUTE6）は startup でまだ入れない。DHCP の interface の lease が route の後に取れると、その resolv.conf が file の DNS を置き換え得る。
- build: warning 0。QEMU（amd64、SSH）で /etc/net.conf を ue0 の静的な 10.0.2.15/24、route default 10.0.2.2、dns static 10.0.2.3 に書き、resolv.conf を消して poweroff、同じ disk で起動し直すと、`route show` に `default 10.0.2.2 UG ue0`、resolv.conf に `nameserver 10.0.2.3` が入っていた。遅れて現れる USB の NIC（QMP の device_add）での確かめと実機は未実施。
