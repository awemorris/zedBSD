# BUG-263: AF_UNIX の datagram の socket で、相手が閉じると poll は読めると言うのに recv が待ち続ける

- 状態: reproduced（QEMU、T1-405 の bt-pair-p004 の読み。host でも再現: dgram-eof-host） / scheduled（2026-10-08 P2 q914: 直し、host の試験 PASS、QEMU の smoke は T1）
- 発見: 2026-10-08 P2 の ws143-p004 i03 の調べ（T1-405 の `the child killed ends the parent (got 2, want 0)`）。
- 観察: bluetoothd の privsep の親子は SOCK_DGRAM でつなぐ。子が死ぬと親の socket は poll で読める（POLLIN）になるが、recv は EOF も error も返さず block した。親は recv で止まり waitpid に戻れず、子は zombie のまま残った。bluetoothd の側は recv を MSG_DONTWAIT にして避けた（eb13fe3ae）。
- 期待: poll が POLLIN を返したら recv は block しない（0・EOF か error か data を返す）。相手が閉じた接続の datagram の socket は、POLLHUP を返すか、recv が error（ECONNRESET 等）か 0 を返すかで、poll と recv が食い違わない。
- 場所（P2 の読み）: src/kern/ の unix-socket.c。

## 次

- unix-socket.c の datagram の poll と recv の peer の close の扱いを読み、host か QEMU の小さな試験で再現して直す（Linux の AF_UNIX SOCK_DGRAM の挙動を参考に）。

## 原因と直し（2026-10-08 P2、q914）

- 原因: `unix_socket_receive_begin`（src/kern/net/unix-socket.c）の待ちの loop は、stream の時だけ「空で read_shutdown なら 0 を返す」を持っていた。datagram の pair は、相手の close（`unix_endpoint_close`）と SHUT_WR で `read_shutdown` が立つ。このため poll（`socket_poll_common`）は POLLIN|POLLHUP を返すのに、recv は待ち続けた。
- 直し: datagram でも、queue が空で `read_shutdown` なら 0（end of file）を返す（Linux の AF_UNIX SOCK_DGRAM の RCV_SHUTDOWN と同じ）。あわせて `unix_socket_receive_message` は、end of file の時に `*file_count`・`*control_truncated` を 0 にする（前は呼び手の容量が数として残った）。
- 試験: [dgram-eof-host.sh](BUG-263/dgram-eof-host.sh)（本物の socket・poll・AF_UNIX の code を host で動かす。stub は plan/ws014/tests/handle-fd.c の物）。確かめる物:
  - datagram の pair で、相手が 1 byte 送って close → byte が届く → poll が POLLIN と POLLHUP → blocking の recv が 0、file 0。
  - stream も同じ（今までどおり）。
  - datagram の SHUT_RD → recv が 0。
- 結果:
  - 直す前: `dgram: after the peer's close, receive -24 files 1`（待ちになる、file の数が残る）で FAIL。
  - 直した後: plain と ASan/UBSan で PASS。既存の `plan/ws014/tests/run-handle-fd-test.sh` も PASS。
  - kernel の build（`make ZEDBSD_CONFIG=config/current-uat.mk BUILD=build/bug263 vmunix`）は warning 0、include check・vmunix check PASS。style-check の数は直す前と同じ。
- 残り: QEMU の smoke（T1）。bluetoothd の MSG_DONTWAIT の回避（eb13fe3ae）は残してよい（害は無い）。
