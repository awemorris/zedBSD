# BUG-263: AF_UNIX の datagram の socket で、相手が閉じると poll は読めると言うのに recv が待ち続ける

- 状態: reproduced（QEMU、T1-405 の bt-pair-p004 の読み） / tracking
- 発見: 2026-10-08 P2 の ws143-p004 i03 の調べ（T1-405 の `the child killed ends the parent (got 2, want 0)`）。
- 観察: bluetoothd の privsep の親子は SOCK_DGRAM でつなぐ。子が死ぬと親の socket は poll で読める（POLLIN）になるが、recv は EOF も error も返さず block した。親は recv で止まり waitpid に戻れず、子は zombie のまま残った。bluetoothd の側は recv を MSG_DONTWAIT にして避けた（eb13fe3ae）。
- 期待: poll が POLLIN を返したら recv は block しない（0・EOF か error か data を返す）。相手が閉じた接続の datagram の socket は、POLLHUP を返すか、recv が error（ECONNRESET 等）か 0 を返すかで、poll と recv が食い違わない。
- 場所（P2 の読み）: src/kern/ の unix-socket.c。

## 次

- unix-socket.c の datagram の poll と recv の peer の close の扱いを読み、host か QEMU の小さな試験で再現して直す（Linux の AF_UNIX SOCK_DGRAM の挙動を参考に）。
