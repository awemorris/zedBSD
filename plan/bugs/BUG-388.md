# BUG-388: VF2 で USB の keyboard から console に login できない

- 状態: open（2026-11-01 08:43 Q1 が起票）。2026-11-01 09:2x P1: 有線の keyboard は VF2 の画面の console まで届くと確かめた。残りは Logitech の Bolt の受信機（046d:c548）で、key を押す試験を待つ（下の「ユーザーが拾える試験」）
- 発見: 2026-11-01 08:43 ユーザーの報告。VisionFive 2 の画面の console の login で、USB の keyboard の入力が効かず login できなかった。
- 2026-11-01 08:44 ユーザーの補足: keyboard は認識されていたが、console に繋がっていないように見えた（打っても login の prompt に入らない）。
- 未確認: 文字が全く出ないのか一部だけか、どの USB の口か、起動した kernel の版。
  serial の console は入力を受けない（BUG-372 は閉じたが、2026-11-01 の P4 の記録では serial も入力を受けなかった）。
- 関係: [BUG-387](BUG-387.md)。2026-11-01 08:44 ユーザーの補足で、VF2 で Wayland を起動できなかったのは、この Bug で console に login できなかったためと分かった。
- 次: 認識はされているので、入力の経路（HID の keyboard → kbd の多重化 → 画面の console の tty）のどこで切れているかを調べる（x86 と Pi の画面の console では効いているので、VF2 の console の構成・fb の console と kbd の結び付けを疑う）。

## 調べ（2026-11-01 P1、q1829-i01、途中）

- serial（/dev/ttyUSB0）から `kei`・password・命令を打つと、板の kernel（cksum 3758577736）で console に login でき、SSH で tty の上の `-sh` と命令が作った file を確かめた
  （2026-11-01 08:5x）。→ getty・login・console の tty・line discipline は動く。2026-11-01 の P4 の「serial も入力を受けない」は、この時は再現しなかった。
- keyboard の構成（SSH の dmesg）: xHCI（VL805）の port 2 に Logitech の Bolt の受信機 046d:c548。interface 0 = boot keyboard（`/dev/input/event0: USB Receiver`、16 byte）、
  interface 1 = mouse ほか、interface 2（HID++、vendor の page だけ）は `attach-failed error=21`。
- `usbhid.dump=1`（`/boot/boot0/zedbsd.cfg` に 1 行、元は `zedbsd.cfg.q1828orig`）で取った interface 0 の report descriptor（67 byte）は NKRO の bitmap の keyboard
  （modifier 8 bit、LED の出力 5 bit、usage 0x04〜0x73 の 112 bit、0x87〜0x8b、0x90〜0x92、report ID 無し、入力 16 byte）。host で `src/drivers/generic/hid-report.c` に
  この descriptor と「a」「Shift+b」の report を与えると、KEY_A（30）・KEY_LEFTSHIFT（42）＋KEY_B（48）に正しく decode した。
- 受信機は key が押されていない間も 0.5 s ごとに全部 0 の 16 byte の report を送る（idle の繰り返し、起動の後の約 100 s で 198 個）。押された key の report はまだ見ていない（誰も押していない）。
- input core から先: `CONFIG_INPUT_TEST_INJECT=y` の kernel（cksum 2789433958、make の変数で足しただけ）で `aat-input`（input core に USB keyboard と同じ形で入る keyboard）から
  `kei`・password・`echo KBD$((6*7)) > /tmp/kbdproof` を打つと console に login でき、SSH で `KBD42` と tty の上の `-sh` を確かめた。→ input core → console.c の
  subscriber → tty_console_input_event（GPU の display の claim の hold は 0）→ tty → login は VF2 で動く。
- 残る切れ目: USB の受信機が key の report を送るか（keyboard の pairing・電源）、usb-hid → hid-input → input core の段。人が key を押さないと分からない。
- 今の板: 診断の kernel（cksum 4157327596、git の外の一時の差分: 0 でない report だけを dump、console と tty の入口で key ごとに log）と `usbhid.dump=1`。
  ユーザーが拾える試験: VF2 の USB keyboard で a・s・d・Enter を押す（時間の制限なし）。その後に担当が SSH の dmesg で `usb-hid-report`・`diag-console`・`diag-tty` を読む。
- 2026-11-01 ユーザーの答え（Q1 の中継）: Pi 5・x86 で効いている keyboard は Bolt の受信機とは別の物。VF2 の Bolt の受信機は、調べの間は外してあった。
- 有線の keyboard（3434:0430、Keychron、port 3、2026-11-01 09:1x に挿された）: 診断の kernel の dmesg で、Enter の 3 回が
  `usb-hid-report: usb0 device 3 interface 2 … 06 00 00 00 00 00 00 01 …`（押した report）→ `diag-console: dev 3 code 28 value 1`（KEY_ENTER）→
  `diag-tty: event d holds 0 vt 0`（console の tty に入った）と通り、login の pid が 21 → 43 に変わった（prompt を出し直した）。→ 有線の keyboard は VF2 の console に届く。
- Bolt の受信機は、挿してあった間に押された key の report が一度も記録されていない（全部 0 の idle の report だけ）。受信機が key を送らなかったのか、key を押していなかったのかは分からない。
- `attach-failed error=21`（EOPNOTSUPP）の interface（Bolt の受信機の interface 2 = HID++、Keychron の interface 1）は、どちらも vendor の usage page（0xff00・0xff60）だけの
  collection で、diag の `item=` は descriptor の長さ（全体として断った印）。input の device にならない vendor の interface を断っているのであって、descriptor の parse の誤りではない。
  keyboard の入力には関係しないので直していない。
- 板を元に戻した（2026-11-01 09:2x）: `/boot/boot0/vmunix` を元の kernel（cksum 3758577736、`vmunix.q1825orig` から）、`zedbsd.cfg` を `zedbsd.cfg.q1828orig` から戻し、
  電源を入れ直して boot の parameters に `usbhid.dump=1` が無く、root が rw と確かめた。診断の kernel の差分は git の外（一時）で、tree に入れていない。

### ユーザーが拾える試験

1. Bolt の受信機を VF2 に挿し直し、その受信機と組の keyboard で a・s・d・Enter を押す。画面の console の login に文字が出るか。出なければ担当に知らせる
   （担当は `/boot/boot0/zedbsd.cfg` に `usbhid.dump=1` の行を足して起動し直し、押した後に SSH の dmesg の `usb-hid-report: usb0 device N interface 0` を読む。
   0 でない report が来なければ受信機が key を送っていない、来ていれば driver の側）。
2. 別の有線の keyboard を VF2 に挿して同じ事（a・s・d・Enter、login まで）。2026-11-01 09:1x の Keychron では Enter が tty に届いた。
