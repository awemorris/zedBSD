# BUG-049（不具合ではない）: amd64 guest（QEMU、8 GiB）で networkd が USB CDC-ECM（`ue0`）を DHCP で設定せず、host から SSH が届かない

Bug ID: `BUG-049`
Reproduction: reproduced（QEMU、amd64 guest 8 GiB、2026-09-25 13:00 の image 2 つ。HEAD 21866849 + HAL の table count、HEAD + kcrt/slab。両方）
Disposition: resolved（不具合ではない。計測用の 2 つの image を `guest.py extra-files` 無しで build したため `/etc/net.conf` が無く、networkd は `ue0` を管理しなかった。extra-files ありの image では SSH が届く（HEAD・p002 の後の両方、2026-09-25）
Date: 2026-09-25
Source: ws061-p002（q433-i01）の計測で `guest.py wait` が 240 s で SSH に届かなかったとき。
Owner: 未定（ユーザー 2026-09-25「USB ECMよりもconfigureパフォーマンス改善を優先」）。
Queue: なし。

## 期待と観測・影響

期待: 起動後に networkd が `ue0` を DHCP（QEMU の slirp、10.0.2.15）で設定し、host の port forward から SSH が届く。今日の午前の guest（同じ harness、8 GiB）は届いていた。

観測（serial で login して確認。console log では判定していない）:
- `ps -e`: init、syslogd、networkd（pid 5）、sshd（listener、`Server listening on 0.0.0.0 port 22`）、cron は動いている。
- `ifconfig -a`: `ue0` は `BROADCAST,MULTICAST` だけで UP でなく、RX/TX とも 0 packet。
- 手で `ifconfig ue0 inet 10.0.2.15/24; route add default 10.0.2.2` の後、`ping 10.0.2.2` は 2/2 応答（driver の RX/TX は正常）。
- QEMU の `qemu.log`: `Slirp: Failed to send packet, ret: -1`（guest が受け取らない間の slirp の送信失敗）。
- worktree の guest では `xhci: port 7 enumeration failed (42)`（keyboard）、本流の guest では keyboard は enumerate できた。network の症状は両方で同じ。
- `strerror` の穴（下）で `route: Unknown error` のように errno の名前が出ない。

影響: `guest.py put/run`（SSH）を使う harness（sh・make の差分試験、kbench/ffault の投入）が使えない。serial（`serial.py`）と image の `ZEDBSD_EXTRA_FILES` で代替できる。

未確認（優先度の指示で中断）: `dhcpc ue0` の手動実行、`net show`、networkd の LAN policy（`/etc/net.conf`）の読み込み。今日の変更で疑わしいもの: libc の timer/pthread/`__libc_init` の signal mask（aa78b79f 以降）、thread の signal mask の継承（`sys_thread_create_call`）。networkd が timer や signal で DHCP の worker を動かすなら、それが届かない可能性がある。

関連: libc の `strerror` に穴がある（29〜31、33〜40、43〜45、53〜66 が "Unknown error"。EADDRINUSE 36、ENETUNREACH 33 を含む）。BUG-050。

## 再開の条件

serial で `dhcpc ue0` と `net show` を実行して、DHCP の送信が起きるか（`ue0` の TX packet）を見る。起きなければ networkd の LAN worker の待ち（timer・signal・event socket）を lldb で止めて見る。受け入れ: 起動後 60 s 以内に `ue0` が 10.0.2.15 を得て、`guest.py wait` が通る。

## 結論（2026-09-25）

不具合ではない。harness の guest は `guest.py extra-files` で `/etc/net.conf`（`ue0` を DHCP で）と SSH の鍵を image に入れる。上の 2 つの image はこれを付けずに build していた。extra-files を付けた HEAD の image と ws061-p002 の後の image はどちらも起動後に `ue0` が 10.0.2.15 を得て `guest.py wait` が通った。driver（USB CDC-ECM）も networkd も正常。strerror の穴は BUG-050 に残す。
