# BUG-185: Settings で WiFi をオンにした時、Connecting… が出ず、Connected になるまで状態の表示があいまい

Reproduction: reproduced（実機）
Disposition: resolved（2026-10-08 夜 ユーザーの決定で close、Q1 の中継）
Discovery: 2026-10-04 夜 ad-hoc UAT-3（実機 Latitude 5330、image `build/uat-3/hdd-image.img` sha256 ada4492e…、main efe846a、[uat.md の uat-3](../uat.md)）
Handling: WS089（Settings の Wi-Fi）・WS131（libkeiland の kl_system_* と compositor の kl_system_manager_v1）・networkd の状態の通知

## 観測

ユーザー「SettingsでWiFiをONにしたとき、Connecting...が表示されずにConnectedまで表示があいまい。実際にはConnectingの動作になっているので、状態取得ができていないように思う。」

## 次

networkd は自動の再接続で join・DHCP を進めている（実際に Connecting の動作）のに、Settings に「接続中」の状態が届いていない疑い。networkd の状態（scanning・associating・authenticating・dhcp）の通知が compositor の kl_system_manager_v1 を経て libkeiland・Settings まで来るか、Settings がその状態を表示の文に変えているかを、経路の各段で確かめる。system bar の menu でも同じか確かめる。[BUG-183](BUG-183.md)（オンの反応が 1 秒）と同じ経路なので一緒に見る。修正は P3 の q700。

## 保留（2026-10-05 未明、q703-i01 P2 generation14。ユーザーの方針「既存BUGはいったん保留して、新規実装を進める」）

- **根（読んで確定）**: networkd は watcher への状態の通知（`deliver_state_changes`）を main loop でだけ行い、Wi-Fi の作業（on の後の自動の探索・join・DHCP）の間は呼ばない。作業の中で `connecting` に移っても、作業が終わる時には `connected` になっていて、watcher（compositor → Settings・system bar）には Connecting が届かない。
- **途中の差分（WIP commit 済み、未試験）**: `userland/base/networkd/main.c` の `service_wifi_wait`（作業中の pump）の先頭で `deliver_state_changes()` を呼ぶ。networkd は build warning 0。
- **残り（再開点）**: (1) Settings の Wi-Fi の words を `KL_WIFI_CONNECTING` で「Connecting to <SSID>...」に、system bar の「Joining %s...」を同じ言い方に揃える。(2) 試験: `userland/tests/network-probe` に join の途中で `connecting` を通知させる（JOIN-SECONDS の間）形を足し、T1 の QEMU で Settings と menu の Connecting の表示を撮る。実機は UAT。

## 再開（2026-10-05、P2 / q703）

- 残り (1) を直した: Settings の Wi-Fi の頁の見出しは `KL_WIFI_CONNECTING` で「Connecting to <SSID>...」（`page-network.c` の `network_wifi_words`）、system bar の状態の行も「Joining」から「Connecting to <SSID>...」に揃えた（`wayland/network.c`）。行の「Connecting...」は前から。
- 試験: `userland/tests/network-probe` に TELL（4 番目の引数）を足し、待つ join の間 `wifi state=connecting ssid=<SSID>` を watcher に出す（networkd の `service_wifi_wait` の通知と同じ形）。`plan/ws089/tests/settings-wifi-bugs.sh` の step 2（Settings の state wifi=3 ssid=Kei Lab、bar の state connecting、connecting.png）を T1 で。実の networkd の作業中の通知（前の WIP、`service_wifi_wait` の `deliver_state_changes`）は実機の Wi-Fi が要る → UAT。
