# BUG-351: /dev/acpi が 0666 で、一般の user が AML の method（EC の書き・SMI を起こす物を含む）を評価できる見込み

- 状態: closed（2026-10-31 Q1 の判定。2026-10-31 P4 q1753-i01、d3219b01a、QEMU で確かめた。main に未 merge）
- 発見: 2026-10-29 P5（q1666、WS303 の設計の design-reviewer の指摘 M6）。
- 観測（code の読み）: `src/kern/devfs.c:589〜601` の既定の mode が 0666 で /dev/acpi も当たる。`acpi-text.c:150` の評価の口と `aml-eval.c:913〜920` は引数の足りない method も評価する。5330 の DSDT では `\_SB.AMW0.WQDS`（EC の書き）、`AMW2._WDG`・`\_SB.VDGS._STA`（SMI）がある。
- 期待: AML の method の評価は root だけ（または読みだけの名前に限る）。
- 影響: 一般の user が EC への書き込みや SMI を起こし、fan・電源・firmware の状態を変えうる。

## 直し（2026-10-31 P4 q1753-i01、d3219b01a）

- `src/kern/devfs.c` の node の mode の選び方で、`acpi` を 0600（root だけ）にした（fpga0・input-inject と同じ扱い）。/dev/acpi は診断用の口で、userland・試験の道具に一般の user の利用者は無い（grep で確かめた）。AML の評価の口そのもの（引数の足りない method も評価する）は変えていない。root には今までどおり任意の method の評価を許す。
- 確かめ（QEMU、amd64、config/ci/config-amd64.mk の image、tree f045ddf59、SSH）: `ls -l /dev/acpi` が `crw------- root wheel`。`su user -c 'head -c 64 /dev/acpi'` が `Permission denied`（終了 1）。root の `head -c 64 /dev/acpi` は 0。amd64 の vmunix は warning 0。
- 未実施: 実機（5330）。
