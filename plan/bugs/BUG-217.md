# BUG-217: 最大化を desktop の session の状態として扱う: 切り替え先の app も最大化し、窓の mode の app から切り替える時は窓にする

Reproduction: reproduced（ユーザー、実機 5330、2026-10-06 UAT）
Disposition: tracking
Discovery: 2026-10-06 ユーザーの UAT のコメント
Handling: WS099・WS142

## 観測（ユーザー）

「1つのアプリが最大化されているとき、WiseviewやAlt+Tabでほかのアプリに切り替えると、切り替え先のアプリがウィンドウモードなら、ウィンドウモードで表示されていますね。これは現在の仕様として妥当なのですが、変更したいです。最大化は「タブレットとして最大化で使う」というユーザの意思だと考えて、デスクトップセッションの状態として捉え、アプリ切り替え時には切り替え先のアプリも最大化したいです。逆もしかりで、ウィンドウモードアプリから最大化アプリに切り替えるときは、ウィンドウ化します。」

## 次（未確認の見込み）

仕様の変更（ユーザーの決定）。WiseView・Alt+Tab・bar の click など全ての app の切り替えで、切り替え元の dock（最大化）の状態を切り替え先に移す。

## 2026-10-08 P2 の確認（q867）

- **実装済み**: [ws142-p008](../ws142/phase008/phase.md)（2026-10-06）。最大化（DOCKED）を desktop ごとの `layout_mode` という session の状態にした。全ての切り替えの入口（WiseView・Alt+Tab・bar の click など）が、切り替え先をその mode に合わせる（`zwl_glass_switch_to`）。窓の mode から最大化の app に切り替える時は窓にする。
- QEMU: p010-guest.sh が T1-342・T1-359 で PASS（ws142-p008 cleared）。
- 後の変更: 2026-10-07 のユーザーの決定 N1（WS181 の review）。docked の窓を閉じて他に窓が無い時も docked mode を終え、次に開く app は floating になる。10-06 の「tablet mode は session の状態」のこの場合だけを置き換えた。切り替えの時の動きは変わらない。
- 残り: 実機（5330）の UAT の確認だけ。直す code は無い。仕様の判断が要る点は見つからなかった。確認できたら resolved の案。
