## 観測

C7: ue0 を抜くと Ethernet のメニューに wlan0 が出て、ue0 を挿し直しても wlan0 が出たまま。有線の device を選び直す時に、種類（Ethernet か WiFi か）を見ていない疑い。

次: compositor の network の表示（`userland/desktop/wayland/` の system bar）と libkeiland-backend の interface の種類の判定を読む。

## 原因と修正（2026-10-05 P1 generation17 / q685）

- 原因: backend（`libkeiland-backend-zedbsd/network-zedbsd.c` の `network_parse_interface`）は、networkd の state の interface の行のうち「Wi-Fi の接続が使う interface（wifi の行の `interface=`）以外で、address を持って online の物」を有線とした。networkd の `interface=` は managed の接続が名を持つ時だけ出て、それ以外は `-`。有線を抜いた後などで managed の接続が名を持たない間、address を持った wlan0 が有線として選ばれ、system bar の menu に「Wired (wlan0)」が出た。挿し直しても先に並ぶ wlan0 が選ばれたままだった。
- 修正: networkd の wifi の行に `radio=IF`（最初の WLAN の interface、無ければ `-`、接続に依らない）を足し（`userland/base/networkd/main.c` の `watch_state`）、backend はその interface を有線に数えず、default route がそこを通る時は Wi-Fi の道として扱う。`radio=` の無い古い networkd では今まで通り。
- 確認: `sh plan/ws033/tests/host-bug169.sh`（backend の `network-zedbsd.c` をそのまま include、ASan・UBSan）8 checks ok。抜いた後の wlan0 は有線でない、挿し直しで ue0 が有線、接続中の Wi-Fi、`radio=` の無い行、radio の無い machine。直す前の source では 3 つが FAIL することを確かめた。build（wayland・networkd）warning 0、style-check 指摘 0。
- QEMU に WLAN が無いので QEMU の試験は無い。実機は次の UAT（ue0 を抜き差しして Ethernet の menu に wlan0 が出ないこと）。
