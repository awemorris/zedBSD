# BUG-414: ブラウザ: JavaScript の `Reflect` の global が無い

- 状態: fixed（2026-11-02 P8 q1977-i01。host で確かめた、QEMU・実機は未実施）
- 発見: store.google.com などの調べ（BUG-411、P8 q1941）で、ECMAScript の `Reflect`（Reflect.apply・construct・ownKeys ほか）の global object が無いと分かった。使う script は TypeError で止まる。
- 扱い: P8（ブラウザ）。

## 修正（2026-11-02 P8 q1977-i01）

- `Reflect`（ECMA-262 §28.1）を native で足した: `userland/desktop/libbrowser/js/builtin_reflect.c`。13 の関数（apply・construct・defineProperty・deleteProperty・get・getOwnPropertyDescriptor・getPrototypeOf・has・isExtensible・ownKeys・preventExtensions・set・setPrototypeOf）は VM の internal method（`vm_get_receiver`・`vm_set_receiver`・`vm_define_own_property`・`vm_own_property_keys` ほか）をそのまま呼ぶので、Proxy の trap も言語の演算子と同じに走る（engine は Proxy を持つ）。CreateListFromArrayLike・newTarget の省略と明示の undefined の区別・key の変換の順は仕様どおり。`Reflect[Symbol.toStringTag]` は "Reflect"（Math・JSON と同じ所で付ける）。global の `Reflect` は writable・configurable・非 enumerable。
- 頁の prelude（`plan/ws074/phase230/prelude.js` → `bind/prelude-source.inc`）にあった JS の代わりの `Reflect`（`if (!g.Reflect)` の中、意味が仕様と違う）は使われなくなったので消した。
- 同じ Queue で直した事（Q1 の指示。Reflect が入って test262 の `isConstructor` が本当に判定するようになって見えた物）:
  - TypedArray の prelude（`js/builtin_typed.c`）の関数（%TypedArray%.prototype の map・filter・sort・toSorted・toReversed・with・keys・entries・values と Array から借りる forEach ほか、%TypedArray%.of・from）と WeakRef.prototype.deref・FinalizationRegistry.prototype.register・unregister が、普通の `function` で作られていて constructor だった（new でき、prototype の property があった）。object literal の method にして、native の built-in と同じに constructor でなく prototype も無い形にした。Array から借りる物は name も正しくした（前は ""）。
  - 計算した key の関数の名（SetFunctionName）: `{ [k]() {} }` が key の式の source の字（例 "k"）を名にしていた。`{ [k]: function () {} }`・symbol の key・計算した key の getter は "" だった。plain な getter・setter に "get "・"set " が付かなかった。数字の key も名が無かった。VM に命令 `SET_FUNCTION_NAME`（R function、R key、I prefix）と `vm_set_function_name`（`vm/class.c`）を足し、compiler が object literal（計算した key と数字の key の無名の関数・arrow・class、全ての getter・setter）、class の method・accessor、計算した key と数字の key の field で出す。名は string の key ならそれ、index なら数字の文字列、symbol なら "[説明]"（説明が無ければ ""）、private name なら "#x"。getter・setter は "get "・"set " を前に付ける。関数の own の name がまだ code の付けた物の時だけ変える（class の static の name の member は残る）。parser は計算した key の method に key の字の名を付けなくなった。private の field の無名の関数の名は "#x" になった（前は "x"）。
- 試験: `plan/ws074/tests/js/reflect.js`（13 の関数・Proxy の trap の順・key の変換・誤りの型）と `plan/ws074/tests/js/function-names.js`（object literal・class・accessor・symbol・private・field の名）。どちらも期待値は host の headless Chromium の出力（run-js-tests.py の PAGE と同じ形で作った）。
