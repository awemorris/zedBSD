## 2026-10-11 (A) の原因と直し（P1、0bc994c29、main に merge）

compositor の settings の store（userland/desktop/wayland/settings-store.h）の KWL_SETTINGS_ENTRIES が 24 で、table の compositor の行は 29。25 番目以降の notify.allow.phone・notify.allow.browser・phone.backend・power.sleep.ac・power.sleep.battery が store に入らず、set は捨てられていた（applied=2）。64 に上げ、plan/tools/settings/host-store.c に全行が store にある検査を足した。(B) の channel=2・paired=0 は (A) の結果。**他の WS の設定（電源の sleep の AC・battery、Phone と Browser の通知の許可）も同じ原因で効いていなかった**。

## 2026-10-11 (C) の原因: usb-bt の data pipe が Transaction Error の後に止まる（P1、885d93c62、main に merge b91d5675c）

- btsnoop（Q1 が 5330 で `bluetoothd -s` で取った、`build/bug287/bt287.snoop`）: **capture 全体で controller から bluetoothd に届いた ACL が 0**（RX は event だけ）。2 回目の phone=1 の pairing は SSP・link key（type 05）・暗号化・key size 16 まで正常、その後の L2CAP の Information Request（pairing の probe）と SDP の Connection Request は Number of Completed Packets まで出たが、答えが来ない → PAIRED の `l2cap=0`、MAP の SDP が止まり Settings は「Messages connecting...」のまま、2 分ほどで link が切れて `map: failed (sdp)`・why=lost。
- dmesg: `xhci: transfer completion=4 residual=4096 … endpoint=5 … direction=in` の後 `usb-bt: …: the data pipe stopped at submit (5)`。bulk IN が 1 回の USB Transaction Error（xHCI の completion 4）で Halted になり、usb-bt は再投入するだけで endpoint を回復しないので、xHCI が submit を EIO で断り data pipe が止まった。以後 ACL（L2CAP）が一切来ない。Bluetooth を入れ直しても同じ（Settings が「adapter が見つからない」になった時もある）。
- 直し（src/drivers/usb/usb-bt.c）: `DRV_USB_URB_IO_ERROR` を stall と同じく `drv_usb_endpoint_clear_halt`（線の CLEAR_FEATURE(ENDPOINT_HALT) と xHCI の Reset Endpoint・Set TR Dequeue）で回復して再投入。連続 8 回（USB_BT_ERRORS_MAX）で諦める。回復ごとに `usb-bt: …: the data pipe went on after a transfer error (N in a row)` を 1 行。Transaction Error が出る理由（線の一時的な誤り）は直していない。
- 1 回目の pairing の `ERROR rejected` の正体（snoop）: IO Capability Reply の後スマホから何も来ず 20 s で supervision timeout（Authentication Complete 0x08）。最初の 2 回の page（前の session の `.phone` による phone link の page）は保存の鍵で Link Key Reply → スマホが受けず → Authentication Failure 0x05 → why=security（スマホの側が bond を消していた）。

## 2026-10-11 残りの 3 点の直し（P1、681f2ce60・cc6078aa0・9df7c25f6）

1. **bond がある機器の Use as phone**（681f2ce60）: bluetoothd は、この run で同じ uid の PAIR が認証済み（MITM）の鍵で作った BR/EDR の bond を覚え（8 個、FORGET で消す）、その uid の `PAIR … phone=1` では保存の鍵を使う（`BTD_PAIR_PHONE_OWN`、スマホに pairing をやり直させない。その時に持ち主が数字を確かめているので p003 §3.2 N2 の保護は保つ）。他人の bond・Just Works の鍵・再起動の後の bond は今まで通り数値比較をやり直す。pairing の失敗の log に何が失敗させたか（`agent`・`ssp`・`auth`）と HCI の status を足した（例 `pairing: ERROR rejected (auth, status 0x08)`）: スマホの拒否・supervision timeout・利用者の No を log の語で分けられる。
2. **Settings の Connect**（cc6078aa0）: Connect・Disconnect は HID host の物なので、種類が Phone・Computer・Audio の機器には出さない（スマホの Connect が HID を試み 12 s で timeout していた）。スマホの接続は Use as phone の phone link が行う。pairing の失敗（`rejected`→ECONNREFUSED、ETIMEDOUT）に文を足し、Use as phone の失敗には「スマホの側でもこの computer を消してからもう一度」と案内する。
3. **Phone の app の案内**（cc6078aa0）: backend が無い（phone.backend 0）時は送らず・保存せず「No phone is set up: in Settings, Bluetooth, press Use as phone on your phone.」、paired の phone の messages が ready でない時は送らず「The phone is not connected: …」（書いた文は残る）。送信の button の灰色は「つながっていて送信を受けない」スマホだけにした。
4. **phone link の進みの log**（9df7c25f6）: bluetoothd の log に `phone: wanted …`・`paging`・`no link (status …)`・`link up`・`authentication failed (status …)`・`encryption failed`・`link ready`・`SDP query of 0x1132 …`・`SDP channel open`・`RFCOMM …`・`link ended (reason …, why)` を出す（電話番号・本文・address は出さない）。

## 5330 での確かめ（ユーザーの UAT、新しい image）

1. `dmesg | grep usb-bt` に `stopped at` が無いこと（`went on after a transfer error` は出てよい）。
2. Settings → Bluetooth: Pixel が My Devices にあれば Remove、スマホの側でもこの computer を消す。Other Devices の Pixel の **Use as phone** → 両方で数字を確認 → スマホが「メッセージへのアクセス」を聞いたら許可 → 1 分以内に行が「Messages connected」。bluetoothd の log に `phone: link ready`・`phone: SDP query of 0x1132 done (0)`・`map: ready`。
3. 普通の **Pair** の後に My Devices の **Use as phone**（同じ uid、bluetoothd を再起動していない）→ スマホに数字は出ずに phone になる（log の PAIRED が `stored=1 … phone=1`）。
4. スマホの行に Connect・Disconnect が出ないこと。
5. Phone の app: Use as phone の前に送ると「No phone is set up…」、接続中に送ると届く（UAT の手順 6）。
