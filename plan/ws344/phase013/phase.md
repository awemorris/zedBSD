## 3. 試験の項目

- test の側に §13.2 の token の符号化（値 → token・extra bit・符号）を書き、boolwriter で block を組む（既定の係数の確率で）。
- 各 token（DCT_0〜4、CAT1〜6 の最小と最大: CAT6 は 67〜2114）、符号、EOB、DCT_0 の後は EOB の枝を飛ばす、位置 15 の後は EOB 無しで終わる。
- block の type: has_y2 で Y2（type 1、位置 0 から）と Y（type 0、位置 1 から）、無しで Y（type 3）、chroma（type 2）。逆量子化（位置 0 は DC、他は AC、Y2・Y・UV の係数）、zigzag で raster へ、16 bit の wrap（大きな値 × 係数）。
- context: left・above の entry の位置（vp8-tokens.h の式）、値は「最初の位置より進んだか」（すぐの EOB は 0、0 の token だけで 16 まで進んだ block は 1）、coded の bit と bit 31。
- skip_residue: Y・U・V の entry は 0、has_y2 0（B_PRED）の時 Y2 の entry は残る。
- 期待の係数は test が書いた値と §14.1 の係数から手で。
- 全ての単体試験は ASan・UBSan で落ちず（run-unit.sh）、途中で切れた入力・範囲の外の値・乱数の入力で決められた誤りを返す。
- 期待の値は仕様の表・式と手の計算、test の側の逆の処理（lbitwriter・boolwriter で組んだ入力）だけから作る。他の実装の出力を期待の値にしない（fixture の全体の試験は道具が libwebp の出力と比べる）。

## 4. 注意

- RFC 6386 §13.3 の pseudocode の plane の番号と `prevCoeffWasZero = true` と `currentBlockHasCoeffs` は誤り（design.md §1）。§13.3 の list と §20.16 に従う。
- 確率の band は今の位置 i の coeff_bands[i]、context（ctx）は直前の値の大きさ（0・1・2 以上）。
- 符号の bit は確率 128 の bool。category の extra bit は最上位から cat_probs の順。
