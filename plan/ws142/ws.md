## 単一目標

Keiland の compositor（`userland/desktop/wayland/`）で、ユーザーの要望（下）のアプリの切り替えの操作を実装し、マウス・キーボード・タッチパッドの全部から同じ切り替えの UI に入れるようにする。

## ユーザーの要望（2026-10-04 夜、UAT-3 の後、原文）

「以下は実装の要望です。
・Windowsキーでアプリ一覧を出してほしい。
・タッチパッドの下のエッジから2本指でスワイプアップしたらウィンドウ一覧（Wiseview）を表示してほしい。このモーションが利用できないなら、3本指スワイプアップでもいい。
・タッチパッドの左エッジから右に2本指スワイプと、右エッジから左に2本指スワイプは、それぞれ仮想デスクトップの左行き、右行きに対応させてほしい。
・次の実装をしてください。ウィンドウを最大化していないとき、スクリーン上部のバーに、開いているアプリの一覧を出してほしい。アプリアイコンはポイントするとウィンドウプレビューが画面の25%くらいのサイズで出るとうれしい。クリックするとそのアプリを最前面にする。複数ウィンドウがあるアプリの場合、ポイントするとウィンドウが複数表示され、また、クリックすると、ポイントのように一定時間待たなくても表示される。その状態でウィンドウプレビューをクリックすると、そのウィンドウが最前面になる。ウィンドウを最大化表示しているときはこのスクリーン上部のバーにアプリ一覧のアイコンは出なくて、Wiseviewにアプリ切り替えを任せる。さらに、タッチパッドで3本指でタップすると、このアプリアイコンをポイントしてプレビューが出ている状態になる。現在のアプリの1つ次のアプリがポイント・プレビューされた状態になり、その状態で2本指で左右にスワイプすると、次のアプリのプレビューに移る。タップすると選択してアプリ切り替え。この動作はAlt+Tabでも起動できる。ウィンドウを最大化しているときは、最大化していないときのバーのアプリアイコンの位置ではなく、画面の中央に、同様のポップアップが出る。」

## 範囲（p001 で設計して確定）

1. **Windows キー（Super）**: 単独で押して離すとアプリの一覧（App Home）を出す（もう一度で閉じる）。他のキーとの組み合わせの時は出さない。
2. **タッチパッドの下の端からの 2 本指の上へのスワイプ → Wiseview**。タッチパッドの端の検出ができない（device が端の位置を出さない・BUG-165 の I2C HID の状態による）時は、3 本指の上へのスワイプで代える。
3. **タッチパッドの左の端から右へ・右の端から左への 2 本指のスワイプ → 仮想デスクトップの左・右へ**（ws035-p065 の端の swipe と同じ移動）。
4. **上部のバーのアプリの一覧**（窓を最大化していない時だけ）:
   - 開いているアプリの icon を並べる。
   - pointer を icon に置く（hover の待ち）と、その窓のプレビュー（画面の約 25% の大きさ）を出す。複数の窓のアプリは窓を全部並べる。
   - icon のクリック: 窓が 1 つならそのアプリを最前面に。複数なら待たずにプレビューの並びを出し、プレビューのクリックでその窓を最前面に。
   - 窓を最大化している時は、バーにアプリの icon を出さず、切り替えは Wiseview に任せる。
5. **切り替えの UI（3 本指のタップ・Alt+Tab）**:
   - 3 本指のタップ、または Alt+Tab で、今のアプリの 1 つ次のアプリの icon を hover した状態（プレビュー付き）にする。
   - その状態で 2 本指で左右にスワイプ（Alt+Tab では Tab・Shift+Tab）すると、次・前のアプリのプレビューに移る。
   - タップ（Alt+Tab では Alt を離す）で選んだアプリへ切り替える。
   - 最大化している時は、バーの icon の位置ではなく、画面の中央に同じポップアップを出す。
