# ws202-p005: AAC の構文と表

Status: planned
Disposition: normal
Parent: [WS202](../ws.md)
見積もり: 7 LW
依存: p002（stream）、p003（`bits.c`）、H3（HE-AAC の扱い）、H5（表の出典）

## 目的

AAC-LC の frame を全部の field まで読み、channel ごとの量子化値・scalefactor・道具の data を持つ形にする（信号処理は p006）。

## 成果（`userland/desktop/libmedia/`）

1. `aac.h`: 内部の型。`struct aac_config`（AOT、core の rate の index と値、channel の配置、HE-AAC の印と拡張の rate、frame の長さ）、
   `struct aac_ics`（window_sequence・window_shape・max_sfb・group の数と長さ、section の codebook、scalefactor（band ごと）、intensity・PNS の値、
   pulse、TNS の filter（窓ごと: 数・長さ・order・向き・係数の index）、量子化値 1024）、`struct aac_element`（SCE・CPE・LFE、CPE の common_window・
   ms_mask_present・ms_used）、`struct aac_frame`（要素の並び）。
2. `aac.c`（構文の部分）:
   - `aac_config_parse`（AudioSpecificConfig: AOT の escape、rate の index と 24 bit の明示、channelConfiguration、GASpecificConfig、PCE、
     AOT 5・29 の明示と 0x2b7 の暗黙の signalling）。design §6.1 の通り、扱わない AOT は PROFILE、HE-AAC は H3 の回答に従う
     （(a) なら degraded の時だけ受ける）。
   - `aac_frame_parse`（raw_data_block の要素: SCE・CPE・CCE（読んで捨てる）・LFE・DSE・PCE・FIL・END、design §6.2）。
   - ICS: ics_info・section_data・scale_factor_data（global_gain から DPCM、intensity と PNS の別の DPCM、PNS の最初の 9 bit）・pulse_data・
     tns_data・spectral_data（codebook 1〜4 は 4 個組、5〜11 は 2 個組、unsigned の codebook の符号 bit、11 の escape（prefix の 1 の数 ＋ 4 で bit 数））。
   - short の窓の group と band の並べ替え（spectral の index を window・band・係数の順に置く）。
3. `aac-tables.c`: Huffman の codebook（scalefactor 1 個と spectral 11 個）、scalefactor band の offset（rate の index ごとの long 49 以下・short 14 以下、
   swb の数）、TNS の max band、rate の表。H5 の回答に従って作る:
   - (a) の時: `plan/ws202/tests/gen-aac-tables.py` が FFmpeg 9.0.2 の tarball（`userland/packages/multimedia/libavcodec/Makefile` の URL と SHA-256。
     main の checkout の package の download の置き場所を読むだけ、無ければ script が取得して SHA-256 を確かめる。`python3 -I` で走らせる）から
     値だけを読み、zedBSD の名前・並び・型で `aac-tables.c` を書き出す。生成した file の頭に「Generated by plan/ws202/tests/gen-aac-tables.py
     from the values of ISO/IEC 14496-3 tables 4.A.1-4.A.12 and 4.129-4.147 as found in <file> of ffmpeg-9.0.2.tar.xz (SHA-256 …); no code is
     copied」と書く（文は design §6.7 の記録と合わせる）。
   - (b)・(c) の時: その出典から同じ形で起こす。
   - Huffman の復号の形: codeword の長さと値の表から、復号の時に使う 2 段の表（最初 9 bit の直引き＋残り）を init の時に作る（表の file には
     codeword・長さ・値だけを置く）。
4. host 試験 `plan/ws202/tests/host-aac-parse.c`・`run-host-aac-parse.sh`: p002 の AAC の全 stream の全 frame を parse し、(1) 失敗が 0、(2) 各 frame の
   読み終わりの bit が packet の長さ（8 bit の切り上げ）と一致、(3) 要素の並び・window_sequence の数え（`aac-short` に EIGHT_SHORT がある、
   `aac-tools-low` に PNS・intensity・ms_used・TNS がある）、(4) Huffman の表の自己の検査（prefix の符号であること、Kraft の和）。
