## 試験の項目

- 往復: 3x3 程度の picture の context（`struct h264sw_picture_ctx`・`h264sw_slice_ctx`・entry を試験の中で組む: 隣の有無、skip、intra、I_PCM、direct、mvd、cbp、transform_8x8）で、各要素の全値（mb_type の I 0〜25、P 0〜4 と 5〜30（4 を除く）、B 0〜22 と 23〜48、sub_mb_type の P 0〜3 と B 0〜12、ref_idx 0〜31 と範囲、mvd −32768..32767 の境と乱数、cbp 0〜47、qp_delta −26..25、chroma 0〜3、intra の flag と rem、transform）を書いて、decoder の `h264sw_cabac_*`（同じ context の初期値の decoder）で読んで一致。
- I_PCM: mb_type の terminate、`h264enc_cabac_pcm`、その後の要素が `h264sw_cabac_pcm` を挟んで読める。
- end_of_slice: 0 の列の後の 1、その後の整列で decoder が slice を正しく終える。
- 範囲外の値で何も符号化せずに EINVAL。
- 共通: 誤りの引数で落ちず header の誤りを返す。ASan・UBSan の報告 0。期待の値は仕様の表・手の計算・decoder の module の読み戻し（design §10.1）から作り、他の encoder（x264・openh264・JM など）の出力や source を使わない。
