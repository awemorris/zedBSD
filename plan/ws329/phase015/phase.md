## 試験の項目

- 明らかな mode: 縦の縞の source で Vertical、横の縞で Horizontal、平らで DC（16x16 と 4x4、chroma）、勾配で Plane。入手できない端の mode を試さない（picture の左上の MB）。
- block の再構成の一致: 4x4 と 8x8 で決めた levels と mode を `h264sw_mb_syntax` に入れて decoder の `h264sw_recon_mb` で再構成し、決定の時に frame に残った画素と全画素一致（乱数の画、QP 0・20・40）。
- entry の intra4x4_mode の書き方（8x8 は 4 つ）と predicted mode の扱い。cost の式（header の bit の数え）を試験の中の素朴な計算と比べる。
- 共通: 誤りの引数で落ちず header の誤りを返す。ASan・UBSan の報告 0。期待の値は仕様の表・手の計算・decoder の module の読み戻し（design §10.1）から作り、他の encoder（x264・openh264・JM など）の出力や source を使わない。

## 注意

- 予測と端と予測 mode は decoder の関数だけを使う。block の再構成は decoder の scale・idct・add_residual で。
- 他の実装の code・comment・構造・名前を写さない。表は block ごとに `Values referenced: ITU-T H.264 (08/2021) Table ...` の複数行の comment。source の comment に WS・Phase の番号や plan/ への参照を書かない。
