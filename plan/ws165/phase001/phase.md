## 3. 認識の方式（段 1）

- **点群の照合（$P の系統）**: 書いた線の全部の点を 1 つの点の集まりにし（書き順・画数に依らない）、大きさと位置を正規化して 32 点に resample し、
  手本ごとの点群と「貪欲な最小の対応の距離」で比べ、距離の小さい順に候補にする。字ごとに複数の手本（書き方の違い）を持てる。
- 選ぶ理由: 学習が要らず、手本の data だけで動く。数百字なら全部と比べても速い（250 字 × 手本 3 × 32 点）。書き順の違う人にも効く。実装が小さい
  （compositor の中、`keyboard-hand.c` の stub の場所に置ける）。
- 補う特徴: 画数の差に小さな罰（「い」と「り」など）、縦横の比（「ー」と「|」）、点の多い小さな字（「゛」）の扱い。濁点・半濁点は、本体と別に
  認識して合成する（「か」+「゛」→「が」）か、手本に全部入れるかを p002 で比べる。
- 段 2（漢字）は全部と比べると遅い（3,000 字）ので、画数と大まかな形で候補を絞ってから照合するか、小さな学習の model に替える（段 2 の設計）。

## 4. 手本（字形の data）

| 候補 | 中身 | license | 使い道 |
| --- | --- | --- | --- |
| Hershey fonts | 線（stroke）で描いた字形。英数字・記号と、日本語のかなと一部の漢字を含む（字の数は p002 で数える） | 配布の条件は帰属の表示を求める自由な利用（元は NBS の公開物。正確な条件と取得の元は p002 で確かめ、監査して記録） | 段 1 の英数字・記号・かな の手本、段 2 の一部 |
| KanjiVG | 漢字・かなの書き順つきの stroke の SVG（約 6,700 字） | CC BY-SA 3.0（data に share-alike が掛かる） | 段 2 の漢字（手本の data を別の file にし、license を付ける） |
| 自作 | 書いた点の列を記録する道具で、手本を自分で書く | Zlib | 足りない字・書き方の違いの追加 |

- 推奨: 段 1 は Hershey（英数字・記号・かな）に、自作の手本で書き方の違い（例「4」「7」の 2 通り、「さ」「き」の続け方）を足す。
  data は tree の中の生成の道具で変換した C の表（`keyboard-hand-data.c`、生成の元と出どころを記録）。外部の data は tarball を取得・検証して変換する
  （AGENTS.md の外部 package の規則に倣う）。
- 段 2 で KanjiVG を使うなら、share-alike の data を tree に入れてよいか（§7 の H3）。

## 5. 試験の試料（段 1）

- 手本から機械的に作る揺らぎの試料: 各字 20 個、回転 ±10°・縦横の伸び ±15%・点の揺れ（正規分布、文字の大きさの 2%）・線の端の欠け・書き順と向きの入れ替え。
  手本と同じ data から作るので、正答率は上限の目安（本物の手書きより甘い）。
- 本物の手書き: 段 1 の終わりに、ユーザーが 5330（touch・pen）か QEMU の pointer で書いた 100 字を記録する道具（ink を file に書く試験の口、`ZWL OSK hand ink …` の log
  か `/tmp/hand-ink-*.txt`）で集め、試料に足す。正答率はユーザーに報告して判定してもらう。
