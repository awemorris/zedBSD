# zedBSD known bugs

Last updated: 2026-09-01

This ledger records observed defects and their explicit active or deferred
owner. A listed item is not silently treated as a failure of an unrelated
Phase; deferred work returns only through a later finite Queue. Resolved entries
remain as traceable history and are not new implementation work.

| ID | Area | Status / priority | Observation | Resume and acceptance condition |
| --- | --- | --- | --- | --- |
| `BUG-001` | legacy PC/AT IDE ATA CACHE FLUSH | Open; deferred, below the primary amd64 UEFI path | A disposable BIOS/IDE overlay boot can intermittently report `ata: sda op=2 ... error=5 status=C0` while FAT is synchronizing the writable overlay. `op=2` is `BIO_FLUSH`; the same frozen image reaches `login:` on retry, and amd64 UEFI/xHCI USB boots are unaffected. The observation first appeared during `ws018-p004` and recurred once during the `ws018-p009` runtime matrix. | When explicitly selected, boot 1,000 pristine disposable copies with the same image, retain every failure log and seed/topology, measure the rate, then fix the ATA flush completion/timeout path. Accept only after the corrected 1,000-run campaign has no unexplained flush error and ordinary amd64 UEFI regression still passes. |
| `BUG-002` | USB submit/terminal-publication handoff | Resolved (`ws002-p022`) | The apparent init/getty stall was a local xHCI completion interrupt preempting `drv_usb_urb_submit()` after the submitter atomically claimed its stack commit record but before it cleared `submit_commit_pending`. The interrupt saw no record and waited for the preempted submitter, deadlocking a one-CPU boot. A stopped failure captured the matched, successful CSW event with its URB still pending and the CPU yielding in this handoff; no xHCI event was lost. | Closed. Local IRQ masking now makes commit claim and finish indivisible while preserving remote-CPU completion. The faithful old-order model/source-order gate, USB binding normal/sanitizer/analyzer runs, unchanged ordinary `MAC-T022`, and initial plus final-five fresh-copy exact-login boots pass. Preserve [ws002-p022](ws002-services/phase022-intermittent-console-login/phase.md) and its regression. |
| `BUG-003` | legacy UHCI/EHCI short-transfer semantics | Open; outside `ws004-p016` DMA-retirement boundary | UHCI does not yet provide a complete short-IN path which stops remaining data TDs while still running the mandatory control status stage; EHCI also needs explicit short-chain coverage. Separately, EHCI currently maps every halted qTD to STALL even though babble, buffer, and exhausted transaction errors also halt. These are transfer-result semantics, not premature-DMA-release failures. | Extract a finite legacy-transfer Phase. Add exact per-bit status decoding, control and non-control short-IN state machines, toggle/actual preservation, malformed residual tests, and UHCI/EHCI QEMU descriptor/storage cases. Accept only with the p016 retirement gates unchanged and no false STALL/success result. |
| `BUG-004` | legacy UHCI/EHCI runtime root-port hotplug dispatch | Resolved (`q047`, `ws004-p031`) | P031 added independent worker-context root dispatch while preserving request-retirement progress. HW-T25 ordinary/sanitizer/analyzer gates and both forced QEMU cells pass detach/reinsert across 12 generations, concurrent HID/Storage progress, final detach, and checked worker joins. | Closed. Preserve the p031 root-worker/request-worker separation and shutdown-order regressions. |
| `BUG-005` | generic PCI shared-INTx subscriber source disable | Open; current EHCI/UHCI removal is safe | The shared-INTx dispatcher/list/drain fixture passes, but generic PCI removal does not save, set, and restore a function's `PCI_COMMAND.INTx Disable` bit. A future caller which unlinks a still-asserted function could leave the shared level active after its handler is gone. EHCI and UHCI first quiesce controller-local interrupt generation, so this residual does not weaken the completed p031 result. | Select a finite PCI hardening Phase only when a consumer cannot provide the existing device-local pre-quiesce contract. Freeze and test the source-disable/removal ordering and failure retention without masking or removing peer subscribers; do not infer a broader interrupt redesign. |
| `BUG-006` | Intel Mac / host-relocated GPT compatibility | Automatic repair complete; provisional physical confirmation pending (`ws020-p006`) | The former `FDC1-A4EF` physical handoff exposed a complete physical-end GPT with a stale compact Protective-MBR extent. The parser now treats only that extent disagreement as a warning and makes a CRC/structure-valid GPT authoritative while retaining the protective-entry discriminator, strict geometry/bounds/copy checks, bounded fallback locations, and contradiction rejection. Host ordinary/sanitizer/analyzer, first-only relocated/pristine QEMU, exact login, and uninterrupted six-cell gates pass. | Boot only the published SHA-256 `692160cf...331d`, UUID `A93F-BBBE` image once on the Intel Mac. Close this entry if it reaches the expected GPT warning, root/data/swap, and ordinary login; retain p004's five final cold boots separately. |
| `BUG-007` | i386/PC-98 undefined-symbol build audit | Open; build-integrity hardening, q048 alternate audit passes | The i386/PC-98 Makefile path invokes `$(NOCT_NM) -u` without defining `NOCT_NM`, producing an empty-command `-u` attempt whose exit status is not made fatal. Thus the nominal undefined-symbol check can be skipped even though the full build succeeds. q048 compensated with host `nm -u` over `build/pcat/vmunix`, every top-level `build/pcat/*.ELF`, and every file in `build/pcat/bin`; `build/q048-regression-tmp/pcat-bin-undefined-symbols.txt` contains zero undefined-symbol lines. | In a finite build-integrity Phase, define and validate the supported `nm` tool for PC/AT i386 and PC-98, make a missing tool or failed scan fatal, and add a negative fixture proving that an undefined symbol fails the build. Preserve the q048 zero-undefined production result. |
| `BUG-008` | legacy UHCI active-request lifetime | Open; deferred WS004 reliability follow-up, q048 semantic acceptance passes | One q048 paired EHCI/UHCI run (`build/q048-p008-paired-usbonly7`) raised a `#GP` at the first `controller->active` dereference in `uhci_retirement_worker`. The same complete HID hotplug, stale-fd, tablet, and concurrent 64 MiB EHCI Storage sequence passed with temporary diagnostics and again with the final uninstrumented production source (`build/q048-p008-paired-uhci-baseline1`). The established `pci-uhci.c` implementation was left unchanged rather than retaining a speculative fix; HW-T25 and the primary xHCI HID cell pass. | A recurrence immediately reopens the q048 legacy acceptance and becomes a finite WS004 Phase. Before otherwise claiming this fault resolved, run the same immutable-image paired EHCI/UHCI cell in 10 fresh QEMU processes with fresh writable media/firmware variables; require 10 consecutive complete semantic passes and no `#GP` or fatal exception. Any failure stops the campaign and retains the exact log for active-list lifetime diagnosis. |
