- 監査の担当（Opus、読むだけ。make・sim・Vivado は走らせていない）。どれも RTL を読んだ見込みで、sim・実機では確かめていない。
- 対象: Gemini の修正 5fb4ad16（13:03）・1e80cfb6（15:04）・50f13348（15:28）、基点 6949b248。台帳の行は [ghci-rtl-questions.md](ghci-rtl-questions.md)（A1〜A11、B1〜B10）。
- 今の合成は変更の後の RTL（ユーザーの確認）。

## 要約

- A1 は一部: SLIM_MMIO は消え Slim の map だけに。page 0 の MAGIC・VERSION・DEVICE_CAPS は仕様の offset で読める見込み。
- ただし KC705 に新しい壊れが表に出た: extended capability の窓への書き込みが捨てられる（A6）、MEM・RESIDENT_WARPS・GCLK_HZ・NATIVE_ISA_ID に答えが無い（A7）、読みの index の流用で SCRATCH・SESSION_ACTIVE・TIMESTAMP・GCLK_HZ・NATIVE_ISA_ID が別の register と混ざる（A8）。
- A2〜A5 は未着手: DEVICE_CAPS・EXT_CAP_FEATURE・EXT_CAP_FMT0 の式は今日の 3 commit で不変（Q1 が `git diff 6949b248 50f13348` で確かめた）。
- preset は効いている: config.mk = minimal.mk、atg_config.vh も minimal から。ただし CAPS の式は構成の macro をほとんど読まない（ROP_PACK・TEX_FFILT・PROT・SRGB を読まない）。

## minimal（KC705）の値

| register | RTL が出す値 | 仕様と minimal から期待する値 | 違い |
| --- | --- | --- | --- |
| DEVICE_CAPS | 0x44010480 | 0x40010480 | [26] ROP_PACK が 1 固定。[24]・[25]・[23:16]・[30] は出所が違うが値は偶然一致 |
| EXT_CAP_FEATURE | 0x00000018 | 0x00110000 | 古い並び。仕様で読むと VA 38・PA 41・MRT 0・LDS 0 KiB |
| EXT_CAP_FMT0 | 0x00000000 | 0x00001200（[15:12] は B5） | [9] SRGB 0、[15:12] 0 |
| MEM（0x1E0〜） | 全部 0 に読める見込み（A7） | LOCAL_BASE 0x80000000、LOCAL_SIZE 0x40000000、WINDOW_SIZE 0x04000000、HOST_LIMIT 0x80000000、WINDOW_CTRL 1 | 答える物が無い |

- EXTCAP の list（XCAP 0x4A6）: DBG・PERF・CPFW・MEM・DISP2。FMT は無い（B6）、PROT は無い（minimal）。見出しは DBG 0x100 → PERF 0x108 → CPFW 0x180 → MEM 0x188 → DISP2 0x190（A10）。

## preset

- macro が無い時に「有り」に倒れる既定（CLIP_POLY・HAS_BLT・TU_BILINEAR）は、Makefile が常に 0/1 を出すので minimal では逆転しない。Makefile を通らない sim・lint では誤る（A11）。
- RTL が読む `CFG_ENABLE_TRILINEAR`・`CFG_ENABLE_SA`・`CFG_ENABLE_MSAA`・`CFG_ENABLE_EARLY_Z`・`CFG_COARSE_SCAN` は 1 の時だけ出力され、minimal では正しく 0。
- 今日の commit で新しく読む macro は無い。
