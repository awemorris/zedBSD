# ws035-p062: タイトルバーのドッキング（最大化 = 上部のバーへの吸着）の疎通確認

Phase ID: `ws035-p062`

承認: 2026-09-26 ユーザー「ウィンドウのフローティングタイトルバーをダブルクリックするか、画面上部にスライドさせると、スクリーン上部のシステムツールバーに、ウィンドウタイトルバーがドッキングする、という仕組みにしたいです。…また、スクリーン上部のシステムバーから下にスライドする操作で、最大化を解除したいです。完璧にしなくてよくて、細かいところはstaticかモックアップでよいです。まずは一本通すというか、疎通確認でモックアップしてみましょう。」（実現イメージの画像と、配置・遷移・3 つの zone の説明を添付）

## ユーザーの説明の要点

- 通常は上段のシステムバーと、その下に浮いたタイトルバーの 2 層。最大化は「窓がデスクトップのシェルにドッキングする」見た目: 本体が画面いっぱい、浮いたタイトルバーは消え、題名が上部のバーの左へ滑り込む。
- ドッキング中の上部のバー: `[アプリ一覧] zedBSD | [W] 題名 …… [— ⧉ ×] [仮想デスクトップ] [通知領域]`（画像の通り）。`— □ ×` は右端でなく通知領域の少し左。`□` は復元（重なった四角）。
- ドッキング中のバーは淡いすりガラスのまま、通常より白の base を 5〜10 % 強める。
- 遷移 200〜250 ms: 本体が四辺へ広がり、タイトルバーが上へ動いてバーに吸収され、元の背景は fade out。戻りは対称。
- 上部のバーの題名のダブルクリック、または下へのスライドで解除。下へのスライドはそのまま窓を引きずり出す。
- 上部のバーの 3 zone: 左 = 今の窓、中央〜右 = 仮想デスクトップ、右端 = 状態・時計・通知。
- 発展（今回は範囲外）: 題名の click でアプリの menu、右 click で窓の menu。

## 範囲（`zwl --glass`）

- ドッキング: 浮いたタイトルバーのダブルクリック（400 ms 以内の 2 回）、タイトルバーの drag で pointer がバーに入って離す（近づくとドッキング先を予告の枠で示す）、最大化 button。本体は (0, バーの下 4 px) から出力の右下まで（下の角は画面の外）、configure でその大きさ。
- 解除: バーの題名のダブルクリック、バーの ⧉、バーの題名を押して 16 px より下へ drag（元の大きさで pointer の下に窓を出し、そのまま drag を続ける）。
- バー: ドッキング中は題名・印・`— ⧉ ×`（hover）を左の zone に、白の base を強める。仮想デスクトップ 4 つ（壁紙の縮小、1 つ目が選択）を通知領域の左に（ハリボテ、常に表示）。
- 遷移 220 ms: 本体の矩形を補間（画像を引き伸ばす）、浮いたタイトルバーの矩形をバーの題名の位置へ補間しながら背景を fade、バーの題名を fade in。戻りは逆。
- 最小化・アプリ一覧・仮想デスクトップの操作・menu は見た目だけ。

## 受け入れ

1. ダブルクリック・上への drag・最大化 button でドッキングし、上部のバーが画像の並びになる（画面を撮ってユーザーに見せる）。
2. バーの題名のダブルクリック・⧉・下への drag で元に戻る（下への drag では窓が pointer に付いて出る）。configure と client の resize を log で確かめる。
3. 遷移の途中の frame が描かれる（log または画面）。p052 と p059（新しいドッキングに合わせて直す）の試験が通る。build は warning 0、style-check の指摘 0。
