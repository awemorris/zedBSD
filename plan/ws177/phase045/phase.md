## 範囲と設計の案（下調べの結果）

- 17（`userland/base/net/reconcile.c`、`emit_ipv6`・`emit_routes6`）: 前の program との差を取り、消えた静的な IPv6 の address に `-inet6`、消えた
  route に `route -6 delete`。
- 20（`networkd/ipv6.c`）: `networkd_ipv6_events` が RTM_ADDRINFO（`RTM_ADDRINFO_DUPLICATE`、`struct rtm_addrinfo`）を読む。重複した address が
  今の一時的な IID なら新しい乱数で作り直す。安定の address（autoconf・link-local）なら (ifindex, prefix) ごとの DAD の回数を増やし（3 回まで）、
  `slaac_stable_iid` の dad_counter に渡して作り直す（以後の RA でもその回数を使う）。重複した address は SIOCDIFADDR_IN6 で消す。EUI-64 は作り直さない。
- 21: 一時的な address の表（`ipv6_temporary`）に作った時刻を持ち、寿命を作った時から数える（RFC 8981: valid は作成から 2 日、preferred は
  1 日 − desync まで。RA ごとに延ばさない）。純粋な関数を slaac.c に（host で試す）。preferred の残りが REGEN_ADVANCE（5 秒）を切る前に
  新しい IID の address を作る。RA の間で切れないよう、作り直しの時刻を `networkd_ipv6_poll_timeout`・`networkd_ipv6_run_due` に入れる。
  古い address は kernel が寿命まで持つ（延ばさない）。
- 22: router の表（ifindex・router・寿命）を持ち、既定の route は優先の interface（有線を Wi-Fi より、有線の中は main.c の順。main.c に
  `networkd_interface_is_wifi` などの口を足す）の router だけ。他の interface の router の route は消す。RTM_IFINFO の carrier down で、その
  interface の AUTOCONF の address（SIOCGIFADDRS_IN6 の `IN6_IFF_AUTOCONF`）と router・route・RDNSS を消して選び直す。
- 23・27: RDNSS の server を interface ごとに寿命と一緒に memory に持つ。resolv.conf への書き込みは 1 つの関数（merge）: 今の file の先頭の
  comment 行（`# Generated by dhcpc for IF` など）・search・IPv4 と他の IPv6 の nameserver を保ち、前に networkd が足して今は無い RDNSS を除き、
  今の RDNSS を足す（3 つまで、重複なし）。main loop の各回で resolv.conf の (ino, size, mtime) が networkd の最後の書き込みと違えば merge
  （dhcpc の DHCPv4・DHCPv6 の書き込みの後に RDNSS が戻る）。完全な「DNS の 1 つの表」（dhcpc が resolv.conf を書かない形）は dhcpc と
  networkd の役割の変更が大きいので、この形にする（Q1 に報告）。
- 24: `dhcpc -6` を fork・exec で非同期に。entry に pid と開始の時刻、`networkd_ipv6_poll_timeout` は子が走っている間 200 ms、`run_due` が
  waitpid(pid, WNOHANG) で終わりを受け、15 秒を越えたら SIGTERM・SIGKILL。networkd に waitpid(-1) は無い（確かめた）。

## 決定（2026-10-08 夜 Q1）

- resolv.conf は前の世代の案のとおり、DHCPv4・DHCPv6・DNS の命令が書き直した後に networkd が RDNSS の server を足し戻す形にする。
- 「DNS を 1 つの表で持ち、networkd だけが resolv.conf を書く」形は dhcpc と networkd の役割の変更が大きいので **F-091**（Future Work、
  Q1 が台帳に載せる）。起こり得る残り: networkd の merge（読み → rename）と非同期の `dhcpc -6` の書き込みがごく短い間に重なると、dhcpc の
  書いた DHCPv6 の server が次の dhcpc の実行まで消える。

## 実装（2026-10-08 夜 P1）

- 17（`userland/base/net/reconcile.c` の `emit_removed6`）: 前の program の静的な IPv6 の address で target が同じ address・長さで名指さない物
  （inet_pton で比べる）に `STATIC6_REMOVE IF ADDR/LEN`、target が経路を持たない宛先の IPv6 の route（default は ROUTE6_CLEAR の物）に
  `ROUTE6_REMOVE DEST` を、interface の設定の前に emit。target が IPv6 を off にする interface は off が全部を消すので出さない。
  wire: `NETWORKD_OP_STATIC6_REMOVE`（15）・`NETWORKD_OP_ROUTE6_REMOVE`（20）（`net/protocol.h`、net の `backend_opcode`・`backend_payload`、
  networkd の確認の取引の範囲・実行（`ifconfig IF -inet6 ADDR`・`route -6 delete DEST`、既に無い物は成功）・rollback の行・field の検査・名前）。
- 20（`networkd/ipv6.c` の `ipv6_duplicate`）: RTM_ADDRINFO の DUPLICATE で、networkd が作る /64 の address だけ: 一時的な物は外して新しい乱数で
  （`temporary_retries`、3 回まで）、安定の物（link-local も）は今の counter の IID と一致を確かめて外し、(ifindex, prefix) の `dad_counter` を
  増やして作り直す（3 回まで。以後の RA・link-local もその counter）。EUI-64・静的・DHCPv6 の物は kernel の印（duplicated）のまま。
- 21（`slaac.c` の `slaac_temporary_aged`・`slaac_temporary_regenerate`・`slaac_temporary_desync`、`ipv6.c` の `ipv6_prefix_state`）:
  一時的な address の寿命を作った時から数える（valid は 2 日、preferred は 1 日 − DESYNC_FACTOR（作るたびに乱数、0〜34560 秒）まで、
  RA が延ばさない）。作成から 1 日 − desync − REGEN_ADVANCE（5 秒）で新しい IID の物を作る（`ipv6_temporary_due`、poll の期限に入る）。
  古い物は kernel が寿命まで持つ（renew しない）。prefix の最後の RA の寿命と時刻を持ち、残りで足す。
- 22（`ipv6_router`・`ipv6_routes_apply`・`slaac_router_choose`、main.c の `networkd_interface_rank`）: router の表（8）を持ち、既定の route は
  順位の最も良い interface（managed の有線はその順、他の interface、Wi-Fi の接続の interface の順）の router だけ。同じ順位では今の物を
  保つ。選びが変わると他の interface の ::/0 を消す。寿命の切れた router は表から外して選び直す。RTM_IFINFO の CARRIER_DOWN・REMOVAL
  （`ipv6_carrier_down`）で、その interface の AUTOCONF の address（SIOCGIFADDRS_IN6）・router・RDNSS・DNSSL・一時的な IID・DHCPv6 の予定を
  消して選び直す（DAD の counter は interface が在る間は保つ）。
- 23・27（`networkd/resolver6.c` の `resolver6_merge`、`ipv6.c` の `ipv6_resolver_sync`）: RDNSS（と DNSSL）を interface ごとに寿命と一緒に
  memory に持つ。main loop の毎回、resolv.conf の (dev, ino, size, mtime) が networkd の最後に見た物と違うか、表が変わった時に merge する:
  先頭の comment 行・search・他の行・他の server を保ち、networkd が前に足して今は要らない server を除き、要る server を後ろに足す
  （3 つまで、重複なし）、search が無ければ足す。dns static の時は足さない（前に足した物は除く）。先頭の comment が無い file には
  `# Generated by networkd`。
- 24（`ipv6_dhcp_run`・`ipv6_dhcp_wait`・`ipv6_dhcp_done`）: `dhcpc -6` を fork・execv で子にし（出力は networkd の物）、子の間は poll を 200 ms で
  起こして waitpid(pid, WNOHANG)。15 秒を越えたら SIGTERM、その 2 秒後から SIGKILL。走っている間の再実行の求めは `again`、interface の
  下ろし・RA の mode NONE は子が終わるまで entry を残す。main.c の `networkd_run_command` は使う所が無くなったので外した。
