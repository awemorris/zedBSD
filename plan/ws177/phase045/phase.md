## 範囲と設計の案（下調べの結果）

- 17（`userland/base/net/reconcile.c`、`emit_ipv6`・`emit_routes6`）: 前の program との差を取り、消えた静的な IPv6 の address に `-inet6`、消えた
  route に `route -6 delete`。
- 20（`networkd/ipv6.c`）: `networkd_ipv6_events` が RTM_ADDRINFO（`RTM_ADDRINFO_DUPLICATE`、`struct rtm_addrinfo`）を読む。重複した address が
  今の一時的な IID なら新しい乱数で作り直す。安定の address（autoconf・link-local）なら (ifindex, prefix) ごとの DAD の回数を増やし（3 回まで）、
  `slaac_stable_iid` の dad_counter に渡して作り直す（以後の RA でもその回数を使う）。重複した address は SIOCDIFADDR_IN6 で消す。EUI-64 は作り直さない。
- 21: 一時的な address の表（`ipv6_temporary`）に作った時刻を持ち、寿命を作った時から数える（RFC 8981: valid は作成から 2 日、preferred は
  1 日 − desync まで。RA ごとに延ばさない）。純粋な関数を slaac.c に（host で試す）。preferred の残りが REGEN_ADVANCE（5 秒）を切る前に
  新しい IID の address を作る。RA の間で切れないよう、作り直しの時刻を `networkd_ipv6_poll_timeout`・`networkd_ipv6_run_due` に入れる。
  古い address は kernel が寿命まで持つ（延ばさない）。
- 22: router の表（ifindex・router・寿命）を持ち、既定の route は優先の interface（有線を Wi-Fi より、有線の中は main.c の順。main.c に
  `networkd_interface_is_wifi` などの口を足す）の router だけ。他の interface の router の route は消す。RTM_IFINFO の carrier down で、その
  interface の AUTOCONF の address（SIOCGIFADDRS_IN6 の `IN6_IFF_AUTOCONF`）と router・route・RDNSS を消して選び直す。
- 23・27: RDNSS の server を interface ごとに寿命と一緒に memory に持つ。resolv.conf への書き込みは 1 つの関数（merge）: 今の file の先頭の
  comment 行（`# Generated by dhcpc for IF` など）・search・IPv4 と他の IPv6 の nameserver を保ち、前に networkd が足して今は無い RDNSS を除き、
  今の RDNSS を足す（3 つまで、重複なし）。main loop の各回で resolv.conf の (ino, size, mtime) が networkd の最後の書き込みと違えば merge
  （dhcpc の DHCPv4・DHCPv6 の書き込みの後に RDNSS が戻る）。完全な「DNS の 1 つの表」（dhcpc が resolv.conf を書かない形）は dhcpc と
  networkd の役割の変更が大きいので、この形にする（Q1 に報告）。
- 24: `dhcpc -6` を fork・exec で非同期に。entry に pid と開始の時刻、`networkd_ipv6_poll_timeout` は子が走っている間 200 ms、`run_due` が
  waitpid(pid, WNOHANG) で終わりを受け、15 秒を越えたら SIGTERM・SIGKILL。networkd に waitpid(-1) は無い（確かめた）。
