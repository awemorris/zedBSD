# Userspace shell, init policy, root bind mount, and Linux boot plan

## 0. Document status

- Status: **implementation plan; not yet implemented**

  the completed working-tree diff for human review.

This document is intentionally prescriptive. A lower-capability implementation

instead of silently inventing a second architecture.

## 1. Fixed product decisions

The following decisions are already made and are not open implementation
choices.

1. The boot FAT partition is the root filesystem, `/`.
2. The same mounted FAT instance is also visible as `/disk1`. This is one
   filesystem instance with a namespace bind/alias, not two independent FAT
   mounts.
3. Other mountable partitions are exposed as `/disk2`, `/disk3`, and so on.
   The boot partition always owns the `disk1` name even when it was not first
   in physical discovery order.
4. `/dev` remains devfs and shadows any physical `dev` entry in the boot FAT
   root.
5. The default init executable is `/bin/sh`.
6. The image build can select `/bin/noct` instead. Init receives no extra
   arguments in this milestone.
7. `sh` is the current zedBSD command shell moved to an ELF32 ring-3 process.
   It is not a POSIX shell and must not acquire POSIX grammar, pipes, jobs, or
   redirection in this work.
8. `noct` is installed as `/bin/noct`. Invoking it with no arguments starts
   the Noct REPL. The explicit `--repl` form may remain accepted.
9. Linux loading is provided by the separate `/bin/linux` ELF and a
   kernel ioctl. No user program receives I/O privilege or direct low-memory
   access.
10. The initial kernel context is process0/thread0. After it starts init, it
    becomes the permanent idle context. It does not join or wait for init.
11. If init exits, the reaper collects it and the machine remains in the idle
    loop. It does not reboot and does not restart init in this milestone.
12. Linux boot is a point of no return. All fallible reads and validation
    occur before the request is accepted. Final quiescence and overwrite are
    performed by thread0 in kernel space.
13. Existing GUI menu, Noct, Remacs/Emacs, text shell, Linux handoff, FAT,
    swap, and multi-drive behavior must have no regressions.
14. No commit or staging is permitted during implementation.

## 2. Required end state

The milestone is complete only when all statements below are true.

- `namei` carries both a mount context and an inode. `..` behaves correctly at
  `/disk1` and at every other mount root.
- Resolving `/bin/sh` and `/disk1/bin/sh` reaches the same underlying FAT inode
  and uses a single FAT mount, disk open, FAT cache, and swapfile pin.
- `/disk1/disk1` does not recursively follow the bind alias. It resolves only
  if a physical `disk1` entry actually exists in the boot FAT.
- The process0 cwd is `/` after VFS initialization. A child inherits its
  parent's cwd and file descriptors 0, 1, and 2.
- The kernel reads a bounded init-path configuration generated by the image
  builder, defaults to `/bin/sh` when it is absent, and spawns exactly one
  init process with PID 1.
- thread0 is never enqueued as an ordinary round-robin task after entering
  idle. It is selected only as the scheduler fallback and for pending
  kernel-only work such as the final Linux handoff.
- A timer or device interrupt wakes the idle CPU without a lost-wakeup race,
  and a newly runnable task is scheduled promptly after the interrupt.
- User `sh` can spawn and wait for `/bin/noct`, Noct programs, and
  `/bin/linux` through bounded syscalls. It never passes a kernel pointer.
- The current shell commands and startup/AUTOEXEC policy remain usable, with
  privileged actions implemented through cdev ioctls.
- The historical flat applet `run` command executes in ring 3 at address
  `0x50000` using RW load followed by RX protection. It never executes an
  applet with ring-0 callbacks.
- `/bin/linux` validates an already-open regular file, supplies a bounded
  command line and boot-device selection to `/dev/boot`, and reaches the
  existing PC-98 Linux entry path.
- Once `/dev/boot` accepts a request, the requesting syscall does not return.
  thread0 removes all user tasks, releases their vmspaces and swap slots,
  shuts down swap, and commits the staged Linux image.
- `vmunix` no longer links the interactive kernel shell or startup menu after
  parity is demonstrated.
- Host tests, focused QEMU tests, the full existing regression set, opcode
  checks, `git diff --check`, and an unstaged-diff review all pass.

## 3. Explicit non-goals

Do not implement any of the following in this milestone.

- `fork`, `fork1`, `execve`, copy-on-write, pthreads, or multiple threads in a
  user process;
- background commands, pipelines, shell redirection, job control, process
  groups, sessions, terminal ownership, or POSIX shell syntax;
- general signals or a user-visible kill API;
- dynamic ELF, PIE, shared libraries, `PT_INTERP`, relocations, or ASLR;
- a general VFS mount syscall, user mounts, unmount from userspace, mount
  propagation, or namespaces per process;
- file-backed mmap, `MAP_SHARED`, destructive `MAP_FIXED`, or W+X pages;
- user access to VRAM, BIOS gateways, I/O ports, page tables, HAL task handles,
  or physical memory;
- changing the INT `0xc2` register convention or renumbering syscalls 1-16;
- FAT32 policy changes, FAT12/16 case changes, LFN changes, FAT allocation
  changes, or swapfile-format changes;
- network APIs or the previously discussed LGY-98/TCP/IP work;
- automatic init restart or reboot when init exits;
- deleting historical source files merely because they leave the final link.
  First stop linking them; deletion requires a separate review.

Synchronous child execution is intentional. If future work adds background
children, it must revisit process groups, orphan reparenting, console
ownership, wait-any semantics, and signal delivery.

## 4. Baseline facts the implementation must respect

- `process_init()` already binds process0/thread0 to the initial HAL task.
  thread0 has no separately allocated HAL task stack.
- `sched_yield()` currently enqueues every running current thread. Therefore
  `sched_unlink(); sched_yield();` is not an idle implementation.
- `process_spawn()` currently resolves files and clones cwd from process0,
  opens a new console for descriptors 0-2, and optionally provides result fd
  3. It is not yet a user-child spawn primitive.
- `process_wait()` already blocks a parent and copies the bounded result sink.
- The process reaper currently wakes every scheduler tick. It should become
  event-driven so an idle system is actually idle.
- `mount()` currently requires a synthetic rootfs mountpoint inode and accepts
  only one-component paths. Mount crossing is keyed only by inode identity.
- `cwdinfo` currently stores only root/cwd inode pointers and a textual path.
  Inode-only state is insufficient when one inode is visible through both
  root and a bind mount.
- `kern_vfs_init()` currently mounts a synthetic root, devfs, then FAT
  partitions, and changes cwd to the boot `/diskN`.
- `process_spawn_init("INIT.ELF")` is hard-coded in `src/kern/main.c`, after
  which the kernel still owns the startup menu and command loop.
- Syscalls 1-16 already implement exit, fd I/O, cwd, anonymous mmap,
  mprotect, ioctl, monotonic time, and sleep.
- User mmap rejects `MAP_FIXED` and W+X. User ELF text starts at `0x00400000`;
  the historical applet address `0x00050000` is free.
- `/dev/console` and `/dev/graphics` already exist and must remain the sole
  user interfaces to text/keyboard and graphics.
- The Linux loader presently consumes legacy `struct zedbsd_file` and calls
  `process_quiesce_users()` from the kernel UI. The new caller is a user
  process, so final execution must be handed to thread0.
- The PC-98 Linux loader stages all loadable bytes before overwriting target
  physical addresses. Preserve that safety property.
- The build currently emits `INIT.ELF` and `NOCT.ELF` at the FAT root. Image
  tests assume those names and must be migrated deliberately.
- Current shell/startup code directly accesses HAL, VFS internals, legacy
  device arrays, and kernel globals. It cannot be linked into ring 3 without
  replacing each privileged call.

## 5. VFS mount-context design

### 5.1 Add struct path

Define the following kernel-private type in `include/kern/mount.h`, before
`struct mount`:

```c
struct path {
        struct mount *p_mount;
        struct inode *p_inode;
};
```

Add these helpers:

```c
void path_init(struct path *);
void path_set(struct path *, struct mount *, struct inode *);
void path_ref(struct path *);
void path_release(struct path *);
int path_equal(const struct path *, const struct path *);
```

Rules:

- a live path owns one inode reference and one mount-use reference;
- an empty path has both fields NULL;
- `path_set` takes references; it does not consume caller references;
- `path_release` clears both fields after releasing them;
- mount objects are from the existing static pool, but `m_usecount` still
  prevents unmount while cwd/open paths refer to the mount;
- inode `i_mount` continues to identify the filesystem instance which owns
  the inode. It is not overwritten for a bind alias.

### 5.2 Refactor struct mount into a mount tree

Keep `struct mount` as the filesystem-instance/mount-view object and add:

```c
char m_name[NAME_MAX + 1U];
unsigned m_usecount;
unsigned m_internal_flags;
struct path m_cover;
struct mount *m_bind_source;
struct mount *m_children;
struct mount *m_sibling;
```

Use an internal `MOUNT_BIND` flag distinct from public mount flags.

Interpretation:

- the root mount has empty `m_name`, empty `m_cover`, and no parent;
- a child mount's `m_cover` is the parent-directory path and `m_name` is the
  component shadowed by the child;
- `m_parent` identifies the parent mount view;
- a normal filesystem mount owns `m_disk`, `m_type`, `m_data`, and `m_root`;
- a bind mount owns no filesystem data and no disk open. Its `m_root` is a
  referenced source inode and `m_bind_source` identifies the source view;
- mount-tree children are keyed by parent mount view, cover inode, and
  component name, not by inode alone.

Do not use a second call to `fat_filesystem_type.mount` to create `/disk1`.
Do not call `disk_open` twice for the boot partition. Do not duplicate
`fat_inode_info`, inode caches, namecache entries, or swap state.

### 5.3 New mount API

Replace the rootfs-specific boot sequence with these kernel interfaces:

```c
int mount_root_create(const char *type, int flags, void *data,
                      struct mount **result);
int mount_at(const char *type, const struct path *directory,
             const char *name, int flags, void *data,
             struct mount **result);
int mount_bind_at(const struct path *source,
                  const struct path *directory,
                  const char *name,
                  struct mount **result);
struct mount *mount_root_get(void);
int mount_lookup_child(const struct path *directory,
                       const struct componentname *component,
                       struct path *result);
int mount_cross_parent(const struct path *current, struct path *result);
```

The old public-looking `mount()` can remain as a temporary internal wrapper
while callers migrate, but no final caller may depend on synthetic rootfs
directories. Remove `mount_rootfs()` from the boot path.

`mount_lookup_child` is checked before backing-filesystem `inode_lookup`.
Thus `/dev` and `/diskN` exist as namespace mount components even when there
is no corresponding FAT directory. The namespace component shadows a same-
named FAT entry only in that mount view.

### 5.4 namei and cwd changes

Change `struct cwdinfo`:

```c
struct path root;
struct path cwd;
char cwd_path[ZEDBSD_PATH_MAX];
```

Change the signatures:

```c
int namei_at(struct cwdinfo *, const char *, struct path *);
int namei_parent_at(struct cwdinfo *, const char *, struct path *,
                    struct componentname *,
                    char storage[NAME_MAX + 1U]);
int cwdinfo_init(struct cwdinfo *, const struct path *);
```

Traversal algorithm for every component:

1. Start from the complete root path for an absolute path or cwd path for a
   relative path.
2. Collapse `.` without changing the path.
3. Clamp `..` at `cwdinfo.root`.
4. If `..` is requested at the root inode of a non-root mount view, replace
   the current path with that mount's cover-directory path.
5. Otherwise call the backing inode's `lookup("..")` and retain the same mount
   view.
6. For a normal component, first ask `mount_lookup_child` whether the current
   directory path has a mounted child with that name.
7. If so, enter that child mount root without looking up a physical inode.
8. Otherwise call `inode_lookup` and retain the current mount view.

Required examples:

- `/disk1` -> bind-view mount + boot FAT root inode;
- `/disk1/..` -> root-view mount + the same boot FAT root inode;
- `/disk1/bin/sh` -> bind-view mount + FAT inode;
- `/bin/sh` -> root-view mount + the same cached FAT inode;
- `/disk1/disk1` -> physical lookup inside bind view, not the root-view alias;
- `/dev/..` -> root-view boot FAT root;
- repeated `..` above root -> root.

Convert `cwdinfo_clone`, `cwdinfo_release`, `fs_chdir`, and all namei callers
to use path references. Keep `cwd_path` as the canonical user-visible string;
it is not authoritative for mount traversal.

### 5.5 struct file path ownership

Add a `struct path f_path` to `struct file` and keep `f_inode` as a temporary
convenience alias to `f_path.p_inode`. `file_openat` receives a complete path
from namei and transfers it into the file. `file_close` releases `f_path`
exactly once.

Pseudo files have an empty `f_path` and NULL `f_inode`.

Directory operations continue to use `f_inode` for backing-filesystem work,
but `file_readdir()` must merge virtual mount children with the backing
directory. Add a per-open mount-child cursor separate from the backing
`f_offset` and implement this order:

1. emit mount-tree child names for `f_path` in stable mount order;
2. read backing entries from the filesystem;
3. skip a backing entry whose name is shadowed by a mount child in this mount
   view;
4. emit every other backing entry unchanged.

Thus `ls /` shows `disk1` and `dev` even though no FAT directory was created,
while `ls /disk1` shows only physical FAT entries because that bind view has
no root-view child mounts. No name may be emitted twice. Add
`mount_readdir_child()` and `mount_child_shadows()` helpers rather than
teaching FAT or devfs about the global namespace.

Keeping `f_path` also prevents loss of mount context when future `openat` and
`fchdir` are added. Do not implement those syscalls now.

### 5.6 Boot-root selection and numbering

Refactor `kern_vfs_init()` in this exact order:

1. Reset mount, cdev, partition, file, and relevant caches.
2. Register FAT and devfs filesystem types.
3. Register console, graphics, system, and boot cdevs.
4. Snapshot physical disks already registered by the PC-98 platform.
5. Scan every physical disk and create partition disks without mounting them.
6. Identify the boot partition by both the boot physical disk and
   `handoff->boot_partition_lba`.
7. Probe the boot partition as FAT. Absence or an unmountable boot partition
   is a VFS initialization failure; do not fall back to the legacy kernel UI.
8. Mount that FAT partition once with `mount_root_create("auto", ...)`.
9. Initialize process0 cwd/root to the root-mount path and set textual cwd to
   `/`.
10. Bind the root path at the virtual component `/disk1`.
11. Mount devfs at virtual component `/dev`.
12. Mount each other mountable partition at `/disk2`, `/disk3`, ... in stable
    physical-disk/partition discovery order.
13. Record the mount path on the corresponding partition metadata for system
    enumeration.
14. Activate the boot swapfile through `/swapfile`. `/disk1/swapfile` must
    resolve to the same inode, but must not create a second activation.
15. Return success only after root, disk1 alias, devfs, cwd, and swap policy
    are settled.

Keep a bounded rescan helper for explicit `probe-ide`/`probe-scsi`:

```c
int kern_vfs_rescan_partitions(void);
```

It scans only newly registered physical disks, never renumbers existing
mounts, never remounts the boot partition, and assigns the next free diskN
number. It is called by the system-device probe ioctl after platform probing.

### 5.7 VFS tests

Extend `tests/vfs-host-test.c` to prove:

- root FAT and disk1 share one filesystem mount callback and one disk open;
- root and disk1 paths return the same inode identity but different mount
  views;
- all dot/dotdot cases in section 5.4;
- mount components shadow backing names only in their parent view;
- root readdir merges `disk1`/`dev` exactly once and bind-view readdir does
  not recursively expose root-view mounts;
- unmount rejects a source mount with a live bind;
- cwd clone/release balances inode and mount references;
- opening and closing through both aliases does not double-free an inode;
- swapfile path aliasing does not produce a second open/pin;
- partition numbering reserves disk1 for the boot partition.

Do not weaken existing FAT12/16 lowercase or FAT32 case-sensitive tests.

## 6. thread0 and scheduler idle design

### 6.1 Thread flag and scheduler ownership

Add `THREAD_FLAG_IDLE` to `include/kern/thread.h` and set it only on thread0
during `process_init()`. Do not add a separately allocated idle kthread.

Add these scheduler interfaces:

```c
void sched_idle(void) __attribute__((noreturn));
int sched_has_runnable(void);
```

Rules:

- an idle-flagged thread is never appended to a run queue;
- `sched_yield()` must not append an idle current thread;
- when no run-queue entry exists and the current thread cannot continue,
  `sched_switch()` selects thread0 rather than calling `HAL_FATAL`;
- when thread0 is already current and no work is runnable, control returns to
  `sched_idle`;
- ordinary RUNNING threads retain current priority/quantum behavior.

### 6.2 HAL idle primitive

Add one small HAL API in `include/hal/hal.h`:

```c
void hal_cpu_idle(void);
```

The i386 implementation executes the equivalent of `sti; hlt; cli` and
returns with interrupts disabled. Document that contract. It must not allocate
a task, alter page tables, or become a PC-98 BSP policy function.

`sched_idle` loop:

1. disable interrupts;
2. if a kernel boot request is pending, call its thread0 executor;
3. if any task is runnable, switch to it;
4. otherwise call `hal_cpu_idle()` atomically;
5. after an interrupt, call `sched_switch()` before sleeping again.

This ordering prevents the classic check-then-HLT lost-wakeup race.

### 6.3 Event-driven reaper

Change the reaper to sleep indefinitely with `sched_sleep(0)` when there is no
zombie. Wake it from `exit1()` whenever an autoreap process becomes zombie.
Do not poll every tick.

When a process exits, reparent any remaining children to process0. Mark
unwaited reparented children `PROCESS_AUTOREAP` so init exit cannot leak a
future zombie. This is cleanup, not background-shell support.

### 6.4 Main flow

After VFS and init-path resolution, `kernel_main()` must:

1. spawn init with result pointer NULL, making it autoreap;
2. log the PID and selected path through the existing console/debug channel;
3. on spawn failure, log the error and continue to idle;
4. call `sched_idle()` and never return.

Do not call `process_wait()` for init. Do not reboot when it exits. Do not keep
the old kernel command loop as a hidden fallback in the final build.

### 6.5 Scheduler tests

Extend `tests/sched-host-test.c` for:

- idle thread never entering a run queue;
- sleeping current with empty run queues selecting thread0;
- a woken higher-priority thread displacing idle;
- timer wakeup after idle;
- `sched_yield` from an ordinary thread retaining round robin;
- no `HAL_FATAL("no runnable thread")` on the legitimate idle path;
- reaper wake being event driven rather than tick polled.

## 7. Minimal user process spawn/wait ABI

### 7.1 Stable syscall additions

Append, without renumbering 1-16:

```c
ZEDBSD_SYS_spawn = 17,
ZEDBSD_SYS_wait = 18,
```

Register convention remains the existing INT `0xc2` convention.

`spawn` arguments:

| argument | meaning |
|---|---|
| 0 | user pointer to executable path |
| 1 | user pointer to NULL-terminated argv pointer array |
| 2 | user pointer to NULL-terminated envp pointer array, or zero |
| 3 | flags |
| 4-5 | zero |

Return the positive child PID or `-errno`.

`wait` arguments:

| argument | meaning |
|---|---|
| 0 | exact positive child PID |
| 1 | optional user `int *status` |
| 2 | options; must be zero |
| 3 | optional result-buffer pointer |
| 4 | result-buffer capacity |
| 5 | zero |

Return the waited PID or `-errno`. PID -1/wait-any, `WNOHANG`, stopped
children, and signal status encoding are not supported yet.

### 7.2 Public process header and libc

Create `include/uapi/zedbsd/process.h` with:

- `ZEDBSD_SPAWN_RESULT = 0x00000001U`;
- fixed limits matching the kernel: 32 argv entries, 64 env entries, 16 KiB
  aggregate strings, and `ZEDBSD_PATH_MAX` path handling;
- declarations for the zedBSD spawn/result helpers when included by user
  libc.

Create `libc/include/sys/wait.h` with `waitpid` and the minimal exited-status
macros used by sh.

Implement:

```c
pid_t zedbsd_spawn(const char *path, char *const argv[],
                   char *const envp[], unsigned flags);
pid_t zedbsd_wait_result(pid_t pid, int *status,
                         char *result, size_t capacity);
pid_t waitpid(pid_t pid, int *status, int options);
```

`waitpid` delegates to `zedbsd_wait_result` with no result buffer.

### 7.3 Bounded copyin

Add `exec_copyin_vector()` in `src/kern/exec.c` or a nearby kernel-private
file. It must:

- copy each 32-bit user pointer separately with `copyin`;
- stop only at a copied NULL pointer;
- enforce entry and aggregate-byte limits before allocation/copy;
- use `copyinstr` for each string;
- reject integer overflow, unterminated arrays, and pointers at/above
  `0x80000000`;
- produce one kernel-owned allocation with stable argv/envp pointers;
- free every allocation on all errors;
- never retain a user pointer after syscall validation.

### 7.4 Parent-aware process spawn

Refactor the internal entry point to:

```c
int process_spawn(struct process *parent, const char *path,
                  char *const argv[], char *const envp[],
                  unsigned flags, struct process **result);
```

All path lookup and cwd cloning use `parent`, not process0.

Add `filedesc_clone_stdio(parent->fd, child->fd)`:

- copy only descriptors 0, 1, and 2 using `file_ref`;
- if process0 has no standard descriptors, init setup opens
  `/dev/console` with read/write modes exactly as today;
- do not inherit graphics, arbitrary descriptors, or result fd 3;
- result fd 3 is created only for `ZEDBSD_SPAWN_RESULT`.

The user syscall always requests a returned process pointer internally and
therefore does not set autoreap. After the PID is returned, its direct parent
must wait. Kernel-origin `process_spawn_init(..., result=NULL)` remains
autoreap.

Add `process_find_child(parent, pid)` and keep the current direct-child rule.
Do not expose a raw `struct process *` through UAPI.

### 7.5 Mutable libc environment

Replace the current override-only environment behavior with a small
libc-owned mutable `environ` vector initialized from crt0 envp.

- `setenv` replaces or appends an owned `NAME=value` entry;
- `unsetenv` removes it and compacts the vector;
- `getenv` reads the current vector;
- spawned children receive the current `environ`;
- limits remain bounded and allocation failures report errno;
- Noct environment import behavior remains unchanged.

This is required so shell `set`/`unset` values propagate to Noct children.

### 7.6 Process tests

Add focused tests for:

- malformed argv/envp pointers and missing terminators;
- aggregate strings over 16 KiB;
- relative spawn using the parent's cwd;
- stdio reference balance;
- exact-child wait and rejection of a non-child;
- result fd 3 and bounded result copy;
- parent exit reparenting and autoreap;
- repeated spawn/wait returning heap, vmspace, task, fd, and swap counts to
  baseline.

## 8. Privileged system cdev

### 8.1 UAPI

Create `include/uapi/zedbsd/system.h`. Use fixed-width fields, zeroed reserved
fields, and ioctl group `'s'`.

Define these bounded structures:

- `zedbsd_system_info`: boot BIOS id, device count, partition count;
- `zedbsd_system_device`: input index plus class, flags, BIOS id,
  display index, heads, sectors, block size/count, and disk name;
- `zedbsd_system_partition`: input index plus parent device index, partition
  slot, flags, start/data/count, label, and mount path;
- `zedbsd_system_probe`: requested IDE or SCSI class and returned count;
- `zedbsd_system_vmstat`: all values currently printed by `vmstat`, expressed
  as `uint64_t`;
- no pointers and no variable-length trailing payloads.

Define:

- `ZEDBSD_SYSTEM_GET_INFO`;
- `ZEDBSD_SYSTEM_GET_DEVICE`;
- `ZEDBSD_SYSTEM_GET_PARTITION`;
- `ZEDBSD_SYSTEM_PROBE_CLASS`;
- `ZEDBSD_SYSTEM_GET_VMSTAT`;
- `ZEDBSD_SYSTEM_HALT`;
- `ZEDBSD_SYSTEM_REBOOT`.

### 8.2 Kernel implementation

Create `include/kern/system-device.h` and `src/kern/system-device.c`.
Register `/dev/system` from `kern_vfs_init()`.

Move ownership of the validated handoff/device snapshot out of
`src/kern/main.c` into a small kernel inventory API (either a focused new
`src/kern/device-inventory.c` or the privileged subset retained in
`src/kern/device.c`):

```c
void kern_device_inventory_init(const struct zedbsd_handoff *,
                                const struct zedbsd_device *, unsigned);
const struct zedbsd_handoff *kern_device_handoff(void);
unsigned kern_device_count(void);
const struct zedbsd_device *kern_device_at(unsigned);
int kern_device_probe_class(unsigned device_class);
```

The inventory copies descriptors into kernel-owned bounded storage; it must
not retain a pointer to a temporary user object. `kernel_entry()` initializes
it immediately after `kern_platform_init()`. VFS, system-device, and the Linux
prepare path query this API. The final kernel must not depend on the shell-era
`kern_handoff`, `kern_devices`, `curdev`, `parts`, or macro aliases in
`src/kern/internal.h`.

The device:

- snapshots only public data into UAPI structures;
- calls existing HAL/kernel statistics functions for vmstat;
- uses `kern_device_probe_class()` in the kernel, then calls
  `kern_vfs_rescan_partitions()`. The baseline probe can only rediscover
  firmware-reported/registered units; do not invent unsafe BIOS SENSE calls
  for units which the compatible BIOS did not report;
- validates probe class as IDE or SCSI;
- performs halt/reboot through `kern_platform_halt/reboot`;
- never returns kernel addresses, raw handoff pointers, disk objects, or HAL
  handles.

No credentials exist yet, so all processes may open it. State that limitation
in comments; do not invent a partial credential model here.

## 9. Linux boot cdev and point of no return

### 9.1 UAPI

Create `include/uapi/zedbsd/boot.h` with ioctl group `'b'`:

```c
struct zedbsd_boot_linux {
        int32_t kernel_fd;
        int32_t boot_device_index;
        uint32_t command_line;
        uint32_t command_line_length;
        uint32_t flags;
        uint32_t reserved[3];
};
```

- `kernel_fd` is an open regular file in the caller.
- `boot_device_index == -1` derives the physical device from the file's
  mounted partition and `d_parent`. A nonnegative value is validated against
  system-device enumeration.
- command length excludes the NUL and is at most 4095 bytes.
- flags and reserved fields must be zero.
- define `ZEDBSD_BOOT_LINUX` as an `_IOW` request.

### 9.2 Prepare/commit split

Refactor `src/kern/pc98/linux-boot.c` into an explicit two-phase API:

```c
int pc98_linux_prepare(struct file *kernel, const char *arguments,
                       int boot_device,
                       struct pc98_linux_image **result);
void pc98_linux_commit(struct pc98_linux_image *)
        __attribute__((noreturn));
void pc98_linux_discard(struct pc98_linux_image *);
```

Prepare phase:

- accepts `struct file` and uses `file_pread`;
- validates ELF header, program headers, entry, sizes, destinations, overflow,
  and command line;
- resolves and snapshots PC-98 disk setup data;
- allocates staging memory above all Linux destinations;
- reads every file byte into staging;
- performs no user-process destruction and no low-memory overwrite;
- releases all references on failure and returns errno;
- leaves a fully kernel-owned immutable request on success.

Remove the Linux loader's dependency on legacy `struct zedbsd_file`. Do not
change the PC-98 boot-parameter offsets, E820 construction, disk setup node
format, or final assembly entry.

### 9.3 Boot request handoff

Create `include/kern/boot-device.h` and `src/kern/boot-device.c`. Register
`/dev/boot`.

Only one request may be pending. On `ZEDBSD_BOOT_LINUX`:

1. copy and validate the UAPI request;
2. get and `file_ref` the caller's fd;
3. copy the command line into kernel memory and NUL terminate it;
4. call `pc98_linux_prepare`;
5. if prepare fails, release all state and return errno;
6. release the now-unneeded executable file reference; the prepared object
   must already own every staged byte and its command-line/device snapshot;
7. atomically publish the prepared request;
8. request rescheduling to thread0;
9. put the caller to indefinite sleep;
10. never return after publication.

After publication, ownership belongs to the global boot-request slot.
Closing the caller's `/dev/boot` file during final process teardown must not
cancel or free the request. The cdev close callback is therefore a no-op for
published work; only prepare failure/discard or the thread0 executor owns the
prepared image.

Add:

```c
int kern_boot_pending(void);
void kern_boot_execute_pending(void) __attribute__((noreturn));
```

`sched_idle` calls the executor from thread0/process0.

### 9.4 Final quiescence

The thread0 executor:

1. disables new spawns and new boot requests;
2. unlinks every non-thread0 user thread from run/sleep queues;
3. destroys noncurrent user HAL tasks;
4. closes user fds, including graphics ownership;
5. frees every user vmspace and releases swapped pages;
6. reaps process objects;
7. verifies no user process/thread remains;
8. calls `swap_shutdown`;
9. treats any failure after request publication as fatal and halts; it must not
   try to resurrect the shell;
10. disables interrupts, copies staged segments, zeroes BSS, constructs boot
    parameters, and jumps to Linux.

Because this runs in thread0's HAL system task, no active user page table or
user task stack is destroyed underneath the executing code. This is the
reason the ioctl may not directly commit from the linux user thread.

Keep all fallible disk reads before publication. No target physical byte may
be written before the final commit step.

## 10. Userspace applet execution

The current `run` applet is linked at `0x50000` and receives a service table.
Preserve it without running arbitrary code in ring 0.

### 10.1 Public ABI header

Move/copy the applet header and service-table definitions from kernel-private
`include/kern/boot.h` into `include/uapi/zedbsd/applet.h`. Keep magic,
version, packed layout, CRC rule, and 36-byte header unchanged. Kernel boot
headers may include the UAPI header temporarily to avoid duplicate
definitions.

### 10.2 Fixed no-replace mapping

Add `MAP_FIXED_NOREPLACE` to `libc/include/sys/mman.h` and support only this
safe fixed form in `sys_mmap_call`:

- page-aligned user address and rounded length;
- no overlap with ELF, stack, or any vm region;
- `MAP_PRIVATE | MAP_ANONYMOUS | MAP_FIXED_NOREPLACE` only;
- existing `MAP_FIXED` remains rejected;
- W+X remains rejected.

Add a vmspace helper which returns `EEXIST` on overlap rather than replacing
anything.

### 10.3 user/sh/applet.c

The ring-3 loader must:

1. open and size-check the file (36 bytes through 64 KiB);
2. map enough pages RW at `0x50000` with no-replace;
3. read the entire image;
4. validate header, image size, entry range, flags, and CRC;
5. mprotect the complete mapping read+execute;
6. create service callbacks implemented inside `/bin/sh` using normal
   read/write;
7. call the applet entry with user-space argv pointers;
8. report nonzero status exactly as the current shell does;
9. munmap the image on all return paths.

Do not pass HAL/kernel function pointers in the service table. Do not add an
applet execution ioctl.

## 11. Userspace sh design

### 11.1 File layout

Create:

- `user/sh/main.c`: init environment, startup policy, and REPL loop;
- `user/sh/shell.c` and `user/sh/shell.h`: tokenizer and command dispatch;
- `user/sh/startup.c` and `user/sh/startup.h`: startup menu/AUTOEXEC policy;
- `user/sh/console.c`: text/key helpers over fd 0-2 and console ioctls;
- `user/sh/system.c`: `/dev/system` wrappers and cached device/partition view;
- `user/sh/spawn.c`: synchronous child and result-fd helpers;
- `user/sh/noct.c`: Noct source/NAP resolution and invocation;
- `user/sh/applet.c`: section 10 loader;
- `user/sh/boot.c`: shell-side kernel/arg state and linux invocation.

The shell may include UAPI and libc headers only. It must not include
`kern/*`, `hal/*`, drivers, or PC-98 register headers.

### 11.2 Command behavior

Port commands with these exact backends:

| command | userspace implementation |
|---|---|
| help/echo/pause/wait | libc, console read, nanosleep/poll-event ioctl |
| env/set/unset | mutable libc environ |
| pwd/cd/ls/cat/source | POSIX cwd/fd/dir APIs |
| vmstat | `ZEDBSD_SYSTEM_GET_VMSTAT` |
| device | system info/device enumeration |
| probe-ide/probe-scsi | system probe ioctl, then refresh enumeration |
| disk/part | userspace selection over system enumeration; no remount |
| kernel/arg | shell-local Linux path/command-line state |
| linux | synchronously invokes `/bin/linux` |
| boot | invokes `/bin/linux` when kernel state exists; otherwise retains the current chain-boot-unavailable message |
| run | ring-3 applet loader from section 10 |
| noct | no args spawns `/bin/noct`; arguments resolve programs as below |
| emacs | spawns `/bin/noct /cmd/remacs.nap ...` and sets dictionary default |
| halt/reboot | system ioctls |
| unknown name | current `/cmd/NAME.NCT` then root and NAP fallback |

Keep the current simple splitter, quoting behavior, comments, error printing,
prompt form, ESC behavior, and source-file line reporting. Do not “improve”
the parser into a different shell language.

`disk` and `part` maintain selection metadata for Linux boot diagnostics.
They do not change cwd; `cd` remains the only cwd-changing command.

`/bin/linux` accepts exactly:

```text
linux [-d DEVICE_INDEX] KERNEL [KERNEL-ARG ...]
```

It opens KERNEL read-only, joins remaining arguments with single spaces into
a command line no longer than 4095 bytes, and issues `ZEDBSD_BOOT_LINUX`.
Without `-d` it sends boot-device index -1 so the kernel derives the physical
disk from the kernel file's partition/disk-parent chain. The shell's `linux`
and saved `kernel`/`arg`/`boot` paths add `-d` only when the user explicitly
selected a physical disk. Invalid syntax or an ioctl prepare error returns a
nonzero exit status and leaves sh running.

### 11.3 Noct path rules

Use lowercase VFS paths:

- executable: `/bin/noct`;
- commands: `/cmd/name.nct`, then `/name.nct`;
- bytecode fallback: `/apps/name.nap`, `/cmd/name.nap`, then `/name.nap`;
- Emacs: `/cmd/remacs.nap`;
- dictionary: `/home/skkjisyo.dic`.

FAT12/16 lookup already lowercases names. Do not add userspace uppercase
rewriting. FAT32 remains case preserving/sensitive according to existing VFS
policy.

### 11.4 Startup menu and AUTOEXEC

The kernel starts `/bin/sh` unconditionally. The shell owns all user-facing
startup policy and performs these steps before its first prompt:

1. clear `/dev/console` with `ZEDBSD_CONSOLE_CLEAR`;
2. set the cursor to row 1, column 0 so the banner starts on screen line 2;
3. print the specified NEC PC-9800 and zedBSD 0.0.1 banner, with one blank
   line between each text line;
4. if `/boot.cfg` is absent, enter the interactive shell immediately;
5. drain stale POST input, print
   `Starting boot.cfg... (Press any key to cancel)`, and poll console events
   for exactly one monotonic second;
6. on any event, consume the event, skip `/boot.cfg`, and enter the shell;
7. on timeout, execute `/boot.cfg` one line at a time, report a failed line,
   continue with later lines, and finally enter the interactive shell.

`AUTOEXEC.NCT` has no implicit startup meaning. A BOOT.CFG that wants the GUI
menu uses the explicit shell command `autoexec /autoexec.nct`. That command
runs `/bin/noct` with `ZEDBSD_SPAWN_RESULT`, accepts one bounded `BOOT_ACTION`,
and executes that result as one shell command. Normal `noct` remains a plain
child invocation without the result channel.

The generated message table must be usable by both kernel Linux progress and
user sh. Generate one neutral header under `$(BUILD)/generated` rather than
giving user code a `kern/messages.h` include.

Do not remove kernel startup/shell objects from `vmunix` until this userspace
path passes the same QEMU menu/AUTOEXEC tests.

## 13. Init configuration and image layout

### 13.1 Fixed init path

`kern_init_start()` always calls `process_spawn_init("/bin/sh", NULL)`.
There is no init configuration file, environment override, argument parsing,
direct-Noct init variant, or fallback kernel shell. A missing or invalid
`/bin/sh` logs the spawn error and leaves thread0 in the permanent idle path.

`ZEDBSD_SH_IMAGE` exists only as an image-construction test hook that replaces
the bytes installed at `/bin/sh`; it does not change the kernel path. The
missing, malformed, trap, and swap-init tests use this hook to exercise the
same fixed lookup as release images.

`process_spawn_init()` supplies this fixed initial environment while still
passing only `argv[0]` and no extra arguments:

```text

PATH=/bin:/cmd
REMACS_SKK_DICT=/home/skkjisyo.dic
```

The user shell may subsequently modify and propagate this environment.

Keep the fixed spawn in `include/kern/init.h` and `src/kern/init.c`; do not put
startup policy in `main.c`.

## 18. Error policy

- VFS root failure: print precise errno/reason, then idle.
- Missing or malformed `/bin/sh`: print path and errno, then idle.
- User child spawn failure: return errno and keep sh alive.
- User child abnormal exit: sh prints status and keeps running.
- system ioctl invalid index/class/reserved field: `EINVAL` or `ENOENT`.
- applet validation/mapping failure: print command error, unmap/close, keep sh
  alive.
- linux prepare failure: return errno, discard staging, keep sh alive.
- failure after boot request publication: fatal diagnostic and halt. Never
  return to partially quiesced userspace.
- Linux destination overwrite begins only after the last possible recoverable
  error.
